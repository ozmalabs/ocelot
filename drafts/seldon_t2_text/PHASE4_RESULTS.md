## 3. Dockerfile — decisions, each tied to a contract fact

- **Base `python:3.13-slim`** — `qfbench2-common 2.3.1` requires Python ≥3.13 (PHASE0
  §10). "slim" keeps the image small because the phase clock bills a **90–187 s cold
  image pull per unit** (PHASE0 resources), making image size a first-order budget lever.
- **`qfbench2-common @ v2.3.1` from the toolkit git URL** — omitting it is exactly the
  `ModuleNotFoundError: qfbench2_common` failure the guide flags (PHASE0 §10). Pinned to
  the tag. `jsonschema` is installed as a production dep (g1 fail-closes without it).
  **[RUN]** verified inside the built image:
  ```
  qfbench2-common version: 2.3.1
  direct_url.json: {"subdirectory":"common",
    "url":"https://github.com/Agenthon-2026/Agenthon2026-public.git",
    "vcs_info":{"commit_id":"9c5541adaeafd60afbadd393fd902367f8b6b078",
                "requested_revision":"v2.3.1","vcs":"git"}}
  ```
  i.e. it really installed from VCS at tag v2.3.1, commit `9c5541a` — the same commit the
  Phase-0 clone pinned. Build-time network is allowed; only **run** time is `--network=none`.

### 3.1 substrate_rs — the lightest viable path (this was the explicit ask)

The OCELOT substrate is the Rust crate `substrate_rs` (`runners/dsl`, built with maturin).

- A **full in-image Rust build** — `cd runners/dsl && maturin develop --release` — is
  **too heavy**: it needs the Rust toolchain (~1.5 GB) in the build, and the crate's
  `[profile.release]` is `lto="fat", codegen-units=1`, which **[BUILD] measured at
  2 m 41 s** on this machine (`maturin build --release`, user 157.5 s). That compile would
  be paid on every `docker build`, and it pulls the crate's heavy optional deps
  (wgpu/dynasm/rustfft).
- The crate already emits an **abi3 wheel** (`crate-type=cdylib`, pyo3 `abi3-py39`), so
  **one** wheel — `substrate_rs-0.1.0-cp39-abi3-manylinux_2_35_x86_64.whl`, **4.3 MB**
  **[BUILD]** — works on any CPython ≥3.9. **[RUN]** it installs into a clean py3.13 venv
  and imports.
- **Chosen path:** build the wheel **once, outside the image** (`build.sh` step 1) and
  `COPY` + `pip install` it. Zero Rust in the image, ~11 MB added layer, no per-build
  compile. The Dockerfile documents the exact heavy alternative (a `rust:1-slim` builder
  stage) should a fully self-contained build ever be required.
- **Honest scope note:** the **shipped** forecast arm (`JointDrawEngine` + rules text)
  does **not** import `substrate_rs`; only the optional TimeInfer-centering study arm
  (`forecast_text.py`) does. substrate is installed so that arm is available and the image
  is a faithful OCELOT runtime, but the container is admissible and fully functional
  without it. **[RUN]** `import substrate_rs` succeeds inside the image under
  `--network=none`.

### 3.2 Verb exposure

- `forecast` is on PATH via `docker/bin/forecast`; **no ENTRYPOINT** (`docker inspect` →
  `Entrypoint=null`) — so the harness's `<IMAGE> forecast …` runs it as the command
  (PHASE0 §1). The launcher also strips a leading positional `forecast`, so an
  ENTRYPOINT-style `<IMAGE> forecast forecast …` still works. **[RUN]** both forms tested.
- `LABEL qfbench2.interface_version="2.0"` set. **[RUN]** `docker inspect` → `2.0`.

## 4. The `forecast` verb (`forecast_cli.py`)

Exact signature (PHASE0 §1, SUBMISSION_CLI.md line 104):
```
forecast --panels /input/panels/ --text /input/text/ --asof YYYY-MM-DD --out /output/forecast.parquet
```

- **Grid source.** The verb args carry only panels/text/asof/out — **not** the target
  grid (asset_ids/horizons/unit_id). Those live in `card.toml`, which the harness mounts
  *inside* the unit dir at `/input` (SUBMISSION_CLI.md line 11: *"the UNIT DIRECTORY
  itself is mounted at /input"*). The verb resolves `card.toml` by walking up from
  `--panels` (`…/panels → …/card.toml`). **[RUN]** confirmed real cards carry the full
  grid (asset_ids/horizons/target_type/`[task].id`); only `target_dates` is sealed. A
  panels-only fallback keeps the verb from hard-failing if no card is present (smoke use).
- **Numeric core** = phase12 `JointDrawEngine` (the 30% joint-variogram arm), using the
  FFT `FastSeldonForecaster` so the long F3 horizons (63/126) solve in ~ms.
- **Text arm** (phase3): default **rules-only** — OCELOT-native, **network-free**, the
  floor phase3 proved *safe* (4.4% wrong-direction; failures are silence, not error). A
  **precomputed alias index** (`_ASSET_ALIASES`, a dict) links typed docs to the closed
  target-asset vocab — this is the budget lever the plan calls for ("precompute an alias
  index so it fits"); the graph-native `EntityLinker` (which boots the agent + runs rules
  per surface) stays available for offline study but is **not** booted per-surface inside
  the per-unit budget. `apply_text_shift` nudges each asset's draws by a **bounded
  0.5·σ** additive location shift in the signalled direction — this **preserves the joint
  correlation** (phase2), since it is the same shift on every draw of that asset.
- **Text never breaks admissibility.** Any exception in the text path is caught and the
  run falls back to the text-blind numeric forecast.
- **MODEL_ENDPOINT arm** routed EXCLUSIVELY via `HTTP_PROXY`/`HTTPS_PROXY` →
  `MODEL_ENDPOINT` (model id `MODEL_NAME`), **no vendor API, no hardcoded key** (PHASE0
  §1). It is OFF unless `QFB2_TEXT_ARM=model` **and** `MODEL_ENDPOINT` is set — otherwise
  it silently downgrades to `rules`, so an offline smoke never touches the network.

### 5.4 MODEL_ENDPOINT live wiring — proven against a local mock  [RUN]

The organizer's house endpoint is not reachable here, so the **live model accuracy is
NOT measured** (that remains the phase3 open item). But the **transport wiring** is proven
end-to-end: a mock OpenAI-compatible `/v1/chat/completions` server on localhost, with the
container run `--network=host -e MODEL_ENDPOINT=http://127.0.0.1:8099 -e
MODEL_NAME=house-model -e QFB2_TEXT_ARM=model`:
- the mock **logged 2 hits** (`model=house-model`, one per corpus doc),
- the container parsed the responses (`direction: up` ×2), applied the signal, and
- the output was **still admissible** (g0–g3 pass).

This proves the path is env-driven (`MODEL_ENDPOINT`/`MODEL_NAME`), OpenAI-compatible, and
carries **no vendor URL and no API key** — auth is left to the audited proxy (PHASE0 §1).

## 7. Exact commands to reproduce / to run in the real harness

Build the image (from repo root):
```bash
bash drafts/seldon_t2_text/docker/build.sh
# or reuse an existing fresh wheel:
SKIP_WHEEL=1 bash drafts/seldon_t2_text/docker/build.sh
```

Offline smoke on the exemplar (the GATE):
```bash
UNIT=<staged unit dir with card.toml + panels/ + text/>
OUT=$(mktemp -d)
docker run --rm --network=none \
  -v "$UNIT":/input:ro -v "$OUT":/output \
  qfb2-t2-ocelot:latest \
  forecast --panels /input/panels/ --text /input/text/ --asof <ASOF> --out /output/forecast.parquet
# score gates (needs the toolkit venv / installed scorer):
python -m qfbench2_track_forecasting.scoring score --card "$UNIT/card.toml" --forecast "$OUT/forecast.parquet"
qfbench2-smoke "$UNIT" "$OUT" --track forecasting
```

Restricted-net run with the house endpoint (the real T2 mode — organizer supplies proxy +
endpoint env):
```bash
docker run --rm --network=qfb2-eval \
  -e HTTP_PROXY -e HTTPS_PROXY -e MODEL_ENDPOINT -e MODEL_NAME -e QFB2_TEXT_ARM=model \
  --cpus=16 --memory=128G \
  -v "$UNIT":/input:ro -v "$OUT":/output \
  qfb2-t2-ocelot:latest \
  forecast --panels /input/panels/ --text /input/text/ --asof <ASOF> --out /output/forecast.parquet
```

In-image Rust build alternative (documented; NOT used — too heavy):
```
cd runners/dsl && maturin build --release   # ~2m41s here; needs Rust toolchain (~1.5GB)
```
