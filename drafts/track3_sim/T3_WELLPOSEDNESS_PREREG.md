# PREREG — Tier-A is ill-posed: an exactness gate below the model's own noise floor

**Committed BEFORE any number.** This is a WELL-POSEDNESS PROOF, not an
optimization. The output is a theorem about the QUESTION: given Track 3's stated
constraints, the exact-trace gate (Tier-A) demands agreement on coordinates the
model's own declared physics leaves free — so it measures implementation
identity, not simulation correctness, and is ill-posed with respect to the
competition's stated goal ("a faster simulator that still behaves like a real
exchange"). Per CLAUDE.md: the output is INFORMATION (a held, transferable
shape), never a benchmark number; the reducibility limit is the shape.

## The reframe (why "make ABIDES faster" was the wrong problem)

The task has been read as "this works, we need it faster." That accepts the gate
as well-formed. It is not. The claim, made provable:

> Under the DECLARED stochastic-latency constraint, there is a reducibility
> limit — the equivalence class of traces generated by valid re-draws of the
> latency stream. The realism/Tier-B tolerances are calibrated to admit that
> whole class (the README states 0.08 "comes from the natural run-to-run
> variation of correct simulations"). Tier-A rejects all but one member of it.
> Therefore Tier-A requires resolution FINER than the model's own noise floor.
> An exactness gate below the noise floor of its own stochastic physics is
> ill-posed.

This is a theorem decided by measurement, not an opinion about benchmark design.

## The constraints, taken as GIVEN (not disputed)

1. **Latency is a declared per-message random draw** (lognormal/uniform/pareto,
   `abides_fork/config.py get_latency`). Stochastic delivery time is a stated
   feature of the scenario, not an artifact.
2. **The comparators have finite, organizer-calibrated tolerances:** Tier-A ±1µs
   + Kendall-τ≥0.999; Tier-B KS≤0.08 + spread±10bps; the four stylized-fact
   ceilings. Tolerances exist because run-to-run variation of correct sims is
   real and conceded.

These two together DEFINE the reducibility limit. The proof is that Tier-A sits
past it.

## The two gates are separable (verified) — the instrument of the proof

`qfbench2_track_simulation.semantics.check_tier_a(cand, ref)` (exact) and
`qfbench2_common.scoring.stylized_facts.stylized_fact_report(...)` →
`admissible(report, ceilings)` (tolerant) + `semantics.check_tier_b(cand, ref)`
are independent functions over the SAME trace pair. So one trace can be shown to
FAIL Tier-A while PASSING realism/Tier-B — that gap IS the malformity.

## Method / discipline

- Perturb via latency SEED only (Half 1's verified stream split); scored engine
  math untouched; pinned checkout untouched. ≥3 valid re-seeds per scenario, the
  public family panel.
- Score EVERY re-seeded trace through BOTH gates on the same bytes:
  `check_tier_a` AND (`stylized_fact_report`+`admissible`, `check_tier_b`) — the
  real organizer functions, never a bespoke metric. The ceilings are the
  organizers' own (KS 0.08, ACF 0.12, Hill 1.5, depth-JS 0.10, Tier-B spread 10bps).
- The stylized-fact report needs BOTH cand and ref prices/depth; use the same
  mid-price/depth extraction the scorer uses (`semantics.mid_price_series`,
  `depth_histogram`) so the comparison is the real one.
- PREREG-then-measure; report whole distributions per family; the null (H-W1
  fails) is the finding and inverts the theorem honestly; no fabricated numbers.
  A faster submission is NOT the deliverable; the theorem is.
