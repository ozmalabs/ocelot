# PROGRAM TRAJECTORY BUDGET — PREREGISTRATION

**Date:** 2026-08-04

## Claim under test

The developmental motor residual is not a shortage of actuator authority.  A
single receipt-grounded compound program can improve its immediate vestibular
coordinate and still remain trapped in one support basin.  The missing object
is an arbitrary-order program trajectory whose intermediate states and edges
are graph data, and whose expansion horizon is supplied by the situated body
rather than by a source-code constant.

This is a general cognition mechanism.  Humanoid rolling is its first
discriminative consumer, not its ontology.

## Representation

- A transition is an observed, verified program-to-program relation carrying
  integer state-shape and consequence coordinates.
- A path is a prefix tree over those transitions.  It is not an AST and it is
  not a list of joint targets.
- Each longer path extends exactly one shorter prefix by one compatible edge.
  Therefore arbitrary order is representable while each tick still collapses
  to one compound motor outcome.
- Energy, load, boundary transitions, orientation span, and practice remain
  separate coordinates.  Pareto dominance may refute a path; it may not turn
  incomparable paths into a scalar utility.
- A path and every imported program are output-null until the ordinary motor
  release and receipt machinery verifies the situated action.

## Registered gates

### PT1 — order N changes the answer

On a constructed transition graph, an order-1 edge with the largest immediate
orientation change ends in a dead basin, while a two-edge prefix crosses the
declared orientation boundary.  With horizon two, the graph must construct and
select the depth-two prefix.  An implementation that merely re-ranks the first
edge fails.

### PT2 — the budget is graph data, not a magic number

Run the same graph twice.  With horizon one the depth-two prefix must not
exist; changing only the held horizon to two must make it exist.  No authored
depth or beam constant may appear in the rule bodies.

### PT3 — trade-offs remain Pareto

Two verified paths that exchange orientation progress for energy must both
remain on the frontier.  A third path that is no better on any coordinate and
worse on at least one must be marked dominated by the existing
`cognitive_pareto` faculty.

### PT4 — graph native and integer native

The generated seed contains no floating-point value, anatomy name, joint
target, Python decision, or direct actuator authority.  Path construction,
extension, dominance inputs, selection, and lifecycle are Rules/Terms executed
by Rust.

### PT5 — humanoid bridge, not humanoid core

The humanoid developmental seed may publish verified motor transitions into
the generic relation vocabulary and consume the selected first/next program.
The generic seed must contain none of `humanoid`, `rolling`, anatomical names,
or simulator vocabulary.  The bridge must preserve the existing one-compound-
outcome motor release and subsequent receipt verification.

## Experimental report boundary

Passing PT1–PT5 establishes the mechanism.  It does not establish that the
current PyBullet body rolls.  The floor-mobility run is reported separately:
orientation-class transition, path depth actually replayed, support contacts,
energy/load coordinates, and any remaining residual are all reported rather
than collapsed into one score.
