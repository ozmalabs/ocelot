# P2-B1 threat model

The worker is adversarial and its proposal/export is untrusted. The evaluator retains authoritative state, held-out mechanism composition, secret seed, fixture paths, simulator, action authority, and enactment rank. It validates canonical signatures and bounded fields before launch; independently reconstructs after output; and defaults to no broker call on any mismatch.

Containment is rootless Podman only: exact digest with `--pull=never`; fixed `/runtime/p2_native_worker` entrypoint; `--network=none`; read-only root; read-only noexec `/agent` and `/input`; fresh noexec/nosuid/nodev `/work` tmpfs; non-root fixed UID/GID; `cap-drop=ALL`; `no-new-privileges`; explicit seccomp; `--pids-limit=32`; 512 MiB; one CPU; minimized environment; no socket or writable host mount. Podman missing, non-rootless, policy mismatch, image mismatch, launch failure, overlong output, or a non-native/undeclared entrypoint is denial—not a local/Bubblewrap fallback.

Release tests execute two digest-pinned bypass images inside actual Podman: a native probe and a finite locally staged Python probe. The Python probe really imports and executes Python, then attempts shell/external command, agent/input write, evaluator host path, host socket, network, undeclared binary, callback, and raw ID-only action routes with valid Python rather than malformed JSON. Every hostile route must report denial/no effect; the evaluator independently commits the mounted agent/input trees before and after both probes and rejects any mutation or missing token. The Python image is probe-only and is never available to the native worker. The test suite also attacks identifier/order ranking, stale state, unavailable actions, unsupported correlations, replay, duplicate submission, and restart. This boundary does not claim protection against a compromised host kernel or evaluator signing key; such a condition invalidates the run.
