# P5-R0 local transfer gate preregistration (five-repair protocol)

Feature/ledger ID: `p5-r0-local-transfer-gate-v2`. This is evaluator-owned, local readiness evidence only. It cannot establish P5 release, adoption, positive transfer, general intelligence, or any external claim. No network, image pulls, commits, publication, release, or control-plane mutation is permitted.

Production requires an externally supplied trusted evaluator authority and transport/attestation binding. `validate_lock()` rejects a missing or mismatched authority, authority/key ID, public-key digest, transport attestation, manifest, card commitment, or lock signature. A generated signer is test-fixture-only; a self-authored lock cannot be production evidence. Receipt signing must use a signer bound to that external authority.

The signed V2 lock binds both DomainCards, taxonomy, split, public case-manifest digest, evaluator-private case-store/truth digest, mechanics commitments, policy, and exact native closure. Closure is not represented by booleans: it binds immutable image reference and ID, entrypoint, complete path-to-content-digest closure, seccomp profile path/content digest, architecture/default action, exact allowed syscall set and digest, hardened argv digest, runtime, network/pull policy, and finite limits. Preflight and every native invocation recheck rootless Podman, selected `crun`, image identity, profile/closure content, argv, and limits. Any missing or substituted value fails closed.

The canonical split is 48 committed cases (T01–T04 train, D01–D02 development, H01–H02 held-out; three cases per domain/combination). Each case runs cold-reset, frozen-transfer, and warm-adaptive. The evaluator executes the bounded private transition oracle through one worker/evaluator operation for primary and control tasks. Worker frames contain bounded observations, opaque legal-action tokens, step/session metadata, and the arm only; truth, target actions, private seeds, factor names/parameters, family, and split remain evaluator-private.

Factor tuples are behaviorally distinct. Reset versus persistent memory changes session-dependent observations; causal-present versus causal-absent changes predictive observations; flat versus compositional effects changes ordered subgoal trajectories; sparse-goal versus constrained-progress changes reward/terminal policy; and primitive versus composed tools changes interaction arity. Paired one-factor contrasts must differ in evaluator trajectory/effect/terminal evidence, not only in commitment digests.

Each arm is initialized once in committed case order. Warm carries its evaluator-owned session state forward and logs only bounded adaptation-namespace writes with session ID, ordinal, pre/post state digests, and write-set digest. Frozen uses the training artifact and has no writable session namespace: attempted writes produce `containment_failure`, restore the pre-state, and receipt the forbidden/empty write set; ordinary episode transitions cannot mutate the frozen session artifact. Reordering or reinitializing a session is a protocol failure.

Required controls are executable evidence entries: exact and template memorization, label and mechanics permutations, altered-semantics rejection, illegal-action, resource-exhaustion, safety-violation, leakage, containment, and negative-transfer controls. Every control invokes the same worker/evaluator seam as a primary task and receives a task digest, worker invocation/exit, evaluator outcome, expected outcome, and signed receipt. Controls are present exactly once in the same chain as primary records; hard-coded control booleans are not evidence.

A result cannot GO on receipt cardinality alone. GO additionally requires external-authority verification, exact 144 primary records and complete held-out coverage, native execution of every primary and control task, exact closure attestation, mechanics contrast evidence, warm/frozen session evidence, zero leakage/safety/resource/containment/negative-transfer/rollback failures, verified final chain closure, and exact rollback. Non-native callbacks are unit-test harnesses only and always no-go. If closure is unavailable or mismatched, execution returns `impasse` / `local_readiness_only/no_go` without attempting a pull or network action.

Every terminal, control, rollback, impasse, and run-closed path is signed. The final V2 result binds manifest/lock/policy/closure evidence and the definitive verified chain digest. Results remain raw finite records with no composite capability score and retain the claim boundary above.


## P5 gate closure amendment

The split lock now contains an explicit `contrast_matrix`, rather than a global diversity summary. Its five committed one-factor edges are `T01↔T02` (memory), `T02↔T03` (causal), `T04↔D01` (memory), `D02↔H01` (action effect), and `H01↔H02` (memory). Each edge is preregistered as `non_invariant` and is executed for both opaque domains, all three case ordinals, and all three arms: 90 paired cases / 180 side executions. The pair sides use the same worker/evaluator seam and matched nonce; each side receives a signed `contrast` receipt containing case, factor, task, worker, evaluator, and behavioral evidence. A pair passes only when the observed behavioral digest relation matches its locked invariant/non-invariant declaration. Missing, duplicate, null, unverified, or commitment-only pairs are no-go.

The GO gate is evaluator-owned and receipt-bound. Every primary and control result must contain a non-null digest receipt hash. The hash must be unique, belong to the verified signed chain for the current run, and bind the returned row/control projection, outcome, run ID, and lock context. The gate also requires the complete locked primary case set, controls in exact preregistered order and cardinality, exactly one signed receipt for every pair side, one restored rollback receipt, one verified close receipt, and a final digest recomputed from the verified chain. Caller-provided `chain_verified`, `controls_passed`, or mechanics booleans are not evidence. Native closure remains mandatory for GO; non-native worker callbacks are test harnesses and remain fail-closed.



## V3 repair amendment (approved local repair set)

The V3 repair keeps the V2 lock, receipt directory, and native run artifacts immutable and creates a distinct V3 lock/output root. The local authority boundary remains unchanged: workspace/test authorities are not external custody and cannot support release, adoption, or promotion.

1. **Illegal-action control:** the locked worker control must emit an out-of-range action or an equivalent worker-boundary protocol failure. The runner may carry that failure only as `protocol_error`; it must not substitute a legal action, and the evaluator must not report evaluator success for the stimulus.
2. **Warm reset:** an already armed session may be reused only with the same arm, order, and explicitly supplied session identity. A mismatch is rejected before native invocation, leaves evaluator state unchanged, and is recorded as a signed V3 `reset` mutation artifact with exact rollback.
3. **No-go evidence closure:** a completed V3 result, including a no-go, must retain the locked primary, control, contrast, rollback, and close evidence. A result with an omitted control or shortened evidence shape is not resealable; only an explicit `impasse` may omit the workload.
4. **Host closure:** the V3 closure binds the host runner, native command builder, evaluator, worker validator, repair/authority path, receipt chain, evidence/seal path, rollback path, and kill supervisor in addition to the worker/runtime/image/seccomp material. Host execution, runtime, and kill evidence must carry the V3 closure and lock bindings. Missing or mismatched evidence is a no-go.
5. **Execution policy:** all checks remain local, offline, `--network=none`, `--pull=never`, and fail closed. No network, pulls, commits, or authority/promotion claims are introduced by this amendment.
