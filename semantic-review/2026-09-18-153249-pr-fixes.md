# Fail-closed P5 readiness and one-shot repair

The repair moves V3 native readiness onto an explicitly supplied durable private store, makes the one-shot seed a service-owned timing/receipt event, gates supervisor promotion behind a trusted independent adapter, and requires authorized task execution with exact start commitments. It also adds checkpoint rehydration around post-evaluation persistence and expands negative-path tests. The private-store, supervisor, and authorization fixes are behaviorally present, and the normal successful seed path now advances the timing chain in order. **Watch for:** **confirmed** post-evaluation persistence failures still cannot rehydrate the last durable checkpoint, and **confirmed** timing-ledger advancement is not transactional with service-state persistence, so a failed seed/state write can permanently desynchronize retries.

**Verdict**: NEEDS_CHANGES

## High-level view

V3 readiness now rejects absent private truth before closure or worker execution and passes the explicit store through manifest validation and evaluator construction. The native result remains no-go unless a configured trusted, independent supervisor authenticates the complete observation; self-digested caller evidence is projected as unavailable rather than promoted.

The one-shot wrapper now requires a service-owned timing-seed operation, checks the returned run commitments against its configuration, and runs authorization before the callback. On a successful durable path, the seed is the first timing event and its digest is committed in the receipt chain, but **confirmed** the bridge and state store can still disagree after a persistence failure.

**confirmed** Checkpoint rollback is not complete at the persistence boundary. The evaluator checkpoint in the local state object is overwritten with the post-evaluation checkpoint before evidence, receipt, seal, or final state writes; the rollback helper then rejects the supplied pre-evaluation checkpoint because it compares it with that already-mutated state, leaving the run without a rehydrated engine.

1. **HIGH — Post-evaluation rollback cannot rehydrate** (**confirmed**) — `submit_result` updates the in-memory checkpoint before terminal persistence, while `_rehydrate_after_failed_evaluation` requires that checkpoint to match the old checkpoint it was given; on evidence/receipt/seal/state failure it raises instead of restoring the last durable engine. Restore from the supplied durable checkpoint independently of the mutated state and add a retry assertion.
2. **HIGH — Timing bridge and service state can diverge** (**confirmed**) — `issue_time_seed` and normal task/result timing call the external recorder before the timing object and service state are durably committed. If the later object or state write fails, the bridge has consumed a sequence that the durable run does not know about, so retry fails closed on sequence validation. Add an idempotent durable timing transaction/outbox or recover the committed bridge record before retrying.
3. **MEDIUM — Missing integration regressions for the repaired boundaries** (**confirmed**) — the 226-test suite covers fakes and injected failures, but does not exercise a real chained timing adapter through seed → task → result or assert that a post-evaluation failure rehydrates and can retry from the durable checkpoint. Add those cases, including partial receipt/seal persistence.

<summary>Details</summary>

### V3 native readiness and explicit private truth

**confirmed resolved:** `run_readiness_gate` rejects a V3 invocation without `private_store` before native preflight and validates the supplied object against the manifest and lock commitments. The evaluator is then constructed with that same object (`validate_manifest_integrity(bundle, private_store)`, `private_store_for(bundle, private_store)`, and `P5R0Evaluator(bundle, private_store)`); the process-local fixture registry remains only in the compatibility helper and is not a V3 production fallback.

### Trusted supervisor observation and native claim boundaries

**confirmed resolved:** `_host_evidence` accepts a positive observation only after closed-schema validation, a configured supervisor reports `trusted` and `independent`, and its `validate_execution_evidence` returns true. The candidate is bound to the run, lock, closure, exact native invocation count, exit code, cleanup status, and host-kill digest when present. Without that adapter, even a self-consistent record claiming `verified_supervisor_observation` becomes `unavailable_unattested_local`, and readiness and one-shot result surfaces keep `native_verified` and `external_authority_verified` false. No production authority, worker containment observation, or P5 capability result is fabricated by this path.

### Service-owned timing seed and durable chain boundary

**confirmed resolved on the successful path:** the one-shot runner cannot call a raw timing adapter or derive input directly. It calls `service.issue_time_seed`, which records the first `task_issued` event through `_record_timing`, persists the timing object, appends a `time_seed_issued` receipt binding, and saves `time_seed_timing_record_digest` before returning the record to `derive_time_seed`. The subsequent service task event therefore expects sequence 2, and the one-shot evidence validator binds callback evidence to the seed and input digests. The RFC3161/FreeTSA proof remains an injected independent bridge capability; it is not synthesized by the evaluator.

**confirmed remaining risk:** those writes are not one transaction. `_record_timing` mutates `state["timing_sequence"]` and the externally chained recorder advances before `timing/{...}-seed.json`, the receipt, and `state.json` are all committed. A state-generation failure leaves the durable run at sequence 0 while the bridge is at sequence 1; a retry calls the bridge again and is rejected as out of sequence. The same ordering exists for ordinary `task_issued` and `result_received` events around `_save_state`. The operation must be replay-safe and recover an already committed timing record, or use a durable transaction/outbox that makes the bridge head and run state advance together.

### Post-evaluation checkpoint restoration

**confirmed unresolved:** `submit_result` captures `checkpoint_before` but immediately calls `_checkpoint_engine(state, engine)`, replacing `state["engine_checkpoint"]` with the mutated checkpoint. When a later `_post_evaluation_call` fails, `_rehydrate_after_failed_evaluation` checks `state.get("engine_checkpoint_digest") != digest(checkpoint)` and rejects because the current state contains the post-evaluation digest. The direct evidence-store failure reproduction therefore returns `durable evaluator checkpoint unavailable; fail closed` and leaves `_engines[run_id]` absent rather than rehydrating the pre-evaluation engine.

This is fail-closed in the narrow sense that the mutated engine is not left live, but it does not satisfy rollback: a same-process retry has no restored engine, and partial evidence/receipt/seal files can also make a subsequent commit conflict with the still-old durable state. The helper needs to validate the supplied checkpoint itself, temporarily rehydrate from it without consulting the mutated checkpoint, and leave the run at the last durable checkpoint; persistence-failure tests should verify both engine state and retry behavior.

### One-shot authorization and commitment binding

**confirmed resolved:** `OneShotConfig.validate` now requires a callable authorized-task validator. Attested Confidential Space activation remains mandatory through the typed adapter binding and certified timing/KMS/store capabilities. After `start`, the runner compares lock, manifest, and worker-contract digests exactly with `OneShotConfig`, validates the returned run identifier, validates the closed task response, and checks run ID and sequence before invoking the executor. An authorization failure is raised before the callback, as covered by the negative test. The callback is also barred from setting native or external-authority claims, while the final public result is forced to diagnostic no-go fields.

### Failure-path coverage

**confirmed gap:** the focused and broad suites pass (`226 passed`), including explicit-store rejection, forged supervisor evidence, missing timing operation, authorization ordering, start commitment mismatch, and evidence persistence failure. They do not use the production-shaped chained timing bridge for the one-shot sequence, and the rollback test asserts only that the engine map is cleared; it does not prove rehydration from the old checkpoint or a successful safe retry after partial terminal persistence.
