# Locked sealed-input P2 release path

P2-B1 now loads the lock-measured sealed input, requires the caller bytes to match it, verifies the envelope signature, and passes the measured digest through its worker, evaluator, and receipt paths. The evaluator independently reconstructs the one-step graph rather than calling the worker implementation, and receipt persistence has a preflighted primary chain plus an evaluator-signed failure chain. These are bounded, fail-closed improvements, but the native frames still treat `verified_input_digest` as an asserted label rather than a digest of their supplied envelope, so either frame can score a different valid envelope while retaining the locked digest label. The focused Python run also demonstrates that the terminal record for a denied alternate envelope uses the caller digest, not the locked input digest. Watch for: **confirmed** native worker/evaluator envelope binding is not independently enforced; **confirmed** the denial receipt breaks the lock-to-terminal identity chain; **confirmed** no actual digest-pinned hardened release image is staged or executed.
**Verdict**: NEEDS_CHANGES

## High-level view

The trusted Python release runner correctly gates execution on a canonical byte-for-byte match to the staged sealed input and lock digest. However, the native worker and evaluator receive an arbitrary envelope plus an independently formatted digest string; neither recomputes or verifies their relationship. The runner is therefore the sole enforcement point for an identity property that the worker/evaluator are expected to uphold.

Receipt handling has the intended terminal posture for storage faults. Both receipt authorities are probed before execution, a primary append failure returns zero credit only after a signed failure-chain append succeeds, and the replay claim is removed. A denied alternate envelope nevertheless reaches the normal receipt path carrying the alternate caller digest, not the sealed-input digest that release attempted to use.

The release policy constructs a hardened, rootless, no-network Podman command and its preflight rejects absent local pinned images. Local evidence is only fail-closed: the checked-in lock is an intentionally invalid pre-release V1 placeholder, the scratch image context lacks the native worker and library closure, and the required pinned images are unavailable; the integration tests otherwise exercise mock shell/Python stand-ins.

## Native authority accepts an asserted digest label

**Confirmed.** `P2Runner._locked_envelope` prevents its caller from launching with a different envelope: it loads canonical bytes from `sealed_input`, requires `canonical_bytes(envelope) == raw`, verifies its signature, then supplies the lock's file digest.

`p2_native::worker_reply` and `evaluator_reply` only call `verified_input_digest`, which validates the supplied string's SHA-256 shape. Neither function hashes its `envelope`, reads the staged sealed artifact, or verifies the signature; it subsequently puts the supplied string in the proposal, evaluator response, reconstruction, and score. A direct native request can therefore pair any structurally valid `P2ObservationEnvelopeV1` with the lock digest and receive a plan/evaluation for that other envelope. The current Rust regression only proves that a missing digest rejects and that changing the evaluator label makes a previously generated proposal mismatch; it does not prove that a digest mismatched to otherwise valid envelope bytes rejects.

The worker and evaluator need an authority-local equality check: canonical sealed bytes must be measured by the same digest definition used in the lock, and that result must equal `verified_input_digest` before graph reconstruction. If the native runtime cannot reproduce the lock's canonicalization, the request must carry the measured sealed bytes/artifact from a read-only lock-bound location rather than a detached assertion.

## Caller mismatch denial is sealed with caller identity

**Confirmed.** `score` initializes `input_digest` with `_safe_digest(envelope)` before preflight and `_locked_envelope`. When `_locked_envelope` rejects a valid, separately signed caller envelope, execution goes through the `P2ProtocolError` branch before `input_digest` is replaced with `lock["artifacts"]["sealed_input"]`. `_finish` then writes that caller-derived value into the primary receipt and returns it as `verified_input_digest`.

`test_valid_but_separately_supplied_envelope_is_denied_before_worker_launch` exposes the behavior: the suite ran 14 passing tests and this test failed because `response["verified_input_digest"]` was the alternate caller digest rather than the staged sealed-input digest. The execution denial is correct, but its terminal evidence cannot be joined to the lock-sealed input. Load or derive the staged digest before attempting caller comparison and use it for all terminal release evidence after the release artifacts are trusted.

## Hardened policy remains a fail-closed prerelease gate

**Confirmed.** The Podman contract requires rootless execution, a fixed non-root UID, no network, read-only root and mounts, dropped capabilities, no-new-privileges, a digest-bound seccomp profile, and a pinned local image. `ReceiptLog`/`ReceiptFailureLog` preflight and append behavior also preserve the requested receipt-failure boundary: preflight denial occurs before native execution, and a primary append fault becomes a zero-credit result only after a distinct signed failure record exists.

There is no real release artifact set to establish the bounded release scope. `evaluation/p2/p2.lock.json` is an invalid `P2EvaluationLockV1` placeholder while the release code requires a trusted `P2ReleaseLockV2`; `evaluation/p2/Containerfile` references `p2_native_worker` and `lib/`, but neither exists in the local context. Rootless Podman is available, but image inspection for the pinned test image returns “image not known.” The real integration suite is designed to fail under `P2_RELEASE_LANE=1` when the bypass-image digest is absent, while ordinary replay tests use a shell script that impersonates Podman and an evaluator script. This is safe failure, not hardened-lane success evidence.
