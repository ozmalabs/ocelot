# Confidential Space evaluator adapter with attestation-gated cloud capabilities

This change adds a locked Confidential Space bootstrap for the evaluator: it parses non-secret policy, fetches and verifies a metadata attestation, exchanges that JWT through Workload Identity Federation, and only then constructs scoped GCS and KMS capabilities. The worker-facing evaluator receives the authenticated task protocol rather than cloud clients, while timing and receipt artifacts remain signed by the pinned KMS authority. The deployment artifacts are review-only placeholders and the local tests cover the locked state, exact image/nonce checks, fake STS/KMS/GCS activation, path scoping, and a basic configuration failure. Watch for: **confirmed** STS provider/audience incompatibility; **confirmed** ambient-ADC and audit-policy escape hatches; **confirmed** denial-of-service exposure in the WSGI body read; **likely** service failure after the federated token expires; **confirmed** mutable image-build input.

**Verdict**: NEEDS_CHANGES

## High-level view

The adapter has the **confirmed** high-level gate: no cloud client or truth read occurs before attestation, and capability creation is fed an explicit federated token. However, the configured attestation audience is the full IAM URI while the configured WIP provider and STS payload use the short resource form; because the production STS client ignores its `audience` argument, activation is likely to fail against Google STS. The claim-path configuration also has a **confirmed** gap: it does not cover every path that the deployment checklist says must be frozen.

Storage and signing are separated from the worker and the scoped wrapper limits evaluator object names to the intended prefixes. That boundary is weakened by the public `GCSStore` fallback to `storage.Client()`, which can create an ambient-ADC client outside the adapter, and by the **likely** lack of a reactivation or refresh path once the one short-lived federated token expires. The health policy digest has a **confirmed** incomplete commitment to the authentication policy.

The HTTP wrapper has a **confirmed** pre-limit body-read gap: it reads the declared request body before the evaluator’s 1 MiB limit can run, so an untrusted or negative `Content-Length` can defeat the intended memory guard. The image recipe has **confirmed** mutable build input because it pins a Python tag rather than a content digest, meaning the attested final image can be bound exactly only after a mutable base has already entered the supply chain. The focused fake tests pass, but they do not exercise these production boundaries.

## STS audience binding and Confidential Space claim contract

The **confirmed** STS request is not bound to the canonical provider audience used by the attestation endpoint. `confidential-space.metadata.example` defines `P5R0_ATTESTATION_AUDIENCE` as `//iam.googleapis.com/projects/.../providers/...`, but defines `P5R0_WIP_PROVIDER` as `projects/.../providers/...`. `ConfidentialSpaceAdapter` passes the latter as both `audience` and `provider`, and `GoogleSTSClient.exchange` ignores its `audience` parameter and serializes `provider` into the RFC 8693 `audience` field. Google STS provider audiences use the canonical `//iam.googleapis.com/...` resource form, so the current production path is likely to reject the exchange or bind it to a different resource than the one reviewed. Normalize the provider representation and serialize the explicit audience; add an opener-level test that inspects the form body rather than only asserting a fake client call.

There is a **confirmed** mismatch between the deployment checklist and the configurable claim contract. The lock document asks reviewers to freeze paths for audience, nonce, `iat`, and `exp`, but `LockedBootstrapConfig.claim_paths` only permits paths for the eight workload-policy claims; `AttestationGate` hard-codes `aud`, `exp`, `iat`, `nonce`, and `iss`. This is compatible only when every target token uses those exact top-level names. Either make the standard claim paths explicit immutable configuration, or narrow the checklist and test against the actual Confidential Space token shape.

## Explicit capability creation versus ambient credentials

The **confirmed** ambient-ADC escape hatch is in `GCSStore`: omitting `client` calls `storage.Client()` with default credentials. The adapter’s `CapabilityFactory` currently injects a client, so the normal path does not use the fallback, but the exported store class still permits a future caller or refactor to bypass the attestation/STS boundary. The same fail-closed contract should be enforced at the storage abstraction itself by requiring an explicit credentialed client (or by making the ambient path test-only and unreachable from production imports).

The federated token has a **likely** lifecycle failure. `activate_attested_service` builds one `Credentials` object from one `FederatedAccessToken` and never refreshes or re-enters the attestation gate; after `expires_at`, the long-lived Gunicorn process remains marked `attested` while GCS/KMS calls begin failing. Bound the process/run lifetime to the token, or add a locked refresh path that repeats attestation and STS before expiry and atomically replaces capabilities. A test should advance a fake clock past expiry and verify either refresh or a deliberate locked response.

The health endpoint exposes a **confirmed** incomplete policy commitment. `LockedBootstrapConfig.policy_digest` omits `caller_audience`, `allowed_subjects`, `expected_issuer`, and the configurable metadata URL even though those values change who may invoke the service, which issuer is trusted, and where attestation is fetched. Two deployments with different application allowlists or issuer can therefore report the same policy digest. Include every security-relevant policy field, or label the value as an attestation-only digest and provide a separate complete deployment-policy commitment.

## HTTP ingress before evaluator limits

The WSGI adapter has a **confirmed** request-size gap. It converts untrusted `CONTENT_LENGTH` to an integer and calls `wsgi.input.read(length)` before `EvaluatorService._json_body` can enforce its 1 MiB limit. A large declared length causes the server to read and retain the large body first; a negative length asks the stream to read until EOF. Invalid lengths are also converted into a generic 503 rather than a client error. Reject non-integer, negative, or over-limit lengths before reading, and use a bounded read for streams without a trustworthy length. Add an application-level test for oversized, negative, missing, and malformed lengths.

## Image reproducibility and deployment contract

The **confirmed** image recipe does not provide exact build-input binding: `Containerfile` uses `FROM python:3.12.8-slim-bookworm`, a mutable registry tag. Runtime attestation can verify the final image digest, but it cannot make a rebuild from a changed base image equivalent to the reviewed build. Pin the base image by digest and keep the resulting final-image digest in the reviewed deployment record; the lock document should treat the base digest as an immutable input rather than only the deployed image digest.

The deployment documentation has a **confirmed** operator-facing naming asymmetry. The metadata example uses `P5R0_EXPECTED_IMAGE_DIGEST`, while the README tells operators to replace `P5R0_IMAGE_DIGEST`; the code accepts both, but this leaves two names for the same security binding and makes a reviewed manifest easy to configure inconsistently. Choose one canonical variable name across the adapter and review artifacts, or state explicitly that the legacy alias is unsupported for Confidential Space deployment.

## Trust-boundary coverage in the local tests

The focused tests are **confirmed** to cover only fakes: they pass six tests and verify the locked state, exact image/nonce rejection, injected client construction, STS failure, scoped paths, and one missing environment value. They do not cover the production metadata URL request, canonical STS form body and response validation, hard-coded versus configured claim paths, issuer/time/secure-boot/project mismatches as a matrix, the no-client GCS fallback, token expiry, incomplete policy-digest binding, or WSGI body limits. Add tests for those boundary contracts before treating the adapter as deployment-ready; retain the existing fake-client tests because they correctly ensure no cloud calls happen during locked bootstrap.
