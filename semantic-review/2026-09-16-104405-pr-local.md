# Lock-bound evaluator authority for P4 native readiness

P4 stages a canonical evaluator-authority artifact, commits its digest in the signed local lock, and mounts it read-only at the worker’s fixed trust path. The request can no longer select authority or lock identity, and `run_local` accepts only the concrete hardened Podman spec and launcher. **Watch for: confirmed — the pinned fixture image is absent locally, so this pass establishes fail-closed local no-go behavior rather than successful Podman-contained execution.**

**Verdict**: APPROVED

## High-level view

Trust selection now happens before the request reaches the worker: the signed lock commits the staged authority artifact and the runner validates its identity, digest, and closure membership before launch. Production workers load only the fixed mounted artifact; the host-path override is explicitly unit-harness-only.

Readiness certification has one concrete Podman boundary. Look-alike launchers and specifications fail before invocation, while the native outcome path admits completion only after validation against the staged evaluator authority.

The regression suite covers authority, lock, artifact, closure, and launcher substitution. The unavailable local image deliberately leaves every real preflight result as `no_go` with rollback and no promotion authority.

## The worker derives evaluator trust from the staged lock commitment

**confirmed** — `preregister_local` writes `p4-trusted-evaluator.json` with the lock digest and evaluator authority, then stores that artifact’s SHA-256 digest in the signed lock. Before launch, `run_local` validates the lock, no-symlink closure, artifact digest, artifact lock digest, and authority tuple; `P4PodmanLauncher` repeats the staged-artifact digest check while constructing the fixed read-only mount.

The production request schema contains only execution and outcome bindings. The worker loads evaluator authority and lock identity from `/trust/p4-trusted-evaluator.json`, so caller-supplied authority material cannot influence verification. The native integration regression supplies an attacker key, matching signed outcome, and legacy request authority fields; the worker rejects it. A valid evaluator-signed outcome reaches `complete` only when the staged authority matches it.

## Podman remains the only readiness-certification route

**confirmed** — `run_local` requires exact `P4PodmanSpec` and `P4PodmanLauncher` types, rejecting an arbitrary launcher before preflight or command construction. The direct host-worker helper is confined to `P4_UNIT_HARNESS` and cannot certify readiness through `run_local`. The production command retains `--pull=never`, `--network=none`, a read-only root filesystem, dropped capabilities, `no-new-privileges`, seccomp, fixed unprivileged user, and the read-only authority mount.

**confirmed** — rootless Podman is enabled, but the local fixture image `sha256:aaaa…` is not inspectable (status 125). Preflight therefore produces an impasse, and the public result remains `local_readiness_only`, `no_go`, non-promotional, and rolled back. **Not tested:** successful end-to-end Podman completion cannot run on this host without pre-provisioning the pinned image; no pull was attempted.
