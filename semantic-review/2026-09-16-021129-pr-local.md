# Hardened P3 worker/evaluator boundary

P3 replaces the host-side execution seam with a Podman-launched worker, a separately invoked evaluator, a lock-bound staging closure, and append-only evaluator receipts. Candidate admission is fail-closed, local P0/P1/P2 attestations and candidate/snapshot digests are bound into the release lock, and the local path always rolls the candidate back instead of adopting it. Rollback write or verification failures are routed to signed terminal impasse evidence rather than silently treated as ordinary denials. **Watch for:** **confirmed** task-envelope signatures are created but are never verified at the visible worker/evaluator boundary; **confirmed** the hostile-container probes are only exercised through a fake launcher, so this checkout does not demonstrate that the asserted real Podman isolation failures are contained. **Verdict**: NEEDS_CHANGES

## High-level view

The worker is launched only through rootless, no-network, read-only Podman with a bounded stdin/stdout channel; evaluation is a distinct executable and no local runner API accepts an executor callback. The local runner retains no adoption authority and uses `custody_ok=False`, so even a successful statistical result remains a local no-go.

The lock and staging index enumerate the worker image, evaluator, runtime and control-plane artifacts, re-hash staged files, and preflight the digest-pinned local image. Pair receipts are lock-, candidate-, snapshot-, and receipt-bound and append before scoring; rollback failures become `impasse` receipts. **Confirmed** gap: the sequence is not cryptographically enforced at the worker/evaluator interface because the signed task envelope is accepted solely by its caller-supplied digest.

**Confirmed** gap: the containment API asks a container to report that five attacks were blocked and compares the two read-only mount trees, but the P3 test suite supplies that report with `FakeLauncher` rather than a built P3 image under Podman. The launch policy is tested as construction, not as an executed hostile-container proof.

## Signed task release is not enforced where the worker accepts it

`materialize_study` signs every `P3TaskEnvelopeV1`, including its run ID, distribution, ordinal, budget, and digest. The subsequent acceptance path does not authenticate that signature: `P3WorkerClient.execute_next` checks only that `envelope_digest` has digest syntax, writes the complete caller-supplied mapping into `next-task.json`, and sends just that digest to the worker. `validate_pair_evidence` checks that evaluator-signed evidence echoes the caller's digest and pair ID, but neither it nor `P3EvaluatorClient.evaluate` receives a task-release public key or validates the envelope's signature, canonical content, ordinal, or one-time release state.

This is **confirmed** from `evaluation/p3/study.py`, `evaluation/p3/execution.py`, and `evaluation/p3/runner.py`. The normal local loop calls `release_next` sequentially, but that is coordinator behavior rather than a boundary guarantee: any caller of the public worker client can supply a self-consistent unsigned envelope, and the visible evaluator contract will accept a signature over evidence bound to that envelope. The scorer reconstructs its own envelope sequence and matches only `pair_id`, not the evidence's released-envelope digest. Bind the evaluator's task-release verification key and release ledger to both sides, reject already-released or out-of-order envelopes, and make scoring compare the signed evidence digest to the expected released envelope digest.

## Containment probes are a protocol claim, not executed P3 evidence

The launcher requires rootless Podman, a locally available digest-pinned image, no pulls or network, a non-root fixed identity, dropped capabilities, `no-new-privileges`, a hashed seccomp profile, only read-only agent/input mounts, and bounded resources. It calls preflight and `adversarial_probe()` before task one, but this does not demonstrate the image's runtime behavior.

The lack of an executed probe is **confirmed**. The sole P3 references to `/runtime/p3_worker` and `/runtime/p3_probe` are the Python launcher, and `test_p3_execution.py` substitutes `FakeLauncher`, which returns the exact all-`blocked` probe report without creating a container. No P3 worker image definition, probe implementation, or native evaluator implementation is included in the new P3 tree; the only discovered Containerfile is a generic acceptance fixture. The focused P3 suite consequently passes (41 tests), but it proves request construction and response validation, not containment against an actual image. A real local acceptance run must build/provision the lock-pinned image without pulling, exercise all five attacks inside it, and retain signed output plus host-side mount/control-plane integrity checks.

## Local no-adoption and terminal rollback handling remain bounded

The local R0 runner makes adoption unreachable: its E1 decision receives `custody_ok=False`, it records a no-go result, restores the pre-snapshot, and returns `adopted=False` with `custody="local-test"`. On an execution failure it attempts the same rollback; if restore or verification fails, it produces evaluator-signed `P3RollbackImpasseEvidenceV1` inside an `impasse` receipt rather than claiming a completed rejection. **Confirmed** by `evaluation/p3/runner.py`, `evaluation/p3/admission.py`, and the rollback tests.

The artifact closure is explicit: the lock has a fixed artifact-name set, the staging index requires every entry, hashes local files below the staging root, and requires image references to equal the lock digest. This is only a local closure mechanism. A trusted release still requires independently controlled evaluator/task-release/receipt keys and custody, independently provisioned and attested P0/P1 confinement evidence, a verified immutable worker image and evaluator artifact, external signed P0/P1/P2 go attestations, and a sealed E1 result whose task-envelope and containment evidence have been independently verified. None of those trusted-release conditions are granted by this local checkout.
