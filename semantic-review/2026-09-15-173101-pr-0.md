# Rootless Podman mapping is live, but the acceptance worker cannot start

The repaired profile replaces the unusable private user namespace request with an explicit `0:1:65536` UID/GID map and retains `--user 65534:65534` plus the existing network, mount, privilege, and resource restrictions. The preserved rootless Podman evidence shows that this map was applied to each created container, and the host's parent rootless mapping translates its mapped IDs into `matt`'s `100000:65536` subordinate range rather than the host UID 1000. None of the three hostile acceptance cases reached their worker behavior: each bootstrap exits at package import because the staged image omits `evaluation.p0a.broker`. **Watch for: confirmed — the gate remains fail-closed before hostile filesystem/network probing, forged-frame handling, or descendant-stop verification; confirmed — it also records but does not enforce the live UID/GID mapping needed to preserve this safety property on later runs.**

**Verdict**: NEEDS_CHANGES

## High-level view

The actual map is safe on this host. Podman's rootless parent map reserves parent ID 0 for host UID/GID 1000 and maps parent IDs 1–65536 to host IDs 100000–165535; the container's `0:1:65536` map therefore gives worker UID/GID 65534 the subordinate host identity 165534, not the invoking host identity. The live inspect evidence for all cases retains `User=65534:65534`, private user namespace mapping, no network, read-only root, no bind/volume mounts, dropped capabilities, no-new-privileges, seccomp, and the configured resource ceilings.

The staged image copies `evaluation/p0a/__init__.py` and `agent_worker.py` but not the module imported by that package initializer. That prevents every case from getting past `python -m evaluation.p0a.agent_worker`; no hostile report, terminal protocol record, live descendant snapshot, or post-stop assertion exists.

## Subordinate mapping excludes host worker authority

The current execution evidence demonstrates a rootless, non-remote Podman 4.9.3 engine. Its parent UID and GID maps are `0:1000:1` and `1:100000:65536`; `/etc/subuid` and `/etc/subgid` both grant `matt:100000:65536`. Each preserved hostile-case artifact records the child maps as `0:1:65536`, a private user namespace, and `Config.User` as `65534:65534`. This composes worker UID/GID 65534 to host UID/GID 165534. Host UID/GID 1000 is represented only by parent ID 0, which the child mapping excludes, so the configured worker has no host-user identity authority.

The same inspection records the original containment profile: `NetworkMode=none`; read-only root; no declared or bind/volume mounts; `/workspace` as the only writable tmpfs; no capabilities; no-new-privileges and the explicit seccomp policy; private PID, IPC, UTS, cgroup, and user namespaces; PID 64, memory/swap 256 MiB, CPU 0.5, and both ulimits. **Confirmed gap:** the live assertion checks these fields but never reads `HostConfig.IDMappings`; the unit fixture deliberately passes with no mapping field. The deterministic command assertion detects a source-level change, not an engine-side mapping mismatch. The gate must make exact inspect mapping and its safe parent-map translation an acceptance condition.

## `evaluation.p0a` bootstrap fails before every hostile probe

`_stage()` copies `evaluation/p0a/__init__.py`, `agent_worker.py`, `agent_protocol.py`, and `canonical.py`. Starting `python -m evaluation.p0a.agent_worker` imports the `evaluation.p0a` package first, whose initializer imports `.broker`; that file is not copied into the image. **Confirmed:** the retained hostile, forged, and stop artifacts each return exit code 1 with `ModuleNotFoundError: No module named 'evaluation.p0a.broker'`.

This is the exact fail-closed block. The hostile case emits no filesystem/socket/descriptor report or sealed opaque-proposal receipt; the forged case emits no forged raw frame or terminal `sandbox_protocol_violation` record; and the stop case creates no descendant, cgroup snapshot, or post-stop proof. Although Podman created and inspected containers with the hardened profile before the bootstrap exited, none of the acceptance claims about worker behavior executed. A repair must stage the complete minimal import closure with its digests captured in evidence, or avoid importing broker-only host code in the worker package initialization, then rerun the three provisioned tests to completion.
