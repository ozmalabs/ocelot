# Bounded scratch-native P2 planning release repair

The repair creates a release-only path that stages a measured ELF closure into scratch images, runs a fixed Rust worker under rootless Podman, and seals outcomes through a native evaluator and signed receipt chain. A local offline release exercise independently passed here: it built the worker and bypass scratch images, completed one accepted evaluation, and verified the retained test receipt with the fixture signing key. The bounded runtime and receipt mechanics are therefore demonstrated for that local fixture, but they are not release evidence. The checked-in lock is deliberately invalid, the results document is still a template, and no signed 320-episode held-out run exists. **Watch for:** **confirmed** release certification is blocked by the absent real lock and preregistered held-out evidence; **confirmed** the required Python hostile attempt is not implemented; **confirmed** the native implementation does not invoke the preregistered future-manifold selection path.  
**Verdict**: NEEDS_CHANGES

## High-level view

The scratch-worker boundary is concrete rather than mocked: the runner verifies a complete artifact closure, probes the digest-pinned image, and uses rootless Podman with no network, read-only mounts, dropped capabilities, a fixed UID, seccomp, and finite CPU/memory/PID/output limits. The measured local exercise establishes that this arrangement can run a native one-step worker and produce a signed local receipt, not that a release artifact or score has been produced.

The held-out generator fixes a 320-entry index and scoring code rejects incomplete coverage. **Confirmed:** the preregistration itself says no score is claimed until a real lock and held-out run exist; neither is supplied, so the release endpoint must remain unavailable.

The hostile probe performs real shell, executable, write, network, Unix-socket, callback, and ID-route attempts inside the hardened container. **Confirmed:** it does not attempt the preregistered Python execution route, and the planning binary only uses local deterministic selection over sealed bindings rather than the declared future-manifold selection integration.

## Scratch closure is executable, bounded, and release-gated

The release runner requires every named artifact, verifies the lock against a trusted key, checks staged file digests and runtime-closure identity, preflights both images, probes the actual worker image, and runs the bypass image before it accepts a plan. The Podman command has no local fallback and constrains the worker to a digest-pinned image with `--pull=never`, rootless execution, `--network=none`, read-only root and mounts, no capabilities, no-new-privileges, seccomp, a fixed non-root identity, and finite resource limits. The local offline test passed in this review, including the actual scratch worker and bypass containers; its acceptance receipt at `/tmp/pytest-of-matt/pytest-2748/test_local_only_p2_release_and0/receipts/000001.json` reloads successfully with the test fixture key.

That test proves the mechanism for a single synthetic sealed envelope. It creates ephemeral local images, stages test artifacts for fields outside the worker/evaluator/closure set, signs with deterministic fixture keys, and scores one episode. **Confirmed:** it cannot establish the locked release closure, custody, or performance of the preregistered study.

## Release evidence has not crossed the preregistered gate

**Confirmed:** `PREREGISTRATION.md` marks this state as “pre-release native scaffolding only” and requires a real lock published before scoring, all 320 held-out entries, chained receipt hashes, raw counts, and Wilson intervals. `p2.lock.json` instead has the obsolete `P2EvaluationLockV1` shape, all-zero artifact digests, and no valid release signer; the runner accepts only a signed `P2ReleaseLockV2` with a complete artifact manifest. Independent validation of that file fails at lock-schema validation before any worker can start.

The only retained receipt is internally valid as a fixture-chain entry: it has sequence one, a verified test-lock status, and an accepted synthetic outcome. It is signed by the same deterministic fixture authority used to build the test lock and binds one sealed input; it does not include a published production lock, release authority, 320 receipt hashes, scoring evidence, or the preregistered aggregate criteria. `RESULTS_TEMPLATE.md` remains unfilled. This is an exact no-go for release certification, not a partial approval.

## The worker is native but not the declared future-manifold planner

The scratch image executes `/runtime/p2_native_worker`, and the binary does construct `WorldModelObservation`, `BeliefState`, `WorldModelAction`, and one-step `SimulationRequest`/trajectory records in Rust. **Confirmed:** after those checks, `p2_native.rs` derives each prediction directly from the public binding’s `effect` and `cost`, then uses its own `select` function to sort candidates by cost, confidence, and node ID. The only bounded-planner imports are belief revision and `simulate_one_action`; neither `p2_bounded::select_all_actions` nor the repository’s future-manifold projection/selection code is called.

**Confirmed:** this leaves a narrower, deterministic native selector over evaluator-supplied public mechanics, rather than the preregistered “native future-manifold projection/selection path.” The claimed boundary can be made truthful either by connecting the worker/evaluator to that path and measuring it in the release image, or by changing the preregistration before issuing a new lock to claim only this local sealed-binding selector.

## Hostile bypass evidence is real but incomplete against its own contract

The bypass binary actually attempts a shell, undeclared executable and callback, writes to both mounted directories, a TCP connection, a Unix-socket connection, and reads of evaluator/ID-route paths. It emits a fixed report only when all those operations fail, and the runner rejects scoring unless every named result is `blocked`; this is stronger than a malformed-input-only control. The runtime’s fixed worker diagnostics likewise avoid laundering raw OCI failures into semantic planning outcomes: semantic worker failures use a closed vocabulary, while unexpected launch failures are recorded generically.

**Confirmed:** the preregistration and threat model name Python import/execution as a mandatory in-Podman hostile route, but `p2_bypass_probe.rs` contains no Python execution attempt. Its `evaluator_path` and ID-route checks also use fixed absent paths, so they only establish that those exact paths are unavailable rather than exercising an exposed evaluator interface. The missing Python route alone means the declared mandatory control set has not passed.

The skipped tests require separately provisioned release image digests, which were not available as release evidence. Not tested: a real trusted release lock, retained production artifact digests, an independently held 320-episode execution, aggregate signed scoring evidence, and the complete preregistered hostile-control set.
