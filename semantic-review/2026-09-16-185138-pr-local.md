# Real-crun V3 rerun and locked GO-gate verification

The V3 workload ran twice through rootless Podman/crun, covering 144 native primary records and all 11 locked controls per run. The behavioral projections were repeatable (144/144 rows equal), and the warm-reset mismatch was rejected before native invocation with unchanged state plus signed mutation and rollback receipts. The runs remain `local_readiness_only/no_go`: the native illegal-action control returned a legal action, host/kill evidence was not bound, and the required mechanics contrast was absent. **Watch for:** **confirmed** no GO seal is justified until those three closures and completed receipt evidence are repaired.

**Verdict**: NEEDS_CHANGES

## High-level view

The two native runs used the same immutable image ID, `/usr/bin/crun`, rootless Podman, `--pull=never`, `--network=none`, read-only root, dropped capabilities, private namespaces, and the lock-bound seccomp profile. **Confirmed:** primary behavior was repeatable, but the real image worker accepted the illegal-action stimulus as action `0`, so the locked protocol-error predicate was not enforced at the native boundary.

**Confirmed:** the warm-reset identity mismatch was rejected before native invocation, preserved the pre-reset digest, emitted a signed rejected mutation artifact, and ended with exact rollback. The normal warm-adaptive path emitted adoption mutations, but completed evidence still failed receipt and host-evidence closure.

**Confirmed:** the result gate stayed no-go. The empty contrast matrix makes the required mechanics predicate unreachable, and the host/kill evidence projection contains null digests for required closure artifacts.

## Real-crun worker contract diverges from the repaired Python boundary

**Confirmed:** the host-side V3 worker rejects `control_id == "illegal_action"` with a locked protocol error, but the image entrypoint used by both native runs implements only the memorization null-action rule and otherwise returns action `0`. `_invoke_native_case` accepts that reply under `allow_invalid`, and the runner records the legal reply as `control_failure`. Both runs therefore show `expected: protocol_error`, `observed: control_failure`, `passed: false`, `worker_invocation: native`, and `worker_exit: 0`.

This is a fail-open control outcome at the native boundary. The fix must be in the image-bound worker contract or an equivalently lock-bound native rejection path; changing only the host fallback would leave real crun behavior unchanged.

## Closure status drops the files required to prove host and kill execution

**Confirmed:** the V3 lock contains the required host closure keys and preflight reports the image, runtime, worker, seccomp, argv, and closure checks true, but `closure_status` returns no `files` map. `_host_evidence` therefore emits null runner, native, and supervisor digests, and `evaluate_gate` rejects those fields against the lock-bound closure.

**Confirmed:** the kill record is synthesized with `observed: true`; the normal worker path does not demonstrate an actual kill event. The evidence producer must bind an observed supervisor/kill artifact rather than infer it from a successful worker exit.

## Warm reset, receipts, rollback, and repeatability

**Confirmed:** the dedicated warm-reset run stopped before native invocation with zero primary/control records. Its signed mutation artifact records `outcome: rejected`, identical pre- and post-state digests, and `rollback_exact: true`; the run closed no-go after exact rollback. Each normal run produced 144 primary records, 11 native controls, 206 receipts, and warm-session adoption mutations. Canonical comparison found 144 compared rows, all equal, with no field differences.

**Confirmed:** focused activation tests preserve V2 lock bytes/mode and reject mutating an impasse result toward GO. These protections prevent false promotion but do not convert the failed completed V3 evidence into approval.

## Gate reachability and completed result sealing

**Confirmed:** the run lock inherited an empty contrast matrix while `mechanics_contrast_required` is true and the runner sets `mechanics_contrasts_verified` from nonempty contrast evidence, so this lock cannot produce GO even if primary and control records pass. Preregistration must carry and execute the exact required left/right pairs.

**Confirmed:** both completed runs report `receipt_evidence` and `receipt_chain` among their gate reasons. The chain is verified during runner closure and rollback, but the completed projection fails the stricter bound-evidence path. A GO-capable path must expose the first validator failure, repair that binding, and independently reload and verify the final seal; neither run may be resealed as GO.
