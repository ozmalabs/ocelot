# Bounded local P4 container readiness with fail-closed execution evidence

P4 now binds a finite native ELF/runtime closure, a default-deny seccomp profile, and a staged evaluator authority into a signed local lock before constructing the rootless Podman command. The native adapter checks the signed evaluator transport against the persisted replan, proposal, reservation, sequence, snapshot, and outcome bindings, while the evaluator restores a canonical deep snapshot and records the rollback in the signed receipt chain. The real local run used the pinned image and hardened command, but Podman failed before worker startup with the exact procfs error `ensure /proc/thread-self/fd is on procfs: operation not permitted`; no container completion is claimed. **Watch for:** **confirmed** this approves bounded `local_readiness_only` containment and rollback only; native-container success, trusted release evidence, P4 adoption, and P5 remain unproven. **confirmed** the seccomp validator accepts extra calls such as `mount`, so exact allowlist derivation is still a trusted-release limitation.

**Verdict**: APPROVED

## High-level view

The local lock binds the worker, resolved ELF closure, support files, agent/input trees, Containerfile, seccomp profile, and image digest. Startup is proven on the host and the image is locally inspectable/rootless, but the actual run is blocked by Podman’s procfs restriction.

The evaluator/native boundary is causal: a signed replan precedes the proposal, the evaluator signs the outcome, and Rust verifies it against the staged authority and persisted bindings. Exact nested rollback is recorded in a contiguous signed impasse → no-go → rollback chain, making this a local containment result rather than trusted execution or P4/P5 evidence.

## Measured ELF closure reaches startup before containment

**confirmed** — `var/p4-real-run3/local.lock.json` binds the worker digest `sha256:d4381f…`, runtime tree digest `sha256:30a5cf…`, seccomp digest `sha256:d86dad…`, Containerfile/input/agent digests, and image `sha256:ce1108…`. The runtime manifest records the loader plus `libc`, `libcrypto`, `libgcc_s`, and `libm`, with `/etc/ld.so.cache` and the OpenSSL configuration as measured support files. The source worker and staged runtime worker have identical SHA-256 values, and `ldd` resolves exactly the five ELF objects recorded by the manifest.

**confirmed** — `post_build_runtime_probe` and the seccomp measurement both run the native ELF with an empty frame and require the expected protocol rejection rather than a loader failure. The local probe exits 65, the staged profile uses `SCMP_ACT_ERRNO`, and its 33-name allowlist covers the measured startup surface plus the fixed runtime floor. Closure validation is repeated against the signed lock immediately before Podman preflight and command construction, so the local artifact cannot silently substitute a worker, tree, or policy after registration.

## Default-deny seccomp is narrow, but its validator is permissive for future profiles

**confirmed** — The pinned `var/p4-real-run3/seccomp.json` has one x86-64 architecture, `SCMP_ACT_ERRNO` as the default, and no wildcard action. The current local profile is therefore narrow and measured for the worker used in this run.

**confirmed gap** — `validate_seccomp_profile` checks that required and observed calls are included and that the list is bounded, but it does not reject additional privileged calls. A temporary profile containing `mount` passed validation with the same worker. The current profile’s digest is locked and contains no such call, so this does not invalidate the bounded local artifact; exact measured-set enforcement is required before this policy can be treated as trusted release containment.

## Signed replan provenance reaches the native completion adapter

**confirmed** — `P4R0Evaluator._parent_replan` requires the proposal’s causal parent to be a signed receipt of kind `replan` with matching run, lock, fixture, and snapshot context. Grant and action creation then append proposal, grant, action, and outcome receipts, and `verify_sealed_action_outcome` checks their chain, reservation digest, proposal/grant/broker bindings, sequence, and replan parent before exporting native fields.

**confirmed** — The Rust worker does not accept authority material from the request. It loads `/trust/p4-trusted-evaluator.json`, binds its authority and lock digest to the staged artifact, verifies the canonical Ed25519 transport, and derives the expected proposal, reservation, run, sequence, snapshot, replan, and outcome bindings from native state. Forged signatures, altered reservations, wrong keys, replayed outcomes, noncanonical JSON, and self-consistent caller authority fields are rejected by the native integration tests.

## Nested rollback is canonical and receipted

**confirmed** — `P4R0Evaluator` checkpoints canonical bytes and restores by reparsing them, which breaks nested aliases rather than reusing mutable references. Restoration also resets grants, reservations, and simulator-call state; the repair test verifies all of those side effects and confirms that the snapshot itself cannot be mutated through the frozen checkpoint.

**confirmed** — The real run’s receipt log validates as a three-record signed contiguous chain: containment preflight fails closed as an impasse, the result is `no_go` with `local_readiness_only`, and rollback records `snapshot_encoding: canonical-deep` plus equal pre-run/restored snapshot digests. No terminal receipt or nonzero resource ledger is emitted because the worker was never reached.

## Real Podman evidence is genuine failure evidence, not execution evidence

**confirmed** — Podman 4.9.3 reports rootless mode, and the exact pinned image ID is locally inspectable. Replaying the hardened invocation with `--pull=never`, `--network=none`, `--read-only`, dropped capabilities, `no-new-privileges`, the locked seccomp profile, fixed UID/GID, bounded resources, read-only mounts, and the staged trust artifact reproduces exit 255 with `ensure /proc/thread-self/fd is on procfs: operation not permitted`.

**confirmed** — The runner records this as `containment:PodmanPolicyUnavailable`, followed by signed no-go and rollback receipts. It does not fall back to the host worker, and the direct host harness is explicitly unit-only. **Not tested:** a successful native worker start and completion inside the real image, hostile behavior after startup, or a release-lane Podman setup with compatible procfs support.

The local lock explicitly sets `non_release`, `classification: local_readiness_only`, `adopted: false`, and `promotion_authority: false`. **confirmed limitation:** no external key custody, independent evaluator, reproducible release image provenance, P4-E1/E2 statistical/adoption evidence, or P5 capability is established by this run.

## Test coverage

`pytest -q evaluation/p4/tests` passes all 30 tests, including the native worker integration, authority and lock substitution, closure mutation, seccomp rejection, nested restore, receipt binding, and real-Podman fail-closed paths. The native worker builds offline with `cargo build --offline --bin p4_native_readiness_worker`. A crate-wide `cargo test --lib` was not available in this workspace because unrelated existing PyO3 linker symbols fail during test-binary linking; the focused Python integration tests still build and exercise the native worker directly in the unit-only harness.
