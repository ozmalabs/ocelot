# Local P3-R0 readiness coordinator

P3-R0 adds a local-only coordinator that verifies signed `local-test` P0/P1/P2 go artifacts against an immutable lock, admits a byte-bound mutable candidate, stages it, runs a 12-by-30 four-arm accounting loop, seals its result, and rolls the source back without adopting it. The live runner—not a test helper—invokes preflight validation, staging, sequential envelope issuance, decision calculation, sealing, and rollback; its custody flag is deliberately false, so even a statistical pass resolves to no-go. Watch for: **confirmed** the runner delegates execution to an unrestricted in-process callback rather than a Podman-controlled worker; **confirmed** returned pair evidence is neither signed nor cryptographically bound to the released envelope; **confirmed** rollback failure is suppressed on the E1 error path. The P3 implementation and tests are also untracked, so they are absent from `git diff main` and cannot be reviewed as a PR artifact yet.

**Verdict**: NEEDS_CHANGES

## High-level view

Admission is centralized in `P3R0Runner._admit`: it checks all three trusted local signatures, hashes the complete signed artifacts against the lock, binds native-export/candidate/pre-snapshot digests, validates the proposal and candidate payload, and stages a regular read-only file. This is a local readiness gate rather than release custody; `custody_ok=False` forces rejection.

The runner issues one signed envelope at a time for every distribution and validates four arm-shaped responses before computing a sealed decision. The callback has host authority over the staged candidate and output it reports, so task-release and containment boundaries are not enforced at the live execution boundary.

Podman is installed locally and reports a rootless socket, but P3 does not call a Podman launcher. The hostile-container acceptance suite skipped because its provisioned profile was not requested; P3 tests attack canonical candidate payloads only, not a P3 container/worker.

The result seal binds lock prerequisites and aggregates, but `receipt_digest` is accepted as any digest-shaped string and raw four-arm evidence/resource ledgers are not sealed per pair. A trusted release must make evaluator-generated receipts and task envelopes verifiable inputs and treat failed rollback as terminal.

## Local attestation gate and immutable candidate admission

`P3R0Runner._admit` calls `verify_preflight` before `validate_and_stage`. The preflight path verifies each exact signed P0, P1, and P2 `local-test` go artifact using separately supplied trusted key maps, then compares the canonical digest of the complete signed artifact—not an unauthenticated field—to the corresponding lock binding. It also binds the native export, candidate request, candidate bytes, and pre-snapshot bytes to the signed lock; admission rejects control-plane names and lock-artifact digests before staging.

This establishes bounded local no-adoption readiness: tampered/untrusted go artifacts deny before staging, and the focused test drives the live runner through staging and rollback. It is not an independent P0/P1/P2 release claim: fixtures mint local keys and the result path forces `custody_ok=False`. Approval must remain local-only until external attestation authorities, evidence, and the release lock are independently provisioned.

## Host callback substitutes for the locked worker boundary

**Confirmed concern.** `run_e1_local_test` releases an envelope and immediately calls `executor(envelope, staged)`. The callback is ordinary in-process Python and receives a `Path` in a directory owned by the same host user; mode `0400` is not an isolation boundary. Nothing in `evaluation/p3` invokes `evaluation.p2.podman.PodmanLauncher`, validates a container launch receipt, mounts the candidate read-only into a worker, or controls the worker lifecycle.

```
current:  P3R0Runner ── signed envelope + Path ──> arbitrary host callback
required: P3R0Runner ── lock-bound launch ──> constrained P3 worker
                                      │
                               signed result receipt
```

`podman info` succeeded locally (`rootless=true`, socket present), but the provisioned P0 acceptance suite was not enabled and skipped all 13 hostile-container cases. P3 has no integration with that suite. Without a provisioned locked worker, local execution should terminate as impasse/no-go before E1 instead of accepting host-callback output as execution evidence.

## Four-arm statistics accept untrusted evidence

**Confirmed concern.** The runner covers all 12 distributions and 30 records per distribution, and `score_four_arm_distribution` checks that each result contains the four required arms and lock-budget-shaped ledgers. `validate_pair_execution` only requires a digest-shaped `receipt_digest` and a matching `pair_id`; it neither requires the released envelope digest nor verifies a signature over the result, candidate/lock binding, scores, or resource ledger.

The test executor returns the same synthetic `sha256:ffff...` receipt digest for all 360 pairs. The coordinator seals per-distribution outcomes and lists of those unverified strings, not signed per-pair evidence. A malicious callback can therefore fabricate scores, safety flags, retention/transfer deltas, and resource usage that are incorporated into the coordinator signature. Require a signed evaluator receipt that binds exact envelope, candidate, lock, observations, resources, and safety outcome; reject absent, duplicate, invalid, or out-of-order receipts before statistics run.

## Rollback is not fail-closed when execution fails

**Confirmed concern.** Normal E1 completion calls `reject_and_rollback` and checks the restored candidate digest. On an executor or scoring failure, the exception path attempts rollback inside a nested broad `except`, discards any rollback error, and returns a normal denial. A callback can replace the candidate with a symlink or otherwise cause rollback to fail after admission; the denial does not establish byte-exact restoration.

The symlink test calls the helper directly, but no live-runner test drives a mutation followed by a forced E1 failure. Make this a distinct terminal containment failure and preserve failed path/digest evidence without following it; no readiness result should issue until verified recovery succeeds.

## Payload attacks do not establish worker or container resistance

**Confirmed concern.** `test_p3_control_plane.py` submits lock-bound candidate files containing direct/transitive artifact-digest and control-name mutations, proving parser/admission rejection before staging. It does not execute attacks against a P3 worker or container, or cover writable remount, result reread, evaluator-key replacement, score injection, baseline write, delayed/out-of-order receipt, receipt-writer disconnect/tamper, or broker compromise.

The four executed Podman tests validate P2 argv/preflight construction; the P0 hostile-worker tests skipped. For P3, retain a sealed impasse when the local profile/image/attestation is unavailable; when available, execute the locked adversarial matrix through the P3 launch path and bind container, receipt, and rollback evidence to the P3 lock.

## Release scope and missing review artifact

**Confirmed concern.** `git ls-files --others --exclude-standard` reports all P3 Python/Rust modules and P3 tests as untracked. `git diff main` therefore contains only module declarations in `runners/dsl/src/lib.rs`, not the implementation being assessed. Add the intended P3 artifacts before a PR review can establish what ships.

External trusted release remains gated on independent P0/P1/P2 go attestations and evidence; evaluator-owned signing and artifact closure; a lock-bound P3 Podman worker with no host/control-plane access; signed ordered envelopes and signed per-pair result/resource/safety receipts; retained raw evidence and seal verification; hostile-container/mutation attacks; and rollback evidence that cannot be downgraded to a denial. `local-test` attestations and forced no-adoption do not satisfy those requirements.
