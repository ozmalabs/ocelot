### Remote provenance and immutability cannot self-promote

The runner explicitly leaves both authenticated remote evidence sources unavailable. A positive `remote_provenance_verified` or `immutable_verified` value therefore fails before any caller-provided self-digesting record can be accepted. The validator still checks canonical schemas, request/operation/image/resource bindings, command digests, timestamps, and record digests when a future reviewed source is supplied, but those integrity checks are not treated as authenticity by themselves.

The current candidate binding and interpretation preserve `remote_provenance_verified=null` and `immutable_verified=null`. The existing remote claim is limited to the observed Artifact Registry digest, which matches the candidate digest; the correction artifact explicitly distinguishes that identity observation from provenance or repository immutability.

### Strict booleans and digest formats protect the binding

The loader and operation-1 path use exact boolean type checks for registry publication, push, provenance, validation, and evidence state. Nullable remote claims accept only `None` or a real `bool`, so values such as `0`, `1`, and other truthy objects cannot promote a claim through equality semantics.

All relevant candidate, local, remote, observed, and operation-1 response digest checks use `^sha256:[0-9a-f]{64}$`. The focused regressions mutate candidate, remote, and observed digests to malformed values and replace publication/evidence booleans with integer lookalikes; each is rejected fail-closed.

### Local correction remains outside the cloud boundary

The local R15 loader and forged-evidence tests monkeypatch the runner subprocess entry point and socket constructors to fail on use, then assert that both candidate loading and positive-claim validation complete without recording a call. This directly protects the correction path from a future refactor that might invoke `gcloud`, Podman, or network access while validating local artifacts.

The candidate binding’s canonical digest is `sha256:88d5611b4301a62f1ceda500ebb8a85b8cf2154c553080aac05d49613cdd0e2b`; the interpretation artifact is `sha256:90367ddc571eeea06534cf4fb77b1f9fd612ec8d8a566b7bc87305d7bbe1bdc2`. Both retain the review-only/non-production classification and the unsupported remote claims as `null`.

### Historical ledger and validation evidence remain intact

The historical operation ledger remains append-only with raw digest `sha256:7e4835d39c7cd0abe56adbf159179cf73546018f5db09de56b5ce6b2c0bf1d9a`.
