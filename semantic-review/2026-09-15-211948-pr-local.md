# Locked P2-B1 envelope execution and receipt sealing

The P2-B1 release runner measures the staged sealed input, rejects a caller-supplied envelope unless its canonical bytes exactly match that artifact, and carries the measured input digest through the worker, evaluator, terminal receipt, and result seal. It preflights both receipt authorities before the worker path and converts a primary receipt-append failure into a signed record in a separate failure chain while removing the replay claim. **Watch for: confirmed — both receipt writers accept short writes as successful durable appends, so a truncated record can be acknowledged and only discovered after restart; confirmed — the replay suite that is meant to prove sealed-input rejection, preflight blocking, and failure-record recovery fails before exercising any of those paths.**

**Verdict**: NEEDS_CHANGES

## High-level view

The lock/canonical-byte gate precedes worker launch, and the measured input digest crosses the native worker/evaluator boundary into the receipt and result seal. The persistence guarantee breaks at the final write boundary: each chain fsyncs whatever `os.write` returned without requiring the complete signed payload to reach the file.

The targeted replay coverage is designed around the critical release behaviors, including independently signed but different envelopes, preflight failure, append failure, claim cleanup, and verified failure-log restart. **Confirmed:** its fixture construction references an undefined `spec`, so all six tests terminate with `NameError` and provide no coverage of those behaviors.

## Receipt and failure chains can acknowledge truncated signed records

**Confirmed:** `ReceiptLog.append` calls `os.write(fd, payload)` and immediately fsyncs the descriptor without checking whether the call wrote all bytes (`evaluation/p2/receipts.py:131-133`). POSIX permits a successful short write; in that case the method advances its in-memory hash-chain state and returns a receipt hash for a file that cannot be parsed or signature-verified on restart. The same defect is duplicated in `ReceiptFailureLog.append` (`evaluation/p2/receipts.py:222-224`), so the fallback intended to create independently durable evidence has the identical gap. Loop until all payload bytes have been written, treating a zero-byte return as an error, before fsyncing and exposing either seal; test a monkeypatched short write followed by a fresh log instance.

## Replay tests abort before exercising the release guarantees

**Confirmed:** `_runner` passes `worker_spec=spec`, but `tests/evaluation/test_p2_replay.py` imports `PodmanSpec` rather than defining or importing `spec` (`tests/evaluation/test_p2_replay.py:11,59`). Each of the six replay tests fails at runner construction with `NameError: name 'spec' is not defined`, including the separately signed-envelope rejection test (`:74-84`), primary append-failure/failure-log restart test (`:87-96`), and receipt-preflight blocking test (`:99-105`). Import the established `spec` factory or construct the required `PodmanSpec` in this module, then run the suite; without that repair, the core P2-B1 end-to-end guarantees are untested.
