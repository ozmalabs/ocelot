### Canonical provider identity and explicit no-etag state

`canonical_provider_resource_name` accepts the two intended resource spellings but emits only the full IAM resource form, and independently checks the fixed project number, pool, and provider. The normalized value is used for the provider digest and state comparisons, preventing equivalent spellings from producing different approval bindings or redirecting commands to another provider. **confirmed**

`_state_from_gcloud` treats the absence of both `etag` and `fingerprint` as a distinct state: it sets `fingerprint` to `None` and `etag_unavailable` to `true`, and rejects ambiguous or unresolved fingerprint fields. `_validate_state_integrity` requires the same representation, while the stable configuration digest excludes the volatile fingerprint but retains `etag_unavailable`; the no-etag state therefore has an explicit digest identity without manufacturing a concurrency token. **confirmed**

### Exact prestate gate and fixed mutation boundary

The expected prestate is loaded from canonical bytes and validated before the first describe. The fresh describe is canonicalized and compared for full object equality, including provider identity, mapping, condition, fingerprint representation, availability flag, and all recomputed digests. Mapping or condition drift, a fingerprint mismatch, or a digest mismatch stops the run before the update command. **confirmed**

For an explicit no-etag prestate, `_update_command` requires `fingerprint is None` and omits `--etag`; an etag-bearing state requires a resolved fingerprint and emits the corresponding `--etag`. A placeholder or stale fingerprint cannot be sent to the provider. **confirmed**

### Poststate and rollback closure

Poststate validation requires the normalized provider identity, the approved mapping, and the exact desired condition expression and digest relationships. A mismatch enters the failure path rather than producing a verified result. Once the mutation boundary is entered, rollback describes the current state, passes its explicit etag-availability flag through the same fixed update runner, describes again, and requires the restored configuration digest to equal the captured expected configuration. A changed etag is allowed after restoration because it is volatile; mapping, condition, provider identity, and availability state remain covered by the configuration digest. **confirmed**

Ledger write uncertainty returns a manual-review/no-retry result with a recovery marker, and rollback failure returns `rollback_failed_manual_review`; neither path claims successful restoration. The command runner uses an absolute executable, fixed argv, no shell, and disabled stdin. **confirmed**
