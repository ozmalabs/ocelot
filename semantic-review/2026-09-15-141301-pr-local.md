# Local P0-A evaluation containment harness

The change adds a signed-manifest, default-deny action-broker harness and dormant guards for selected legacy host-I/O routes. The enforcement path is incomplete: `evaluation_mode` verifies a manifest and enables in-process guards, but never instantiates or routes actions through `ActionBroker`; the broker is exercised only as a test fixture. The launcher’s process-I/O interception is also bypassable through unpatched standard-library I/O, and the receipt and kill tests do not prove the claimed integrity and control-plane guarantees end to end. Custody limits are explicitly documented as a local approximation rather than evaluator custody. Watch for: **confirmed** broker bypass by construction, **confirmed** `os.open` host-I/O bypass during interception, **confirmed** receipt-chain tampering that restart validation accepts, and **confirmed** disconnected kill state.  
**Verdict**: NEEDS_CHANGES

## High-level view

The manifest’s empty `enabled_methods` list makes the standalone P0-A broker deny its fixture action, but the explicit evaluation launcher yields only a `VerifiedManifest`. No production action facade receives the broker, so nothing establishes the required “all actions traverse default-deny broker” topology.

Legacy guards cover several named application routes, but evaluation mode depends on Python-level monkeypatches rather than an enforced boundary. Calls outside its short monkeypatch list can still access the host; `os.open` remains available inside the interceptor.

The documentation explicitly limits same-user execution to a local harness approximation, not evaluator custody. That disclosure does not repair local protocol gaps: receipt restart validation accepts a recomputed tampered chain without checking its writer signature, and the supervisor/control state is not connected to the broker’s kill state.

3. **Receipt signatures are never verified** — **confirmed:** validate every receipt’s writer signature with an independent public key before accepting a log head, and add a recomputed-chain tamper test.
4. **Kill authority is not connected to action execution** — **confirmed:** have the broker consult evaluator-owned terminal control state or have the supervisor atomically kill the broker; test the supervisor path rather than calling `broker.kill()` separately.
5. **Adversarial tests mask the intended failure modes** — **confirmed:** strengthen tests to assert actual execution routing and signed binding failures, and exercise every claimed interceptor; current tests rely on manual guard calls, stale request hashes/signatures, and a socket-only interception assertion.

## Evaluation mode never hands action execution to the default-deny broker

**Confirmed.** `evaluation/p0a/entrypoint.py`’s `evaluation_mode` only calls `manifest_verifier.verify(...)`, enters `activated(...)` and `intercept_legacy_process_io()`, then yields the verified manifest. It neither imports nor constructs `ActionBroker`, and the repository-wide search finds `ActionBroker(...)` only in `tests/evaluation/conftest.py`. The broker’s default-deny registry is therefore real in isolation, but it is not the action boundary reached by an evaluation run.

The P0-A test proves only that a separately constructed fixture broker denies an action when its manifest has no enabled methods. It does not start evaluation mode, submit an action through its public surface, and show that the broker receives and denies it. Any evaluation code that reaches an effectful function not covered by a guard remains outside broker policy, grants, replay tracking, and receipt emission.

## In-process interception leaves direct host I/O available

**Confirmed.** `intercept_legacy_process_io` replaces six attributes: `socket.socket`, `urllib.request.urlopen`, `subprocess.Popen`, `os.system`, `os.execv`, and `os.execve`. It does not constrain `os.open`, `pathlib`, file descriptors, aliases captured before monkeypatching, HTTP libraries other than `urllib`, or external processes reached through other APIs. A focused smoke probe run in this checkout successfully opened `/dev/null` with `os.open` while the interceptor was active: `BYPASS: os.open remained available`.

The named legacy guard points deny before their respective effects when their functions are called under `activated()`, but that is a route inventory rather than a containment boundary. `tests/evaluation/test_legacy_io_blocking.py` calls the guards or guarded functions manually; its interceptor test is named for socket, urllib, subprocess, and exec but asserts only `socket.socket()`. This does not establish that evaluation mode blocks or excludes direct host-I/O pathways.

## Receipt restart validation accepts a recomputed tampered chain

**Confirmed.** `ReceiptLog.append` writes a `writer_signature`, but `ReceiptLog.validate` checks sequence, predecessor hash, receipt hash, and head only; it has no writer public key and never invokes `verify_signature`. Since `receipt_hash` is an unkeyed hash, a writer can alter a receipt, recompute its hash, rewrite the head, and retain an invalid old signature without detection. A focused temporary-directory probe changed `outcome`, recomputed `receipt_hash`, updated `head.json`, and successfully reopened the log: `BYPASS: receipt tamper accepted at sequence 1`.

The existing tamper test changes text without recomputing the hash, so it detects accidental mutation but not the meaningful adversarial case. The receipt claim needs a verifier-owned public key and a test that recomputes all unkeyed hashes and the head while leaving the signature invalid.

## Supervisor kill state does not stop the broker

**Confirmed.** `LocalSupervisor` owns a `RunControl`, while `ActionBroker` owns a separate boolean `killed`; neither object references the other. `LocalSupervisor.stop()` changes its own control state and optionally signals a process group, but it does not call the broker, and `ActionBroker.submit_action()` does not consult `RunControl`. `test_kill_supervisor.py` mirrors this split: it tests a standalone `RunControl`, then separately calls `target.kill()` before submitting an action.

A kill issued through the advertised supervisor path therefore has no demonstrated effect on broker authorization. Evaluation execution must have a single evaluator-owned terminal state that the broker checks before accepting and immediately before executing a request, with an end-to-end test using `LocalSupervisor.stop()`.

## Policy and bypass tests do not isolate the promised protections

**Confirmed.** In `test_policy_grants.py`, changing request arguments leaves the original `request_hash`, so rejection occurs in request-shape/hash validation before grant binding is tested. Changing `bad["method"]` likewise leaves an invalid signature, so it does not prove a validly signed wrong-binding grant is rejected. The tests have access to the fixture private key and can construct canonical, validly signed negative cases instead.

The test suite passes without weakened assertion failures—`tests/evaluation` passed 14 tests and the supplied focused legacy suite passed 60 tests in this checkout—but the passing tests do not establish the security predicates required for approval. Add end-to-end evaluation-mode tests for mandatory broker routing, control-plane kill propagation, recomputed receipt tampering, pre-import aliases/unpatched I/O, and independently valid but mismatched signed grants.
