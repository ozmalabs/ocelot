# Evaluator-owned startup evidence and graph-only action ingress

The change creates a local P0-A launcher that verifies an attested manifest and native graph export before exposing an opaque proposal-ID client to a broker process. Startup denials are centralized: failures before a verified receipt chain use a separately signed `EvaluationLaunchFailureV1`, while verified-chain failures append a signed impasse receipt. The action path defaults to no enabled methods and permits the fixture counter only with both fixture flags, provenance, and a bound grant. **Watch for:** **confirmed P0** arbitrary filesystem I/O bypasses the in-process guard, and **confirmed P1** tampered or unavailable receipt storage produces an unaudited post-authority impasse. **Verdict**: NEEDS_CHANGES

## High-level view

`evaluation_mode` establishes a control-plane recorder before manifest verification, then switches to the manifest-bound receipt chain only after verifying that binding. The declared earliest auditable boundary is therefore a supplied recorder or usable receipt-writer authority at launcher entry.

The proposal endpoint accepts only an identity; the evaluator process resolves it from the attested export, projects it to V2, and records denials. This blocks public raw-V2, grant, method, and callback injection, but does not contain local-process filesystem operations or recover signed evidence when the receipt path itself fails.

## Signed startup evidence is centralized until receipt-chain trust is established

`evaluation_mode` derives or accepts `LaunchFailureRecord` before manifest verification. Its context hashes cover the raw manifest candidate, expected digests, export, and receipt-log configuration, so malformed, expired, unauthorized, and fixture-policy manifests can be rejected without inventing a run ID or verified manifest identity. After verification, `record_terminal` revalidates the manifest-bound receipt chain immediately before writing an impasse; a mismatched or untrusted chain instead uses the signed control-plane record.

The stated boundary starts only once the caller has supplied an evaluator-owned `launch_failure_record`, or the launcher can derive one from `receipt_log`. If that authority cannot be created, the launcher raises `launch failure authority unavailable` and cannot emit evidence. **Confirmed:** `evaluation/p0a/supervisor.py` states that same-user code can subvert the local supervisor, and `legacy_io_guard.py` labels its guard as non-OS-boundary defense in depth. Those local-harness limitations must remain explicit; they do not make the unguarded I/O path below safe within this claimed evaluation boundary.

## Proposal identities, provenance, and enablement gate action dispatch

The client retains only a process connection and accepts a string proposal identity. The evaluator process resolves that identity from the sealed export, checks provenance and causal parentage, maps the catalogued proposal to a request, and obtains a grant only after confirming the manifest enables the method. Raw V2-shaped IPC is denied receipt-first, while the broker rejects requests lacking the evaluator-generated provenance binding. The default P0 manifest records even a valid fixture proposal as `method_not_enabled`; the enabled fixture regression retains exported `steps=1` rather than a caller-forged value.

Supervisor stop reaches the broker process through shared control state, so a request submitted after `stop` is recorded with a `killed` phase. Replay state is restored from signed receipts, including graph proposal identity and digest, making a re-submission after broker restart a recorded replay denial.

## In-process direct I/O escapes the claimed blocking boundary

**Confirmed P0:** `intercept_legacy_process_io` monkeypatches `socket.socket`, `urllib.request.urlopen`, `subprocess.Popen`, a small selection of `os` functions, and legacy route-specific guards. It does not patch `builtins.open`, `io.open`, `pathlib.Path.write_*`, `os.mkdir`, `os.rmdir`, `os.fork`, or native/library routes that can perform host I/O. `Path.write_text()` therefore lets evaluated code write arbitrary host files inside the active context without reaching `deny_direct_io`, the broker, or a receipt.

The direct-I/O test proves only the enumerated monkeypatches and seven instrumented legacy routes raise `DirectIODenied`; it neither demonstrates a complete host-I/O boundary nor asserts signed evidence for those denials. The documented same-user limitation is appropriate for a local approximation, but it cannot turn an incomplete Python monkeypatch list into an authority boundary. Move evaluation work to an evaluator-owned restricted process/container with filesystem and network policy, or reject workloads requiring such isolation.

## Receipt-loss paths become unaudited post-authority impasses

**Confirmed P1:** `_projector_endpoint` has no access to `LaunchFailureRecord`. If `ActionBroker._reply` cannot append a receipt—for example because receipt publication fails—it sets `impasse` and returns an impasse reply with `receipt_sequence_or_null=None`; no signed receipt or control-plane record is written. `test_graph_receipt_writer_failure_is_terminal_impasse_without_effect` asserts that effect-free impasse, but does not and cannot verify signed evidence.

After a successful launch, `evaluation_mode` calls `receipt_log.validate()` directly in its `finally` block. Evaluated code can alter `receipts.ndjson` through the unpatched filesystem route; teardown then raises without `record_terminal`. Because the chain is no longer trustworthy, the control-plane signer must record `receipt_log_untrusted` with the existing signed context hashes from a path outside the compromised log. The parent must own or receive a one-way failure signal from the child so malformed IPC, writer failure, and child/process death have the same signed terminal fallback.

## Coverage proves intended branches but not evidence under failure

`pytest -q tests/evaluation` passes all 45 tests. The suite covers successful attested startup, P0 default denial, an enabled fixture action, malformed retained-endpoint IPC, replay after restart, legacy host-handler guards, startup rejections, export/attestation failure, and supervisor kill. It independently reopens startup records and receipt logs to validate signatures where evidence is expected.

**Confirmed gap:** receipt tampering is tested only as a failure to reopen a standalone `ReceiptLog`, not during active `evaluation_mode` teardown; no test requires a signed control-plane record then. **Confirmed gap:** direct-I/O coverage excludes standard file-opening APIs and no test requires evidence for a direct-I/O rejection. Add adversarial active-run tests for `open`/`Path.write_text`, child receipt-writer failure, receipt corruption before teardown, malformed IPC with receipt storage unavailable, and evaluator child termination; each must assert no effect and independently verify the appropriate signed terminal artifact.
