# V3 native preflight proves bounded local crun execution, not external readiness

Two independent child-process runs exercised the locked worker through Podman with rootless crun, `--pull=never`, `--network=none`, read-only root, no capabilities, the locked seccomp profile, and the fixed resource limits. Each run produced 144 primary records, 11 native controls, 90 paired contrast cells, 335 native worker invocations, 386 signed receipts, and an exact rollback; the primary behavior projection was repeatable across both runs. The result correctly remained `local_readiness_only/no_go` because the native illegal-action control observed `complete_wrong` rather than `protocol_error`, and the adversarial suite exposed two acceptance gaps. **Watch for:** **confirmed** the locked closure omits host-side execution code; **confirmed** warm-session reset and control omission are accepted in targeted mutations; **confirmed** the authority and signer are workspace-local test material, not external custody or service readiness.

**Verdict**: NEEDS_CHANGES

## High-level view

The local native seam is real and bounded: preflight verifies rootless Podman, crun identity and digest, image identity, seccomp content and syscall commitment, worker content, argv, no-network/no-pull policy, and finite limits before `subprocess.run` is reached. The two completed runs then invoke that seam for all primary, control, and contrast-side tasks. **Confirmed gap:** the closure is not complete for the host-controlled execution path because the lock stages only the containerfile, worker, repair module, and crun binary, not the runner, native command builder, evaluator, or worker validator.

The workload is substantial local evidence rather than a release result. Both runs have the expected cardinalities and identical 144-row behavioral projections, while the signed chain reloads and exact snapshot rollback verify successfully. **Confirmed gate failure:** the checked-in worker returns a legal action for the illegal-action stimulus, so the expected `protocol_error` is not demonstrated and the result stays no-go.

The adversarial suite rejects authority, signer, lock, image, ordering, nested-private, and receipt-tamper mutations before any native call. **Confirmed gaps:** it does not reject a mismatched warm-session identifier, and it can reseal a no-go result after controls are removed because no-go sealing does not enforce completed-evidence cardinality.

Receipts are Ed25519-signed and independently reloadable within the workspace, and each run records exact rollback. **Confirmed scope limitation:** the supplied authority is explicitly `local-test-v3-authority` with a `workspace-only-preflight` transport attestation; the validator's weak prefix check permits that identity to satisfy the boolean external-authority field. No independent authority, evaluator-held key custody, external receipt writer, private-input release service, attestation service, or kill supervisor is present.

### Podman/crun execution and the lock-bound native boundary

The local closure report verifies `/usr/bin/podman` in rootless mode, selected runtime `crun` at `/usr/bin/crun`, runtime digest `sha256:bd8ad7e7…`, image `sha256:cceda04a…`, seccomp digest `sha256:cc374cf2…`, and closure digest `sha256:f1c334f7…`. The actual runner constructs the fixed argv and invokes `subprocess.run` with canonical task bytes; it rejects non-zero exits, oversized frames, malformed replies, and invalid V3 actions. The two recorded runs therefore support a bounded local statement that the native child-process seam was used rather than the in-process fallback.

**Confirmed gap:** the exactness claim stops at the staged closure boundary. `run_complete.py` supplies only `containerfile`, `worker`, `repair.py`, and `runtime` to `closure_spec_v3`; the lock therefore cannot detect a later change to `evaluation/p5_r0/runner.py`, `native.py`, `native_worker.py`, `evaluator.py`, or related host dependencies. The image, seccomp, runtime, and worker bindings are exact for the material supplied, but the complete execution closure is not yet bound.

### Repeatability, workload coverage, and the red native control

The run summaries show 144 primary records, 11 controls, 90 contrast cells, and 335 native calls per run: 144 primary plus 11 controls plus 180 contrast sides. Each chain has 386 signed records and reload verification succeeds; the two run projections compare equal for all 144 primary rows, including outcomes, state digests, adaptation counts, and worker exits. V2 artifacts remained hash-immutable during the run.

**Confirmed gate failure:** the native control catalog expects an illegal action to become `protocol_error`, but the locked worker's native reply is a legal action (`0`) and the evaluator records `complete_wrong`; this is why the control gate reports `control_failure`. The gate prevents promotion on this failure, but the native control suite is not passing evidence.

### Adversarial fail-closed behavior and the two accepted mutations

The mutation report shows zero native calls and exact rollback for authority-ID, receipt-signer, lock-field, image-substitution, task-order reorder, task-order duplicate, nested-private, and receipt-tamper mutations.

**Confirmed warm-session gap:** once an arm is active, `arm_context()` accepts the caller's new `session_id` argument by returning the existing context without checking it. A caller can therefore present a reset-like session identifier without receiving the expected protocol rejection. The session identity and order must be compared on every reuse, not only at initial context creation.

**Confirmed sealing gap:** the control-omission mutation remains no-go, so `seal_result()` reloads its chain and accepts it even though a required control was removed. That cannot create a GO under the current gate, but it means a sealed artifact no longer proves that the locked control workload was retained. Completed no-go evidence needs the same cardinality and semantic-coverage checks as GO evidence.

### Signed receipts, rollback, and the local authority boundary

Each completed run carries a V3 receipt public key and metadata; `verify_result_seal()` reloads the receipt directory, checks sequence/hash links, verifies Ed25519 signatures, checks run binding, and checks the final chain digest. The rollback receipt binds matching pre- and restored-snapshot digests and is followed by the close record. These are valid local integrity and rollback observations, not independent custody.

**Confirmed authority gap:** the authority artifact makes the scope explicit: `local-test-v3-authority`, local test transport attestation, offline pinned artifacts, and workspace-only preflight. The implementation nevertheless treats any supplied authority object that passes the weak naming check as external, and the completed summaries report `external_authority_verified: true`. A production verdict must derive that field from an independently provisioned trust root and attested transport, not from a caller-provided local JSON object.

### Requirements before external-service readiness

**Confirmed readiness gap:** no external evaluator owns the authority and receipt-signing key, releases or attests the private held-out store independently of the worker workspace, attests the exact host/container closure and runtime, or retains write-once chain custody. No external supervisor monitors liveness and terminates the agent, broker, evaluator, and worker process group without agent override. Until those services and attestations exist, the evidence supports only the bounded local native claim and the explicit no-go result.
