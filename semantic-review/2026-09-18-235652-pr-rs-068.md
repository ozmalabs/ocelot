# RS-068 repository authority and WIP remediation contract

This change adds a repository-only RS-068 proposal that names the evaluator authority as `self-custodied/ocelot-proof/p5-r0/evaluator/p5-v3-authority`, pairs it with `p5-v3-authority`, and records the selected KMS version and public-key digest. It also defines a canonical desired WIP mapping/condition and a validator that keeps signing, approval, lock mutation, and cloud operations disabled. The observed provider snapshot still lacks the repository-required debug-state, TEE, hardware-model, and secure-boot mappings; the proposal records that drift rather than treating the desired policy as applied. **Watch for:** **confirmed, blocker** the WIP artifact is validated as review data but is not wired to a rerunnable IaC/resource renderer; **confirmed, high** the stable authority ID/key remains proposal metadata because the KMS authority-binding digest and lock binding are still null; **confirmed, high** the proposal and frozen request live under ignored `var/`, so the repository contract is not reproducible from tracked files.

**Verdict**: NEEDS_CHANGES

## High-level view

**Confirmed, high.** The authority identity identifies the intended project KMS key, but it is not yet a cryptographic or signed-environment authority binding: the validator reports `authority_id_resolved` only for the review proposal and leaves promotion false.

**Confirmed, blocker.** The desired WIP contract covers the missing claim paths, mappings, and conditions, and the runtime deployment renderer separately emits a complete mapping. The standalone RS-068 artifact is not consumed by that renderer or represented as an executable declarative provider resource, so “rerunnable as IaC” is not established.

**Confirmed, high.** The cloud-side observation remains a blocker rather than a silent fix: the recorded active provider still has the four mapping omissions, while all apply, signing, approval, and production outputs remain absent. The evidence boundary is fail-closed, but the proposal/request inputs are ignored by Git and therefore do not form a durable repository-side contract yet.

<summary>Details</summary>

### Stable evaluator authority label without a promoted KMS binding

**Confirmed, high.** `authority_binding_proposal.py` fixes the authority ID, key ID, KMS version, and public-key digest and rejects substitutions, while the proposal carries the same values in its authority and KMS metadata. `kms.authority_binding` is explicitly `null`, the generated request’s `authority_binding_digest` is `null`, and the frozen lock remains without authority material. The existing KMS contract requires a `P5R0KMSAuthorityBindingV1` digest that agrees with the authority ID, key ID, key version, and public-key digest; creating that locally would violate the stated boundary, so the proposed state must remain `BLOCKED` pending signed-environment approval and binding evidence.

### Desired WIP mapping is validated, but not executable IaC

**Confirmed, blocker.** The canonical remediation policy contains the required mapping and condition entries, including debug state, TEE, hardware model, secure boot, workload, image, project, zone, subject prefix, audience, issuer, and diagnostic smoke. The validator checks the exact canonical policy and the standalone template test checks that key strings are present. However, `wip-provider-policy.cel.tmpl` still contains `REPLACE_PROJECT_ID`, `REPLACE_ZONE`, `REVIEWED_EXACT_64_HEX_DIGEST`, and other review placeholders, and the RS-068 validator neither renders this template nor compares it with the runtime `_wip_policy_contract` used by `deployments.py`. No IaC resource or plan is present under the evaluator deployment surface. This is a complete review specification, not a rerunnable repository-side WIP remediation.

### Observed provider drift remains a blocker, not a silent fix

**Confirmed, high.** The proposal retains the observed active provider mapping with only image, project, workload, zone, and subject entries; it also retains the observed condition separately from the desired condition. Validation requires that exact observed snapshot and rejects attempts to add the missing debug-state mapping or tamper with the observed mapping/condition. The boundaries report no apply, cloud operations, lock modification, signature, or task execution. The actual provider remains noncompliant until an authorized remediation and fresh observation occur.

### Signed-environment boundary and evidence status

**Confirmed, high.** The local validator reports `signature_present=false`, `production_promotable=false`, and `signed_environment_approval_required=true`; it rejects promoted signature or approval fields and never invokes KMS, WIP, GCS, Confidential Space, or deployment APIs. No signed or production result is fabricated by this change. The `observed_kms` and `observed_wip_provider` objects are internally checked against fixed repository constants, not independently authenticated by this validator; they must remain review observations rather than production evidence until their source is validated in the signed environment.

### Ignored proposal and request inputs

**Confirmed, high.** `DEFAULT_PROPOSAL` and `DEFAULT_LOCK_REQUEST` resolve into `var/p5-r0-diagnostic-inputs/public`, while `.gitignore` ignores `var/`; neither the proposal nor the frozen request is tracked. The new validator passes in this worktree but cannot be reproduced by a repository checkout that lacks those ignored files. This is a repository durability gap, separate from the intentional absence of cloud mutation.

### Validation coverage

**Confirmed, blocker.** The targeted RS-068 proposal and deployment tests pass (`30 passed`), and the local proposal validator emits the expected blocked state with the fixed authority metadata and WIP policy digest. The tests cover canonicality, wrong ID/key rejection, mapping omission, provider/audience confusion, observed snapshot tampering, and signature-promotion attempts. They do not exercise an actual IaC plan/apply or prove parity between the RS-068 JSON, standalone template, and runtime renderer; those remain the blocking coverage gaps.
