The release runner now ties lock signer identities, evaluator and receipt keys, all measured non-image artifacts, two locally inspected image content IDs, and the byte-identical canonical sealed input together before launch. The graph kernel remains narrowly bounded to four actions, one horizon and branch, eight nodes per action, public graph bindings, explicit intervention costs, and abstention when no compliant action exists. Its unit coverage exercises mechanics and opaque-label invariance, but the required held-out family matrix and paired label/order controls have not been executed or reported.

## Byte-bound input and independent reconstruction retain denial evidence

The runner reads the staged sealed-input bytes, requires canonical form and canonical byte identity with the caller envelope, verifies its signature, hashes the raw staged file against the lock, and passes that digest to both native processes. Each native process recomputes its canonical envelope hash before graph work; the evaluator rebuilds its expected all-action plan before comparing the worker reply. Over-budget bindings are now marked infeasible and excluded from both selection and evaluator metrics, so the earlier signed-cost-cap bypass is closed.

Terminal outcomes are chained and signed, with unverified pre-lock failures carrying null lock-bound digest fields and separately named caller evidence. Replays create a durable proposal claim only after worker/evaluator exchange and become signed zero-credit `replay_denied` results; failed primary receipt persistence creates a separately signed failure chain and releases the claim. The focused Python suite passed 14 tests with 2 release-lane Podman skips, and the native executable boundary passed 3 tests. Those passing Python replay fixtures emulate Podman and worker/evaluator executables, so they validate receipt/replay semantics but cannot substitute for the failed real-container acceptance run.
