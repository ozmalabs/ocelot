It binds a raw and normalized prestate, uses literal absolute `gcloud` argv with shell-free subprocess execution, and records a one-attempt hash-chained ledger with rollback/manual-review outcomes. ### Literal IAM commands and the credential boundary

The fixed backend selects literal `/home/matt/google-cloud-sdk/bin/gcloud` tuples for the reviewed reads, keyless account creation, custom-role create/update, exact conditional grant/removals, token-creator binding, and inverse rollback operations. `SubprocessGcloudRunner` rejects unknown argv, uses `shell=False`, sends `DEVNULL` stdin, and removes three credential override variables.

**Confirmed**, this is not the credential boundary declared by the packet. The runner copies `os.environ` and invokes gcloud without an injected signed-environment credential or verified access-token handle. Removing credential-file override variables does not prevent local gcloud configuration, other `CLOUDSDK_*` settings, cached credentials, or other ambient authentication. The packet's `adc_discovery: false` field is asserted by `_load_packet` but not enforced at the subprocess boundary. The effectful path must route through `ReviewedIAMExecutorAdapter` with an injected, expiry-checked, attestation/provider/image/authority-bound credential, or implement an equally closed authentication mechanism that rejects ambient gcloud state before any cloud read or mutation.

### APPROVAL-023 child approval and source provenance

The loader binds the fixed parent approval ID, dispatch, operation, attempt, target, source paths/digests, and disabled-downstream contract, and checks the embedded digest seals of the referenced artifacts. **Confirmed**, no verifier-issued child approval is loaded or cryptographically verified: the packet status is a repository string, its artifact digest is a hardcoded expected value, and there is no approval signature, expiry, approval-artifact digest, credential-binding digest, or independent verifier identity.

This conflicts with the runsheet's `child_approval_required`/signed-environment boundary and makes the future `apply` command effectful based on self-authored JSON. Bind the packet to a canonical child approval that independently authorizes exactly this packet digest, attempt, operation, expected prestate, credential evidence, and expiry; reject apply unless that approval and signer are verified.

### IAM versions, mutation sequencing, and rollback

**Confirmed**, the fresh prestate and mutation gates require exact policy etag/fingerprint fields, and the poststate validator requires the reviewed role, bucket condition/removals, token-creator binding, keyless GCS-only account, unchanged existing KMS account, and private bucket posture. Rollback refuses a resource whose current state differs from the last observed mutation snapshot.

**Confirmed**, rollback success is incompatible with ordinary IAM version evolution. Each restore helper uses binding add/remove or role update commands, then the executor calls `iam.validate_prestate(restored, expected)`, comparing the restored state's etag/fingerprint to the original prestate digest. A successful write normally produces a new policy/role version, so restoring bindings cannot restore the original version token; the real backend will fall into `rollback_failed_manual_review` rather than `rolled_back_verified`. Replace old-version equality with a version-aware compare-and-swap restore contract and a receipt containing fresh restored versions, or make every post-mutation rollback terminal manual review and remove any claim that verified rollback is available. Retain the never-delete/manual-review rule for a created account.
