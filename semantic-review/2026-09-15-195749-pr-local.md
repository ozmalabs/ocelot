# Bounded native P2 planning and evaluator containment

P2 adds a bounded, all-actions planning contract: a Rust kernel models one-step beliefs and counterfactual records, while Python validates envelopes/proposals and is intended to reconstruct before sending one selected action to the broker. The checked-in release lock is deliberately invalid, and the native worker/evaluator binaries both default-deny, so this repository cannot score or enact a release run by itself. That fail-closed posture is valuable, but the implemented seams still leave policy obligations unenforced if release infrastructure supplies an accepting reconstruction callback. **Watch for:** **confirmed** the Podman policy permits `/` or any other arbitrary host directory as an “artifact” or “input” bind mount; **confirmed** replay prevention disappears after a `P2Runner` restart; **confirmed** P2Runner does not verify the envelope signature; and **likely** the native selector treats model confidence as goal probability.
**Verdict**: NEEDS_CHANGES

## High-level view

**confirmed** — The containment command has strong flags for a trusted staging specification, but does not constrain its host source directories. A compromised or mistaken specification can bind arbitrary host-readable data into the native worker despite read-only/noexec options.

**confirmed** — validation and reconstruction precede the broker within one Python process, but the runner neither verifies the envelope signature nor retains consumed proposal digests across restart. Identity and replay guarantees therefore depend on release wiring that is not present here.

**likely** — the Rust selector enforces all-action record cardinality but cannot derive its stated goal ordering from counterfactual data: it ranks equal-cost candidates by `confidence_bp`, disconnected from the outcome distribution and `all_goals_predicted` assertion.

**confirmed** — the lock and native binaries default-deny, so this repository cannot score or enact a release run. The required reconstruction and artifact-attestation checks remain an unimplemented release seam; tests model acceptance with a callback returning `{"accepted": true}`.

1. **Arbitrary host-directory mounts** — **confirmed**: `PodmanSpec.validate()` accepts any existing non-symlink directory, including `/`, for `agent_root` and `input_root`, then bind-mounts its resolved path. Restrict both to an evaluator-created staging root (with canonical containment checks) and add adversarial tests for `/`, parent traversal, and symlinked ancestors.
2. **Unauthenticated observation envelope** — **confirmed**: `P2Runner.score()` calls `validate_envelope()` without a signing key, so its signature is only checked for shape. Bind a verified evaluator public key to the release lock/configuration and verify the canonical envelope before launch or reconstruction.
3. **Replay protection lost on restart** — **confirmed**: consumed proposal digests live only in `P2Runner._seen`; a new runner accepts the same valid proposal and can call the broker again. Persist an atomic run/episode/proposal replay ledger, or require an idempotency key enforced by the broker, before any enactment.
4. **Wall/output limits are declarative** — **confirmed**: the launcher sets container resource limits but supplies no wall-clock supervisor or bounded frame reader; the 3-second and 64-KiB protocol budgets are never enforced around `Popen`. Add a process-group-aware deadline, kill/reap path, and capped streaming I/O before proposal parsing.
5. **Seccomp policy is neither constrained nor attested** — **confirmed**: any existing regular file, including the test fixture `{}`, satisfies `seccomp_profile`; neither the lock nor launch code binds its digest or verifies restrictive semantics. Lock and verify the profile digest and require a real-Podman rejection test for the prohibited syscall/bypass surface.
6. **Goal ranking aliases confidence** — **likely**: `select_all_actions()` names its final discriminator `goal_probability_bp()` but returns `confidence_bp`, while neither it nor `CounterfactualPrediction.validate()` binds `all_goals_predicted` to the outcome distribution. Recompute goal probability from reconstructed outcomes (or remove that discriminator) and test conflicting confidence versus goal-probability candidates.
7. **Release reconstruction is only a seam** — **confirmed**: both checked-in native entrypoints deny, and no executable component reconstructs witnesses, provenance, manifolds, selections, or lock artifacts. Implement and exercise the independent evaluator before replacing the intentionally invalid public lock.

<summary>Details</summary>

## Host staging can expose more than the sealed bundle

**confirmed** — `PodmanSpec.validate()` checks only that `agent_root` and `input_root` exist, are directories, and are not themselves symlinks. It does not require either path to sit below an evaluator-owned staging directory; `Path("/")` passes those checks and is rendered as `--volume=/:/agent:ro,nosuid,nodev,noexec` or the equivalent `/input` mount. Read-only and noexec prevent mutation and direct execution from the bind mount, but the native process can still read any host material visible below the mounted tree and return it in its proposal output.

The unit assertion `"-v /" not in joined` does not exercise the long `--volume=/:/agent...` form emitted by the launcher. Treating source roots as capabilities rather than generic paths closes this gap: construct both roots inside a per-run evaluator directory, reject paths whose resolved parent chain is outside it, reject the staging root itself, and bind the expected content digests before launch.

## Signed envelope handling stops at field validation

**confirmed** — the protocol supports `verify_signature()` when `validate_envelope(..., signing_key=...)` receives a key, but P2Runner invokes it without that argument. The lock carries only a fingerprint string, not a trusted key or a binding from that fingerprint to a key, and the runner accepts a structurally valid arbitrary `signature` string. An accepting reconstruction implementation could therefore be given a forged envelope through this interface, contrary to the signed-sealed-input boundary described in the preregistration.

Signature verification needs to occur on the canonical bytes received from the evaluator before the worker is launched, and the same verified envelope digest must be passed to reconstruction. The release lock should identify a key that the evaluator resolves from an authenticated keyring rather than trusting a caller-supplied callback or mapping.

## Broker mediation is not restart-safe

**confirmed** — P2Runner inserts the proposal digest into its in-memory `_seen` set before reconstruction and uses no receipt log, database, or broker idempotency token. The existing duplicate-submission test proves only that a second call on the same object raises; constructing a replacement runner with the same lock resets the set and permits another reconstruction and broker call for the same signed proposal. This contradicts the preregistration's required restart-replay control.

Durable state must be claimed atomically before reconstruction/enactment and retained across restart. The claim should be keyed by the evaluator-bound run and episode as well as proposal digest, with the broker rejecting duplicate idempotency keys even if the runner process or receipt writer fails.

## Native execution has no enforced deadline or output cap

**confirmed** — although the envelope accepts only the fixed 3,000-ms and 65,536-byte budgets, `PodmanLauncher.start()` returns an unrestricted `Popen` pipe after configuring CPU, memory, and PID limits. CPU quota limits rate rather than elapsed runtime; a worker can remain alive or block on pipe backpressure indefinitely. Likewise, no component in P2 reads stdout with a 64-KiB cap before parsing; callers using `communicate()` can buffer a worker's output until timeout or memory pressure.

A release evaluator needs a supervisor that applies the wall-time deadline to the container process group, closes input, caps both output streams while reading, kills and reaps all descendants on any budget breach, and produces an abstention/denial receipt. The absent actual-Podman launch means the current release-only test cannot validate this behavior.

## The seccomp argument is configurable but not a hardened policy

**confirmed** — policy validation accepts `seccomp_profile` solely as an existing regular file, and the regular test fixture contains `{}`. The public lock has digests for the worker and evaluator artifacts but none for seccomp, so the launched runtime has no code-level evidence that a known restrictive policy was used. The command-line presence of `--security-opt=seccomp=...` is therefore not evidence of the syscall control claimed in the threat model.

The release artifact set should include the canonical seccomp profile digest and validate it before launch, ideally opening it from the protected staging root. A provisioned Podman acceptance test should demonstrate that the profile loads and blocks representative prohibited primitives, rather than only asserting that the argument string includes `seccomp`.

## Counterfactual selection does not calculate its stated goal discriminator

**likely** — after feasibility and minimum intervention cost, `select_all_actions()` chooses its native tie set with `goal_probability_bp()`, but that method returns `confidence_bp`. `CounterfactualPrediction` contains an outcome basis-point vector and a self-declared `all_goals_predicted` boolean, yet validation only checks vector length/sum and never connects either field to a goal outcome. A higher-confidence estimate for a less goal-satisfying action can therefore eliminate a more goal-likely equal-cost candidate if confidence is epistemic certainty rather than the declared goal probability.

The evaluator reconstruction is intended to catch this, but the checked-in evaluator always rejects and the Python tests replace reconstruction with a constant accepting callback; no test establishes that the Rust/Python selection semantics agree. Define a goal-probability derivation over the reconstructed outcome vocabulary, carry it explicitly and verifiably in the native record, and test an equal-cost pair where confidence and goal probability disagree.

## Release reconstruction remains a default-deny seam

**confirmed** — `p2_native_worker` always returns `unestablished`, `p2_evaluator` always returns `accepted:false`, and P2Runner's only acceptance test injects `lambda _e, _p: {"accepted": True}`. The invalid checked-in lock correctly prevents scoring, so this is fail-closed rather than an authority bypass; nevertheless, none of the proposed witness/provenance, manifold, selection, lock-artifact, or evaluator-clone checks exists in executable release code in this change.

Before replacing the placeholder lock, release infrastructure must provide the independently reconstructing evaluator and a test that runs it against malformed witnesses, stale belief digests, false causal witnesses, invalid tie/minimal claims, and mismatched image/rule/seed artifacts. This is a release-establishment prerequisite rather than a reason to make the public placeholder permissive.
