# Signed-environment credential bootstrap remains blocked

The change adds a review-only Confidential Space/WIF bootstrap that validates exact environment bindings, obtains short-lived credentials through the existing launcher/STS path, and emits only a redacted receipt. It deliberately does not mutate IAM, create keys, sign with KMS, upload to GCS, deploy, or execute diagnostics. The fail-closed shape is useful, but the new boundary still accepts caller-authored approval and capability claims, and its credential-only factory cannot drive the adapter's default service path. The live environment and the full P5 evidence chain also remain incomplete, so no effectful external operation is safely executable.

**Watch for:** **confirmed** `APPROVAL-013` has no concrete child-approval artifact, while the new validator accepts a self-digested mapping with `attestation_verified=true`; **confirmed** the capability binding can likewise be promoted from caller-supplied booleans rather than verifier-owned remote evidence; **confirmed** the production adapter path is not wired for the credential-only capability object; **confirmed** live IAM/Cloud Run state is still the legacy shared-account path and the GCS-only account is absent.

**Operational disposition**: BLOCKED  
**Verdict**: NEEDS_CHANGES

## High-level view

The bootstrap composes a locked configuration, KMS authority binding, capability binding, launcher JWT verification, STS exchange, bounded IAM-Credentials token, and redacted receipt. It correctly keeps KMS signing, GCS, and diagnostic operations outside this boundary, but the inputs that are supposed to represent reviewed external state are not independently authenticated.

The approval contract is one-operation scoped and request-digest-bound, yet it has no parent approval, actor, signature, or external verification binding. `APPROVAL-013` therefore remains a broad continuing authorization in the runsheet, not the missing child approval required to activate this operation.

The current live state cannot satisfy the reviewed bindings: the local provider proposal is stale, the existing evaluator service uses the legacy image/account path, and the reviewed GCS-only service account, narrow IAM grant, and operation-4 objects are absent. Even after credential bootstrap is repaired, KMS lock signing, bundle custody, timing, supervisor evidence, authorized task execution, and result sealing remain separate blocked gates.

### Launcher/STS bootstrap is redacted but not production-integrated

`CredentialOnlyCapabilityFactory` restricts the intended capability output to an expiry-bearing object and relies on `ConfidentialSpaceAdapter` for the launcher Unix socket, JWT verification, nonce, claim checks, and STS exchange. The receipt retains digests, identities, expiry facts, and explicit non-mutation flags rather than raw tokens or key material.

**confirmed** — `CredentialOnlyCapabilityFactory.build()` returns an object containing only `credentials_expires_at`, while `ConfidentialSpaceAdapter.activate_attested_service()` always passes that object to `service_factory`. The adapter's default `_default_service()` immediately requires `capabilities.store`, `capabilities.signer`, and `capabilities.timing_attestor`. With no repository wiring that supplies a credential-bootstrap-specific service factory, the new production path will fail after real attestation and token derivation instead of returning the bootstrap receipt. Split credential bootstrap from evaluator-service activation, or provide a dedicated adapter path whose successful contract is the redacted receipt and which cannot construct later-operation clients.

### Child approval and capability evidence remain self-authored

The new request is closed, digest-bound, and fixed to `bootstrap_signed_environment_credentials`; it rejects ordinary capability factories before launcher activation. A digest over a caller mapping is not evidence that the mapping came from the project control plane or a fresh remote observation.

**confirmed** — `validate_child_approval()` accepts any nonempty `approval_id` and requires only `approval_source == "confidential_space_attestation"`, `attestation_verified == true`, and a recomputed `approval_digest`. It does not bind a parent/master approval, dispatch, actor/signature, exact live prestate, or verifier-owned attestation receipt. The test fixture constructs exactly this synthetic shape. Replace it with an externally authored child approval bound to the exact request, current live bindings, `P5-MASTER-001/APPROVAL-013`, and one operation; verify its provenance before activation, and keep it disabled otherwise.

**confirmed** — `validate_capability_binding()` treats `narrow_writer_verified`, `broad_grant_absent`, `token_creator_verified`, and `public_principals_absent` as caller-provided booleans inside a self-digested mapping. `observation.source == "reviewed_iac_remote_observation"` and an arbitrary state digest do not establish that a fresh IAM prestate/poststate was actually observed. This leaves the exact verifier-owned credential-readiness gap identified in REVIEW-055/057/059. Consume a sealed verifier result that derives these facts from authenticated remote observations and binds the result to the current provider, image, target account, bucket, prefix, and run.
