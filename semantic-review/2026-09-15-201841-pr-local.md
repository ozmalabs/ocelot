# Native bounded P2 graph execution

P2-B1 replaces placeholder Rust entry points with a finite sealed-graph worker and evaluator, then adds protocol validation, receipt chaining, and a hardened Podman policy around that bounded path. The worker derives all action predictions from `P2PublicGraphV1` bindings, and the evaluator rejects a submitted proposal unless it matches a native reconstruction. The direct native smoke test demonstrates that an `advance` binding is selected over a cheaper `correlated` binding, while label/order permutation is bound to the graph node rather than label spelling. **Watch for:** **confirmed** — evaluator reconstruction directly calls the worker implementation, terminal receipts are omitted for validation/replay failures, and the actual hardened digest-pinned container case has not run because its evaluator-provisioned image is unavailable.  
**Verdict**: NEEDS_CHANGES

## High-level view

The bounded mechanics are real rather than binary stubs: the shared native graph reads every legal binding, runs a one-step simulation, and gives `advance`, `hold`, `unsafe`, `stale`, and `correlated` different transition outcomes. This demonstrates only the finite P2-B1 kernel, not general planning or a release capability.

The evaluator rejects forged worker records and has no Python callback, but its reconstruction calls `worker_reply` directly. **Confirmed:** this leaves a shared implementation defect as a common-mode scoring risk.

Receipt storage is append-safe: exclusive creation, file and directory sync, a signed predecessor chain, and restart verification protect committed records. **Confirmed:** malformed protocol inputs and replayed proposals exit before the receipt path, so not every terminal release-scoring failure is recorded.

The Podman policy and local image builder are fail-closed in isolation, including fixed non-root identity and `--pull=never`. **Confirmed:** neither is invoked by `P2Runner`, and the release-gated bypass-container test fails here because no digest-pinned evaluator fixture image was provisioned.

## Sealed one-step mechanics and opaque action identities

`p2_native::graph` accepts at most four legal actions and eight observation/goal nodes, requires one unique binding per action, and permits only five sealed effects. `worker_reply` builds a fresh belief and invokes `simulate_one_action` for every legal binding. `advance` predicts every requested goal at 9,000 bp and becomes feasible; `hold` stays below threshold; `unsafe` is infeasible; `stale` and `correlated` are unestablished. The direct native smoke test selected a cost-1 `advance` action over a cost-0 `correlated` action, whose prediction was unestablished.

Selection uses binding cost, predicted mechanics, and stable `node_id`; renaming/reordering labels while preserving node bindings produces the renamed equivalent selection. The test suite covers this local permutation property, not broader transition semantics, so the evidence supports bounded P2-B1 execution only.

## Worker-derived evaluator reconstruction

**Confirmed.** `evaluator_reply` obtains its expected proposal with `worker_reply(envelope.clone())`, then accepts only an equivalent submitted proposal and calculates metrics from that expected proposal. It neither trusts Python callbacks nor worker-provided fields, but any error in `make_prediction` or `select` appears identically in the evaluator's expected proposal and score.

Evaluator-native reconstruction must calculate expected transitions and scores from the sealed graph without calling the worker entry point. This turns proposal comparison into a check on a second implementation rather than an equality check against the same implementation.

## Terminal receipt coverage stops before protocol rejection

**Confirmed.** `ReceiptLog.append` locks, reloads and verifies the signed chain, creates the next record with `O_EXCL|O_NOFOLLOW`, syncs record and directory, and rejects changed or invalid records at restart.

`P2Runner.score` calls `validate_envelope`, `validate_proposal`, and `_claim` before `_receipt`. A malformed signed envelope, malformed proposal, or duplicate claim raises `P2ProtocolError` with no score receipt. Record these failures in a terminal, fail-closed receipt without relying on fields from an invalid proposal.

## Hardened Podman policy is not composed into scoring

**Confirmed.** `PodmanSpec` permits only `65532:65532` and builds a no-network, read-only, capability-dropped, no-new-privileges command with a digest-bound seccomp profile and bounded resources. `build_or_fail_closed` performs a local networkless build and compares the resulting digest. Yet the release runner directly executes a caller-provided local evaluator binary and invokes neither `require_release_ready`, `PodmanLauncher`, nor `build_or_fail_closed`; it also does not hash that binary against `evaluation_lock["evaluator_binary_digest"]`.

With `P2_RELEASE_LANE=1`, the bypass-container test fails rather than skips because `P2_TEST_BYPASS_IMAGE_DIGEST` is absent. This is fail-closed, not evidence that the hardened container contained the bypass payload. The release entry point must make image/binary/lock binding mandatory, and release infrastructure must provide the pinned fixture so the adversarial case executes.

## Removed release callback leaves a stale replay test

**Confirmed.** `P2UnitRunner` isolates the test-only callback seam, but `tests/evaluation/test_p2_replay.py` still constructs `P2Runner(reconstruct, ...)`. The independent run fails before replay behavior: `P2Runner.__init__()` rejects the positional callback. Replace it with a native-evaluator replay test or move its callback expectation to `P2UnitRunner`.
