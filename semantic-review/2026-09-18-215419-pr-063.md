### Generated commitments and runtime source closure

The validator’s in-memory regeneration and exact comparison of generated commitments address the earlier ignored-`var/` portability gap. Present files are checked against regenerated records, while absent files use the same canonical objects without writing private truth; the artifact index, lock request, private-store boundary, and control commitment therefore remain deterministic and non-release.

**confirmed** the source map is not closed over the behavior that the generated diagnostic uses. `evaluation/p5_r0/fixture_generator.py` imports `spec_for`, `private_truth`, and `private_observation` from `evaluation/p5_r0/mechanics.py`; `build_private_manifest()` calls `spec_for()` and `private_truth()` while building the generated private store, and the eventual evaluator/worker path also uses mechanics behavior. The repaired request hashes `fixture_generator.py` but not `mechanics.py`. A change to mechanics transition or observation behavior can therefore pass `_validate_sources()` without a source-digest failure, and a behavior change that does not alter the generated commitments can pass the commitment check as well. The source map should include this module and a test should mutate it in the clean-checkout fixture and require validation to block.

### Clean-checkout regeneration is implemented but not fully tested

The fallback path in `_validate_artifacts()` is explicit: if the artifact index or unsigned lock file is absent, it compares against the in-memory generator output instead of requiring ignored files, preserving `ready: false`, `cloud_operations: []`, and `mutations_performed: false`.

**confirmed** the adversarial test does not execute that path from the copied checkout as its name implies. `_copy_definition_sources_without_var()` copies files into `tmp_path`, but the test calls the already-imported `validate_execution_request` and `build_diagnostic_artifacts`; only `repository_root` changes.
