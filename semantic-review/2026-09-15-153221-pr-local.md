# Active I/O interception and terminal receipt-failure evidence

The change expands evaluation-mode interception from legacy adapters to Python file entry points and adds an evaluator-signed `EvaluationRuntimeFailureV1` control-plane record when receipt publication breaks after a run starts. It preserves receipt and failure-writer handles captured before activation, while the broker fails closed, kills shared run control, and withholds handlers after an append failure. The new tests exercise `open`, `Path.read_text`, `Path.write_text`, failed head publication, and active-chain tampering. Watch for: **confirmed** — saved pre-activation file handles and unpatched `os.chmod` still bypass the guard; **confirmed** — a failed head publication remains restartable and the terminal record is not used to reject that restart; **confirmed** — failure-record publication errors are discarded.  
**Verdict**: NEEDS_CHANGES

## High-level view

Evaluation mode monkey-patches common process and `pathlib.Path` I/O entry points only while the caller owns the run context. Receipt and runtime-failure writers retain early-captured primitives so they can publish evidence after the ordinary path is closed. That trust model does not distinguish evaluator-held pre-captured primitives from a reference retained by agent code before activation, so global patching cannot establish the claimed in-process file-I/O boundary. **confirmed**

The broker treats every receipt-append exception as terminal for the current endpoint: it enters impasse, kills shared control, and does not invoke the host handler. The durable state does not make that terminal across a new launch, however: the receipt validator accepts a nonempty signed receipt file without its required head, and neither startup nor broker construction rejects an existing runtime-failure record. **confirmed**

The new tests establish same-run containment and verify the fallback record through its signature-validating reader. They do not cover direct low-level mutations that remain reachable, retained I/O capabilities, fallback-publication failure, or restart after interrupted head publication. **confirmed**

<summary>Details</summary>

## Global patching leaves retained file capabilities outside the trust boundary

The tamper test itself obtains `unsafe_open = builtins.open` before entering `evaluation_mode` and uses that reference to rewrite `receipts.ndjson` while the guard is active. The same retained reference is available to in-process agent or legacy code and can read or write arbitrary host paths without reaching `_blocked`. A local probe retained `builtins.open`, entered `activated()` and `intercept_legacy_process_io()`, and read a file successfully. **confirmed**

The receipt and runtime-failure writers need their early-captured capabilities, but a global monkey-patch cannot distinguish those capabilities from an agent-held one. Establish the claimed boundary with a process/capability boundary for untrusted code, or guarantee that only evaluator-owned code can retain file primitives before activation. **confirmed**

## `os.chmod` bypasses the expanded mutation guard

The `os` inventory omits `os.chmod`. An active evaluation call to `os.chmod(path, mode)` changes a host file's permissions without reaching `deny_direct_io`, so it produces neither `DirectIODenied` nor reporter evidence. A local active-context probe changed a temporary file to mode `0600` through this path. **confirmed**

Deny this and the remaining relevant raw metadata/mutation APIs, then test both the exception and authority evidence rather than only the currently patched routes' in-memory reporter entry. **confirmed**

## Receipt-head interruption is recorded but does not make the run terminal across restart

A head replacement failure leaves the receipt line durable but preserves the preceding in-memory head in the runtime-failure record. `ReceiptLog.validate()` only checks the head when `head.json` exists, so a valid signed receipt file without a head is accepted as sequence 1 instead of being treated as a partial publication. A local probe forced `_replace` to fail and then successfully reopened the log as sequence 1 while `head.json` was absent. **confirmed**

Neither `evaluation_mode()` nor `ActionBroker.__init__()` reads `runtime_failure_record`; therefore the separately signed terminal record cannot stop a new run from resuming this state and attempting host actions. Require a matching head for every nonempty chain and make a verified terminal record a startup gate for its bound run. **confirmed**

## The independent fallback is attempted but not guaranteed evidence

`ActionBroker._record_runtime_failure()` and the active teardown helper both discard every exception from `runtime_failure_record.record()`. The broker remains in impasse and kills control, but the required signed terminal artifact is absent if its captured writer fails, with no signal for a supervisor to preserve or escalate. **confirmed**

The append-failure and tamper tests verify successful record publication through `RuntimeFailureRecord.read()`. They do not force the independent fallback writer to fail, so they do not establish the required evidence behavior when its store is unavailable. **confirmed**
