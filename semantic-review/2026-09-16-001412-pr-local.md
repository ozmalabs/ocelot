# P2 bounded-selection routing and hardened Python hostile control

The release worker and independent evaluator both derive their proposal selection through the declared `P2BoundedFutureManifoldV1` path, with the evaluator rebuilding the proposal before accepting it. An independently executed local release exercise built digest-pinned worker, native-bypass, and Python-bypass images locally, ran them rootlessly under the hardened Podman policy, and passed. The regenerated local 320 artifact records 320/320 selection-path provenance while explicitly excluding release custody and authority; its below-threshold feasible-minimal result is reported without a capability claim. **Watch for:** **confirmed** the durable receipt retains only a V2 hostile-control hash and `contained` status, not the per-route denial/no-effect results or evaluator mount commitments needed to inspect that evidence later; **confirmed** three P2 control tests still construct the old selection shape and fail after the new selection exports.  
**Verdict**: NEEDS_CHANGES

## High-level view

The native worker’s sole selector adapter converts every sealed prediction into `CounterfactualPrediction` and invokes `select_all_actions`; the evaluator independently performs the same reconstruction and rejects any non-identical worker proposal. The executable control exercises label and binding-order permutations and verifies that the selected opaque label is the minimum-cost graph-derived candidate, rather than a label- or order-driven choice.

The hardened release path preflights rootless Podman, digest-pinned local images, no pulling, no network, read-only mounts, dropped capabilities, a fixed non-root UID, seccomp, and bounded resources. Its real Python probe did execute under that policy and returned `executed_no_effect` for Python plus blocked hostile routes, but the receipt only preserves a digest of that complete result, so the denial and unchanged-mount facts are not durably readable from the evidence chain.

The 320-episode artifact is a local development control with fixed local keying and synthetic receipts. Its own status, documentation, and regenerated output deny trusted-release status; it must remain separate from release gates.

## Native reconstruction follows the bounded future-manifold selector

**confirmed** The worker’s `select` adapter creates one bounded prediction for every legal action and calls `select_all_actions`; it then exports that selector’s feasible, minimal, and native-tie sets with the `P2BoundedFutureManifoldV1` label. It does not choose from action labels or input ordering outside that path. The evaluator rebuilds the same predictions and selection from the sealed envelope and compares the entire worker proposal to its authoritative reconstruction, preventing a worker-supplied alternative selection from being accepted.

The executable-boundary test passed all label and binding-order permutations, and the bounded-selector tests passed. This establishes only the local bounded-path claim; it does not turn the synthetic corpus into a release result.

## Python bypass execution is real, but receipt evidence becomes opaque

**confirmed** The independently run `P2_RUN_LOCAL_OFFLINE_RELEASE=1` exercise passed on this host: Podman reported rootless operation, the test built nonce-scoped local worker, native-bypass, and Python-bypass images with `--pull=never` and `--network=none`, invoked the release runner, and removed only its three scoped tags. The Python image launches `/runtime/python3 -I -S /runtime/p2_python_bypass_probe`; the release runner accepts it only when every hostile route is `blocked`, Python is `executed_no_effect`, and evaluator-side before/after commitments for `/agent` and `/input` match.

The evidence returned by `NativeWorkerClient.bypass_evidence` contains the complete fixed route maps and unchanged-mount outcomes. In `_receipt_payload`, however, this object is discarded after hashing: the durable receipt receives only `hostile_bypass_evidence_hash` and `hostile_bypass_status`. The hash cannot show which routes were denied, that Python ran without effect, or that both mount commitments matched unless the hashed object is also durably stored. Retain the canonical V2 evidence payload in the receipt or write it as a receipt-addressed immutable artifact and record that artifact’s digest and path.

## Synthetic 320 evidence remains bounded to local development

**confirmed** Regenerating the corpus into a temporary path produced `local_synthetic_not_externally_trusted_release_evidence`, 320 episodes, and `{'P2BoundedFutureManifoldV1': 320}`. The checked-in JSON declares no release lock, Podman custody, or receipt authority; its companion markdown repeats that it cannot satisfy the primary gate and reports only 170/320 feasible-minimal successes. No trusted-release claim was found in this synthetic evidence.

## Selection-schema migration left three controls failing

**confirmed** `python3 -m pytest -q tests/evaluation/test_p2_protocol.py tests/evaluation/test_p2_controls.py tests/evaluation/test_p2_podman.py tests/evaluation/test_p2_runtime.py` produced 11 passes and 3 failures. The unavailable-action and over-budget controls now omit mandatory `selection_path`, `feasible_action_ids`, and `minimal_action_ids`; the scrambled-label control retains derivation IDs from the original labels. These failures mask the intended regression coverage for the control cases and should be repaired alongside the protocol expansion.
