# Bounded native P2 release runner

This change introduces a release-only P2-B1 planning path: a fixed native worker runs in rootless Podman, a separate native evaluator rebuilds and scores sealed one-step clones, and every returned terminal result is sealed by an append-only signed receipt. The production runner accepts no proposal, callback, broker, or reconstruction injection from its caller; the worker reply is only an untrusted consistency input to the evaluator. Replay claims and receipt recovery are durable, while unavailable local images or hardened-runtime prerequisites deny the run rather than falling back. The scope is deliberately pre-release only because the checked-in lock is invalid and the real local P2/bypass images are not staged. Watch for: **confirmed** the lock's signing and content attestations are not actually bound to the runtime, and **confirmed** evaluator-selected actions can exceed the signed envelope's intervention-cost cap.

**Verdict**: NEEDS_CHANGES

## High-level view

The native evaluator reconstructs its expected plan and scores it before comparing the worker reply, so a worker cannot establish score inputs by submitting favorable predictions. A mismatch retains the authoritative metrics and becomes a zero-credit, receipted terminal result rather than an alternative evaluation path.

The release runner fixes the Podman topology to a rootless, digest-pinned, no-network, read-only container with a fixed non-root identity and a staged seccomp policy. The real-container lane is intentionally guarded: it fails in a release lane if Podman or the evaluator-provisioned bypass image is unavailable, and otherwise does not claim that developer-machine skips prove containment.

Receipts and replay claims are treated as release evidence: preflight, worker, evaluator, and duplicate-submission denials return a signed terminal record when the receipt store is healthy. However, the lock proves only the shape of several promised artifacts, and the scoring kernel does not use the envelope's declared maximum intervention when accepting or selecting a sealed action.

## Authoritative clone scoring precedes the worker comparison

`p2_native::evaluator_reply` calls `evaluator_plan` before it compares the proposal. The evaluator rebuilds bindings, predictions, selection, and metrics from the sealed envelope; a tampered reply only yields `worker_mismatch` with the reconstruction's digest and metrics retained for its receipt. **Confirmed**: scoring does not rely on worker predictions.

## Lock contents and signer identity are not release gates

`validate_lock` in `evaluation/p2/lock.py` validates that required digest fields are non-placeholder SHA-256 strings, but `P2Runner._release_preflight` in `evaluation/p2/runner.py` measures only the evaluator binary, worker binary, worker image, and seccomp policy. The locked native-rule, native-seed, action-vocabulary, outcome-vocabulary, and split-commitment values are never compared with a staged artifact or evaluator input. The runner also accepts any non-`None` `envelope_key`; `evaluator_signing_key_fingerprint` is validated syntactically but is never read to confirm that this key, or the receipt signer, is the lock-authorized identity.

**Confirmed**: a caller that supplies a different key and envelopes signed by that key passes signature verification, even if its key does not match the lock's fingerprint. The release preflight needs canonical public-key fingerprinting and a concrete artifact manifest whose measured digests are compared to every applicable lock field before a worker can start.

## The signed cost bound does not constrain the native plan

The envelope protocol requires `cost_bounds.maximum_intervention`, but neither `validate_proposal`, `p2_native::graph`, nor `p2_native::select` compares that value to a binding or prediction cost. The evaluator rebuilds a plan from `training_bundle.action_bindings` and accepts the worker only when it matches that plan, so this is not a worker-input issue: the evaluator itself can endorse a sealed over-budget binding.

**Confirmed** by a direct build-and-run smoke test: an envelope with `maximum_intervention: 0` and one sealed `advance` binding at cost `1` produced an accepted proposal with that action selected. The public budget must participate in authoritative reconstruction and selection, otherwise the receipt can certify an action outside its signed planning contract.

## Receipted denials and hardened-container evidence remain bounded

`P2Runner.score` converts validation, preflight, worker, evaluator, and replay failures into a signed terminal receipt; receipt-append failure raises rather than returning an uncertified result and releases the unfinished claim. The replay test performs a first worker/evaluator exchange then produces a receipted `replay_denied` result for the duplicate. The Podman command fixes no pull/network, read-only mounts and root, dropped capabilities, `no-new-privileges`, seccomp, fixed UID/GID `65532:65532`, and resource limits; in `P2_RELEASE_LANE`, missing Podman, the local digest-pinned image, or the bypass fixture fails the test. **Confirmed**: the current placeholder lock and unstaged real images therefore fail closed and make no real-container evidence claim.

The focused Python P2 suite passed 22 tests with 2 guarded real-Podman skips, and both native binaries built. `cargo test p2_ --lib --bins` could not link the repository's existing Python C-API dependencies; `cargo build --bin p2_evaluator --bin p2_native_worker` succeeded. Not tested: rejection of a mismatched attestation key/artifact and the over-cap cost behavior.
