## High-level view

The direction-aware proxy is a clean sibling. `make_realized_text_aware` calls `make_realized` for its base draw and layers a gold-direction nudge on a `p_signal` fraction of signalled cells using a *distinct* RNG (`2_000_000+seed`) so the base draw is untouched; `p_signal=0` returns the base unchanged. `make_realized` contains no text/gold/p_signal logic, and the symmetric-proxy consumer `measure_h2.py` still imports `make_realized` and still runs its coin-flip null — both verified by re-run.

Direction is graph-native, not a coin flip. Each cell's shift direction is `arm.decode_utterance`'s `direction` datum, read off the winning StanceReading node; the winner is selected by an in-Rust Argmax term, not a Python argmax. Arms 2 (`flat_0.1σ`) and 3 (`grounding_weighted`) share that same decoded direction and differ only in magnitude: `sign×0.1σ` vs `0.1σ×arm.shift` where `arm.shift = sign×grounding_weight`. The grounding_weight for every signalled unit is 0.333 (hops=3), so grounding_weighted is a uniform 0.333× attenuation of flat here — a magnitude-only difference, correctly directed.

The whole grid is swept and reported. `p_signal ∈ {0,0.3,0.5,0.7} × e ∈ {0.5,1.0}` produces the 8-row table in the results doc; the H2a/H2b/H2c verdicts are computed over the full sweep, not read off one cell. The reproduced numbers match the doc to 5 d.p.

The scored path applies the graded per-cell shift. `cell_shift_grid` builds a per-cell shift array from the arm's decode and `apply_band_shift_percell` translates each cell's draws by `shift×cell-std`. For grounding_weighted this is `0.1σ×0.333=0.0333σ`, not a flat constant — verified against the doc's bear-flattener example.

Everything is RAW_UNRANKABLE and the nulls are reported as findings: H2a confirms direction converts to composite gain, H2b is reported as a flat-wins/mixed near-tie (not tuned away), H2c confirms graceful attenuation. The doc separates what a direction-sensitive proxy can establish (relative magnitude-policy ranking) from what it cannot (any absolute/sealed-board claim; the gold is the arm's own decode).

### Transport of direction: the sibling proxy leaves the symmetric base intact

`make_realized_text_aware` (run_variogram_eval.py:130) opens by calling `make_realized(card, panel, seed, k=k, mode=mode)` for its base draw, then returns that base unchanged when `p_signal<=0 or e==0.0 or not gold_dir`. The nudge loop uses a separate selection RNG seeded `2_000_000+seed`, distinct from `make_realized`'s draw RNG (`1_000_000+seed`) and the text-aware nudge's own arithmetic, so *which* cells carry signal is fixed per seed and does not perturb the base draw. The nudge is `v + gd*e*cell_sigma` where `cell_sigma = |beta[ai]|*h_scale` — the same daily/beta scale `make_realized` draws at, so `e` is genuinely in cell-σ.

The signal fraction is applied exactly as prereg §fix.1 requires: `if gd != 0.0 and sel_rng.random() < p_signal` nudges; the `else` (unsignalled asset, or the `1-p_signal` abstain draw on a signalled asset) keeps the unchanged proxy value. The typer's real error/abstain is not assumed away — 10/22 units decode `direction=none` and contribute exactly zero, and on signalled units only a `p_signal` fraction of cells is nudged.

`make_realized` (run_variogram_eval.py:94) is a genuine sibling, not an edited parent: its source contains no `text_aware`, `gold`, or `p_signal` reference (checked via `inspect.getsource`). The symmetric-proxy consumer `measure_h2.py:35` still imports `make_realized` and calls it at line 133 with its coin-flip `unit_dir` (measure_h2.py:106) intact; I ran it on two F3 units and it still reports `NEUTRAL-OR-BETTER: False`, reproducing the original null on the symmetric proxy.

### Direction is the arm's graph decode, held correct across arms 2 and 3

`decode_utterance` (arm.py:298) returns `direction` by reading the `direction` attr off the winning StanceReading node (arm.py step 8), where the winner is chosen by `native.evaluate(_winning_stance_term(market), {})` — an in-Rust held-Argmax term, explicitly not a Python argmax loop. `shift = base_shift * grounding_weight` (step 11), with `base_shift` a codebook lookup `{"up":1,"down":-1,"none":0}[direction]` keyed by the graph-decoded direction. This is a mechanical read-back, not a Python branch deciding direction from graph content.

`measure_h2_directed.py`'s `cell_shift_grid` consumes those values: `flat_0.1sigma` uses `sign*flat_shift`, `grounding_weighted` uses `flat_shift*dec["shift"]` = `flat_shift*sign*grounding_weight`. Both arms carry the same `sign`, so they differ only in magnitude. In the re-run every signalled unit decoded `gw=0.333, hops=3`, so grounding_weighted is a uniform 0.333× attenuation of flat — the two arms are cleanly separated on magnitude policy alone, direction held correct for both.

### CLAUDE.md: the graded shift is read, not decided

CLAUDE.md:112 forbids "conditionals over graph state" in the host adapter; Python translates I/O and reads graph state back out. The scored path honours this. The `if policy ==` in `cell_shift_grid` selects the arm (a config/experiment choice), not a decision over graph content — the direction and magnitude come entirely from `dec["sign"]`/`dec["shift"]`, which are graph reads. `decode_utterance` performs the selection in-Rust (Argmax term) and reads the direction datum off the winning node. No Python if/elif inspects graph state to choose a direction or magnitude.

### Scored forecaster applies the graded per-cell shift

`apply_band_shift_percell` (measure_h2_directed.py) translates each cell's draws by `shift_sigma_cell[a,h] * that cell's own std` — a per-cell additive, contract-preserving translation (correlation is translation-invariant), the same discipline as the reused scalar `apply_band_shift`. For grounding_weighted the per-cell value is `0.1σ × 0.333 = 0.0333σ`, not the flat `0.1σ` — matching the doc's bear-flattener check (`grounding_weighted[cell]=0.0333` vs `flat[cell]=0.1`). The graded shift is genuinely wired into the scored composite path, not a flat constant.
