# P4 local readiness gate

The change introduces a P4-R0 local-only evaluator package, an offline/rootless Podman policy, receipt primitives, and a Rust graph state machine intended to express the bounded intervention → replan → action sequence. Its output remains explicitly local readiness only, non-promotional, and `no_go`. However, the coordinator currently records the intended run rather than executing the native state machine or hardened worker, and the boundary between intervention and action outcomes is not enforced. **Watch for:** **confirmed** — the local runner can emit a completed local receipt sequence without exercising containment or native cognition; **confirmed** — a sealed action result is accepted before the action is proposed; **confirmed** — the supplied preregistration lock neither binds all declared inputs nor is validated before a run.  
**Verdict**: NEEDS_CHANGES

## High-level view

The design separates untrusted cognition from evaluator-owned actions: Rust is meant to emit graph-only proposals, while Python owns task release, grants, outcomes, receipts, and rollback. The Podman specification also describes a constrained local process with no network, no pull, a digest-pinned image, dropped capabilities, and a read-only filesystem. **Confirmed:** `run_local` does not join those pieces: it appends static receipt events and invokes only rollback, so the reported local run does not establish that the native graph logic or container boundary was used.

Preregistration is modeled as a canonical local lock and the result remains explicitly non-promotional. **Confirmed:** the generated lock does not include the Containerfile, seccomp, native worker/export, or image digests that the preregistration says are locked, and `run_local` accepts any dictionary with two booleans instead of authenticating or validating that lock. A caller can therefore produce receipts under a substitute configuration rather than a preregistered one.

The graph state machine creates a causal graph before it asks for an intervention, then accepts a sealed intervention outcome before it replans. **Confirmed:** the next phase accepts any status with a `sha256:`-prefixed parent string; the existing trace test passes a sealed action outcome there and receives the action proposal afterward. That permits an action outcome to arrive before its proposal and breaks the intended causal gate.

<summary>Details</summary>

## The coordinator records a run without running the hardened path

`run_local` iterates the five arm names and appends `task_release` records, appending one `replan` record for `graph_planner`; it never calls `P4PodmanLauncher`, `P4R0Evaluator.release`, `grant`, or `act`. It therefore never consumes a `GraphActionProposalV1`, executes the Rust `advance_p4_r0` state machine, enforces a grant, or subjects a worker to the offline/rootless Podman argv. The only evaluator operation is `restore`, while every resource ledger is fixed at zero.

This is a **confirmed** trust-boundary gap, not merely missing end-to-end coverage: the `result` and `rollback` receipts assert a local run structure even if no worker image is present, no worker can start, and no native graph computation has happened. The container policy is useful configuration but unused operationally. Couple the coordinator to a staged, digest-verified `P4PodmanSpec`, exchange only validated frames with the worker, and derive receipts and resource accounting from evaluator-verified events. If Podman, the local image, the worker, or the expected graph trace is unavailable, terminate as an impasse/no-go without emitting a completed run sequence.

## The local lock does not bind the configuration it claims to preregister

The preregistration document says a generated lock fixes the Containerfile, seccomp, native export/worker, and image digests. `preregister_local` writes only the preregistration and fixture digests, static limits and arms, and a test key ID. Neither the Podman spec nor staging validation is called, so these executable security inputs can change without invalidating that lock.

`run_local` then checks only `non_release` and `promotion_authority` on an in-memory mapping. It does not require the lock's schema, recompute `lock_digest`, ensure the configured limits and arms match the lock, or verify a persisted preregistration predates the receipt chain. This is **confirmed** to defeat preregistration-before-results for the local gate: a caller can supply a hand-built mapping with arbitrary `lock_digest` and fixture digest and the coordinator will produce signed receipts referring to it. Treat the generated lock as a closed canonical artifact, validate every field and digest against staged inputs at run start, and bind the verified lock digest into the first receipt before releasing any task.

## The causal trace accepts an action result before authorizing its action

At phase 2, `advance_p4_r0` checks only that `parent_receipt` is present before creating `GraphActionProposalV1`. It does not require an expected observation status, verify the receipt's full digest or associate it with the intervention/replan proposal, or enforce increasing logical time. The integration test demonstrates the consequence directly: after the intervention creates a `Replan`, it supplies `SealedActionOutcome` at time 3 and receives `ProposeAction`.

This is **confirmed** to violate the stated intervention-before-rule-dependent-action behavior: an already-known action outcome can be injected as the replan-parent signal, so the proposed action is no longer causally prior to its result. Represent the required sealed replan/intervention acknowledgement explicitly, persist the expected receipt/proposal identifier in graph state, require the matching full digest and monotonic logical time, and reject every other status before action proposal. Add negative tests for an early action outcome, an unrelated receipt, a malformed-length `sha256:` string, and replayed/stale logical times.

## Coverage proves isolated invariants, not the gate composition

The targeted suites pass (Rust: 4 tests; Python: 7 tests), covering unsupported manifolds, bounded unknown-output retry, receipt chaining, grant replay/expiry, the local no-go label, and construction of the Podman argv. **Confirmed:** they do not execute the coordinator against the native worker or Podman preflight, and the Rust trace currently encodes the invalid early-action outcome described above as its positive path. Add a local integration test with a staged fixed image/worker fixture that verifies the full receipt-to-proposal-to-grant-to-outcome order, plus fail-closed tests for unavailable Podman and changed staged/lock artifacts.
