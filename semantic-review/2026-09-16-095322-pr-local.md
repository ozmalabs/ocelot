# Evaluator-verified reservation handoff into native P4

The change adds a canonical reservation commitment to Python’s evaluator output and a Rust-only capability that P4 requires before it can complete its action phase. The native state machine persists the reservation/proposal binding and compares it against the sealed outcome; raw JSON cannot construct the completion capability. Python verifies the evaluator receipt chain before serializing the compact outcome transport, while Rust rejects missing, altered, and unverified fields. **Watch for:** **confirmed** — this is not yet an actual evaluator-to-Rust runtime handoff: the only Rust receipt verifier and bridge caller are test-only, so a real evaluator-verified outcome cannot currently complete native P4 in production. **Verdict**: NEEDS_CHANGES

## High-level view

The local native gate is fail-closed. Completion depends on an opaque `VerifiedActionOutcome`, and the reservation digest must agree with the action reservation persisted in the P4 graph. The Python producer derives that digest from the run, proposal, sequence, snapshot, and reserved resources before exporting its canonical transport.

The trust boundary stops at an abstraction rather than a deployed integration. Rust parses the transport and offers a crate-private adapter, but it has no non-test receipt verifier and no non-test caller that feeds verified Python output into the adapter. The checked mock proves the gate’s shape, not that the evaluator’s signed receipt chain reaches native P4.

## Reservation-bound completion capability

`P4R0Evaluator` computes `reservation_digest` from the run ID, proposal digest and sequence, pre-run snapshot, and resource reservation before embedding it in proposal, grant, broker, and outcome bindings. `verified_native_outcome` only exports after `verify_sealed_action_outcome` validates the signed receipt chain. Phase 2 stores the proposal and reservation digests on the concrete `ActionReservation`; phase 3 requires a successful opaque outcome whose reservation digest still matches that persisted reservation. A direct `SealedActionOutcome` fails at `verified_action_outcome_required`, while an altered binding fails before completion.

## Receipt verification exists only as a test seam

**Confirmed:** `seal_serialized_evaluator_outcome` is referenced only by `p4_evaluator_adapter_tests`, and `SignedEvaluator` in that same test module is the only `EvaluatorReceiptVerifier` implementation. No production worker owns the evaluator receipt log, verifies the evaluator’s Ed25519-backed chain, or invokes the bridge with `serialized_verified_native_outcome`. The Rust transport contains receipt digests rather than the receipt chain or a signature, so it cannot independently establish that those digests came from `P4R0Evaluator` without such a trusted verifier or boundary.

The positive Rust test uses a static transport accepted by `SignedEvaluator`; it does not consume bytes emitted by a real `P4R0Evaluator`. Its forged and altered cases prove the mock adapter rejects deviations from its hard-coded values, but do not establish that an attacker cannot substitute a transport at the missing production boundary. Add the runtime contract and test it with the actual evaluator’s canonical serialized output; retain the altered reservation and forged-receipt cases at that boundary.

## Validation and release boundary

Python evaluator coverage passed: `python3 -m pytest -q evaluation/p4/tests` reported 20 passed. `cargo check --tests --offline` completed successfully. **Confirmed:** `cargo test p4 --offline` could not start tests because linking the crate fails on unresolved PyO3/Python C symbols (for example `PyNumber_Index` and `PyGILState_Ensure`), so the Rust positive and negative tests were not executed in this environment.

**Confirmed:** Podman was not run, and no image, container, or release artifact was built or exercised. This review therefore makes no Podman or release-readiness approval; even after the runtime verifier is added, a release-capable environment must run the linked Rust suite and the intended containerized handoff before that claim can be made.
