# Macro-release numeric-surprise mechanism as a reuse of the ToM stance arm

The build closes the one coverage gap the induced-belief arc left open: the ToM speech-act decode scored 0.0 on `macro_release` prints because a CPI/NFP print is a NUMBER, not a speech act. The new path reads the print's numeric surprise (released vs the print's own stated prior, or vs a panel trend, or a qualitative cue) into a bare surprise sign, multiplies it by a per-series `hawkish_sign` taught as `MacroSurpriseSign` data, mints a `MacroSurpriseReading`, and lets a new seed rule (`ib_decode_macro_surprise`) type it into the *same* `StanceReading` shape the ToM `ib_decode_stance` rule emits — so it flows through the unchanged `concept_apply_evidence` → Argmax → `grounding_reach` readout on the same `<stance>_stance_for:rates_market` CAN Concept. It is gated to `macro_release` doc_types; every other doc_type still goes through the untouched ToM decode. The whole arm lives under untracked `drafts/seldon_t2_text/` with no substrate/domains/worlds/seeds edits.

Watch for: (1) the winning-stance's `stance`/`band_sign`/`direction` triple is computed in Python inside `decode_macro_surprise` and then copied verbatim by the rule (confirmed) — the rule's Eq-join is real but does not itself derive the direction the way `ib_decode_stance` derives it from taught `CBSpeechAct` data; this is a weaker "decision is the rule" claim than the prose asserts. (2) The H-M1 100% is honestly scoped but the panel-trend path (source `quantitative_panel`) was never exercised by the frozen set (confirmed against `hm1_results.json`) — every one of the 17 rows is `quantitative_text`/`released_sign`/`none`. (3) The H-M3 shift-artifact confound is disclosed accurately and the numbers reconcile with `hm3_results.json`. (4) A stale docstring in `measure_hm1.py` states the wrong gold distribution (possible).

**Verdict**: APPROVED

## High-level view

The reuse story holds. The macro path does not fork the belief machinery: it mints its evidence onto the identical `<stance>_stance_for:rates_market` Concepts the ToM arm mints, calls the same `native.concept_apply_evidence`, reads the winner with the same `_winning_stance_term` Argmax, and gates confidence with the same `grounding_reach`. There is no second belief mechanism and no parallel readout.

The "no Python decides the stance" claim is mostly satisfied but has one honest seam. Which sign is hawkish is genuinely taught data (`MacroSurpriseSign`, keyed on series), and the surprise sign is I/O arithmetic. But the concrete `(stance, band_sign, direction)` triple the rule stamps onto the `StanceReading` is precomputed in Python (`band_sign = surprise_sign * hawkish_sign`; `band_stance(...)`; `frame.SIGN_DIRECTION[...]`) and merely copied through the rule, whose Eq-join is on `series` only. The ToM arm instead joins the `(stance, sign, direction)` in from a separate taught `CBSpeechAct` node — the band derivation is the rule's, not host code's. This is a real, if narrow, asymmetry with the ToM decode's discipline.

The gating is clean and the non-regression is real: `_derive_text_signal_tom` dispatches only `macro_release` to `decode_macro_surprise` and everything else to the unchanged `arm.decode_utterance`, and the doc reports `measure_h1.py` and the exemplar gate as byte-identical. The gate JSON confirms both arms admissible on both macro units.

The H-M1 headline (17/17) is real decode output and the doc is forthcoming about what the perfect score hides: single-annotator, CPI-dominated, small-n, and that the panel-trend path never fired on this set. The H-M3 branch is reported as the pre-committed *partial/confounded* outcome, not a clean win; the direction-independent shift-center artifact (−0.279 at `p_signal=0`) is surfaced as dominating the genuine direction effect (−0.0088 residual) ~30×, and every number reconciles with the result JSON.

### The decision seam: what the rule decides vs what host code decides

The user's constraint (1) is that no Python `if/else` may decide a stance/direction over graph state; which sign is hawkish must be taught data, the stance decision must be the seed rule, winner selection must be the Argmax, direction read off the graph.

Three of the four hold cleanly. Which sign is hawkish is `MACRO_SURPRISE_SIGN` taught as `MacroSurpriseSign` nodes (`teach_macro_codebook`), read back off the graph in `decode_macro_surprise` (it iterates `sub.nodes("MacroSurpriseSign")` and reads `hawkish_sign`, falling back to the Python dict only if the node is absent). Winner selection is the reused `_winning_stance_term(market)` Argmax evaluated via `native.evaluate` — no Python argmax. The final direction is read off the winning `StanceReading`'s `direction` attr.

The seam is in how the band gets computed. In the ToM arm, `frame.codebook_entries()` produces `(stance, sign, direction)` per taught `CBSpeechAct`, and `ib_decode_stance` Eq-joins a `FrameReading`'s `(symbol, motion)` against a `CBSpeechAct` and copies the *codebook node's* stance/sign/direction onto the `StanceReading`. The decision "this (symbol, motion) is hawkish +1 up" lives in the taught node and is selected by the join.

In the macro arm, `decode_macro_surprise` does:

```python
band_sign = int(surprise_sign * hawkish_sign)
stance = band_stance(band_sign)                 # dict lookup {1:hawkish,...}
direction = frame.SIGN_DIRECTION[band_sign]      # dict lookup {1:up,...}
```

then mints those onto the `MacroSurpriseReading`, and `ib_decode_macro_surprise` copies them onto the `StanceReading` via `{"__term__": Attr(mr, "stance")}` etc. The rule's `where` joins `mr.series == ms.series` and adds a `reads_macro_codebook` provenance edge, but it does not multiply the surprise by the hawkish sign — that already happened in host code.

This is not an `if/else` deciding over graph state: the inputs are a taught `hawkish_sign` and an arithmetic surprise sign, combined by dict lookups (the same class as `frame._direction`), and the codebook comment is explicit about the arrangement. But the results doc's claim that "the DECISION … is the seed rule `ib_decode_macro_surprise`" does more rhetorical work than the ToM arm's equivalent: here the rule joins on `series` and passes through a precomputed band rather than joining the band in from taught data. A stricter reuse would put the sign→(stance, direction) mapping on the `MacroSurpriseSign` node (or a companion taught node keyed on `band_sign`) and let the rule's effect derive the band, so the multiply is graph-native.

### Reuse of the belief machinery — no fork

`decode_macro_surprise` composes on the same belief, not a parallel one. It resolves the market's stance Concepts from `mk["concepts"]` (built by `arm.build_market` via the reused `bigville_can_beliefs.build_resident_can_mt` and `mint_resident_tom_belief`), and applies evidence with `native.concept_apply_evidence(concept, 1.0, alpha)` — the identical primitive `decode_utterance` calls. It reuses `_arm._resolve`, `_arm._mint_message`, `_arm._anchor_corpus_message`, `_arm._winning_stance_term`, `_arm.gr`, and `frame.SIGN_DIRECTION`/`frame._attr`. The `force_all_dirty()` → `run_rules()` GOTCHA ordering is honored. The grounding provenance mirrors the ToM arm: a real surprise mints `read_from`/`grounded_in` edges; a print with no recoverable surprise (`surprise_sign == 0` or no series) mints no anchor edge, reaches nothing, and shifts ~0 — the silence-not-error floor.

The one duplicated-rather-than-shared piece is the marshal-in/tick/read-out body of `decode_macro_surprise`, which re-implements the back half of `decode_utterance` (winner read-back, `win_dir` extraction, `grounding_reach`, hop-discount weight, `base_shift`). This is copy-structured reuse of a private flow rather than a shared helper — not a belief-mechanism fork, but duplication that will drift if `decode_utterance`'s readout changes.

### Gating and non-regression (H-M2)

`_derive_text_signal_tom` sets `_MACRO_DOC_TYPES = {"macro_release"}` and branches per doc: `is_macro` → `decode_macro_surprise(agent, d["text"], mk, panel=panel)`, else the unchanged `arm.decode_utterance(agent, d["text"], mk)`. `derive_text_signal` and `run_verb` thread `panel` through so the macro path can read the trend baseline. The branch is the only place the macro path can fire, and it keys strictly on `doc_type`, so non-macro reads take a byte-identical code path to the pre-macro arm.

The doc's H-M2 evidence is a byte-identical re-run of `measure_h1.py` against committed `h1_results.json` and a byte-identical exemplar `gate_g0g3_results.json`. Those artifacts weren't re-executed in this review, but the gating structure supports the claim: the macro code is reachable only through the `is_macro` branch, and boot adds nodes/rules the ToM decode never queries. `gate_macro_results.json` confirms both arms admissible on both macro units, with `UST_10Y: 0.3333` (some-pain, from the FOMC ToM decode with the CPI print typing to `none`) and `NFP: -0.3333` (covid, from the qualitative macro path).

### H-M1 — honest scope of the 100%

17/17 is real decode output; `hm1_results.json` per-snippet rows each carry a live `source`, `surprise_sign`, `marginal`, `grounding_weight`, and `shift`. The gold distribution (up=6/down=9/none=2) matches the study set and makes >0.5 a genuine bar. The doc's structural caveats match the JSON:

- No `quantitative_panel` row exists in `by_source` — the 6 no-prior prints (`m_qe2jh_2010`, `m_tapertestimony_2013`, `m_fundingstress_2008`, `m_qe1_2009`, `m_taperwarning_2013`, `m_ustdowngrade_2011`) all have `source: "released_sign"` with `trend: null`. The released-vs-implicit-zero fallback carried them, not path (b). The doc states this plainly, but it means one of the two advertised quantitative paths has no measured coverage in the headline result, and the independent `t2-F4-cpi-vintage-2022` panel verification is narrative only, not a committed row.

- The `none` bucket in `by_source` shows 1/1 while there are two gold=`none` snippets: `m_taperbegins_2013` (source `null`) and `m_tradewar_2019` (source `quantitative_text`, `surprise_sign: 0`). The equal-to-prior print is typed by the quantitative_text path (surprise 0 → none), so it lands in `quantitative_text`'s 10/10 — the buckets are distributed by *read source*, not *gold label* (10 + 6 + 1 = 17). The doc's by-path table reproduces this faithfully.

The stale docstring in `measure_hm1.py` ("up=5/down=9/none=2") contradicts the actual data and the emitted JSON — a wrong number sitting in a measurement harness.

### H-M3 — confound disclosed, numbers reconcile

The doc reports H-M3 as LITERAL-CONFIRMED but SHIFT-ARTIFACT CONFOUNDED, the pre-committed partial branch from the prereg:

- `hm3_results.json` `summary` gives `mean_signalled_delta_composite = -0.2875`, `empty_signal_abs_delta_composite = 0.2787`, `shift_artifact_confound = true`, `mean_direction_only_gain = -0.00883`, `direction_only_all_negative = true`. The doc's headline numbers (−0.2787 at `p_signal=0`, −0.29 signalled, −0.0088 residual, "~30×") all trace to these fields and the per-cell grid.
- The grid values in the doc's table (14.71464 / 14.43595 no_shift/macro_shift at p=0, tail 0.24270 / 0.24560, Δ −0.27869) match the JSON cells exactly.
- The confound is characterized correctly: at `p_signal=0` the proxy carries no gold, yet `macro_shift` already beats `no_shift` by the same magnitude, so the raw win is a direction-independent shift-toward-center artifact on single-asset level series, and the genuine direction effect is the small monotone residual. `direction_only_monotone_in_p_and_e` is left `null` in the JSON (a comment defers monotonicity to the doc); the doc's residual table (−0.00277 → −0.00931 → −0.00972 at e=0.5; −0.00365 → −0.01345 → −0.01405 at e=1.0) shows the claimed monotone-in-both pattern, and the per-cell `direction_only_composite_gain` values in the JSON support it. This is a manual read, not a machine assertion.

No overclaiming: the doc refuses to report the 6/6 literal pass as a clean win, states RAW_UNRANKABLE, and notes the proxy's gold direction is the decode's own direction (sympathetic by construction). The proven-vs-assumed ledger files H-M3 under PARTIAL/HONEST-NULL and the RAW_UNRANKABLE status under ASSUMED.
