# Repaired P5 V3 run fails closed, but the repaired evaluation did not run

The repair preserves the prior V2 failure run and creates a separate signed V3 lock bound to the V2 parent digest before the attempted native stage. The closure-bound V3 stage then fails closed because no independent external authority or authority-bound signer is available; its native worker is explicitly not invoked, leaving no primary records, controls, contrasts, or warm-arm observations. The three V3 receipts and exact rollback are internally chained, and the old 337-receipt V2 run remains intact with its original failure reasons. **Watch for:** **confirmed** no repaired P5 controls or warm safeguards were exercised; **confirmed** the production runner still validates only `P5R0LocalLockV2`, so the V3 lock cannot drive a successful native run; **confirmed** the V3 seal does not carry enough public-key/receipt validation material for independent signature verification.

**Verdict**: NEEDS_CHANGES

The original V2 lock, result, evidence, and 337 receipts remain separate from two V3 fail-closed attempts. The V3 lock is read-only, carries the parent lock digest, declares non-release status, and records the closure, worker contract, and safeguard policy; the closure-bound artifact reports `native_attempted=false` rather than fabricating execution.

The repaired run stops at the authority gate, so the requested behavioral claims cannot be evaluated. Its zero records, zero controls, and zero contrasts mean there is no evidence that worker-authoritative controls are real, that bounded warm adoption was exercised, or that negative-transfer detection was preserved. **Confirmed** no-go: an authority-bound native rerun is required.

The artifact chain is hash-consistent and the rollback is exact, but the implementation path is not yet closed for V3 execution. **Confirmed** `run_readiness_gate` calls the V2 validator, while the new lock is `P5R0LocalLockV3`; independently verifiable receipt signatures are also not possible from the sealed artifact because the corresponding public key is omitted.
