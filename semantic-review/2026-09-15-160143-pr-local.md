# Fresh-exec OS-isolated P0 launch path

The change replaces the P0 fork/Pipe endpoint with a Bubblewrap-launched worker communicating with an evaluator-resident broker over bounded, nonce-bound stdio. It fails closed when the launcher, Bubblewrap executable, staged paths, or cgroup-controller interface is unavailable, while grants, provenance, receipt signing, and action projection remain in the parent process. The mount plan uses an empty root and opaque proposal IDs rather than the legacy in-process guard. **Watch for:** **confirmed** the required OS-isolation acceptance path contains no executable containment probes and fails unconditionally even when marked provisioned; **confirmed** advertised timeout/whole-scope supervision is not connected to the launch lifecycle; **likely** the documented worker command cannot receive its required entrypoint through the launcher’s cleared environment.  
**Verdict**: NEEDS_CHANGES

## High-level view

The worker protocol exposes proposal identities only; the host resolves authenticated graph evidence, grants, actions, and receipts. That is a fresh-process authority split, conditional on real Bubblewrap and evaluator-owned cgroup deployment.

Construction tests inspect an isolated Bubblewrap argv and a missing-sandbox denial, but no test executes a sandboxed worker against retained-descriptor, mmap, directory/metadata, network, or host-I/O attacks. The purported acceptance test always fails instead of running these probes.

The supplied supervisor is unused and heartbeats do not drive a deadline, so the code does not provide the documented timeout or verified whole-scope cleanup guarantee.

<summary>Details</summary>

## Bubblewrap policy has no deployment proof

The launcher requests new user, PID, network, IPC, UTS, and cgroup namespaces, an empty tmpfs root, read-only `/runtime`, `/agent`, and `/input` binds, tmpfs `/work`, and `close_fds=True`. It passes only stdio plus a transient seccomp-policy descriptor; the worker then requires `/proc/self/fd` to contain only `0`, `1`, and `2`. The stdio schema excludes paths, descriptors, grants, callbacks, raw requests, and result-file fields, keeping control-plane state, grants, receipt keys, provenance, and action dispatch in the host.

**Confirmed:** the integration test never starts Bubblewrap, an agent, or an adversarial probe. Without the marker it fails at its assertion; with the marker it reaches unconditional `pytest.fail`. It therefore cannot verify that retained host descriptors or mmaps are unusable after exec, that host `listdir`/`stat` data is unavailable, that host paths cannot be read or written, or that AF_INET and Unix sockets are denied. It does not establish a kernel-accepted seccomp policy either: the constructor test only inspects argv and writes `b"policy"`. A deployment-owned test must run an intentionally adversarial staged agent and record all of these denials before the path can be approved.

## Broker-only actions preserve the intended key boundary in code

**Confirmed:** the worker has no broker, grant resolver, receipt writer, or usable in-parent action client. Every proposal frame is run- and nonce-bound, and the host resolves its identity from an attested export before constructing any request, resolving a grant, dispatching, and signing a receipt. This code-level split preserves the control-plane and receipt keys outside the agent process; the missing OS probe means retained-FD/mmap and host-I/O resistance remains unverified rather than established by the in-process compatibility guard.

## Supervisor promises are disconnected from the worker lifecycle

**Confirmed:** `evaluation_mode` accepts `supervisor` but never reads it; `_HostProtocolServer._serve` accepts heartbeats without tracking a deadline; and no `CgroupSupervisor` is instantiated. Protocol failures and explicit `stop()` call the launcher wrapper’s controller kill, but a silent worker has no timeout-driven termination despite the documentation claiming it.

**Likely:** attaching the controller only after `Popen` returns cannot establish that every early descendant belongs to the killable scope, since untrusted code may begin before attachment. The controller contract has no atomic create-scope-and-spawn operation, concrete implementation, or provisioned descendant-kill test. Launch inside an evaluator-owned cgroup/scope before executable code runs, enforce manifest deadlines externally, and prove all descendants die together.

## Staged worker startup lacks an explicit entrypoint channel

The test command starts `evaluation.p0a.agent_worker`, whose `main()` requires `P0_AGENT_ENTRYPOINT`. **Likely:** that command cannot complete because `safe_environment()` replaces the child environment with a fixed dictionary that omits the variable, and no `SandboxSpec` builder or launcher API supplies it. A custom command could set it itself, but this is neither modeled nor validated.

Add a trusted immutable entrypoint field to `SandboxSpec` (or a fixed staged bootstrap) and pass it through a narrow launcher contract. A successful provisioned worker exchange is necessary; current evidence is compatible with a path that fails closed for every real run.

## Terminal evidence is bound, but release coverage is incomplete

`RunPaths` derives receipt and terminal locations from the verified UUID run ID and manifest digest; `RuntimeFailureRecord` binds its signed record to the same pair. A verified launch denial is an impasse in the bound receipt chain, while pre-verification failures use a fresh attempt-scoped signed record. The documentation correctly limits these same-user artifacts to a local harness approximation rather than evaluator custody.

**Confirmed:** `python3 -m pytest -q tests/evaluation` reports 22 failures, including action-routing, startup-rejection, and runtime-failure-record coverage tied to removed APIs. The focused construction group passes (10 tests), but neither it nor the failing broader suite exercises a successful worker lifecycle or real sandbox terminal path. Migrate the tests and add the provisioned probes to demonstrate that run-bound terminal evidence survives the transport change.
