# P3 real-worker launch cannot reach evaluation

P3 adds independent worker and evaluator release ledgers and gates the real Podman probe on a provisioned local image. The release path still cannot execute its worker as configured: the launcher removes Python from the container PATH, while the image entrypoints rely on PATH-based interpreter discovery. Separately, the admission staging permissions make the verified candidate directory unreadable and untraversable by the fixed non-root container identity. **Watch for:** **confirmed** the provisioned release lane will fail before a worker or containment probe can run; **confirmed** a candidate produced by P3 admission cannot be read by the worker under the declared UID. **Verdict**: NEEDS_CHANGES

## High-level view

The new task-release ledgers close the prior unsigned-envelope boundary by independently verifying signature, lock/run binding, expiry, global order, and replay state before either worker or evaluator uses a task. That control only becomes useful after the container starts; the launcher’s `PATH=/agent` conflicts with both image entrypoints’ `#!/usr/bin/env python3` interpreter lookup, so every real invocation exits before emitting a bounded protocol response.

Admission creates a private evaluator-owned stage with a `0700` directory and a `0400` candidate. The Podman policy deliberately runs as `65532:65532`, so that identity cannot traverse `/agent` or read `/agent/candidate.bin` when the admitted stage is mounted; the current real-Podman probe test uses a separately created, permissively readable fixture and never executes the worker against this admission output.

<summary>Details</summary>

## The hardened launcher prevents both P3 image entrypoints from starting

`P3PodmanLauncher.argv` sets the container environment to `PATH=/agent`. The image’s `/runtime/p3_worker` and `/runtime/p3_probe` scripts both use `#!/usr/bin/env python3`; after the kernel invokes `/usr/bin/env`, that program resolves `python3` through the replacement PATH. The mounted `/agent` closure is constrained to the host worker file and `candidate.bin`, so it contains no `python3` executable. The real worker exchange and the adversarial probe therefore exit nonzero and are translated to `P3ExecutionFailure` before any task or containment evidence is produced.

This is **confirmed** by `evaluation/p3/execution.py` and both scripts under `evaluation/p3/container/`. The release-lane test provisions the image digest but does not alter this environment, so setting `P3_RELEASE_LANE=1` makes the otherwise skipped test fail rather than validate containment. Pin the base image’s interpreter location and use that absolute shebang, or set PATH to an explicit, minimal interpreter path in addition to `/agent`; the release test should exercise both `/runtime` entrypoints after that change.

## Admission’s read-only stage is also unreadable to the declared worker identity

`stage_isolated_candidate` creates the stage directory with mode `0700` and writes `candidate.bin` with mode `0400`. The launcher bind-mounts that directory at `/agent` and forces `--user=65532:65532`. A rootless container process with that UID/GID is neither the evaluator-owned directory’s owner nor granted group/other traversal or file-read permission, so it cannot open the candidate that `p3_local_worker.py` reads. The failure occurs even if the interpreter launch issue is fixed.

This is **confirmed** by `evaluation/p3/admission.py`, `evaluation/p3/execution.py`, and `evaluation/p3/container/p3_local_worker.py`. `test_p3_readiness.py` asserts the restrictive admission modes, while `test_p3_podman_integration.py` creates an unrelated default-mode `agent` directory and only runs the probe; `test_p3_execution.py` substitutes `FakeLauncher`. Preserve evaluator ownership and read-only mounting, but provide execute traversal on the mounted directory and read access to this one immutable candidate for the container UID, or use an appropriate rootless UID mapping. Add a non-mocked worker exchange using the actual `stage_isolated_candidate` output to prevent the permission contract from drifting.
