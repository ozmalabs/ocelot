# Confidential Space evaluator hardening for attested, run-scoped execution

This change adds a locked Confidential Space bootstrap, exact WIP/claim policy checks, federated-only GCS/KMS construction, run-scoped object capabilities, signed timing/evaluator artifacts, and receipt-backed terminal seals. The service binds tasks and results to immutable digests and short-lived server timestamps, while intentionally reporting a non-release impasse when native closure evidence is unavailable. The targeted suite passes, but its fixtures do not exercise the production scoped-store paths or a successful environment parse. **Watch for:** **confirmed** over-escaped provider and run-artifact regexes prevent valid activation and production receipt/timing/evidence writes; **confirmed** nested authority and claim-path configuration remains mutable after parsing; **confirmed** independent timing records are not pinned to a configured independent key and legacy timing signatures are not verified.

**Verdict**: NEEDS_CHANGES

## High-level view

The bootstrap has the right fail-closed topology: policy is parsed before attestation, the metadata endpoint is pinned, STS receives the exact WIP provider, and cloud clients are built only after verification. **Confirmed:** the implementation currently cannot realize that path for the documented provider form because its provider regex is over-escaped.

Run capabilities are intended to isolate state, receipts, timing, evidence, seals, observations, and idempotency objects below one derived run prefix. **Confirmed:** the capability boundary is conceptually narrow, but the production regexes reject every non-state artifact, so a run cannot persist its normal lifecycle records.

Timing records carry task/result payload digests and sequence values. **Confirmed:** the service does not pass an expected independent authority or key to validation, and the default record source is a process-local V1 signer marked diagnostic-only with a process-wide sequence counter despite per-run state validation.

<summary>Details</summary>

### Provider and run-artifact path contracts

**Confirmed:** `LockedBootstrapConfig.from_env` uses a raw regex whose source contains `\\.` for the dots in `iam.googleapis.com` (`services/p5_r0_evaluator/confidential_space.py`, `from_env`). That pattern requires a backslash before the separator rather than matching the documented canonical provider, so a valid `P5R0_ATTESTATION_AUDIENCE`/`P5R0_WIP_PROVIDER` pair is rejected before attestation. The same doubled escape appears in every non-state suffix pattern in `RunScopedObjectStore._safe` (`confidential_space.py`): `receipts/000001.json`, timing, evidence, compute-class observation, and idempotency names all fail, while `state.json` is the only lifecycle object accepted. In the federated production path this causes run start to fail when `_append_receipt` creates the preregistration receipt; the local tests miss it because `MemoryStore` has no `bind_run` and bypasses the child capability.

### Mutable authority and claim policy after bootstrap

**Confirmed:** `LockedBootstrapConfig` is a frozen dataclass, but `from_env` stores the mutable `authority` dict, its nested `transport_attestation` dict, and the mutable `claim_paths` dict directly (`confidential_space.py`, `LockedBootstrapConfig`). A caller retaining or obtaining the config can alter claim paths after validation, changing which verified token fields `AttestationGate.verify_startup` reads, or alter authority metadata later consumed by `CapabilityFactory`. The `policy_digest` also reads the live claim mapping, so it does not provide an immutable commitment. The contract needs immutable nested structures (or defensive deep copies plus no exposed mutable references), with mutation attempts covered by a boundary test.

### Independent timing signatures and authority binding

**Confirmed:** `validate_attestation` verifies the Ed25519 signature only for V2, and its `expected_authority_id`, `expected_key_id`, and `expected_public_key_digest` parameters are optional (`services/p5_r0_evaluator/timing.py`, `validate_attestation`). `_record_timing` calls it without any of those expectations (`service.py`, `_record_timing`), so a V2 attestor can return a validly self-signed record under any key and still be accepted. V1 is explicitly retained as diagnostic compatibility, but its `signature` is only checked for non-empty text; the default `SignedTimingAttestor` therefore produces records that are not independently authenticated. Store an immutable independent-ledger authority/key commitment in the bootstrap policy, pass all three expectations on every V2 validation, and make certification impossible for V1 or unverifiable signatures.

### Per-run versus process-wide timing sequence

**Confirmed:** `EvaluatorService` initializes each run with `timing_sequence: 0` and requires every returned record to equal the run-local previous value plus one (`service.py`, `_record_timing`). `SignedTimingAttestor` instead increments a single `self.sequence` shared by all runs (`confidential_space.py`, `SignedTimingAttestor.record`). After one run has emitted timing events, the first event of a second run receives a sequence greater than one and is rejected; an independent global ledger has the analogous problem because the new run requires `previous_digest is None` while the ledger may return the prior run's digest. Choose either per-run attestors/chains or a globally persisted ledger cursor and encode that scope in the state and validation contract.

### Boundary coverage for production capabilities

**Confirmed:** the tests do not mutate a parsed nested config, parse a valid `P5R0PublicAuthorityV4` environment, or create each allowed production artifact path through `RunScopedObjectStore`; the passing suite therefore cannot detect the regex failures or the mutable-policy gap.
