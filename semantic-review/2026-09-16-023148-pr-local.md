# Bounded local P3-R0 worker/evaluator release path

P3-R0 now gives both the worker and evaluator independent, evaluator-keyed release ledgers, so a task must carry a valid signature, lock/run binding, canonical task digest, expiry, fixed budget, and exact global sequence before either side consumes it. The hardened execution path verifies that the worker image equals the `native_worker` digest in the signed P3 lock before running the retained five-route containment probe under rootless, no-network, read-only Podman with pulls disabled. Pair evidence is evaluator-signed and bound to the exact task, candidate, and snapshots; failures after a task release produce receipt-chain-signed terminal task evidence before rollback is attempted. The R0 path remains local and cannot adopt: successful local accounting is sealed as `no_go` and rolled back, while a failed restore becomes a signed impasse rather than a successful denial. Watch for: **confirmed** this is bounded local P3-R0 evidence only; an external trusted release still needs independent evaluator/key custody, provisioned lock artifacts, and a release-lane execution of the real Podman probe. **Verdict**: APPROVED

## High-level view

The task authority is separated from both consumers: a release is canonicalized and signed by the evaluator, then each side advances its own one-time, globally ordered ledger. Tampering, expiry, replay, or order changes stop before worker execution or evaluator scoring.

Containment is an admission gate. The runner checks the staged closure and lock-pinned worker image, runs the hostile-route probe through the hardened Podman launcher, and retains its result before task one; absolute interpreter entrypoints and an immutable, container-readable candidate remove the prior live-lane startup and access failures.

The evidence chain keeps the exact task identity through scoring. Evaluator-signed pair records retain task digests and sequences, while an in-flight failure records terminal envelope evidence in the evaluator-signed receipt chain before the runner restores the pre-snapshot.

Local success has no adoption authority. Even a sealed E1 result has `custody_ok=False`, is recorded as `no_go`, and invokes rollback; unavailable or failed rollback is made visible as a terminal impasse rather than being reclassified as a routine rejection.

## Evaluator-signed envelopes bind both consumers to one task order

`P3TaskEnvelopeV1` commits the evaluator release to the P3 lock, run ID, distribution/pair, sequence and ordinal, nonce, expiration, fixed threshold budget, and canonical task digest. `TaskReleaseLedger` is instantiated independently by the worker and evaluator clients, each requiring the next exact sequence and refusing a previously consumed digest. The worker consumes the envelope before it writes the one-file `/input/next-task.json` closure or launches the container; the evaluator repeats the validation before it invokes the evaluator executable. Focused tests cover forged content, expiry, out-of-order release, and reuse.

## Lock-bound Podman containment is retained before task one

The runner resolves the staged evaluator artifact from the finite staging index, compares `worker.spec.image_digest` to the signed lock’s `native_worker` artifact, verifies evaluator receipt authority, and only then runs the probe. The launcher requires a cached digest-pinned image in a rootless engine and runs it with `--pull=never`, `--network=none`, read-only root, dropped capabilities, no-new-privileges, seccomp, the fixed non-root UID, and read-only agent/input mounts. The probe must show all five hostile routes blocked and both mounted trees unchanged before the runner appends containment evidence.

The provisioned worker and probe use `/usr/local/bin/python3`, avoiding dependence on the launcher’s minimal `PATH=/agent`; admission exposes only an immutable candidate (`0555` directory, `0444` file). The gated integration test invokes an actual rootless Podman probe against a locally supplied cached image and fails rather than skips when `P3_RELEASE_LANE=1`; this review run did not have those release inputs, so it was the single skipped test. **confirmed** external trusted-release validation must provision the signed lock’s exact OCI artifact and execute that lane under the release authority; local source and test gating do not establish independent custody.

## Pair and terminal receipts preserve the in-flight task identity

`P3PairEvidenceV1` carries the envelope task digest, pair ID, sequence, candidate and pre/post snapshot digests, bounded four-arm resources and scores, then signs the canonical evidence digest with the evaluator key. The runner appends that validated evidence before score accounting, and pair-execution validation repeats the task-digest/sequence match against the released envelope.

Once an envelope has been released, any exception produces `P3EnvelopeTerminalEvidenceV1` with that envelope’s digest and sequence. It is included in a `terminal` receipt whose chain hash is evaluator-signed and structurally revalidated on reload, before rollback is attempted.

## Local accounting is deliberately unable to adopt

The local E1 runner passes `custody_ok=False` to the adoption decision, writes a `no_go` result describing local-test custody, and calls `reject_and_rollback` after sealed accounting. Preflight failures deny before staging; a normal failure restores and byte-verifies the pre-snapshot.

If restoration or its verification fails, the runner calls `terminal_rollback_impasse`. The receipt records the expected snapshot digest, safely observed candidate digest if available, failure class, and a canonical evidence digest; it does not retry, report a completed no-go, or permit adoption. **confirmed** trusted release additionally requires independently operated receipt, rollback, and evaluator authorities rather than this same-environment signer and filesystem.
