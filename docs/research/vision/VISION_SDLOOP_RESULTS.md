## WHAT THIS IS — and, more importantly, WHAT IT IS NOT

**It is real:** the substrate's own general cognition loop, with **no vision-specific
machinery and no learning rule at all** (no Oja, no BCM, no Butts, no GCAL), ingests a
retina's ON/OFF support and grows a codebook that folds an orientation family. Nothing in
the sd loop knows what vision is. **That much is the genuinely novel result this arc was
looking for.**

**It is NOT "orientation emerged as a dimension", and the same data proves it:**

- **The held group has order 4, so orbits are at most 4 ⇒ mints → N/4.** A **bounded
  constant-factor fold**, not a dimensional collapse. A *true* orientation dimension gives
  **O(1)** mints at every N; this gives **10 at N=36** and grows without limit.
- **`sd_infer_dimension` NEVER minted a new generator.** Every `LatentDimension` is
  `latent:<held generator>` — `rotation90`, `reflection_r`, `reflection_c`, and the length-2
  composite. The ladder's *"the dimension set itself is dynamic — quanta OF dimensions"* is
  realised here as **"name which HELD generator applied"**, not as "discover one you did not
  hold". **The 15° step itself was never learned.**
- **N=9 is the proof, and it cuts both ways.** The loop cannot rotate by 20°, so it fell back
  to reflections alone and minted 5 of 9. It did not *approximate* the missing generator; it
  simply did without it.

**So the paradigm answer is two-sided and neither half is rhetorical:** the core loop **does**
produce visual structure from decorrelated retinal output with no vision machinery — and the
structure it produces is **exactly the orbit decomposition of the generators it was seeded
with, and nothing more.** It composes what it holds; it does not discover what it lacks.

## THE ENGINE DEFECT THIS RUNG FOUND — it nearly produced a FALSE NEGATIVE

**`StringConcat` evaluates to `Value::Surface(Text)`** — `term.rs` says so in its own words
(*"evaluate() can't intern new Syms, the same reason StringConcat returns Surface rather than
Str"*). **`load_parts` (`shape_decode.rs:189`) reads the codebook name as**

```rust
let Value::Str(name_sym) = &nv else { continue };
```

**with no Surface arm.** So **a `ShapeSignature` whose `name` a RULE built by concatenation is
silently dropped from the codebook** — no error, no warning; the part simply does not exist,
and every later observation re-mints against a codebook that never grew.

**It bit immediately and it looked exactly like a result:** all four LATTICE orientations
minted. Reported as-is, that would have been *"the core loop cannot fold orientation even at
90°"* — **a paradigm NEGATIVE that was a harness artifact.** What caught it was **not** a gate:
it was that **0° and 180° are the same bar** and yet minted twice — an identity the physics
guaranteed, so the number had to be wrong.

- **Blast radius:** any rule-driven codebook growth. This is plausibly **why `grow_part_library`
  is a Python builder** — a rule *cannot* name a codebook entry it grows. An open-ended
  graph-native growth loop hits this the moment it tries.
- **The engine already knows this bug class:** `graph_rules.rs::as_str` accepts **both** Str and
  Surface, added because *"a Rule node whose id attr was set from a dynamically-concatenated
  string would silently read back as `<unnamed>`"*. `load_parts` / `load_generators` were never
  given that arm.
- **Workaround used here (no Rust):** name the part `IndexAt(obs.key, 0)` — an **already-interned
  `Value::Str`** — so the name is still read off the graph and never supplied by Python.
- **Not fixed here, deliberately:** the one-line fix is cross-cutting (37 seeds use
  `StringConcat`), and an FFI-perf agent owns adjacent Rust (§11.4 — own your files). **Pinned
  by a gate instead** (`test_shapesignature_named_by_StringConcat_is_SILENTLY_dropped_...`), which
  fires the day it is fixed. **Recommended for the supervisor to sequence.**
