# Live held-topic evidence v1.3 amendment (2026-09-26)

V1.2 confirms two `ground_topic` calls on each controlled unknown-topic turn, but its patched grounder records only phrase and arguments. Source inspection shows multiple `_answer_topic_reply` call sites; counts alone cannot identify the caller or establish whether graph evidence changed between calls. V1.3 keeps the v1 evidence, route, answer, and work panel fixed and adds bounded Python call-stack frames plus same-topic answer Goal, SearchRequest/GroundRequest, and total graph-size snapshots immediately before every controlled no-result grounder call. This is diagnostic instrumentation only; it does not alter dispatch or retry behavior.

The probe uses the same full-seed boot, source-closure hashing, and three fresh-process replication as v1.2. The additional output is descriptive: stack frames identify the Python caller, while unchanged snapshots support (but do not by themselves prove) that no relevant graph evidence arrived between attempts. Successful, unresolved, release, unknown no-leak, route-repeat, and work measurements retain their v1.2 checks. Active Goal status is not mutated by this probe: `outcome` is the explicit topic-answer result consumed by gap-awareness rules, and whether Goal status should separately terminalize is a contract question outside this capture.
