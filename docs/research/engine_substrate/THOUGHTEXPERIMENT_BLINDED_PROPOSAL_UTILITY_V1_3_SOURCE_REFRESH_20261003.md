# Source refresh amendment: blinded proposal utility v1.3

Date: 2026-10-03

The v1.2 four-family study remains valid as a historical capture, but a current
source audit finds hash drift in `domains/edit_ops.py`,
`domains/reflective_faculty.py`, the loaded native binary, seven Rust engine
files, and `seeds/shape_decode_loop.json`. The current build passes
`build_is_stale` with no stale components. Because those changes can affect
proposal enumeration, graph selection, branch semantics, or inference, v1.2 is
not treated as source-current evidence for the current checkout.

V1.3 repeats the same four independently authored families (shape-axis,
recurrence, navigation, and control-kind), four worker seeds, five ordering
policies, complete candidate-level held-out scoring, receipt verification, and
primary-state checks. It freezes orders before opening held-out outcomes. The
new source lock binds the current runner, analyzer, four task builders, common
adapter, rank policy, task protocol/amendment history, all declared engine and
seed inputs, semantic engine fingerprint, and loaded native binary. The old
v1.2 captures are preserved and not overwritten.

No task or candidate set is expanded in this refresh. The question is whether
previously measured bounded proposal ranking and transfer outcomes reproduce
on the current source, not whether the domain has become broader. In
particular, the four task families and four workers do not establish natural
prevalence or open-ended candidate invention. Any changes in candidate lists,
selection, held-out utility, refusal, or cost are capability outcomes to report,
not grounds to alter the protocol after order freeze.
