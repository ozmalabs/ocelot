# Cognition signature contract v1

This is a typed, versioned descriptor over existing representations. It does not replace `QualiaDimension`, rewrite lexical qualia, or treat similarity as verification.

## Descriptor

Each descriptor records `schema_version=1`, a stable `signature_key`, `owner_id`, `source_id`, `source_kind`, `source_epoch`, optional `frame_id`, `evidence_status`, `dimension_ids`, and an ordered `coordinates` list. A coordinate has `dimension_id`, `value_kind`, `value`, `is_missing`, and `grain`. `value_kind` is one of `finite_number`, `integer`, `token`, `ordinal_rank`, or `sequence_ref`. `is_missing=true` is distinct from numeric zero and carries a null value. A descriptor retains a reference to the full source value; projection never destroys the source.

Dimension identities are namespaced (`qualia:<QualiaDimension.name>`, `numeric:shape_rank:<order>:<position>`, `temporal:frame:<index>`, `temporal:time`, and `observer:<frame-dimension>`). Comparisons require the same schema version, owner scope, frame semantics, dimension identities, value kinds and compatible grains. Missing coordinates are not imputed. Incompatible descriptors cannot match.

The source epoch is the owning representation's revision, not wall time. A projection stores the observed source epoch; a consumer discards or rebuilds a view when that epoch changes. `evidence_status` distinguishes `observed`, `verified`, `inferred`, `imagined`, and `asserted`. Only an exact downstream verifier can promote a candidate; a recalled or inferred signature never grounds itself.

## Numeric Shape signature compatibility

The legacy oracle is `number_runner.aperture_signature(coord, k, substrate)`. `coord` is a finite ordered numeric vector of length at most 64; `k` is an integer in `[0, len(coord)]`. The signature is the k-th forward finite difference, ranked by `memory::shape_signature`, then padded with integer zeroes or truncated to exactly eight values. Each rank is the count of other entries strictly below it, so ties share a rank. For a one-element input, the existing Rust contract casts the value to integer. For `k == len(coord)`, or an empty difference result, the signature is eight zeroes. Negative orders, non-finite values, non-numeric values and vectors over the bound are invalid and yield no Shape candidate. The full original coordinate, order, and oracle/source provenance remain attached for audit.

The graph path must match this oracle byte-for-byte for supported finite vectors and orders. Signature collisions are expected and do not establish a reading. A `Shape` is scoped by owner, frame, order and schema version; matching candidates are ranked by distance, but equal best distances remain ambiguous. Ambiguity leaves the reading unresolved until the existing exact verifier distinguishes a candidate.

Verified outcomes are keyed by stable `outcome_id`. Replaying the same outcome is idempotent. Positive evidence may ground the exact verified reading; negative evidence updates only shape valence and cannot ground, replace, or create a positive reading. Conflicting outcome records are retained separately and do not overwrite one another.

## Qualia adapters

Existing qualia coordinates map reversibly to descriptors: dynamical field steps retain their declared dimension and grain; lexical role coordinates retain the role dimension and token; open attr/relational/phenomenal coordinates retain their source family and token or integer kind; verified `QualiaShape.valence` is a `qualia:valence` finite-number coordinate with explicit source and evidence status. Its source epoch advances with the source Shape's evidence-record count, so a new verified outcome refreshes and invalidates the prior valence projection. No cross-family coercion is permitted. The standing/live overlay is marked separately from crystallized dimensions.

Verified numeric `QualiaShape` records are adapted as one exact `sequence_ref` coordinate whose dimension is `numeric:shape_rank:<order>` and whose value is the complete fixed-width rank vector. This preserves the vector as a unit and scopes its source by owner, frame and epoch. It is not numerically compared against ordinary Observation coordinates; their schemas and dimensions must match before recall can compare them.

## Temporal envelope

A `SequenceObservation` owns an ordered set of real `FrameObservation` references. Each frame records `frame_id`, `owner_id`, monotone sequence index, finite timestamp, source event id, source epoch and measured signature. Repeated source event ids are deduplicated within the owner/window; a duplicate does not create another funded inference request. Windows have stable `(owner_id, window_id, first_event_id, last_event_id)` identity and bounded frame count. Out-of-order or non-regular timestamps are retained as unsupported evidence and cannot enter the regular `motion_seq` bridge. Missing frames are never synthesized. Predictions remain `inferred` and distinct from observed frames.

The graph event schema uses `TemporalFrameEvent{owner_id,window_id,source_epoch,event_id,sequence_index,timestamp,frame,dim_types,status=observed}` and a `TemporalFrameWindowSeal{owner_id,window_id,source_epoch,expected_frame_count,dim_types,status=closed}` linked to its unexplained source Observation. The engine sorts events by sequence index, requires contiguous unique indices and the sealed count, checks all event dimensions against the seal, derives the sampler period from the first two ordered measurements and checks every timestamp against that period within the policy's explicit `timestamp_tolerance` (default zero). It retains ordered event ids, timestamps and frames in a graph-linked `TemporalSequenceWindow`. Identity is owner/window/source-epoch scoped; duplicate seals do not mint another window. Short, oversized, incomplete or irregular streams are refused. Only windows with at least three and at most 64 measured frames can request the shared `ThinkingBudget`; one request is keyed by owner/window/event endpoints/source epoch, and a separate `motion_seq` Observation is created only after same-epoch debit approval. TimeInfer terminal paths restore the prior flag. This assembler handles explicit sealed event windows; upstream producers still must provide observations, measured frame events and their close seals.

## Recall record contract

Nearest recall is a pure candidate query over individual records, not ShapeIndex clusters. Each stored record has stable `record_key`, owner, frame, schema, source epoch, signature descriptor, liveness/tombstone state and provenance. Queries declare the same scope fields, `k`, and a dimension-aware tolerance. A query never mutates graph or durable state. It returns at most `k` `{record_key, distance, source_epoch}` candidates ordered by `(distance, record_key)`; ties are deterministic but remain candidates, not truth. `k=0` returns an empty list. Invalid or incompatible queries return a typed error/empty result and never widen scope.

For contract v1, equality of schema version, owner, source, frame, source epoch, coordinate dimension IDs and value kinds is required before scoring. Missing coordinates must be missing on both sides and contribute zero; a missing/present mismatch rejects the candidate. Finite numeric, integer and ordinal-rank coordinates contribute absolute difference in their declared units, and each must be within its query-declared nonnegative tolerance. Token and sequence-reference coordinates require exact equality and contribute zero; they are never coerced to numbers. Total distance is the sum of compatible numeric differences represented in fixed-point micro-units (1,000,000 units per declared distance unit). At least one present coordinate is required. A mismatch or malformed/non-finite coordinate rejects that candidate. `candidate_cap` bounds descriptor examinations before filtering; a truncated scan is reported as incomplete and cannot claim exhaustive-nearest results. Until a persistent per-record index and tombstone recovery are implemented, the engine implementation must be described as bounded exhaustive scan, not indexed recall.

Updates and deletions tombstone the prior key before a replacement is queryable. Stale source epochs are excluded. Recovery rebuilds the record index from live records; checkpoint round trips preserve keys, tombstones and tie order. Query work is bounded by the explicit candidate cap and indexed dimensions. The evaluation must compare against an exhaustive reference scan and report index construction, exact candidate checks and query work separately.

The graph adapter starts from `Agent --observed--> Observation --has_signature_source--> CognitionSignatureSource` with `evidence_status=observed`. It projects a typed query keyed by the source signature and observation key, then runs before the P3 extended-thinking rules. A recalled candidate can settle the observation only when the scan is complete, exactly one candidate has zero distance, the current descriptor exactly matches the typed coordinates, and the observation links a `CognitionSignatureVerificationReceipt` for the same record, observation and source epoch. This seed consumes verifier receipts; it does not mint them. A missing or stale receipt, tie, nonzero nearest candidate or incomplete scan emits a `SimilarityRecallFallback`; the existing funded P3 executor then proceeds.
