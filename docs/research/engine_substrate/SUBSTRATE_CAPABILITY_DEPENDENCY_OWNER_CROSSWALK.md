## Dependency order and decision points

1. Complete P0/A provenance and workload selection before new confirmatory claims.
2. Close engine effect accounting and native access fidelity before using closure/scheduler work as a structural-locality oracle.
3. Run structural census and bounded algorithm envelopes before extrapolating CPU costs.
4. Keep held-structure application separate from P3 induction/memory acquisition and from P4 action/transfer.
5. Treat P4 action-bearing work as blocked on P0/P1/P2 prerequisites in the general-agency plan; no engine benchmark result waives those controls.
6. Release only after a frozen confirmatory set covers both positive results and known failures.

These are programme dependencies, not claims that every subsystem has the same technical owner. The substrate plan remains the metric/evidence authority; the tractability assessment remains the claim-boundary authority; the general-agency plan remains the action, custody, and release authority.
