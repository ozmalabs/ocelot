# External resource invalidation probe v1 — results

Three fresh processes reproduce all nine preregistered integrity and behavior gates. Each starts with a false callback result from an external temporary file. Phase A evaluates once, makes no progress, and leaves `accepted` absent. In Phase B, the file changes from `0` to `1` with no graph mutation: the engine invokes the callback zero times, reports zero progress, and leaves the target unaccepted. Thus a resource-only change does not wake an already evaluated predicate in this fixture.

Phase C changes the file back to `0` and adds a second matching graph edge. The engine invokes the callback twice (once for each match), and both results reflect the current file value; neither target is accepted. The rule declares `reads_any=true`, so graph changes can wake it, but the engine has no event for the external file change. There is no automatic external-state invalidation path in this measured route.

This isolates invalidation behavior more directly than the earlier stateful callback probe: the callback reads an actual mutable file on every invocation, and phase values and hashes are captured. It remains one synthetic `UseTool` predicate shape. It does not establish how every external Term behaves, how to retract prior effects, or how often this condition occurs in production. The result supports versioned external dependencies or an explicit refresh event before relying on external predicates for stable closure.
