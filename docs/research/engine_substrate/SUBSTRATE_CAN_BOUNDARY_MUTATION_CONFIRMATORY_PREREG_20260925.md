# CAN boundary mutation confirmation protocol — v2

**Status:** preregistered before execution; synthetic mechanism confirmation only. The protocol deliberately tests fixture variation beyond diagnostic v1.1. It is not a test of learned frame discovery, native effect-to-frame notification, minting, natural-task frame locality, or speedup.

## Question

On independently seeded sparse CAN path fixtures, does caller-notified frame settlement preserve the terminal graph projection and local-rule fixed point that full frame rescanning produces after boundary mutations?

## Fixed design

- Rule: only `can_native_update_3state` from `seeds/can_native_reimplementation.json`.
- Frames: contiguous groups of four concepts; one `Microtheory` per initial frame.
- Sizes: N=8, 16, 32.
- Independent fixture seeds: 20260925, 8675309, 104729. Each seed is reused across sizes and mutation arms; non-target fields and non-target path weights are generated by Python's `random.Random(seed + 1009*N)`.
- Path weights: target boundary (3,4) has weight +0.75 except in the insertion arm, where it is absent; other path edges receive independently sampled signed weights from {0.15, 0.25, 0.35}. The reverse directed edge is also installed.
- Target fields: insertion/edge/field/birth arms use external_field(c3)=1.0 and external_field(c4)=-0.1; deletion uses 0 and 1 respectively to make the surviving c3 dependent on c4. c0 starts at field zero so external/identity field controls change its input.
- Mutations: the same eight v1.1 arms—boundary edge insertion, deletion, replacement, external-field write, identity-field write, node birth, boundary-adjacent node deletion, and mixed weight-plus-field write. Each case is run once for each seed and size (72 paired cases).
- Negative controls: omit all caller notifications for insertion, birth, and deletion at N=8 for each seed (9 controls).
- Cap: 100,000 progress applications per arm.
- References: paired full round-robin scoped settlement and a separately coded local-equation residual check over saved final fields, active mask, state, and directed weights.

## Acceptance criteria

Every initial paired graph must settle to identical states. Every mutation must change state or active-node projection. All 72 event/reference pairs must settle under cap, have identical active-node/state projections, and have zero independently recomputed residual. All nine omitted-notification controls must disagree with the reference and have positive independently recomputed residual. Any failed or non-settling cell fails the confirmatory gate; do not edit fixtures after seeing outcomes. Progress counts, frame turns, and rounds are descriptive only; no cost advantage is claimed.

## Provenance and scope

Before execution, hash this protocol, runner, imported v1.1 mechanism implementation, seed manifest, relevant Rust files, and loaded native extension into a lock. Preserve the complete raw output, including failed cells. The test uses a caller-supplied notification set and the synthetic path family; it does not test automatic notification production, runtime-derived partitions, authored task topologies, a general frame hierarchy, multiple births/deletions, or AddNode idempotence. Those require separate gates. In particular, duplicate-mint/idempotence belongs on the full CAN closure rules that contain `can_native_note_coactivation`, not in this SetAttr-only update-rule matrix.
