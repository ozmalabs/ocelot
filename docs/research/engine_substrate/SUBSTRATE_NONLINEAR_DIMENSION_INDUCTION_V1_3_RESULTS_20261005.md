# Nonlinear dimension induction v1.3: coupled quadratic result

## Result

A source/native-locked 40-cell run tested ten replicates each of an enabled inducer and a frozen control on a coupled quadratic map, with a linear positive control. The new relation was `T(x,y) = (x + xy, y + x²)`. All 13 independent admission gates passed, including the exact linear control and a preflight showing that the registered coupled-quadratic schedules do not fit the existing bounded 2×2 integer-linear matrix class.

The enabled linear control acquired the expected matrix, was recognized on both stages, and made the exact independent transfer prediction in 10/10 runs. In the coupled-quadratic enabled arm, none of the ten runs acquired a new linear generator, none made an exact transfer prediction, and production decode recognized neither training nor transfer observations (0/10 each). Each training and transfer observation reported `minted` and added one `CapabilityAxis`; the `DimensionGenerator` count stayed at five before and after. Thus `minted` here is the generic novelty fallback, not successful operator induction. The frozen control also had no valid nonlinear transfer. This finds no evidence that the current bounded production induction path learns this relation, while confirming that the protocol detects the existing linear capability.

Mean reported training/transfer closure time was 12.603/1,909.989 ms for enabled coupled-quadratic runs and 0.511/0.420 ms for frozen runs. Enabled linear-control means were 71.393/0.767 ms. Source-derived counting shows why transfer search grows: `GenInfer` tests `(2B+1)^4−1` integer matrices per eligible base. From the two typed bases supplied by this harness alone, the coupled-quadratic training and transfer fixtures require at least 4,800 and 781,248 matrix attempts per `GenInfer` evaluation, respectively, a 162.76× increase. This is a lower bound; any other eligible unscoped codebook shapes add work. The capture does not expose the exact number of `GenInfer` evaluations per closure, so these counts explain candidate-space growth but do not attribute all measured latency. See the reproducible [search-cost analysis](../../../evaluation/reports/substrate_nonlinear_dimension_induction_search_cost_v1_20261005.json) and its [analyzer](../../../scripts/analyze_substrate_nonlinear_dimension_induction_search_cost_v1.py). These are one process/build timings, not a hardware scaling estimate.

## Interpretation and limits

This is a third independently designed nonlinear family after the prior quadratic and piecewise-shear studies. Together with the positive control, it strengthens the conclusion that successful bounded linear induction does not currently extend to these tested nonlinear families. It does not rule out nonlinear learning under caller-supplied executable-Term grammars, nor does it establish a general negative result for all nonlinear tasks. The earlier executable-Term result depends on supplying the necessary operators and is a separate mechanism.

The analysis report is `evaluation/reports/substrate_nonlinear_dimension_induction_v1_3_analysis_20261005.json`; raw capture is `evaluation/reports/substrate_nonlinear_dimension_induction_v1_3_20261005.json`; preregistration and lock are linked from the protocol and lock artifacts below. Natural-task frequency, open-ended hypothesis induction, and overall learning cost remain unmeasured.

## Next experiment

Before expanding the task family again, instrument this fixed source-locked case: record actual `GenInfer` invocation count, candidate count per eligible base, candidate rejection stage, elapsed time by stage, budget exhaustion, and whether the terminal `minted` event added a quantum or a generator. Then compare a preregistered richer bounded grammar against the current path, with matched linear and nonlinear controls, frozen arms, held-out transfer, and a hard compute budget. Keep supplied-grammar executable-Term performance separate from automatic grammar selection and production `DimensionGenerator` adoption.
