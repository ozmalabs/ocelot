# Live held-topic same-turn local-miss reuse v1.5 amendment (2026-09-26)

V1.4 shows that a completed inline local-only miss is followed by a second identical local lookup while fulfilling the same graph-authored GroundRequest. V1.5 changes that narrow path: `_answer_topic_reply` records `local_grounding_outcome=miss` and the inbound turn id on the exact matching requested GroundRequest after a completed local-only miss. `scan_and_sync_ground` consumes that marker only when the request is still local-only (`allow_web=False`) and the marker's turn id equals the active inbound message; it marks the GroundRequest failed with the same `no answer` error without calling `ground_topic` again. The separate SearchRequest is left for `scan_and_search`.

The gating runner holds the semantic panel and injected local-hit control fixed. It requires one unknown-topic grounder call instead of two, unchanged unresolved/no-leak output and Goal outcome, a failed GroundRequest with the exact source turn marker, a failed SearchRequest, and unchanged success/release/supersession behavior for the injected local hit and all held-answer forms. This is an optimization experiment on the controlled miss path, not a broad source-retrieval or tractability result. Raw workers are written after every completed process before analysis.
