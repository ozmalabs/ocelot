# Thoughtexperiment attribute-site active query v1 — results

**Gate result: pass for prompted ordered-site composition on a second fresh rule shape.** Four source/native-locked workers selected the newly authored `classify_meter_delta` target, chose `swap_term_leaf`, and selected `bad_score -> good_score`. Each generated variant matched the independent generic candidate enumerator semantically and preserved the primary target. Across both backends and four alias rates, all 32 query selections had one bit of disagreement; after the oracle was released, only the proposal survived. It passed all four positive/negative/neutral held-outs in every worker, while the unmodified rule failed all nonzero cases. The analyzer passes 13/13 checks. CoW/full-copy predictions, query orders, random probes, held-out outputs, receipts, and fixed points agree exactly.

Shared-page snapshot CoW branch creation averaged 14.6 µs versus 28.5 µs for full copy (1.95× lower fork time on this tiny graph). Mean end-to-end query time was 70.53 ms for CoW and 69.46 ms for full copy across 200 isolated predictions. Candidate patching averaged 211 µs versus 196 µs per prediction, which outweighed the local fork saving in this capture; no end-to-end speed advantage is established. These four-worker measurements describe this small constructed workload only.

This is a second fresh symbolic target and a different generic edit primitive after the `flip_comparison` threshold-rule gate. The site cue explicitly includes `bad_score to good_score`; it supplies the desired orientation, so the result measures graph target/operator/site selection with an answer-bearing cue. Python still authors the rule, fault, cue, pool, and oracle, and materializes the selected rewrite. It does not show autonomous fault diagnosis, broad edit-site discovery, or open-ended learning. Next vary the cue without naming the site, add independent operators/rule shapes and at least one recurrence-family challenge, and measure prediction costs as graph size grows.
