# Preregistration: episodic checkpoint restart and corruption recovery

**Question.** Does the `WorldAdapter.save/load` checkpoint preserve graph-authored episodic retrieval across a real process restart, and how does the loader/retrieval path behave when a syntactically valid checkpoint has a missing episode link or altered event content?

**Exploratory source inspection disclosed.** Before registration, a disposable one-event checkpoint was inspected to learn the serialized graph shape (`nodes`, `edges`, `next_id`) and confirm Episode nodes and their relations are graph data. It was not queried after restart and is not scored. Source inspection shows save/load serializes the graph, grammar, and rule store; no checkpoint checksum/authentication field is apparent. The evaluation therefore includes corruption cases rather than assuming integrity.

**Frozen fixture.** A writer process creates six observed EpisodicEvent nodes with distinct exact cue keys and summaries, links each to its MemoryContext and MemorySchema, runs closure to bind Episodes, and saves a WorldAdapter checkpoint. Fresh reader processes evaluate four checkpoint variants: intact; one event's `state_summary` changed to a fixed corruption marker; one Episode's root `recorded_episode` edge removed; and syntactically malformed JSON. The first three are loaded in separate reader processes and queried for all six keys. The malformed case records whether loading succeeds or returns an exception; it is never used as a substrate graph.

**Scoring.** Intact checkpoint: all six keys must reconstruct the original summaries with recalled provenance, `not_observed` status, and one candidate each; Episode-to-event/context/schema links and rule availability must be present after reload. Altered-summary checkpoint: record whether changed content is returned as recalled without an integrity warning; count corrupted and unaffected items separately. Missing-link checkpoint: the affected cue should produce explicit `insufficient_information`; unaffected cues should retrieve exactly. Malformed JSON: process must report load failure rather than silently claiming recovery. Record PIDs, checkpoint size, save/load times, query tick times, graph counts, exception type, and peak RSS.

**Claim boundary.** This tests this adapter's graph checkpoint path and selected single-field/link corruption cases over six tiny hand-authored episodes. It is not a durable-memory-store audit, crash-consistency test, adversarial tampering security claim, large-checkpoint scaling study, or natural-task memory evaluation. A successful graph checkpoint round-trip must not be conflated with long-term `MemoryFaculty` record persistence.
