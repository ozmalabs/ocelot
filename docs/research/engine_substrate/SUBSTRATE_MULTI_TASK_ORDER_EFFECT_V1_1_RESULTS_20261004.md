# Multi-task order-effect v1.1 results

After repairing the graph-resident composer seed's missing Goal-to-Message
`comprehends` edge, ten fresh workers replayed five cyclic task orders, with
two workers per order. The source lock binds the runner, analyzer, protocol,
base runtime closure, and eight direct scene/language dependencies including
the changed seed. Independent checks pass for all 50 prompts, all ten PIDs,
source stability, graph-derived Goal/event projections, and exact outcome and
normalized-structure replication within each order.

The four adjudicated task contracts pass 40/40. Scene description, unknown-word
clarification, self-knowledge answer, and self-report action each pass 10/10,
with two passes for each task at every sequence position. The concern-authoring
prompt is retained in all ten episodes but scored unadjudicated: it demands a
comparison of two letters not present in the fixture, so the observed
clarification cannot be called a capability failure before intent review.
There are 32 `responds_to` edges crossing the conservative task-owner sets
across the ten graphs. These encode prompt-response adjacency; the projected
sets remain non-disjoint as graph components.

This confirms the seeded scene Goal-binding repair under all five sequence
positions in this authored panel. It reverses the prior scene-description
failure from the pre-repair panel. The contract no longer includes a fixed
native rule-count delta; it checks the reply and resolved, request-linked Goal
lifecycle. Position counts are uniform, but five cyclic orders and two
replicates do not prove order invariance or natural-task prevalence. The
counterbalanced replay measures route correctness and structural links, not
frame discovery, complete factor scopes, partitioned execution, or scaling.
