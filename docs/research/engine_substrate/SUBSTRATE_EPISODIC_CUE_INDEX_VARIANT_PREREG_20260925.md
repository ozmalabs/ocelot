# Preregistration: request-scoped cue collision variant

**Question.** Can the episodic query path preserve exact answer identity and collision confidence while replacing the every-tick all-pairs overlap-marking rule with a request-scoped count of matching cue records?

**Variant.** In an isolated runtime manifest copy, remove `episodic_mark_overlapping_cues_for_conservative_completion`. Change only `episodic_retrieve_best_partial_cue`'s emitted `confidence` to `IfThenElse(Count(Filter(agent.recorded_episode, cue_key == request.cue_key)) > 1, 0.5, episode.completion_confidence_cap)`, and define uncertainty as `1-confidence`. The count is evaluated only in the selected recall effect. No checked-in seed is changed. The original variant remains the baseline. Both variants use identical event payloads, graph topology, and target key.

**Workloads.** N=6, 24, 78, 192; two independent fresh writer/checkpoint and reader pairs per cell. Workload U has N unique cues and queries one middle cue. Workload C has one two-event cue collision at index 0 and N−2 other unique events, and queries the collided cue. Each checkpoint is read in two fresh processes: uninstrumented wall-time control and native global/per-rule scale audit. The cue collision target is the higher-salience target event.

**Response-level correctness.** Both variants must return one candidate with identical expected target summary, recalled provenance, and `not_observed`. Workload U confidence must be 0.85; Workload C confidence and uncertainty must both be 0.5. The optimized variant must omit the global overlap rule from its active rule store. Record episode attributes separately: baseline is expected to set both colliding Episodes' caps to 0.5 and separation status to overlap-detected; optimized mode intentionally leaves persistent Episode-side collision marks untouched and computes uncertainty at recall time. This is an intentional side-effect change, not claimed graph-state equivalence.

**Measures.** Uninstrumented tick latency; audit overhead; global and per-rule candidate, where, term, rule enumeration, and effect counters; exact output; episode-side attrs; checkpoint/graph sizes; and process RSS. Compare scaling and collision semantics. Count/Filter evaluation may traverse the full recorded-episode neighbor set; candidate-count reduction alone is not treated as proof of linear total work. Use both integer counters and uninstrumented wall time.

**Claim boundary.** This is a prototype on a synthetic exact-key workload, not a production seed change. A successful result would show response-level semantic parity for the specified inputs and cost reduction in the measured range only. It would not establish correct persistence semantics for prior collision marks, complex collision groups, concurrent insertion/retrieval, natural tasks, or large-N complexity. No source seed or substrate implementation is modified by the experiment.

**Execution lock.** The harness argument guards were corrected before any scored execution (writer invocation has six argv entries including the script; reader has seven). Syntax compilation succeeded. No workload pilot or scored subprocess has run. The protocol is frozen before execution: 32 cells (2 workloads × 4 sizes × 2 replicates × 2 variants), each with one fresh writer and two fresh readers; no retries or omitted cells. The run lock records source hashes and runtime environment. Any harness or protocol change after execution begins requires a new amendment and run identifier.
