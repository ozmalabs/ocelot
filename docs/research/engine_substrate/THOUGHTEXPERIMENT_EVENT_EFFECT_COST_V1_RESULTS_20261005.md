# Thoughtexperiment endpoint and per-effect observer cost v1 results

The source-locked capture passes after an independent analyzer correction. Three worker processes agree on all 15 fixture/mode outcomes; 45 isolated processes have distinct PIDs, stable source/native hashes, and semantics matching the worker matrix. Endpoint-only mode emits no effect snapshots. Effect mode preserves `0→1`, `1→2`, and effect-index 2 edge deletion while the enclosing event retains `0→2`. The report-cap fixture stays within 4 MiB / 16,384 retained effect-object bounds and marks truncation. All observer modes produce identical final graphs and closure statuses for these cases.

The selected report-cap stress fixture shows a clear cost for effect detail over endpoint attribution: median wall time rises from 223 ms to 560 ms (2.51×), and post-settlement RSS/PSS delta rises from 118,120 KiB to 269,180 KiB, an additional 151,060 KiB. The effect trace estimates 520,192 payload bytes across 16,256 objects; Python-visible event serialization is 4.29 MiB. The gap between estimated payload and process-memory delta reflects container, allocator, conversion, and retained graph/report costs in this API path. On the small direct fixture the effect arm is 0.221 ms / 592 KiB versus 0.218 ms / 588 KiB for endpoints, too small to interpret beyond this fixture. The combined residual-plus-effect arm is 1.069 s / 480,108 KiB delta on the stress case, including both observers and residual conversion.

These are medians of three fresh processes per cell on an `opt-level=3` build with LTO disabled and 16 codegen units. The repository's default fat-LTO, one-codegen-unit profile was not used. RSS/PSS deltas are sampled after graph construction and after the Python report is returned; they are not transient allocation peaks. This authored stress case is a deliberate fan-out/object-cap probe, not a natural-workload estimate.

The first analyzer attempt failed only because JSON arrays were compared with Python tuples in the isolated semantic parity check. The locked analyzer was left intact; the separate [correction analyzer](../../../evaluation/substrate_capability/analyze_thoughtexperiment_event_effect_cost_v1_correction.py) fixes the comparison and passes every gate. The [locked analyzer](../../../evaluation/substrate_capability/analyze_thoughtexperiment_event_effect_cost_v1.py) and its first output are retained as part of the audit trail. The trace is now a separate opt-in observer so endpoint-only attribution retains zero effect payload. This gate measures cost and transition fidelity only.
