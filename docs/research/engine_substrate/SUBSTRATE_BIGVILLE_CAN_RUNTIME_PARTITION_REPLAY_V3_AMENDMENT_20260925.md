# Bigville CAN runtime partition replay — diagnostic v3 amendment

The v1 and v2 records remain unchanged. V1's authored scenario evidence was repeated after already being applied to every resident and produced no state activity. V2 corrected the timeline to apply evidence once after a prior-only baseline, and its ten paired checkpoints passed state parity and local residual checks. The v2 sensitivity control was incorrectly evaluated immediately after the graph input write, before running either settlement policy; it therefore tested whether an input write mutates `state` synchronously, rather than whether notification is needed to reach the updated fixed point.

V3 keeps the v2 graph, priors-only baseline, evidence timeline, target positions, update rule, access-component derivation, and event/full policies. It repairs only the control protocol: on a fresh third graph, apply the complete ten-event sequence without settling, then compare that stale projection and its independent local residual to the event arm's settled terminal projection. The control passes only if the event sequence changes at least one state, the stale projection differs from the notified terminal state, and the stale graph has positive residual. This is a post-result diagnostic amendment, not confirmatory evidence. No fixture or target is selected based on v2 per-resident state outcomes.
