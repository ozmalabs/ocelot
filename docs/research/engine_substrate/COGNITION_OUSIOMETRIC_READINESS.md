# Phase 28 runtime readiness decision

Date: 2026-10-25. Scope: P28.04 entry gate after the source manifest and
offline geometry audit. This is not an efficacy result or runtime promotion.

## Readiness

**GO, narrowly, for an opt-in finite-world comparison of a common three-value
numeric encoder under its source basis and the frozen Eq. 4 display-matrix
rotation.** Both arms must use the same raw feature records, precision,
aggregate frame/decoder budget, candidate cap, receipt learner, verifier,
native work horizon, and graph-selected action path. Until exact compatible
lexical calibration is independently established, arm labels are
`shared-coordinate-basis` and `published-Eq4-rotation`; they must not be
called validated VAD and PDS encoders for synthetic world features.

**NO-GO for psychological VAD/PDS validation, independent acquisition of
human semantic axes, or a claim that the published transformation reproduces
the original full-precision lexical coordinates.** The paper prints rounded
Eq. 4 coefficients. The pinned official sources are not identical instruments:
the identifier-only audit found 19,970 shared terms, 36 GPADS-only terms, and
one NRC-VAD-v1-only term. The NRC file license prohibits redistribution. The
unmatched terms and version difference remain visible; no label imputation or
substitution is allowed.

## Native expressivity and integration boundary

Existing Rust DSL Terms include `Vec_`, `Dot`, `VecAdd`, `VecSub`,
`TransformDecode`, and `Whiten`. A fixed 3×3 map can be represented as three
graph-resident row vectors and three native `Dot` applications over a
three-coordinate source vector. The inverse is a separately declared map and
is also applied row-wise. `Dot`'s current zip behavior makes a graph-side
dimension guard mandatory; malformed, missing, nonfinite, or dimension-mismatched
inputs must stay unknown. `TransformDecode` and `Whiten` have different
contracts and are not substituted for this arbitrary floating-point frame.
No new Rust primitive is justified for this fixed 3D path. A dynamic general
matrix multiply, host-selected frame, or implicit frame mutation is outside
this gate and would need a new semantic-gap task.

P28.05–P28.08 may build only declared experimental graph frames and an
explicitly loaded investigation profile. The ordinary receipt path remains
identical. Default and conversation profiles remain isolated. Every compared
action must be read from native graph outcomes and verified by the shared
world simulator; the adapter cannot choose the action. If a frame knockout
does not affect the scored native path, no behavioral comparison is valid.

## Unsupported comparisons retained

- Human semantic calibration of synthetic-world measurements is unsupported.
- NRC VAD v2.1 is not silently substituted for the paper's v1 input.
- Missing GPADS/VAD concepts remain missing; lexical coverage and sense
  ambiguity are descriptive only.
- A fixed metric or finite-aperture result can show utility under that exact
  restriction, not added information or a universal PDS advantage.
- A PDS lexical score or safety-word frequency cannot replace witnessed
  physical consequences, the time-indexed manifold residual tube, approvals,
  or host veto.

**Decision:** proceed to frame/acquisition/world implementation only under
the narrower rotation-experiment label. Revisit semantic calibration only if
source provenance and compatible scoring are established before any sealed
lexical score is inspected.
