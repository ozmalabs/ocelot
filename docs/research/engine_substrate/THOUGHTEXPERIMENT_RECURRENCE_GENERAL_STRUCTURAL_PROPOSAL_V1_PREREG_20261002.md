# Thoughtexperiment generic structural proposal on recurrence v1 — preregistration

**Question.** Can the general graph-Term structural composer transfer its four generic edit operators to a recurrence-offer idempotence fault, when the target rule and generic guard cue are supplied?

## Fixed task and responsibilities

Use the existing recurrence fixture: fault `mrl_offer_due_once` by removing its candidate-scoped `Not Exists(has_mint_offer)` condition. Four fresh order workers receive the fixed cue `mrl offer due once guard constrain restrict narrow extra condition equality`; the cue is deliberately sufficient to identify the target and generic operator family, so this is a prompted transfer test, not autonomous diagnosis. The graph composer gets no host candidate list. It must choose the rule and applicable generic `EditOp` and materialize its proposal through `compose_general_structural_variant`.

After all four order records have been written, separate fresh scoring workers evaluate each proposal on the established two-candidate held-out recurrence episode. They also score the known `dedup_identity_fix` reference from the unchanged host candidate generator. The reference is revealed only in scoring and is a positive oracle control, not an input to proposal generation. The independent oracle requires exactly one offer per due candidate and zero further rule work at fixed point.

## Hypotheses and gates

- The generic composer selects the exact recurrence target and builds `add_match_guard` in all four workers.
- The materialized generic proposal fails the held-out recurrence oracle in all four workers; the `dedup_identity_fix` reference passes in all four.
- Candidate receipts and primary-graph isolation pass for every score; source and loaded-native fingerprints remain stable.
- The order capture precedes held-out scoring, and each order record contains no held-out labels or outcomes.

Any discrepancy is retained. Report composer and branch/scoring costs separately. A passing negative-transfer result identifies a proposal-space gap: the generic guard adds a fixed `adopted_variant_probe` condition, while the successful recurrence repair changes identity semantics and mint idempotence. It does not imply that all recurrence repairs need this domain-specific edit or that the system cannot learn new operators. The task cue, fault injection, candidate reference and oracle are externally authored; no autonomous learning claim is permitted.
