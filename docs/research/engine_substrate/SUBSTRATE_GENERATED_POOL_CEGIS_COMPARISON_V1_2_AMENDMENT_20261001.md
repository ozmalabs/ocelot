# Generated-pool active query versus iterative resynthesis v1.2 amendment

The v1.1 capture is retained as a valid diagnostic but reveals that the shared maximum expression size 5 excludes the triangular target `n * (n + 1) / 2` (size 7). Its complete one-behavior pool does not contain a hypothesis correct on held-out values, so selector comparisons on that task are invalid. The square and Euler tasks do have held-out-correct pool behaviors under the original bound.

For a confirmatory rerun, use per-task size ceilings fixed from target syntax before any worker runs: triangular 7, square 5, Euler 5. Every arm for a task uses the same ceiling; all other protocol conditions, literals, operators, candidate inputs, outcomes, and gates stay fixed. The finite-pool cap remains 10,000 fitting behaviors and generation timeout remains 30 seconds. A pool that times out or reaches the solution cap is incomplete and yields no selector success. This amendment promotes target support to an interpretability gate: query-efficiency comparisons count only when a complete pool contains a behavior exact on the held-out set. The original max-size-5 capture remains evidence about model-class misspecification and must not be overwritten.

The v1.1 analyzer also applied its unique-query invariant to MDL CEGIS. That arm legitimately re-examines candidate inputs after each resynthesis; repeated labels remain charged as oracle work. The amended analyzer requires unique queries only for pool policies, whose candidate list is explicitly consumed without replacement. No raw v1.1 rows are edited.

The MDL control is an inline, source-locked replay of the `cegis_synthesize` loop mechanics (smallest fitting recipe, first disagreement scan, add labeled row, resynthesize). It calls `generator.synthesize` directly because the production faculty does not expose the fixed literal set and `include_output_constants=False` controls required for a matched grammar. Therefore it compares algorithms under controlled search settings; it is not evidence that the query policies are integrated into the production CEGIS API.
