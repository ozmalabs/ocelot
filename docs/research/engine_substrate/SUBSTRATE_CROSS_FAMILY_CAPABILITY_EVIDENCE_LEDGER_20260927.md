# Cross-family substrate capability evidence ledger — updated 2026-09-28 (base ledger 2026-09-27)

## Purpose and interpretation

This ledger consolidates selected source-linked outcomes across distinct substrate families to guide the next measurement phase. It is an evidence map, not a pooled benchmark score or a fresh confirmatory study. Rows retain each experiment's task oracle, run state, measured envelope, and known failure boundary. Similar percentages across rows are not comparable: fixtures, units, task contracts, substrates, and novelty levels differ.

The strongest general conclusion is that the repository contains working, measurable mechanisms across several families, but end-to-end competence remains narrow and uneven. Exact task success is shown for selected live conversation, synthetic episodic recall, bounded visual response, and generated program-synthesis tasks. Those successes do not yet establish held-out transfer across task families, natural-task prevalence, or a common economic advantage. Multiple results expose systematic limits: route failures, output/provenance mismatch, false acceptance, cycles, and quadratic memory-query work.

## Cross-family capability profile

### Demonstrated

- Exact fixed-point or task-oracle checks exist for bounded native rule execution, visual response phases, unique-cue episodic recall, and selected synthesis instances.
- The substrate can expose internal route, Goal lifecycle, candidate work, and storage behavior sufficiently to localize failures in several domains.
- The CAN-to-deduction bridge now has an exhaustive answer-translation oracle on its five-topic fixture; this closes the earlier relation-level correctness gap without upgrading the underlying beliefs or the bridge's downstream utility claim.
- Some negative controls are strong: no-memory/reset-memory, ambiguous-cue abstention, retrieval bypass, higher search ceiling, multiple rule topologies, and scope variants.
- Cost is not uniform: a conversation route can be dominated by cold faculty construction; a vision state can require thousands of passes; memory query work can be quadratic; synthesis cost can rise without new held-out success.

### Not demonstrated

- No representative natural-task distribution or externally custodied cross-family test set supports a general success rate.
- No common-task protocol demonstrates transfer of acquired structure from one family or modality to another.
- The vision work now includes three independently adapted checkpoints, but all use one orientation/phase task family; that is not cross-task visual transfer. Memory's exact cues are not semantic retrieval; PBE suites stay inside declared operators; conversation prompts are repository-selected.
- Cheap-cut/frame locality is not established as a naturally learned property across these tasks. Several partition probes use authored or caller-provided frames and notifications.
- Residual-triggered entry demonstrably differs between two measured routes: NaturalProofs statement processing produced no post-startup receipts in 126 worker-task observations, while direct code reading produced 14 receipts in 126 observations (10 minted-edge outcomes, four recognized observations; per worker 7/63). The populations and routes differ, so this is evidence of route/task dependence in selected samples, not a comparative prevalence estimate.
- The learning/minting cost distribution and frequency of residual-driven rung 3/4 entry remain open. ProblemShape, MetaShape, PBE, and GenMint show separate bounded induction/transfer mechanisms, including prior collision and false-accept boundaries, not one general acquisition economy. NaturalProofs produced zero post-startup receipts in 126 task-worker observations, while direct Think Python code reading produced 14 receipts in 126 observations (10 minted-edge outcomes, four recognized receipts). This demonstrates route/task-family dependence in selected samples, not general rarity or prevalence. Code prediction now includes a targeted 37-case CPython replay, 12 authored refusal cases, 27 same-project module-held-out cases, and a nine-case independent-project panel; selected panels pass exactly, but syntax eligibility was only 1/41 external projects and three held-out functions were confined to one CPython module. Coverage, independent-task selection and broader construction families remain open.
- Resource reports use different phase boundaries and process setups; do not compare absolute latencies across families as if they were matched.

## Recommended next measurement sequence

1. **Freeze the evidence contract.** Keep the shared run-manifest and source/runtime-closure requirements; extend the corrected full-runtime lock approach to every task runner, and use set-aware graph canonicalization wherever full graph parity is collected.
2. **Broaden within families before pooling.** The code behavior panel now covers 18 functions but stays within one textbook; extend it to an independent code corpus and held-out construction transfer. Add independently authored visual task families beyond the orientation/phase panel; add semantic/partial and near-neighbor episodic cues with retention and restart; use a newly generated synthesis family with frozen/retrieval controls and held-out scoring; add independently authored conversation task templates and graph-visible output checks; expand MetaShape rung-attribution across schemas with explicit relation-level semantic oracles and prior-collision controls.
3. **Measure transfer directly.** Train/acquire on one subset and evaluate new compositions and a separate task family without prompt, seed, codebook, or rule edits. Report negative transfer and retention alongside gains.
4. **Test structural tractability against controls.** For each family, collect observed dependency/cut structure before partitioning; compare low-boundary cases with coupled/high-boundary controls; measure partition construction, exactness, runtime work, and resource use separately.
5. **Publish a profile, not an aggregate.** Present quality, reliability, abstention, cost, and novelty axes per family. Only define a composite after external task selection and justified weights; never allow a high score in one family to hide a critical failure in another.

## Reproducibility note

The cited results have distinct source locks and run states. Consult each linked result, preregistration, raw report, and independent analysis before reusing its numerical claims. This ledger does not upgrade discovery or pilot evidence to confirmatory status. The 2026-09-27 complete-runtime conversation panel is tied to its isolated snapshot; it does not describe the changing live worktree.
