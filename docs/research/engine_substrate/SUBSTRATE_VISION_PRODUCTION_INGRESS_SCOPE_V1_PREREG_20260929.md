# Production visual ingress and frame-scope pilot v1 preregistration

## Question

Does root-scoped settling preserve an independently driven visual sheet when a second sheet shares the substrate, when frames enter through the production `WaveWorld.step(frame=...)` path? How much measured closure work and wall/CPU time does that path use, and does the target sheet retain orientation information on known grating inputs?

## Design

- Use the three frozen, independently adapted shared-substrate checkpoints from vision checkpoint replication v2.0 (seeds 20260935, 20260936, 20260937). Restore the same checkpoint for every condition and scope.
- Compare the standard global `st_settle` rule with the root-scoped rule generated by the existing v1.4 builder. The runner must verify that the two registered rule signatures differ only in their SUnit population source.
- Conditions are a blank control and four labeled grating orientations (0°, 45°, 90°, 135°). Each grating is delivered over four phases (0, π/2, π, 3π/2); the sibling sheet receives a blank frame at every phase.
- Deliver each target and sibling frame with `WaveWorld.step(frame=...)`, target first and sibling second. This is an explicitly sequential schedule. Record state after each call so cross-sheet effects during the target step remain visible.
- Run every seed × condition × scope from a fresh restored checkpoint: 3 × 5 × 2 = 30 condition workers, with four iterative phases per worker.
- A negative-control arm deliberately removes one target `has_sunit` owner edge. It is restricted to the 0° condition and both scopes for seed 20260935. The analyzer must identify the unowned target unit and report whether the scoped settlement fails to update it.

## Registered measurements and gates

1. Checkpoint digest matches before each worker; source/native fingerprints are stable before and after capture.
2. At each phase, all `lum_raw` values equal the delivered image pixels exactly. Blank frames are verified independently.
3. Report both adapter calls separately: wall time, process CPU time, native step return, peak RSS, root step, graph size, and per-unit `act`, `act_next`, `theta`, `rate`, and update stamps.
4. Recompute `rate = max(act - theta, 0)` independently for values written at the corresponding rate phase; report residuals and phase coverage.
5. Compute four-way orientation accuracy from the phase-averaged target-sheet rate-sum response, with the blank condition as a separately reported baseline. Do not treat accuracy as a pass threshold; this is a capability observation, not a trained classifier claim.
6. Compare each condition's sibling output against its matched blank run at every phase. Root-scoped invariance is a confirmatory gate for `act`, `act_next`, and `rate` (absolute tolerance 1e-9); global transfer is measured, not forced to be nonzero.
7. In omission workers, verify that the omitted SUnit remains a typed global member but is absent from root membership; report its per-phase update behavior separately.
8. Capture failures, cycle/budget exits, and missing phase writes as outcomes. Do not discard them or infer fixed-point termination from a successful adapter return.

## Interpretation boundary

This is a production-adapter integration pilot on one authored synthetic visual family and three adapted checkpoints. The frame roots are supplied by the experiment; this does not measure frame discovery, natural-image accuracy, prevalence of cheap cuts, or general CPU scaling. Wall/CPU measurements include Python adapter work and native closure; report both step-level and accumulated worker totals. The target-first/sibling-second schedule is not simultaneous input.

## Reproduction

The source lock, runner, raw capture, independent analysis, and result note use the `vision_production_ingress_scope_v1_20260929` stem. Capture is permitted only after writing the lock and verifying two identical source probes separated by 20 seconds. Run the analyzer against the raw capture after all workers finish.
