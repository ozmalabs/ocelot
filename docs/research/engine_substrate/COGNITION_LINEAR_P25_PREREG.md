# Cognition Linear P25 preregistration — persistent retention v1

**Freeze status:** pre-registered before any held-out draw. The single held-out allocation is 1,200 paired streams and 300 structural controls. Run once after this file is committed as the only file in its commit, with the frozen source commit as its parent. Keep every failed or censored stream in the ledger.

## Question and hypothesis

Does offline sleep consolidation preserve learned action effects under finite persistent memory better than replay without consolidation, when both receive the same acquired experiences and interference? The primary estimand is the paired mean difference in normalized delayed success AUC, `sleep_consolidation - replay_only`, across the six family-by-capacity cells. The registered minimum useful gain is 0.10. The safety estimand is the paired accuracy loss on one unseen ButtonWidget task, `replay_only - sleep_consolidation`; its maximum allowed value is 0.02. Both are point-estimate thresholds. A 99% paired bootstrap interval is reported for each estimate and every cell, with 20,000 resamples and fixed seed 25,010,241 (cell-specific seeds are deterministic in the analyzer). A valid flat or negative result is retained as a negative efficacy outcome.

## Tasks and allocation

Task families are `thermal` and `latch`, generated by `p25_persistent_retention_worlds_v1`. Each stream receives two target acquisition receipts, a pre-delay score, six interference actions in three two-action groups, and delayed scores after each group. The first interference pair is a confusable ButtonWidget press relation; four later tasks are unrelated. The external evaluator archive holds expected outcomes and never enters learner memory unless a typed receipt is explicitly delivered. Each arm uses a fresh learner initialized from the same arm-independent profile and same stream seed. Capacity is assigned from canonical serialized acquired-content bytes, including 32-byte record overhead and the UTF-8 key, at ratios 0.5, 1.0, and 2.0.

The held-out seed formula is `120000000 + family_index*1000000 + ratio_index*100000 + i`, where family order is thermal/latch, ratio order is 0.5/1.0/2.0, and `i` is 0..199. Stream IDs are `p25:heldout:<seed>`. This gives 200 streams per cell, 1,200 streams, and 4,800 arm rows. Development seeds use the same formula with base 110000000 and two streams per cell. Structural controls use 100 seeds per kind at bases 131000000, 131010000, and 131020000 for eviction, restart, and absent source. Development controls use corresponding base 130000000, 130010000, and 130020000 with two seeds each. Prior numeric envelopes reserved by P16–P19 and P22–P24 are 26,000,000–28,999,999; 29,000,000–29,999,999; 31,000,000–33,999,999; 41,000,000–43,999,999; 90,010,000–90,010,007; 90,020,000–90,020,007; 93,010,000–93,010,199; 93,020,000–93,020,199; 94,000,000–94,002,001; and 97,000,000–97,002,099. P20/P21 allocations use separate protocol-owned string namespaces; P25 uses the new `p25:` namespace. The frozen P24 allocation audit also compared its concrete held-out IDs against P20, P21, P22, and both P24 v1 splits. These checks and the high P25 numeric blocks establish disjointness. The runner rejects duplicate seeds and any overlap with the enumerated numeric envelopes. The runner's canonical allocation digest below binds every concrete ID and seed.

## Arms

1. `sleep_consolidation`: native offline sleep and verified persistent consolidation enabled; shared budget 256.
2. `replay_only`: offline replay enabled, persistent consolidation and sleep-specific library updates disabled; shared budget 256.
3. `awake_matched`: no offline consolidation; awake native work is matched to the sleep arm's measured native rule work; shared budget 256.
4. `no_offline`: no offline work; shared budget 256.

All arms receive exactly the same target and interference receipts, target actions, capacity assignment, delayed queries, and new-task query. Target receipt and interference receipt parity is a structural validity condition. No external model queries are permitted.

## Controls and validity

The 100-per-kind controls test eviction availability, checkpoint/restart preservation, and absent-source refusal. Every control must pass. Every allocated stream and arm must have two target actions, six interference actions, three delayed checkpoints, and one unseen-task query. Retain pre-delay failures, delayed failures, unsolved predictions and exceptions as rows with their status and cause. No row may be removed for low accuracy or an unfavorable capacity outcome. Report allocated, completed, failed, and scored denominators by family, capacity, and arm. Any structural failure invalidates the efficacy claim; it does not authorize replacement draws.

Per-learner ceilings: 250,000 native rule steps; 400,000 serialized graph bytes; 256 shared budget units; two target actions; six interference actions; zero external model queries; three delayed queries; one unseen-task query. Runtime attestation must report `ATTESTED`, with source and build hashes matching the freeze.

## Analysis and decision

The analyzer validates allocation and arm parity, receipt IDs, controls, row counts, resource ceilings, runtime attestation, and recomputed normalized AUC before calculating paired estimates. It reports mean and 99% bootstrap intervals overall and for every family-by-capacity cell, plus arm means and resource/censoring denominators. A P25 advantage passes only if the complete data are structurally valid, all controls pass, the primary paired mean gain is at least 0.10, and the new-task accuracy loss is at most 0.02. This preregistration does not treat mechanism tests or a causal knockout as held-out efficacy.
