# Native candidate-adequacy gate v2 preregistration

## Question

Does class-balanced validation improve detection of out-of-menu numeric relations, and can native graph rules emit a useful explicit request-help action instead of selecting a weak candidate?

## Tasks and fresh panels

Generate ten deterministic panels for each of four relations: additive conservation (`ax+ay==ex+ey`), product conservation (`ax*ay==ex*ey`), componentwise opposition (`ax==-ex and ay==-ey`), and inequality (`ax!=ex`). The first two are in-menu controls; the latter two are out-of-menu challenges for the fixed additive/product candidate set. Use integer values `(-3,-2,-1,0,1,2,3)` to construct each panel's validation pool. Select exactly 16 positive and 16 negative rows per panel with a frozen seeded algorithm that draws eight zero-containing and eight boundary-containing rows per label class, filling any overlap deterministically. Preserve the algorithm, seed IDs, and generated rows in the source lock.

The sealed evaluation set is the disjoint complement of the validation rows in the complete 7^4 integer grid, together with the full 1,296-row fractional grid over `(-2.5,-1.5,-0.5,0.5,1.5,2.5)^4`. Evaluation labels are generated by the harness-held relation only after native candidate predictions and decisions are captured. Validation and evaluation therefore include zero and boundary cases without row leakage.

## Native policy

The supplied candidates remain additive and product equality. Graph rules compute each candidate's true-positive rate and true-negative rate across the balanced 32-row validation pool, then balanced accuracy `(TPR+TNR)/2`. They also compute raw agreement for diagnostic comparison. A fixed balanced-accuracy threshold of 0.75 is preregistered. If the best candidate is below threshold, native rules set `decision=request_help` and select no candidate. If at or above threshold, native `ArgminUnique` over negative score selects a unique candidate; ties produce `decision=abstain_tie`. Otherwise the decision is `selected`. The host installs rows and candidate definitions and sequences graph phases; it does not compute scores, adequacy state, or choice.

No help response or new primitive is supplied in this gate. The outcome is whether the substrate appropriately requests help and how well selected candidates transfer. This isolates adequacy signaling from a teacher's ability to repair the grammar.

## Gates and reporting

Require source lock, 40 expected panels, exactly balanced validation labels, zero/boundary coverage, exact validation/test disjointness, no task identifier in graph attributes, native predictions and balanced/raw score reconstruction, correct threshold/unique-choice/tie/help behavior, label-after-prediction receipts, and independent evaluation scoring. Report mismatch detection, positive-control false help, challenge false acceptance, help/tie/selection rates, selected coverage/utility, raw versus balanced scores, per-task confusion, integer and fractional evaluation separately, and resource costs. Panels are the task units; rows are repeated observations within a panel.

## Interpretation

This is a finite four-relation adequacy study for a supplied two-candidate menu. A request-help result is not a repair. Balanced validation is a fixed design choice and not a calibrated probability. Results will not establish open-ended grammar widening, autonomous operator invention, or natural-task prevalence.
