# Native candidate-adequacy gate v1 preregistration

## Question

Can the substrate detect when neither of two supplied numeric relation candidates has enough validation support, instead of always selecting the best available candidate?

## Panels and threshold

Use all 15 source-locked panels in `numeric_relation_model_adequacy_audit_v1_1_lock_20261003.json`: five additive and five product in-menu positive controls, plus five componentwise-opposition out-of-menu challenges. Preserve each panel's 32-row selection pool for validation and the 1,296-row fractional grid over `(-2.5,-1.5,-0.5,0.5,1.5,2.5)^4` for sealed evaluation. Validation labels are generated by the harness-held task. Evaluation labels are not inserted into the graph until candidate predictions and the adequacy/selection decision are captured.

The fixed acceptance threshold is **24/32 validation agreements (75%)**. It is selected as a prospective minimum adequacy criterion and will not be tuned against this panel or its holdout. A candidate menu is considered adequate when its best-scoring member meets this threshold. Below the threshold, native rules must mark `model_mismatch` and select no candidate. At or above it, native `ArgminUnique` may select a unique candidate; a score tie is an explicit selection refusal. This threshold is a policy choice, not a calibrated probability of general correctness.

## Native responsibility

The graph contains only validation labels, two supplied candidate nodes, native candidate predictions, and native validation agreement scores. It receives no task identifier, challenge label, or held-out label before prediction capture. Graph rules compute the maximum candidate score, compare it with the fixed threshold, mark the adequacy state, and either refuse for model mismatch or apply `ArgminUnique`. The host installs the fixed task examples and candidate definitions, sequences the stages, and scores results after label reveal; it does not compare scores or write the adequacy/selected-candidate decision.

## Gates and reporting

Require source lock, all 15 expected panels, exact validation/grid reconstruction and disjointness, no task identity in graph attributes, native predictions on all rows, independently replayed validation scores, exact threshold-state behavior, correct selection/tie refusal above threshold, no selected candidate below threshold, label-after-prediction receipts, and independent sealed-grid rescoring. Report true mismatch detection, false mismatch on positive controls, false acceptance of opposition, positive-control family choice, selected utility/coverage, fixed-candidate outcomes, per-panel scores, and CPU/wall/RSS costs. Panels, not grid rows, are the independent task units.

## Interpretation

This tests adequacy gating for one fixed two-candidate menu over three authored numeric relation families. It does not test grammar widening, candidate invention, adaptive threshold learning, probability calibration, or natural-task prevalence. A mismatch status is only as good as the fixed validation threshold and panel distribution.
