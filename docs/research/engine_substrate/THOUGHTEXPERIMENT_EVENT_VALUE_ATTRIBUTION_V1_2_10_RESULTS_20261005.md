# Thoughtexperiment combined residual and event journal v1.2.10 results

Three source-locked workers pass corrected independent analysis across ten fixtures. The new opt-in combined API runs the sparse thoughtexperiment residual journal and per-rule event attribution on one mutation log. For every fixture, its `conclusions` receipt equals `Substrate._inner.graph_diff(before, after)` from full graph snapshots, and its event stream equals event-only tracing. Closure status, progress, and final graph parity hold across plain, event-only, full-snapshot exact, and combined modes. The prior experiment journal entry point and existing event report remain intact.

The combined route adds measurable wall/CPU time, including report serialization and sparse residual construction. Median wall time for plain/event-only/exact/combined modes is 0.069/0.081/0.031/0.104 ms on `direct`, 0.021/0.053/0.033/0.080 ms on same-event repeated writes, and 5.089/129.953/13.030/260.137 ms on the report-object cap fixture. The report-cap combined path is about 2.0× event-only tracing. Worker RSS high-water is 474,200–505,776 KiB, but each worker runs all modes and fixtures sequentially; this does not isolate combined-arm memory. The runner did not call the phase checkpoint, so only total `conclusions` residual parity is claimed; `derived_only` semantics were not evaluated. The capture therefore demonstrates functional coexistence and an instrumentation cost increase, not a full memory profile.
