# Bigville Graph Construction and Partition Scaling Preregistration (2026-09-26)

## Question and scope

Measure how authored Bigville graph construction and runtime partition derivation scale when the same five-Concept resident frame is replicated from 100 to 250 and 500 residents. The graph remains disconnected across residents at baseline. This is a controlled scaling probe of one authored frame template, not a sample of natural task graphs and not a closure or inference benchmark.

## Frozen design

Run 3 fresh processes at each size (9 workers total), with sizes 100, 250, and 500 frames (500, 1,250, and 2,500 Concepts). Each process loads the fixed 100-resident cast and deterministically replicates its entries: clone index is assigned uniquely, and clone names receive a deterministic suffix. Resident parameters and frame structure are unchanged. Install authored CAN productions, then time the repeated `build_resident_can_mt` calls separately from engine/production setup.

On the completed live graph, independently derive (1) the owner map by querying each Concept's live `has_concept` in-neighbours, (2) directed `causal_influence` edges by live native adjacency, (3) connected components from those edges, and (4) their composed partition. Collect 31 timed repetitions of each derivation stage after one warmup. Graph construction is one measurement per fresh worker; process-level replicates provide its distribution. Report per-worker and across-worker values, including peak RSS. No timings are discarded as outliers.

## Integrity gates

Each worker must verify exactly N unique resident/Microtheory owners, five Concepts per owner, 5N unique Concepts, each Concept has exactly one live owner, each component equals exactly one owner frame, baseline crossing-edge count is zero, and all timed derivation variants reproduce the same complete owner partition. Keep engine initialization/production installation outside and separately timed from resident graph construction. Preserve exact schedule, source/native hashes, worker PIDs, environment and raw samples. Cost results are descriptive; no pass threshold is imposed on time or memory.

## Claim limits

This tests construction and partition costs on 500–2,500 Concepts generated by repeating one authored five-node template. It does not validate cheap cuts on independent workloads, learning or partition selection, dynamic-boundary maintenance, closure scheduling, inference, natural-task frequency, 10^7-node operation, or commodity-scale capability. The components are intentionally disconnected by resident, so the cut is supplied by the frame ownership relation and checked against graph connectivity.
