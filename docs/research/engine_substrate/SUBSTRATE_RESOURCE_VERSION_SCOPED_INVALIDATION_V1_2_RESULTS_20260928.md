# Resource-version and scoped invalidation comparison v1.2 — results

All nine preregistered gates pass across three fresh workers, six cells per worker, and N=4/16/64 independent frames. In every cell, initial closure evaluates all false predicates; changing frame 0's active external resource file without graph mutation produces zero callbacks and no accepted marker. Then frame 0's graph `resource_rev` is advanced to a newly published `r0_v1` file containing `1`.

Global closure and caller-selected `run_rules_scoped(..., mt0)` produce identical final projections: frame 0 is accepted, and all other frames remain unaccepted. Callback work during the revision update is exactly `2N` for global closure (8, 32, 128 calls) and exactly 4 for scoped closure at all three sizes. The scoped path pays repeated callback evaluation for its one newly accepted match but avoids evaluating unrelated frames. `UseTool` declares `reads_any=true`; the scope is supplied explicitly by the caller after the version fact changes.

At N=64, median update-phase wall time is about 3.05 ms globally and 0.245 ms scoped; timing is descriptive and is not used to claim a hardware speedup. The reproducible callback counts support linear unrelated callback work for global closure and bounded callback work under the selected scope on this authored topology, through N=64. They do not establish total engine complexity: scoped closure still snapshots active rules, and the design does not automatically connect file watchers to graph revisions or select the affected microtheory.

The v1.1 raw capture is preserved but its analyzer failed because the runner did not store phase-local graph projections; the failed assertion inspected final state for earlier phases. v1.2 adds those projections and is the accepted result. The exploratory four-frame pilot is also not confirmatory.
