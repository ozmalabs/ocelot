# ReachableFrom cache mutation invalidation v1 results

The preregistered panel used the authored `browser_affordance_reach` seed in a minimal adapter. Each cache-on arm first retained one live `ReachableFrom(session, contains)` entry with four result nodes; cumulative hit/miss counters were then reset without clearing that entry. Ten public mutation cases were crossed with cache off/on in three fresh workers each (30 workers total).

All ten runner gates and nine independent analyzer checks passed. Every cache-on mutation caused a fresh miss and left one newly computed entry whose result cardinality matched the declared topology. The cache-off arm retained zero cache counters. Cache-on/off graphs, rule progress, and mirror counts matched in every paired worker. Expected reachable sizes were 4 for isolated-node addition and non-topological attribute/type changes, 5 after either checked or unchecked edge insertion, 3 after single-edge or node deletion, and 2 after batch deletion. The cache was primed before each intervention, so the post-mutation miss demonstrates that the former result was discarded before reevaluation.

Coverage includes `Substrate.add_node`, checked `add_edge`, unchecked `add_edge_unchecked`, `remove_edge`, native `remove_edges_batch`, `remove_node`, `set_attr`, `set_attr_many`, `set_attr_each`, and `set_type`. This gives direct behavioral evidence for those public paths in this rule family. It does not cover every internal effect or mutation API in the Rust engine, concurrent access, or other rule families.

This v1 result is historical for the old `browser_affordance_reach` seed. It identified that removing a `contains` edge shrank reachability but did not retract an already derived `has_affordance` edge. The seed cleanup rule was corrected and then validated in a separate seven-checkpoint cache-on/off replay; see the [truth-maintenance result](SUBSTRATE_BROWSER_AFFORDANCE_TRUTH_MAINTENANCE_V1_RESULTS_20260928.md) and the updated [loaded profile result](SUBSTRATE_BROWSER_PROFILE_REACHABLE_CACHE_V1_3_RESULTS_20260928.md). The old raw run and source lock are retained unchanged as evidence of the original gap. No timing or natural workload claim is made.
