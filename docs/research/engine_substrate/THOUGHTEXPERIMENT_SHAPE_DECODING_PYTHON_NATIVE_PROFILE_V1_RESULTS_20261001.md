# Shape-decoding Python/native CPU attribution v1 — results

**Result:** 10/10 amended gates pass across 12 fresh processes. All eight branches in each cell preserve the task oracle, cross-mode/backend semantic parity, primary isolation, and source/native binary lock.

Sequential `cProfile` attribution, with `time.thread_time_ns` and phase timings, shows median self CPU split between Python frames and extension/C calls of approximately 29.5%/70.5% for full-copy and 49.9%/50.1% for shared graph pages. The top full-copy native sites are `fork_full_copy_experiment` and `export_rules`; Python time is led by JSON decoding. Shared-page top sites include branch setup and rule-patch paths. These values describe this shape-decoding fixture and include profiler overhead.

Concurrent cells were deliberately unprofiled after per-thread cProfile activation conflicted and a single-profiled-thread attempt produced invalid negative C-call attribution. The concurrent wave CPU/wall ratios are 0.975× for full-copy and 0.986× for shared graph pages. Thus this capture provides no evidence of CPU-parallel throughput on this task; fanout increases elapsed time versus sequential execution for both backends. Shared-page branch setup remains materially cheaper sequentially, while concurrent phase timings expand under contention. This confirms that single-call GIL release did not remove the dominant pipeline serialization, and it leaves Python/native attribution inside concurrent waves unresolved.

The profile answers where isolated worker CPU accrues, not what fraction of concurrent CPU is blocked on the GIL, native mutex, allocator, or memory traffic. The next discriminating measurement is end-to-end native orchestration of the same branch operation (or a supported GIL-aware profiler), preserving identical task and isolation gates.
