# Thoughtexperiment deferred patch diagnosis v1

The experiment uses the exact `sc_canary_requests_commit` seed rule from `seeds/self_change_reasoning.json`. A small graph satisfies its three-edge join and canary/evidence guards; an active target rule supplies a real RuleUID/hash, and the patch carries a stale expected revision. The production rule dynamically builds a Commit node, queues `ApplyRulePatch`, and the queue drain writes `status=refused`, `reason=stale_revision` on the patch node.

All 17 analysis checks pass across three workers and 12 fresh-process arms. The unique pre-state rematch, all four branch strategies, primary rule/graph isolation, and exact corrected-branch graph equality pass. The deferred event reports source rule `sc_canary_requests_commit`, effect index 3; target-only and value snapshots both associate the drained patch-node write with that source. Target-only retains no value payload and ranks the unique deferred source effect first. Blind search tries four counterfactual branches, complete rematching two, target-only one, and value tracing one. The median isolated times are 2.484 ms blind, 1.013 ms rematch, 0.839 ms target-only, and 0.877 ms value tracing; with three replicates per arm these are exploratory. Target-only's median event report is 3,521 bytes versus 4,889 for value tracing.

This closes the original queue-to-effect identity gap for a uniquely sourced `ApplyRulePatch` node and shows that queue provenance can make the compact target trace competitive on this fixture. It does not establish natural self-repair or task prevalence. Other deferred operation families (`SetRuleClause`, framebuffer samples, net collapse, identity tracking), multiple distinct origins converging on one patch, provenance truncation, no-cause controls, and transient memory cost remain open. When multiple distinct effect origins converge, the current implementation retains the origin list but intentionally emits no single-source effect snapshot; callers must treat that event as ambiguous.
