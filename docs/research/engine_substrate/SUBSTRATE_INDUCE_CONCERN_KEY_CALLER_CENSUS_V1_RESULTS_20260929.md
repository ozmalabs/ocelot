## Key-policy implications from caller review

All 16 direct calls in `domains/` pass `name_hint`: 13 compute or forward an expression and three use fixed string literals. No domain-level call in this census relies on the default predicate-derived key. The explicit hints serve several different roles:

- **Content-derived shape identity:** `domains/ink_decode.py` builds names from `_signature_key(signature)`, a SHA-1 digest of the exact quantized relation signature. The ink and sub-stroke paths use this identity to install a shape quantum idempotently across repeated spans. It is content-sensitive but is not a canonical D4 key.
- **Pattern or construction labels:** `domains/reading_collapse.py` derives a name from relation heads; `domains/metrical_reading.py` names a metrical pattern; `domains/code_reading.py` forwards a caller-supplied construction hint. These are close to predicate-/class-level identities.
- **Caller- or task-owned identities:** `conversation_action`, `conceptualizer`, `substrate_extension`, `self_capability_collapse`, and `character_compose` accept or derive names from their calling context. Their identity contract must be read at the individual caller, not inferred from the shared API.
- **Fixed and feature-derived keys:** `consumption_quality.py` uses three stable concern labels; `recount_faculty.py` uses two fixed faculty tags; `cross_text_prior.py` names a selected style feature.

This mix means that `name_hint` already functions as a domain-specific key policy hook. The polyomino structure-key comparison exercises that hook, but does not imply one global key policy should replace current behavior. Before changing `induce_concern` or axis deduplication, caller contracts need explicit classification: whether an axis denotes a predicate family, a particular structure, a task concern, or a caller-named faculty; which repeated observations should coalesce; and whether callers depend on stable names for grounding or installation.

Tracing the 16 domain calls to their immediate consumers gives a second useful split:

| Consumer path | Calls | What the caller does with the result |
|---|---:|---|
| Concern-to-composer grounding: `consumption_quality` (3), `recount_faculty` (2), `conversation_action`, `conceptualizer`, `substrate_extension`, `cross_text_prior` | 9 | Reads or requires `capability_key` and passes it to `ground_concern`; key identity selects/reuses a task concern or faculty route. These names are not necessarily geometric identities. |
| Local library installation: `reading_collapse`, `metrical_reading`, `code_reading`, `ink_decode` (2), and `character_compose` | 6 | Primarily branches on `minted`, then installs a construction, foot, code form, stroke, sub-stroke, or character under a second domain key. Some paths separately re-decode after installation. `induce_concern`'s axis key and the domain library's install key are distinct identity layers. |
| Gap readback: `self_capability_collapse` | 1 | Returns the concern verdict to the gap caller; the immediate helper does not ground or install it. |

The `character_compose` domain call falls under local installation when reached through `arrangement_codebook.compose_arrangement`: that caller derives `name_hint` from a prefix plus the exact signature hash, branches on `minted`, and installs the character quantum under a content-derived name. This caller trace shows that the same API serves both task/faculty identity and structure-keyed vocabulary growth. Changing the default would affect different downstream contracts in different ways; the source census must be followed by behavioral compatibility tests before policy changes.
