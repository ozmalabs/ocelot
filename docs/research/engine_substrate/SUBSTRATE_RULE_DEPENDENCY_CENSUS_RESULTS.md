# Seed-derived rule dependency census

**Status:** exploratory source-structure analysis on two active workload families; not a runtime graph snapshot, proof of dependency completeness, or partition-preservation result.

## Workloads and extraction

The census covers the six active rules in [`can_native_reimplementation.json`](../../../seeds/can_native_reimplementation.json), exercised by the CAN native tests/orchestration, and the ten active rules in [`conversation_deliberation_phase4a.json`](../../../seeds/conversation_deliberation_phase4a.json), loaded by the boot profile/world adapter and covered by phase 4A tests. The raw manifest records seed versions and content hashes plus those runtime-path references.

Each rule is a node. A directed edge `writer → reader` is added when an effect in the writer rule changes a resource class the reader accesses. Match edge types and term-level edge reads are tracked directly. Two attribute-resource projections test sensitivity to alias assumptions:

- **Global key:** all accesses to an attribute key are treated as potentially aliasing. This is a high-recall overapproximation that can create many false dependencies.
- **Variable role:** attribute access is indexed by the matched edge type and whether the variable is an edge source or target. This is exploratory and can miss real dependencies when runtime nodes alias across roles or when nested terms access nodes through indirect tuple positions.

Both projections use the same effect/resource extraction and balanced hierarchical partition procedure as the synthetic census: seed order versus five fixed shuffled orders, with at most four rules per leaf. Exact treewidth is available because each dependency graph has at most ten nodes. See the [raw census JSON](../../../evaluation/reports/substrate_rule_dependency_census_20260924.json) and [reproduction script](../../../scripts/substrate_rule_dependency_census.py).

The conversation seed is highly coupled if attribute keys are treated as globally shared: 94 directed dependencies out of 100 possible and an exact width of 9. Refining by rule-variable roles reduces this to 29 dependencies and width 4; seed order then yields 14 cross-frame dependencies versus a shuffled median of 16. This large change is evidence that an unqualified “dependency graph” is not sufficient: node aliasing and attribute ownership must be represented. It is not evidence that the role-refined graph is complete. After the native access-walk correction and extractor coverage expansion, CAN has 27 global-key/23 role-refined dependencies and exact width 4 under both projections.

For CAN, both projections preserve a five-rule strongly connected component and one singleton. The global-key conversation projection produces one ten-rule component; the role-refined projection splits into two pairs and six singletons. Since the latter can under-approximate aliasing, those components are a diagnostic of the extraction model, not a discovered runtime decomposition.

## Limits and next gate

### Comparison with the native scheduler access model

The engine computes scheduler access sets in `RewriteRule::derive_access` (`runners/dsl/src/rewrite.rs`) by walking match edges, the where-term (`collect_term_reads`), and effects (`collect_effect_access`). Its keys are global `Edge(type)`, `Type(type)`, and `Attr(key)` resources, plus `reads_any`/`writes_any` flags for dynamic or otherwise untracked accesses. The scheduler's `dirty_by_writeset` consumes those sets. This is materially closer to the census's global-key projection than to its variable-role projection: the native representation does not qualify attributes by matched variable role. Consequently, width 4 for conversation deliberation is a sensitivity result, not a model of current scheduler locality; the global-key width 9 is the relevant structural warning, subject to discrepancies between the JSON extractor and Rust term/effect walkers.

### Native static-access comparison

A read-only PyO3 method, `rule_access_sets()`, exposes the derived keys and wildcard flags. The census now loads each active seed rule through the native rule parser in a fresh substrate, reads back the derived sets, and compares them rule-by-rule with the extractor. Across all 16 rules (six CAN, ten conversation), there are **zero native-only or extractor-only resource keys** and all `reads_any`/`writes_any` flags agree. The raw manifest records the native extension path/hash and source hashes for the binding and derivation code. This is exact static-access agreement for these seed definitions, not evidence that static access sets cover every dynamic graph read during execution.

The comparison exposed an omission in `RewriteRule::derive_access`: typed `Edges` and `ReachableFrom` term reads were not represented in the native edge-key set. The access walk now records their edge type and sets `reads_any` for any-type traversals. `EdgeAttr` reads set `reads_any` because the scheduler key space does not yet distinguish edge attributes from node attributes. The extractor was extended to cover these traversal forms and the raw census was regenerated. This is a correction to scheduler dependency metadata; semantic impact under live mutation still needs a runtime trace and replay evaluation. Native `reads_any`/`writes_any` remain explicit conservative dependencies.

### Runtime wakeup pilot

### Expanded dynamic access recall matrix

The 18-case [dynamic access recall matrix](SUBSTRATE_DYNAMIC_ACCESS_RECALL_MATRIX_RESULTS.md) extends the earlier insertion-focused probes to insertion and deletion across seven traversal forms, edge-weight replacement, node-attribute mutation, and node birth. It was rerun on the rebuilt current-source extension after the `AddEdge` progress-accounting correction and compared each reader output with a direct oracle over the final graph. Seventeen cases refresh correctly; the sole mismatch is an effect-only node-attribute read (observed 0, oracle 7). A predicate read of the same attribute refreshes correctly. All cases have a native static resource overlap and reach a terminal no-work probe.

This narrows the remaining finding: the failed case is not absent from the static access sets. `dirty_by_writeset` intentionally does not re-wake attribute-only consumers with no `where` clause, to avoid replaying effects that may add edges or mint nodes. The operational consequence is stale effect input after a relevant attribute write; the safe replay boundary by effect class has not been measured. This probe remains controlled rule-pair evidence, not full dynamic trace coverage or proof of task-level locality. Raw provenance and case data are in [`substrate_dynamic_access_recall_matrix_20260925.json`](../../../evaluation/reports/substrate_dynamic_access_recall_matrix_20260925.json).

A second diagnostic uses two rules over a tiny graph. Three cases exercise typed-edge insertion, deletion, and overlap between a match-edge type and a term-read edge type. A pre-fix binary control returned 0 for a reader whose direct final-graph count was 1; its binary hash and limitation are preserved in [`substrate_term_edge_wakeup_prefx_20260924.json`](../../../evaluation/reports/substrate_term_edge_wakeup_prefx_20260924.json). The first probe exposed that the dirty bit could be set while the semi-naive cursor remained positioned only on the unchanged `trigger` match. The reader therefore did not recompute its term-derived output. The scheduler now retains typed term-edge reads separately from match-edge drivers and invalidates the cursor when a write can change a term result on an existing binding. In all three corrected cases, the final reader value equals a direct count of the graph's typed neighbours, with three progressing firings per case. Corrected raw evidence and extension/source hashes are in [`substrate_term_edge_wakeup_20260924.json`](../../../evaluation/reports/substrate_term_edge_wakeup_20260924.json); the reproducible harness is [`substrate_term_edge_wakeup_pilot.py`](../../../scripts/substrate_term_edge_wakeup_pilot.py).

This is a small diagnostic set, not general scheduler coverage. It does not cover any-type traversal, `EdgeAttr`, predicate retraction, other execution modes, or broad workload equivalence. Those remain runtime coverage requirements before upgrading scheduler completeness.

These are dependency projections from authored seeds, not extracted dynamic graph state. Attribute resources are conservative only in the global-key projection; the variable-role projection deliberately trades possible false dependencies for possible omissions. The extractor does not yet model typed node ownership, aliases through `Nth`/tuple terms, callbacks/external state, scheduler epochs, rule activation changes, or data-dependent guards. A first native frame pilot now executes CAN rules in independent four-concept substrates and compares them with monolithic execution. It passes exact factorisation on a disconnected positive control (12/12 runs) and shows that independent frame settlement usually fails on connected path, banded, and complete controls: only 3/36 runs both match the monolithic state and remain stable under the full graph. The experiment omits cross-frame edges; it therefore falsifies naive independent settlement but does not implement boundary exchange/wakeup or establish factorisation for connected workloads ([`SUBSTRATE_CAN_FRAME_FACTORIZATION_RESULTS.md`](SUBSTRATE_CAN_FRAME_FACTORIZATION_RESULTS.md)). Dynamic access tracing, message/migration cost, and partitioned closure/inference with preserved boundary semantics remain open.

Next: expand runtime wakeup coverage across term forms, deletions, overlapping match/term edge types, and incremental-matching modes; then collect dynamic access traces on replayable workloads. The shared-graph boundary pilot and static wake queue are now measured in [`SUBSTRATE_CAN_BOUNDARY_FRAMES_RESULTS.md`](SUBSTRATE_CAN_BOUNDARY_FRAMES_RESULTS.md). A guarded matcher-level pushdown is now implemented for the common single `has_concept` edge and reduces candidate/Term counts while preserving outputs on the 48-case CAN envelope; the generic path remains for ambiguous membership. Next extend this optimization only where scope equivalence can be proved, and test dynamic read recall under boundary perturbations and edge insertions/deletions before claiming general frame locality. Keep global-key aliasing and native wildcard behavior as conservative controls. Do not report the role-refined width as a runtime bound until dynamic recall and partition-preservation are measured.
