# P4: rule-edit Terms and variation families as held Programs (2026-10-10)

This is phase P4 of [the open-ended self-improvement plan](OPEN_ENDED_SELF_IMPROVEMENT_PLAN_20261010.md).

## What changed

**Rule-edit Terms** were added to the engine in `runners/dsl/src/term.rs`, `jsonio.rs`, `reflect.rs` and `term_variants.rs`. All of them are pure and deterministic, and return `None` when the edit does not apply:
- **`EditAt{tree, path, op, arg}`** edits a Value tree at a path. The tree is usually a rule. Path steps are dict keys or sequence indexes, with negative indexes counting from the end. The ops are:
  - `set`: a missing final key is inserted;
  - `append`: the List/Tuple kind is preserved;
  - `drop`.
- **`CharRunSub{text, keep, repl}`** and **`StripChars{text, chars}`** together reproduce the identifier slug `re.sub(r"[^a-z0-9]+", "_", s).strip("_")`.
- **`LitRepr`** now also gives the Python repr of a *built* string (Surface text from `StringConcat` and similar). Before, it returned `None` for these.

`InstantiateTemplate` did not need to be a Term. The generator builds rule templates directly into `MkDict`/`Vec` Terms with the bound values spliced in (`build()` in `scripts/gen_family_programs.py`).

**FamilyPrograms.** `seeds/family_programs.json`, generated by `scripts/gen_family_programs.py`, holds the two families that have produced production adoptions as `FamilyProgram{name, program}` nodes:
- `family_disposition_generalise` (tranche 22);
- `family_deep_reader_correct` (tranche 23).

Each Program reads the concern's context from the graph:
- the live StandingConcern for the key;
- the SelfConcern promoted to it, and its turn;
- that turn's communication interpretation;
- the held protected types, the adoptable seeds and the refuted trials.

It returns the builder's report as a value: either the variant rules, or an honest abstain with the same wall text as before.

The host supplies the held rule set plus two mechanical indexes:
- `seed_of`: each seed manifest's own rule list.
- `name_rank`: "the first candidate by name". String order is not a Term comparison, because interned strings compare by interning order.

**Integration**
- `seeds/variation_ops.json` v1.22.0 sets `builder_program` on the two VariationOps.
- `reflective_faculty._compose_from_program` is the one generic interpreter.
- `_builder_for` picks the held Program whenever the op names one, and the Python registry otherwise.
- `OZMA_FAMILY_PROGRAM_PYTHON=1` restores the Python builder, for comparison runs only.
- `OZMA_FAMILY_PROGRAM_PARITY=1` runs both builders and records each comparison.
- `FamilyProgram` is added to `improvement_integrity` `protected_node_types`, so a delta cannot rewrite a family. As with the earlier additions, this list is a human decision and the change is flagged for review.
- `family_programs` is added to the conversation self-improvement anchors.

## Gate F4

| Check | Result |
|---|---|
| Sweep, 120 persona turns: both builders on a concern of each family about every turn (`family_program_parity_v1.py 120 persona`) | 121 + 121 cases, all equal. 51 + 32 variants built, the rest abstained. Wall texts equal too. |
| Sweep, 200 held-out turns (`family_program_parity_v1.py 200 held_out`) | 201 + 201 cases, all equal. 79 + 43 variants built. |
| Production run with both builders compared at every compose (`OZMA_FAMILY_PROGRAM_PARITY=1`, 120 turns) | 6 of 6 equal (1 deep-reader build, 2 generalise builds, 3 generalise abstains). |
| Production run with the Programs as the only builders (the default) | The tranche-24 adoptions reproduce: the deep-reader correction, the generalisation and the chained generalisation, with the same experiments and the same reopen. |

"Equal" compares the delta-relevant report: built, the rules, removed or source rule, guard, new value, basis, and the shallow/deep pair (`family_report_signature`). The prose `how` field is not compared.

The production runs differ from the P2 run only on topic-search question turns, which timed out under load (the two runs ran concurrently). Post-run error/none was 27 and 26, against 25 in P2. Every differing reply is a question turn whose first-pass status was `timeout`.

**Cost.** A Program call takes 0.30 s, against 0.09 s for the Python builder (10 turns × 2 families). Composes happen a few times per run.

## Regression

## Next (P5)

With families held as data, the agent can propose new ones: bounded mutation and composition of held Programs over these Terms, evaluated on a held-out bank of concerns. P2 left a concrete first target. `reply_quality` concerns about `statement->goal_take` are exactly the deep-reader correction's class, but `variation_pick` gates that family by concern kind. A composed family, the deep-reader program reading a reply_quality concern's turn, is the obvious first candidate.

P5 runs propose-only until a human adds the narrow `operator_authorship` exception to `improvement_integrity`.
