# Thoughtexperiment cross-family idempotence transfer v1 — results

**Result:** 9/9 amended confirmatory gates pass; see the [protocol amendment](THOUGHTEXPERIMENT_CROSS_FAMILY_IDEMPOTENCE_TRANSFER_V1_AMENDMENT_20261001.md).

Three workers each trained on an actual shape-axis correction, then compared cold and outcome-informed ranking on fresh recurrence-ledger tasks. The recurrence task's independent oracle requires exactly one candidate-linked offer and a zero-progress closure; candidate rehearsal occurs only on full-copy branches.

| Arm | Trials to oracle | Cross-target prior successes | Oracle passes |
|---|---:|---:|---:|
| `cold` | [1, 1, 1] | [0.0, 0.0, 0.0] | 3/3 |
| `experience` | [1, 1, 1] | [1.0, 1.0, 1.0] | 3/3 |

Outcome transfer reaches the graph-authored policy across the two target rules: the cold traces have no matching class history, while each transfer trace sees the training success. However, both cold and transfer arms rank the repair first and pass in one trial. The structural-cost prior already chooses correctly, so this panel shows evidence consumption but no measured improvement in search cost or outcome. A future evaluation needs a preregistered task on which cold ranking is demonstrably suboptimal before claiming utility gain. The substrate did not invent the shared class, repair, or utility label, and record transport remains host-managed.
