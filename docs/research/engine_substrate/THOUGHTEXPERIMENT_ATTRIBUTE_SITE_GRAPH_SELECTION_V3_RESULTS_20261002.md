# Thoughtexperiment graph-resident proposal selection v3 — results

**Gate result: pass for graph-Term scoring within a host-supplied candidate set.** Four workers repeated the cue-free `classify_meter_delta` task. The ordinary composer abstained; the host enumerator supplied fault, forward swap, and reverse swap candidates. Across 32 CoW/full-copy and alias-rate conditions, each source-locked query's post-oracle evidence selected `forward` as the unique graph-Term winner. It passed all five held-outs per worker; fault and reverse each failed nonzero held-outs. The independent analyzer passes all 18 gates.

Candidate and evidence nodes were written to a fresh snapshot branch. The branch was discarded after scoring, and one `ExperimentResidual` per condition returned the selected proposal ID and probe identity to primary. Across workers, primary retained all original rule definitions, held eight compact residuals, and contained no candidate/evidence nodes. Per-worker tie and all-wrong controls abstained; incomplete coverage and duplicate experiment namespaces were rejected. Incomplete rejection made no graph changes.

Mean graph evidence materialization plus Term selection was 0.205 ms per case; branch fork was 0.0238 ms and compact residual return was 0.0150 ms. Generic candidate enumeration took 0.404 ms, composer abstention 23.18 ms, and the active probe phase took about 148 ms per 100-input pool with three hypotheses. These are small-fixture measurements and the oracle, task, candidate vocabulary, and predictions remain host-supplied. The native Term now owns candidate scoring and unique-winner selection; it does not invent candidate rules or verify oracle truth.

The earlier v2 pilot is censored because its tie control was accidentally a 1-vs-2 score and candidate evidence was written directly to primary. V3 corrects both; the v2 failure is preserved in the [censor note](THOUGHTEXPERIMENT_ATTRIBUTE_SITE_GRAPH_SELECTION_V2_CENSORED_20261002.md).
