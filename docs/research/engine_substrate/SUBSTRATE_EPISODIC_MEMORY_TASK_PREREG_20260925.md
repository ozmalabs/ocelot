# Preregistration: graph-authored episodic memory task pilot

**Question.** Do the current graph-authored episodic rules retrieve task-relevant stored events under unrelated-memory growth, reduce confidence and abstain under cue ambiguity, and distinguish reset-memory from no-memory operation?

**Exploratory work disclosed.** Before this protocol was frozen, development workers were run for all six arms, and an earlier inline probe exercised unique cues and collisions. Those checks informed harness construction and are not confirmatory evidence. The measured run is the first scored run under this frozen protocol.

**Task construction.** Each memory-enabled worker starts fresh with the `episodic_working_memory_core` seed, receives six target route episodes, then runs graph closure once. The targets use unique cue keys, known exact route summaries, observed acquisition status, and fixed high salience/surprise/value. Three load arms add 0, 18, or 72 unrelated high-salience episodes, yielding 6, 24, and 78 expected Episode records. A collision arm instead adds one low-salience alternative with the same cue for each target, plus 18 unrelated episodes (30 total). Each stored task is queried once, followed by one never-seen cue. Reset-memory starts the episodic rules but acquires no events; no-memory starts an empty seed profile. These controls each receive six unique-cue requests, six ambiguous-cue requests, and the unknown-cue request. All workers run in separate child processes.

**Frozen scoring.** Evaluator answers only when reported confidence is at least 0.75; otherwise it abstains. Unique-memory success requires exactly one recall candidate, the exact expected summary, `provenance_kind=recalled`, and `observation_status=not_observed`. Collision success requires a single candidate, confidence and uncertainty both 0.5, an answer drawn from that cue's two stored alternatives, and evaluator abstention. Unknown cues must abstain with insufficient-information or no-memory status. Reset-memory must explicitly return insufficient-information for all requests. No-memory must emit no candidate and abstain for all requests. The unique query identifiers must be distinct within each worker. Episode counts must equal the declared arm sizes.

**Primary measures.** Exact unique-task accuracy at each interference size; collision abstention and confidence; unknown-cue false-answer rate; reset/no-memory false-answer and candidate rates; graph/acquisition counts; per-query tick latency; acquisition closure latency; boot latency; and per-worker peak RSS. Report raw query outcomes and per-arm aggregates. Timing is descriptive: this pilot has no latency pass threshold and does not estimate asymptotic complexity.

**Pass criteria.** All 18 unique-memory tasks across the three load arms meet the exact-recall conditions. All six collision tasks meet the ambiguity/abstention conditions. Every unknown request abstains. Reset-memory has 13 explicit insufficient-information responses; no-memory has zero candidates and zero answers across 13 requests. Declared episode counts and unique query IDs reconcile. Any failed criterion is reported as a failure; no post hoc threshold changes.

**Claim boundary.** This is a controlled, hand-authored cue-retrieval task against the current episodic rule seed. It measures task-linked recall under synthetic unrelated load, ambiguity calibration at one confidence threshold, and two negative controls. It does not establish natural-task memory utility, semantic cueing, durable retention, eviction/consolidation, restart recovery, broad provenance fidelity, learned frame locality, or general capability. The 0.75 threshold is a benchmark policy, not an empirically calibrated universal threshold.
