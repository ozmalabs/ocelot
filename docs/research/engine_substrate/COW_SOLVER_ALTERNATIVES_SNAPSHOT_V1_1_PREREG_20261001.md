# Solver-alternative reusable snapshot consumer v1.1 preregistration

Date: 2026-10-01

This is a measurement amendment and fresh capture after v1 omitted the branch-creation timings required by its protocol. The v1 capture is preserved and is semantic-only evidence.

## Question and workload

Can the actual native CAN solver run multiple local alternatives from one immutable `SubstrateSnapshot`, with reusable CoW branches preserving solver results and primary/sibling isolation against eager-copy controls?

Load the current native CAN rule seed into a fresh Substrate and construct one four-concept Microtheory with bidirectional weighted influences. For each of four preregistered external-field perturbations, create one branch from a shared `snapshot("shared_graph_pages")` and one eager deep-copy branch from the same primary revision. Invoke production `domains.can_native_orchestration.scoped_settle` and `native_audit_basin` on each branch. Repeat each perturbation across five fresh worker processes, varying only deterministic initial fields/weights under the recorded seed schedule (20 workers total).

## Gates

- Complete all 20 unique perturbation × replicate cells in fresh processes under stable source/native locks.
- Snapshot backend and source revision match the primary at capture.
- Every child starts from the same pre-branch model; reusable and eager outputs match exactly on settled states, steps, energy, frustration, and graph facts.
- Branch writes and solver mutations remain isolated from the primary, immutable snapshot, and sibling alternatives.
- Record reusable/eager branch creation time separately from solver time. No speed threshold is set for this small workload.

## Limits

One small native CAN solver, one four-concept topology, four perturbations. This does not validate solver optimality, general planning, concurrent mutation, cancellation/reclamation, adoption/conflict policy, natural-task prevalence, large-scale speed, or vLLM-style serving.
