# Code-write example acquisition v1 — pre-capture lock amendment

Before any experimental worker ran, timing the first lock-generation attempt showed that recursive traversal included more than 300,000 nested seed data files (over 1 GB) that `load_all_seeds` does not load. That initial lock was generated before capture, used an unnecessarily broad input scope, and is preserved as `substrate_code_write_example_acquisition_v1_lock_20261001_pre_run.json`; no trial data were produced under it.

The replacement lock hashes every flat seed manifest and every `seeds/generated/*.json` manifest that full boot may read, all Python/Rust implementation source trees, the Python native binding, and the native binary. A complete pre-panel and post-panel fingerprint guards against source or seed changes during the study. Each worker also checks its active code-reading, code-writing, boot, seed-loader, native, and task-specific seed dependencies against the locked digests immediately before and after its trial. This changes only provenance collection cost and coverage precision; the task panel, schedule, procedure, outcomes, and claim boundary are unchanged. The finalized protocol, runner, analyzer, and new lock are captured together before any worker executes.
