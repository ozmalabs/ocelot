# Contract query batched prediction matrix v1 — preregistration

## Question

The finite disagreement selector repeatedly evaluates the same pure hypothesis/input pairs while filtering observations and rescoring candidate inputs. Does precomputing one prediction matrix per selection sequence reduce end-to-end wall time without changing query choices, predicted values, or finite-set outcomes?

## Arms and panel

Compare the current uncached `select_discriminating_input` with an opt-in batched-matrix implementation. Each fresh worker runs one arm on one generated binary-coded Term family at H/N=(32/500), (128/28), or (512/36), with three paired repetitions per cell and randomized arm order. The same Terms, candidate inputs, initial observation, target, native evaluator, and oracle are used in each pair. The target identifier is analysis-only and is never passed to either selector. Each sequence runs until its finite candidate set identifies the target or its query budget is exhausted.

The matrix arm may cache predictions only within one call sequence, for the exact supplied pure Terms and environments. It must reject unsupported graph-dependent Terms and must preserve candidate order for entropy ties. Both arms also run a fixed misspecification control in which the true function agrees with the surviving finite hypothesis on every available candidate input but differs on a held-out input; both are expected to reach the same finite singleton, demonstrating that batching does not add model-adequacy guarantees.

## Gates and measurements

Require current source/native lock before and after each fresh worker; exact query-history, entropy, prediction, oracle-label, terminal-reason, and survivor parity within every pair; independent closed-form checks for all generated Term values; explicit confirmation that the target is not exposed to the selectors; and equality of the misspecification outcome across arms. Record native calls, prediction-matrix cells, matrix bytes, wall time for the full query sequence, and peak RSS. Preserve all worker errors and timing regressions.

The preregistered decision rule is descriptive: consider the matrix path for production only if it preserves all semantic gates and its median speedup over the current uncached route is at least 1.25× in both the H=128 and H=512 cells without more than 2× peak RSS. Otherwise retain the current selector and report the measured tradeoff. This is a synthetic pure-Term algorithm comparison on one host; it makes no claim about graph-dependent inference, natural task prevalence, or general learning.
