### Fallback and safety contract

When recall is absent, stale, ambiguous, incomplete, cross-domain without a registered mapping, or lacks a matching exact verifier receipt, the system generates a local candidate or opens the existing explicitly funded executor. P5 planning may rank model-supported candidates, but every candidate remains imagined until a current observation/action receipt verifies the exact goal-relevant outcome. A failed or missing P4 C5 benefit cannot authorize a probe or action. G3 must withhold stopped actions at the external/native sink; graph status alone does not count as inhibition. Every P5 decision, temporary policy enablement and funded operation must preserve model/source epochs, provenance, one request/one debit accounting and terminal restoration.

## P5.F1.1 — Attributed-state view contract

The shared view is a provenance-preserving projection, not a shared belief store and not a new truth layer. Each projected row has a stable `view_id`, `source_kind`, `source_node`, `source_epoch` (including an explicit unknown marker), `holder`, optional `target`, `content_ref`, `modality`, and `epistemic_kind`. Rows remain separate when content or holder differs; disagreement is represented by coexisting rows. The projection may add `projects_source` and `uses_vocabulary` lineage edges, but does not edit source records. `TomViewPolicy.enabled` is registered disabled by default; F1.2 must not activate it in CORE/default boot.

The four source forms are mapped as follows:

| Source form | Holder / target | Content and modality | Epistemic kind and boundary |
|---|---|---|---|
| `character_tom` nested `SmEntity` | `belief_holder` / target parsed from the nested proposition when available | source entity plus `flavor` and proposition | `attributed`; character belief-world content is not actual-world truth |
| psychology seed | no holder or target on its own | vocabulary concept reference only | vocabulary-only; it creates no attributed-state row without a separate live state source |
| interlocutor model | observing agent / modeled `Party` | feature estimate or self-report assertion reference | estimates are the agent's `estimate` of the party; the interlocutor's `Assertion` separately records `world_assertion` by its speaker and does not certify truth |
| Bigville resident agency attribution | resident / target resident | `controllability_for:<target>` Concept and its owning Microtheory | `attributed`; resident-owned `regard_for`, `desire_for`, `removal_desire_for`, and `pity_for` are own affect/motivation and must not enter this view as beliefs about the target |

Epoch is copied from a source's explicit revision/version field if present; absent source epochs remain explicitly unknown and must not be fabricated from wall time or a different owner's clock. Revisions produce a fresh projection identity for that source epoch and leave the prior projection/provenance intact. A vocabulary reference can annotate a live state row but cannot supply its holder, target, modality, or epoch. F1.1's contract tests exercise fixtures; F1.2 separately verifies the native graph projection path.

The migration preserves the existing `tom_meta_shape` observation behavior and its two domain-specific translators. The shared attributed-state view does not make unrelated domain corpora structurally identical, and retired Python psychology functions remain retired.

## P5.F2.1 — Recursive ToM contract

A recursive world is identified by the complete ordered holder path, referent, and actual-world version. A second-order state such as “Sally thinks that Anne believes the key is in the drawer” therefore has holder path `[sally, anne]`; it cannot collide with `[anne, sally]` or a first-order `[sally]` world. Actual-world observations are immutable with respect to belief updates. A belief update requires an explicit observation/access event addressed to the relevant holder path; absence of access leaves the queried state unknown. Answers are `true`, `false`, or `unknown`, with unknown preserved when a path is absent, unsupported, cyclic, or deeper than the configured maximum (initially 2 attributed holders). Repeated event IDs are idempotent. Swapping holder order must change identity and may change the answer.

F2.1 fixtures cover a second-order false belief against an unchanged actual world, an update with and without access, path-order identity, cycles, and the depth-2 bound. These tests define the behavior contract; F2.2 will implement it in disabled-by-default native rules, and F2.3 will replace adapter decisions with event/readback mechanics.

## P5.G2.1 — Evidence-preserving reappraisal contract

An observed event is immutable input. Reappraisal may create a separate interpretation view, but it never edits the event, its source, or its forced constraints. A candidate interpretation is admissible only when every factual claim has at least one current evidence reference and no known evidence contradicts it. Mere absence of adverse evidence does not support an optimistic claim. The view records the source event ID, chosen frame ID, evidence IDs, and appraisal result so relief or a frame label cannot masquerade as verified world truth. Arousal changes remain an input to appraisal and do not qualify as evidence for an interpretation. At most two candidate alternatives are considered per probe; no supplied alternative or no evidence yields no reappraisal. The policy remains disabled by default.

The G2.1 development fixtures freeze four discriminators: a supported alternative is represented as a separate reappraisal view; the source event stays byte-for-byte unchanged; optimism unsupported by evidence is refused; and an absent alternative produces no view. The fixtures also carry forced constraints to ensure a later implementation cannot relax them. These tests are specification fixtures, not evidence of runtime behavior; G2.2 owns the native rule implementation and G2 evaluation remains held out.

## P5.G3.1 — Action inhibition contract

The G3 state model separates proposal, selection, revocable authorization, sink-confirmed emission, and later observation; stop-before-commit ends in a terminal withheld state, while a post-commit stop reports `already_emitted` and never claims physical undo. Stop and go for the same request and source epoch resolve stop-first before sink commit regardless of insertion order. Authorization is request/epoch/action/route-specific, single-use, and cannot be reused after sink failure or withholding; a retry requires a fresh request identity. G3.1 identifies `WorldAdapter.fire_reflexes` and Rust `PySubstrate::next_ready_reflex` as the common reflex selection/callback path; the selector's scheduling stamp is not an emission receipt. G3.2 implements graph stop/withhold lifecycle. G3.3 adds a native authorization check immediately before reflex callbacks and consumes authorization once; instrumented reflex sink tests pass. The inventory also found `live`/`live_examined` world `apply_action` behind `_authorize_world_action` and a direct `live_gamma` `apply_action` route; these do not yet cross the common native token gate. G3.3 and the registered G3 held-out evaluation remain pending until those routes are covered.

### G3.2 graph lifecycle implementation

The generated self-load-only `response_inhibition` seed keeps `ResponseInhibitionPolicy.enabled=0` by default. When explicitly enabled, a same-request/same-epoch stop changes proposed, selected or authorized requests to terminal `withheld`, revokes a pending authorization, and marks the stop event `withheld`; a stop linked to an already `emitted` request is recorded as `already_emitted` without changing the request. A stale stop does not affect the request. Terminal withheld requests cannot be rearmed by a later authorization. The contract and native graph lifecycle suite passes 10 tests. This implements graph records only; G3.3 sink enforcement and held-out evaluation remain pending.

### G3.3 reflex callback gate (partial)

Rust `PySubstrate::authorize_reflex_emission` now checks the policy, selected action identity, sink route, current epoch, one pending matching authorization, and same-epoch stop state under the graph mutex. It consumes the authorization before callback invocation; `complete_reflex_emission` records `emitted` plus a sink receipt ID on callback return, or terminal `emission_failed` without restoring authorization. `WorldAdapter.fire_reflexes` is the only caller of `next_ready_reflex` and now routes every registered response callback through this gate. Focused native sink and reflex tests pass 23 cases. A route audit found `live`/`live_examined` world `apply_action` commits and a direct `live_gamma` `apply_action` path that do not use this token gate. ## P5.E3.1 — Finite SCM specification

The new [`COGNITION_SCM_CONTRACT.md`](COGNITION_SCM_CONTRACT.md) freezes a bounded finite acyclic SCM: complete in-domain equations, 16 endogenous variables, domain size 8, and at most 4096 exogenous assignments; over-bound, cyclic, incomplete or unsupported models return unknown. `do(X=x)` replaces X's equation on a detached model; conditioning filters observations; unit counterfactuals preserve the same exogenous assignment. Observational effects require a valid backdoor set, no treatment descendants, d-separation in the treatment-mutilated graph, and positivity in every included stratum. CAN edges and associative CausalFacts are not equations absent explicit mechanism mappings. The pure `SCMIntervene` Term is implemented through R1–R4 with native Rust and Python conformance fixtures for do-versus-condition, shared-exogenous counterfactuals, malformed/cyclic/bounded abstention and source provenance. E3.2 wires it behind a disabled policy using detached supplied models; no result is promoted to observation or action authorization.

The generated `scm_reasoning` seed is self-load-only (SLO) and default-off.
