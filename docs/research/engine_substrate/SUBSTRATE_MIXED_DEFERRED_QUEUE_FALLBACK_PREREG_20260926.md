# Preregistration: mixed deferred-queue fallback parity

**Question.** If one scoped rule firing queues RulePatch, TrackIdentity, and NetCollapse work together, does a caller's global-closure fallback reproduce ordinary full closure across all three state types and downstream frame outputs?

**Frozen matrix.** One, two, or four previous/current percept pairs and frame-owned outputs; two fresh-process repeats; `full`, `scoped_only`, and conditional `scoped_fallback` arms. A controller-owned anchor fires once. That firing queues (a) a CAS-valid RulePatch changing one target rule's `where` from false to true, (b) TrackIdentity over all previous/current percept nodes, (c) one NetCollapse update to a deterministic one-unit ReLU net, and (d) a graph marker that closes the writer trigger. The one-step scoped call must stop with deferred work pending; the fallback arm invokes global closure only on that report.

**Gates.** All three scoped-queued mechanisms must have observable effects after fallback: committed RulePatch receipt and revised target rule, identities assigned to every percept pair, and nonzero updated W2/b2 plus ReflexNet surprise. The newly enabled target rule must reach every frame output. Full and fallback state projections must match exactly, with terminal fixed point and zero follow-up work. Scoped-only must retain pending/unapplied queue results (pending patch, unset identities, zero network readout, incomplete outputs) while the anchor marker shows the initiating firing completed. Require fresh PIDs, identical build identity, and locked hashes.

**Claim boundary.** This tests one simultaneous mixed firing and one deterministic graph at up to four pairs. It is not a stress test for arbitrary queue lengths/orderings, more than one writer firing, concurrent patches, framebuffer effects, natural workload prevalence, or cost. It does not make notifications automatic; callers still must honor pending status and `frame_notifications_complete=false`.
