# Production-derived thoughtexperiment diagnosis v1

The source-locked panel uses the exact `discourse_goal_resolve` rule from `seeds/conversation_discourse_state.json`, except its `outcome` constant is changed from `native_event_result` to a declared `fault_marker`. The fixture supplies a four-edge match, status and event-index guards, the seed's unique `for_goal` condition, and the existing variable-bound `last_transition_event` effect. An independent graph/rule rematcher finds exactly one valid binding. This is a controlled fault injection into one real seed rule shape, not a live task.

All 15 analyzer checks pass across three workers and 12 isolated arms. Blind endpoint search, full rematching, target-only trace, and full value trace all select an omission that removes the fault marker; each branch yields the same exact healthy graph, and all primary graph/rule revisions remain unchanged. Blind, rematch, and target-only methods each try three branches; value trace identifies effect 2 and tries one. Isolated median total times are 1.134 ms blind, 1.865 ms rematch, 1.257 ms target-only, and 1.004 ms value trace. Median serialized report sizes are 921, 921, 1,714, and 2,594 bytes respectively. At this size, the saved counterfactual branch outweighs value capture cost, but three replicates per arm are too few for a stable speed claim. Target-only did not narrow this case beyond complete rematching because several effects write the same goal node.

This result adds evidence that the observer and thoughtexperiment branch path work on a production-derived joined rule with a dynamic Term value. It does not establish natural-task prevalence, broad diagnosis, or self-repair. Deferred effect queues and dynamic deferred arguments are not exercised. Source inspection also shows a concrete attribution gap for the next panel: queued `SetRuleClause`/`ApplyRulePatch` operations are drained after the original effect event, and the deferred event records originating rule names but does not retain the source effect index. Thus current per-effect target/value snapshots cannot attribute the eventual deferred writes to their enqueueing effect. The next gate should use a production-derived deferred effect family and compare the same four policies while auditing queue drains, branch isolation, and returned residuals.
