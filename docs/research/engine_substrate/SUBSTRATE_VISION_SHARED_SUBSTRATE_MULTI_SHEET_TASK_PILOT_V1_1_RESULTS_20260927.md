# Shared-substrate multi-sheet task pilot v1.1: interrupted harness result

V1.1 did not complete its first arm and produced no task-quality measurement. Its heartbeat log records two 3,000-step retinal-development calls in 2.16 seconds, then 200 of 2,000 paired theta-adaptation presentations in 135.9 seconds. The two sampled 100-presentation checkpoint statuses were `repeated_graph_state`. No arm partial or worker source-stability record was finalized. See the [interruption record](../../../evaluation/reports/substrate_vision_shared_substrate_multisheet_task_pilot_v1_1_interrupted_20260927.json) and [heartbeat log](../../../evaluation/reports/substrate_vision_shared_substrate_multisheet_task_pilot_v1_1_20260927.worker.log).

The short development phase reveals a protocol flaw. `WaveWorld.step` calls default `tick`, whose enabled DualProcess path filters rules to the `hard_realtime` latency class. V1.1's benchmark manifest clone only changed `st_settle` scope and did not tag the five vision seed families. Given the previously measured default-tick filter result, development likely advanced the Retina clocks while the vision rules remained inactive. This is a source-based diagnosis; v1.2 must verify execution classes and retinal calibration directly before accepting any task result. Consequently, neither the adaptation timing nor the two status checkpoints describe a calibrated two-sheet vision task.

V1.1 is retained as a failed/censored harness attempt. It establishes that the current per-pixel two-sheet presenter is costly, but does not locate all of that cost or establish engine scaling. V1.2 adds benchmark-only `hard_realtime` tags to the five vision manifests, verifies both retinal gain/channel calibration, uses batched equivalent state writes, and snapshots the prepared graph so blank/replay/grating readouts share one adaptation per scope. The replay control checks that graph restoration reproduces an identical blank response before interpreting the B-to-A contrast.
