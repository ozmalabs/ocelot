# Budgeted staged-revision order and readiness guards v1 results

All preregistered gates pass in three workers at N=2/8/64 across normal/reverse rule order and guarded/unguarded arms. The reverse-order unguarded control reproduces a false commit at every size: with `max_steps=1`, all four rules make progress (overshoot 3), the commit marker advances to revision 1, but `top_count=0` and selection is the empty string although the independent score oracle has a unique winner. A subsequent full settle does no work and leaves the incorrect committed result unchanged.

Readiness guards prevent the false commit. In reverse order, the budgeted pass applies only the max stage, leaves the old `resolved_revision` and selection intact, and returns with `max_revision=1` but count/decision stamps still old. A subsequent full closure resumes the missing stages and commits the correct winner. At N=64, resume uses 709 Term evaluations. In normal order, guarded and unguarded arms both happen to complete correctly in the first pass (four steps, overshoot 3), demonstrating that favorable authored order can mask the missing prerequisite checks.

This establishes that revision stamps alone are not sufficient if downstream stages may compute from stale upstream values; each stage must guard on the current upstream revision, and commit must require all stages. The substrate does not enforce those dependencies automatically. The probe covers sequential authored rule order and one controlled mutation; it does not establish concurrency safety or a universal design for arbitrary rule effects.
