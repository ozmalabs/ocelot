# Preregistration: native exact-cue attribute index

**Question.** Does the substrate's existing `Episode.cue_key` attribute index, queried through `NodesWhere`, reduce request-count prototype query work beyond removal of the pairwise collision rule? Does index reconstruction after checkpoint load preserve results?

**Variants.** `baseline` is the checked-in seed. `request_count` removes only the pairwise overlap rule and computes collision confidence by request-scoped Count(Filter(...)). `request_indexed` removes the same rule, replaces both Count(Filter(...)) and the Argmax Filter source with `Count(NodesWhere(Episode,cue_key,request.cue_key))` and `NodesWhere(Episode,cue_key,request.cue_key)`, respectively. The native attribute index is explicitly declared after writing the graph and again after loading it; indexes are derived in-memory state. All modifications are in isolated manifest copies. No checked-in seed or engine source is changed.

**Workloads.** Exact key unique and one two-event collision workloads; N=6/24/78/192; two fresh writer/checkpoint replicates per cell; each checkpoint read in separate control and audit processes. 48 cells total (2 workloads × 4 sizes × 2 reps × 3 variants). No retries or omitted cells.

**Correctness.** All readers must return exactly one candidate with expected event summary, recalled provenance, `not_observed`, confidence 0.85 for unique and 0.5 for collisions (absolute tolerance 1e-12). Baseline must retain the pair rule and mark both collision Episodes; both prototypes must omit that rule and preserve their existing Episode attributes (`.85` cap and `distinct_event_record`). Indexed variant must report the attribute index declared in both writer and post-load reader; the two other variants must not.

**Measures.** Fresh-reader uninstrumented tick latency, audit overhead, global and per-rule counters, candidate tests, where evaluations, term evaluations, Count/Filter calls, checkpoint/node counts, RSS, episode attributes, and exact result. Primary indexed-vs-count comparisons are candidate tests and term/where evaluations as well as wall time. `NodesWhere` can still be evaluated during rule processing; the retrieval rule's match-edge join may independently enumerate N Episodes. This experiment distinguishes indexable Term work from rule-matcher work; it does not assume total O(1) lookup.

**Claim boundary.** Synthetic exact-key cases only, N≤192, two replicates. It does not establish production semantics, natural workload performance, concurrency correctness, or tractability beyond this path. Checkpoint semantics are tested only insofar as the index is rebuilt from restored graph data before query execution.
