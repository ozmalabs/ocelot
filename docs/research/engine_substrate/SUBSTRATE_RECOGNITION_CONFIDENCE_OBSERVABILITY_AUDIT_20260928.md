# Transform-recognition confidence observability audit

**Question:** can the current substrate transform/dimension recognizers expose a candidate margin that could support calibrated fallback or selective prediction?

## Source findings

- `TransformDecode` returns `explained`, `base`, selected `transforms`/`dims`/`deltas`, `checked`, `residual_unexplained`, and `identity` ([implementation](../../../runners/dsl/src/shape_decode.rs#L2337), result assembly at [L2465](../../../runners/dsl/src/shape_decode.rs#L2465)). `checked` is the number of held shape parts inspected. Successful candidates are ranked by number of changed dimensions and substitution-pair count, then held-part name; an exact remaining tie follows iteration order ([candidate selection](../../../runners/dsl/src/shape_decode.rs#L2384)). It does not return a candidate list, runner-up, score, or margin.
- `DimInfer` returns the selected base/generator/step sequence, `explained`, and `checked` ([implementation](../../../runners/dsl/src/shape_decode.rs#L2602), output at [L2927](../../../runners/dsl/src/shape_decode.rs#L2927)). Successful hypotheses are ranked by composition length, residual dimensions, base name, and step values; equal remaining candidates preserve generator iteration order ([ranking](../../../runners/dsl/src/shape_decode.rs#L2860)). `checked` counts attempted part × generator × parameter combinations, not evidence strength. There is no runner-up score gap.
- `ShapeDecode` exposes selected-plan `covered_count`, `total_fit`, per-step `shape_fit`, and `budget_exhausted` ([implementation](../../../runners/dsl/src/shape_decode.rs#L1614), output at [L1856](../../../runners/dsl/src/shape_decode.rs#L1856)). It returns the selected best-so-far plan, not alternative plans or a normalized probability. `total_fit` is a search ranking statistic; the source does not define it as confidence.
- The LS20 adapter consumes the rule-written `Observation.status`, `covered_by`, and selected `has_transform` node, converts the chosen generator into a canonical key, and returns `None` for refusal ([adapter](../../../worlds/arc_ls20_scenario.py#L145)). It does not read candidate counts or confidence. The sigma-8/10/12/14 replication therefore measured the current fail-closed key/refusal behavior, not a confidence threshold.
- The only `confidence` output found in this Rust module is in the separate `eval_blink_bridge` temporal extrapolation path ([source](../../../runners/dsl/src/shape_decode.rs#L5360)); it is computed from confirmed run support relative to the extrapolation gap, not from transform-candidate separation. Reusing it as transform confidence would be semantically invalid.

## Conclusion and next measurement

The transform path currently offers categorical explanation/refusal plus search-work counts and residuals, but no calibrated confidence or candidate margin. A margin cannot be recovered from `checked`, `total_fit`, or the selected Occam-ranked explanation. The robust sigma-12/14 refusals in the LS20 panel are valuable behavior, but the engine exposes no score that would let a downstream policy distinguish near misses from severe perceptual failure.

Before changing inference semantics, measure the current implementation's candidate structure on a held-out shape family. A separately preregistered instrumentation change could retain top-two candidate ranks and rejection reasons while preserving the selected winner; first require exact winner/status/graph parity on all existing transform/dimension fixtures, then quantify allocations and latency overhead. Calibrate any score only on a disjoint calibration set and evaluate selective risk (wrong-key rate among accepted cases, coverage, refusal cost) on a sealed test set. Do not call raw rank gaps probabilities without that calibration.
