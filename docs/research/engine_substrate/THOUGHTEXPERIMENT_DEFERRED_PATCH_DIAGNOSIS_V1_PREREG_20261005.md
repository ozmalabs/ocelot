# Thoughtexperiment deferred patch diagnosis v1 (preregistration)

Question: does carrying enqueue-effect identity through the `ApplyRulePatch` queue let target/value observers attribute the patch-drain receipt to the production rule effect that queued it?

Fixture: load the exact `sc_canary_requests_commit` rule from `seeds/self_change_reasoning.json`. Add one simple active target rule to obtain a real RuleUID, revision, and content hash. Build a three-edge `SelfChange -> RulePatch -> Canary -> CanaryEvidence` chain satisfying the production rule's pending-canary and evidence thresholds. Set the patch's expected revision to a deliberately stale value while keeping its UID/hash/field/proposed clause well-formed. The production rule's dynamic Commit construction and `ApplyRulePatch` remain intact; the patch queue drains and writes `status=refused`, `reason=stale_revision` to the patch node. This is an authored one-binding fault/control fixture using a production seed rule, not a live self-repair task.

Four arms start from the same graph/rule revision and use shared-graph-page snapshots for actual omission branches: (A) endpoint report plus blind ascending-index omission; (B) endpoint report plus complete pre-state graph/rule rematching; (C) target-only trace and omission search; (D) before/after value trace and omission search. Branches remove one effect, run closure to a 10-pass bound, and are scored by whether the refused receipt is prevented while primary state/revisions remain unchanged. The rematcher must reconstruct exactly one binding using all three directed edges and the canary/evidence attribute guards. The target/value arms may use only their report fields; the target selector ranks a unique deferred source effect before other effects touching the same patch node, while the value selector requires a status transition to `refused`, not merely a post-state value. Three workers and three fresh isolated replicates per arm are planned.

Gates require source lock integrity, one valid pre-state match, queue drain and `stale_revision` receipt in the primary experimental branch, exact equality of cured branch graphs across arms, primary isolation, correctly propagated deferred origin rule/effect metadata, target-only zero value payload, value-trace transition attribution, and worker/isolated parity. Report timings are exploratory at this small scale. This does not test multiple convergent origins, queue overflow, other deferred operation families, no-cause prevalence, or natural self-repair utility.
