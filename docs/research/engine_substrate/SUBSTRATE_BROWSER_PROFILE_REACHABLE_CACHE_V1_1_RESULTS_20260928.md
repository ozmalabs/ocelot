# Browser profile ReachableFrom cache telemetry v1.1 results

**All 12 runner gates and 12 independent analyzer checks pass.** This repeats the 24-worker five-seed `WorldAdapter.tick()` factorial from v1 using the current telemetry-enabled native build. Source/build locks are stable, all eight rules match the transitive seed manifests, and cache on/off preserve exact progress, graph, terminal graph, matcher counters, runtime traces, and expected mirror edges.

The new counters account for every `ReachableFrom` evaluation exactly: enabled-cache hits plus misses equal `term_eval:ReachableFrom` in every worker. Cache-off arms record zero cache activity. At N=128,B=1, the median is 16,382 hits, 2 misses, 2 peak live entries, and an 8,464-byte estimated peak payload. At N=128,B=4, it is 16,763 hits, 5 misses, 5 peak entries, and 8,908 bytes. Both configurations reduce adjacency visits to 257 and 260 respectively. Audited tick medians are 74.1 ms on versus 191.1 ms off (B=1), and 23.8 ms versus 61.1 ms (B=4).

The byte estimate counts the map key/value structs, reachable result-slice elements and Arc headers, and spilled adjacency-footprint storage. It excludes the hash table's bucket/control allocation, allocator metadata, fragmentation, and capacity slack; it is not an RSS measurement. Cache entries are cleared by the time the tick returns, while high-water counters preserve the peak observed during the tick. The maximum peak payload in the panel is 8,908 bytes across five entries.
