**Run:** 2026-09-28; two fresh profiled workers per condition, five authored conversation conditions.  
**Protocol:** [v1.1 preregistration](SUBSTRATE_CONVERSATION_TASK_MODULE_ACTIVATION_V1_1_PREREG_20260928.md).  
**Evidence:** [raw capture](../../../evaluation/reports/conversation_task_module_activation_v1_1_20260928.json), [independent analysis](../../../evaluation/reports/conversation_task_module_activation_v1_1_analysis_20260928.json), [source/input lock](../../../evaluation/substrate_capability/conversation_task_module_activation_v1_1_lock_20260928.json), [runner](../../../scripts/substrate_conversation_task_module_activation_v1_1.py), [analyzer](../../../scripts/analyze_substrate_conversation_task_module_activation_v1_1.py).

The post-hoc [source-inventory crosswalk](../../../evaluation/reports/conversation_task_module_source_crosswalk_v1_20260928.json), generated by [its analyzer](../../../scripts/analyze_substrate_conversation_task_module_source_crosswalk_v1.py), passes five integrity checks. The five tasks called 40 distinct Python `domains.*` modules, all present in the 833-file source census; only 3 of those 40 modules have direct capability-map file links (`conversation_action.py`, `discourse_state.py`, and `reflective_faculty.py`). This is task-observed evidence of a source-linking gap. It does not imply the other 37 modules are unimportant or should each become standalone capability rows.

## Result

All 12 independent integrity and source/cache checks pass. Ten distinct worker processes completed, with exactly two workers for each condition. WordNet corpus and warmed SQLite cache hashes and metadata remained stable, and no worker rebuilt the database. The task oracle passed 8/10 trials:

| Authored condition | Oracle | Domain modules | Domain functions | Domain call events | Instrumented task wall time |
|---|---:|---:|---:|---:|---:|
| Scene description | 2/2 | 32 | 367 | 24,454 | 10.46–11.01 s |
| Held self-knowledge answer | 2/2 | 32 | 281 | 68,348–68,349 | 438–440 ms |
| Self-report action | 2/2 | 29 | 292 | 83,070 | 543–547 ms |
| Unknown-word clarification | 2/2 | 25 | 243 | 3,240 | 249–289 ms |
| Concern authoring | 0/2 | 28 | 262 | 19,751 | 305–324 ms |

For every condition, both replicates have identical module sets, function-key sets, and call-edge-key sets. Held self-knowledge differs by one call event between workers; other listed event totals match. The largest repeated function counts include self-model rule-summary indexing (9,532 generator calls and 4,772 lambda calls in several routes), reflective-faculty residual enumeration, and reference-slab record access. These are observed profiles, not evidence that those functions are necessary or that the observed calls dominate uninstrumented wall time.

## Interpretation and limits

This links five specified conversation tasks to actually invoked Python domain functions, source inventory records, and independently scored outcomes. It extends the earlier profile preload census by distinguishing route-level execution footprints and shows that the capability map directly names only a small fraction of the Python files actually called on these routes. It does not measure Rust/native work, causal necessity, profiler overhead, natural task frequencies, or capability outside these authored routes. The 0/2 concern-authoring outcome is a concrete capability gap for this task contract; this panel does not localize its cause.

The measured times include profiler overhead and are not calibrated against uninstrumented runs. Two workers per condition are enough to check repeatability of the footprint here, not to estimate population variance or a commodity-hardware service envelope. Scene description is also substantially slower than the other selected conditions and merits separate uninstrumented/counter-only decomposition before optimization claims.

The initial v1 capture is retained as exploratory evidence only. It omitted the external WordNet corpus and derived SQLite cache from its lock; a scene worker therefore exercised the cache-build path while its replicate used the warmed path. V1.1 closes that confound for warmed steady-state activation, but does not measure cold-cache build cost.

## Next gate

Before the next task-family expansion, adjudicate the 37 activated-but-unlinked Python modules into capability implementation, shared support, or other status with source evidence; then add reviewed crosswalk links where they belong. Expand the source-locked task-module panel across independently specified capability families already represented in the capability map (at minimum structured perception, relational reasoning, learning/induction, and planning/action selection). For each family, preregister paired task and negative-control cases, an independent outcome oracle, required source/data locks, and one or more native-work counters alongside Python call traces. Keep task-family pass rates separate; do not pool authored panel frequencies as natural prevalence. Calibrate observer overhead on at least one route and measure cold startup separately from warmed task execution. Use failures such as concern authoring to drive targeted diagnosis rather than adding more routes that only confirm successful behavior.
