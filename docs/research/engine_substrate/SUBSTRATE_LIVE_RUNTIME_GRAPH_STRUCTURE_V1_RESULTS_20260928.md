# Live runtime graph structure v1: post-hoc result

This deterministic analysis summarizes the existing full-profile runtime graph capture from the live-task join study. The capture has 25,142 nodes and 11,762 directed typed edges across 264 edge types. Its canonical JSON SHA-256 matches the digest recorded by the capture runner. This is a post-hoc descriptive analysis, not a preregistered hypothesis test.

In the undirected simple projection, the graph has 14,071 connected components; 13,711 nodes are isolated. The largest component has 6,201 nodes (24.7% of the graph). Degree quantiles are p50=0, p90=1, p99=9, maximum=393. There are 1,196 articulation points (4.8% of nodes). Removing all `has_concept` edges (6,320 edges) changes the component count to 20,354 and the largest component to 1,885 nodes; removing `has_rule` edges (2,270) yields 16,341 components and a largest component of 5,460 nodes.

These measurements show sparse global connectivity, substantial isolated-node mass, and some high-degree structure. They do not establish a useful hierarchical frame decomposition. The graph projection discards direction and relation semantics; node articulation points are not separator dimensions for inference; removing a whole relation family is a diagnostic perturbation, not a learned cut. The result therefore does not justify bounded treewidth, factorized inference, or cheap frame-local matching. In particular, one high-degree node could still create a large interface for a selected factor graph.

The next structural gate should map explicit ownership/containment candidates to factor and rule dependencies, then measure separator dimension and induced width at each proposed level. Include a cost for finding and updating the partition under graph mutation, and compare projected inference/matching work with the flat engine on held-out runtime captures. Until that is done, the cheap-cut claim remains an empirical hypothesis.
