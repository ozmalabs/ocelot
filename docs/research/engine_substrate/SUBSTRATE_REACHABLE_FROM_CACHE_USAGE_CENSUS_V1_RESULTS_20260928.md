# ReachableFrom cache usage census v1

The source census found one executable `ReachableFrom` Term AST in the seed library: the `browser_affordance_reach` mint rule. Its two graph rules load through the browser profile, and `worlds/browser.py` documents that seed as required. Three Python literal references occur in `domains`: one is the primitive-authoring helper (`self_extend_rust.agent_specify_reachable_from_primitive`), while two evaluate direct queries (`grounding_reach._reachable_from_native` and `frozen_core.seed_dependency_closure`).

The direct-call path does not currently share the new cache. `PySubstrate.evaluate` constructs a fresh `EvalCache::default()` per call; `EvalCache::default()` leaves `reachable_enabled=false`. The experimental setter exists on the native `PySubstrate`, but the higher-level `substrate_rs.Substrate` wrapper does not expose it. Thus the measured optimization currently applies to rule-rewrite evaluation when a caller explicitly enables the native substrate cache; the source-authored browser rule is the clearest identified consumer candidate. The code scan is bounded to `seeds/*.json` typed Term ASTs and AST string literals in `domains`, `substrate`, and `worlds`; it is not a dynamic call graph or an activation-frequency measure.

The executable audit emits exact file hashes and machine-readable locations ([runner](../../../scripts/audit_reachable_from_cache_usage_v1.py), [capture](../../../evaluation/reports/substrate_reachable_from_cache_usage_v1_20260928.json)). It passes its expected source-shape checks. The next gate is to instrument actual enabled browser-profile runs for cache hit/miss counts and retained bytes, then measure the same path across realistic page topologies and all public graph-mutation routes. Exposing the toggle to the higher-level wrapper should be considered only after those gates establish benefit and invalidation coverage.
