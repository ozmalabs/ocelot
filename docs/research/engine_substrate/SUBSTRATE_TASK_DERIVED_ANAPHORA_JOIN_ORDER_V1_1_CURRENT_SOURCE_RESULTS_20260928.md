# Task-derived anaphora join-order replay v1.1: current-source result

The v1.1 preregistered replication reran the same two-turn anaphora task against the updated `world_adapter.py` source snapshot. It covers all 24 authored permutations of four match clauses, with two fresh-process replicates per permutation. The task oracle, fixed-point terminal status, whole-graph digest, per-clause candidate counts, and per-rule counters were checked independently.

All 48 workers passed the task oracle and fixed-point checks. The analyzer reports all 293 gates passing. The eight installed clause orders requested by the 24 permutations cost 8–16 target candidate tests; the source order costs 13. This confirms reproducible semantic parity and the same bounded order sensitivity on this one linear, task-derived pattern. It does not establish a general optimizer, natural workload prevalence, or a speedup claim.

The post-hoc paired comparison against v1 is descriptive, not preregistered. Across the same 48 cells, installed order, task output, terminal report, graph digest, clause counters, per-rule counters, closure progress, task-oracle result, and global counters excluding timing fields match exactly. Timing fields vary and are not treated as deterministic.

Evidence preservation limitation: v1.1 reused v1's child-log paths, overwriting the original v1 logs. The v1 raw capture retains the original recorded hashes, but the old log files can no longer be verified independently. All 48 v1.1 child logs match their recorded hashes and successful exit codes; the v1.1 lock and post-run source snapshot match. The source-locked v1 evidence remains usable for its raw structured records, while its original per-worker logs are not independently preserved.
