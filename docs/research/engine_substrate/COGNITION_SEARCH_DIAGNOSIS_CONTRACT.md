# P23 search diagnosis contract

**Status:** diagnostic contract frozen before P23.02–P23.04 analysis, 2026-10-24. **Scope:** archived P22 development artifacts and declared training-only branches. **Held-out access:** prohibited. **Agent mutation/output:** prohibited.

## Questions and finite claims

P23 answers only these questions for the hash-bound roots and branch records below:

1. Which distinct D4 effects are reachable from the exact primitive held effects, which are already active/adopted/identity at each root, and which remaining effects satisfy the registered source/child novelty, precondition, and independent-goal qualification rules?
2. For Loopover, what effects have a witness within the stated depth/node bound, what effects are expressible by the frozen search grammar, and what remains `UNKNOWN` beyond that finite bound?
3. At which stage are native attempts lost: malformed syntax, repeated syntax/effect, context guard, candidate cap, independent trial headroom, qualification, approval, or world receipt? Which exact parent and predicate support each rejection?
4. Which measured barrier, if any, justifies a bounded implementation remedy? If none is measured, stop scaling search.

No finite bounded miss is a proof of global impossibility. Every report must distinguish `PROVED_WITHIN_ENUMERATED_FINITE_SPACE`, `WITNESS_FOUND`, `REJECTED_BY_NAMED_PREDICATE`, and `UNKNOWN_OUTSIDE_BOUND`.

## Counter and isolation rules

- A branch's cumulative `OpenProcessSearchAttempt` count is read from its digest-checked `resource_snapshot.node_counts`. Its inherited count comes from the embedded `parent_checkpoint.resource_snapshot_json` when present. New branch work is `cumulative − inherited`; a negative value is invalid.
- For independent sibling restorations, aggregate only each unique branch's new work. Do not add its inherited graph count again. Exclude exact replay rows from aggregate independent work; preserve their row and compare them as reproducibility evidence. An interrupted/malformed allocation with no valid artifact is retained and contributes no completed-attempt count.
- Bind branch goal IDs to the explicit `train` namespace from `independent_worlds.py`. P22 development draws above the preregistered 0–199 panels are permitted only as training draws; they are not members of the registered allocation. Reject any validation or held-out ID, including all IDs from `linear_p22_v1.allocation()`, before diagnostic analysis. Do not materialize labels merely to audit split membership.
- Inputs are read-only. Diagnostic code may emit an external report containing hashes, bounded effect/witness summaries, predicate names, counts, and resource measurements. No diagnostic witness, inferred solution, goal label, candidate, qualification, approval, receipt, checkpoint, or mutation command may be emitted into or consumed by an agent graph, candidate validator, world adapter, or P22 runner.
- Human approvals remain candidate-specific and are outside this diagnostic contract. Diagnostic results cannot authorize adoption or alter the P22 preregistration or its outcome criteria.
