# Live frame rule-scope capture v1.3 results

## Result

The current-source two-request route was replayed in three fresh workers. All nine registered capture checks pass: the workers have distinct PIDs, source locks remain stable, the prompt/export schedule reproduces, all runtime RuleUID observations map to same-request post-request definitions, exported definitions and final graph semantics reproduce, lifecycle and semantic controls pass, and no worker fails. The capture contains 12 before/after exports and 28,338 rule-definition rows. It maps all 2,394 runtime RuleUID observations to 401 distinct rule definitions across 1,688,754 weighted access events. Six definitions are added during the request sequence.

The independent structural analysis passes its six checks. On the reproduced graph (25,065 nodes and 11,543 edges), each worker yields the same two protocol-declared cuts: turn 0 owns 8 nodes, has 38 crossing incidences to 20 distinct external nodes, and an owned-subgraph min-fill upper bound of 2; turn 1 owns 3 nodes, has 20 crossing incidences to 16 external nodes, and an upper bound of 1. These cuts are tiny relative to the graph, but their crossings are not tiny relative to their owned nodes. The cuts were declared by the protocol; they were not learned from the graph.

## Source-to-runtime join

The current Term-access inventory is source-hash matched and passes 237 audited variants. Joining it to the runtime definitions maps all 67 syntactic Term variants and all 401 rules, with zero unmapped variants and reconciled weighted access totals. The raw archive was then independently reduced to one definition per observed RuleUID; all 401 definition hashes and per-rule Term counts match the runtime analyzer. This preserves concrete Term arguments, paths through each definition, match-variable names, match edges, and effect syntax. Across the definitions are 3,574 `Attr` occurrences over 588 distinct literal keys, 174 `NodesOfType` occurrences over 32 node types, 253 outward and 6 inward adjacency occurrences with typed edge labels, 32 `TypeOf` occurrences, and 34 rules containing dynamic helper Terms. These are syntax counts, not per-invocation execution counts.

The source inventory's four access classes remain useful when interpreted carefully: finite resource keys (2 variants in 395 rules), conditional finite-or-wildcard (2 in 124), wildcard reads (12 in 56), and generic-child fallback (51 in all 401). Generic-child fallback means an operator composes over child Terms; it is not itself proof of a global graph scan. The recursive Term listing exposes child graph reads, while 93 definitions explicitly contain whole-population syntax. Of the `Attr` occurrences, 2,910 point directly to a match-bound variable, 598 to a term-bound or unresolved variable, and 66 to a non-variable or unresolved expression. Even match-bound reads do not prove task-frame locality: candidate enumeration, edge crossings, helper implementations, and whether the syntax executes still matter.

The conservative per-rule manifest covers 401 definitions and 1,688,754 weighted access events, marks zero rules as proven local, flags 93 with whole-population syntax, 42 as potentially graph-wide or dynamic, 78 with anchored adjacency but unbounded degree/crossings, and 188 as finite-key or inherited-scope candidates. These categories identify a known limiting operation; they do not claim the rest of a rule is complete. All rules retain explicit blockers for matcher, host, scheduler, rejected-candidate work, and unexecuted syntax. Full frame dependencies and factor scopes remain unmeasured.

## Dynamic-helper source audit

A separate source audit covers all 11 `dynamic_helper` variants present in this live sample and verifies 20 source evidence sites against current files. Nine shape/inference operators call the shared codebook loader, which traverses every node of the declared codebook type. `GenInfer` applies its optional scope predicate only after visiting each codebook node, so it can reduce signature parsing and search but not the population traversal. On `ShapeDecode` cache misses, a second helper also visits every `RelationCueToken`. `ShapeDecode` has a default expansion budget of 20,000; `GenInfer` restricts itself to two coordinate dimensions but enumerates four matrix coefficients over `[-B,B]`, yielding up to `(2B+1)^4` candidates per eligible base before validation/rejection. This is polynomial in numeric `B` but can be exponential in the bit length of an unrestricted integer bound; the live capture does not estimate deployment input distributions or helper timing.

The active `ProgEval` path can decode a program from a graph node by recursively following child edges before running its fuel-limited VM. The inspected decoder has no explicit visited-set or decode-node budget, and VM fuel does not charge decode work. The one live `Join` definition can render Node values by searching `has_rule` neighbors in the active language and decoding the selected template; recursive render depth is capped at 256. These are source-level scope observations, not proof that every helper path ran in the captured route. They show where codebook scans and graph-resident program/render data can bypass a small task frame unless those resources are separately scoped.

The raw native work trace does not measure these paths. Its independent replay covers all six requests in three workers with identical per-prompt access and work rows and zero dropped events, but all 270 work rows are scheduler counters or `operation_kind`; there are no codebook-member, helper-call, matrix-candidate, decoded-subgraph, or render-rule counters. Thus this route confirms the current instrumentation gap rather than providing helper cost estimates. See the [work-trace analyzer](../../../evaluation/substrate_capability/analyze_live_rule_scope_work_v1.py) and [work analysis](../../../evaluation/reports/live_rule_scope_work_analysis_v1_20261005.json).

## Interpretation and next gate

The refresh resolves the source-staleness issue in v1.2 and strengthens the basis for studying one selected live route. It does not strengthen the general cheap-cut claim enough to call frame-local inference tractable: 93 rules contain whole-population syntax, helper code scans declared codebook populations, and the small graph cuts are not proven to bound rule/factor dependencies. Thus the current evidence supports reproducible rule-scope observation and a useful access-class taxonomy; the claimed route from learned frames to polynomial operating cost remains unverified.

Next, reconcile the manifest against full evaluator/source call paths and runtime traces, expanding concrete binding-sensitive arguments and dynamic helper dependencies. Then test it prospectively on independently authored task families with boundaries defined before outcomes. Record false-local classifications as failures. Do not derive factor width until factor scopes and domains are separately identified.
