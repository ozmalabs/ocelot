# ReachableFrom same-graph cache panel v1 results

**Outcome: all preregistered gates pass.** The source-locked panel ran 27 unique fresh workers: three replicates at each N={32,128,512}, R={1,16,64} cell, with cache arm order counterbalanced. Rust source, build record, native extension, runner, analyzer, protocol, and dependency inputs remained stable; the release build was current.

For this typed-star workload, cache-off work is exactly N²R adjacency visits and cache-on work is exactly N. At the largest cell (N=512, R=64), the `ReachableFrom` counter falls from 16,777,216 to 512, a 32,768× operation-count reduction. All nine cells match the preregistered formula. Across all arms, fixed-point reports, serialized graphs, runtime access-trace events, and dropped-event counts match exactly. The cache remains experimental and default-off.

Median audited wall times also favored the cache arm in all nine cells. At N=512, R=64, medians were 1.655 s off and 0.638 s on (2.59×); the small N=32, R=1 case was 0.154 ms versus 0.049 ms (3.12×). These timings include runtime access tracing and scale auditing and are descriptive only; the panel does not isolate cache memory or instrumentation overhead.

The explicit mutation control first reaches a no-write fixed point with N reachable blockers, then inserts one additional `block` edge. Both cache-off and cache-on runs transition from zero to all eight expected slot markers and reach fixed point. Post-mutation work is 72 visits off and 9 on, confirming the changed query was recomputed after mutation. This covers one public mutation path and fixture only.

The result supports an optimization for repeated identical typed `ReachableFrom(start, edge_type)` Terms during an unchanged graph epoch, with trace-footprint replay and tested edge-insertion invalidation. It does not establish natural-task query reuse frequency, concurrent sharing behavior, memory tradeoffs, cache behavior across every mutation API, or general tractability. The next gate is an active-profile census of repeated `(start, edge_type)` keys and cache occupancy, followed by memory/hit-miss measurements and an invalidation matrix for node, edge, and attribute mutations before considering any default-on policy.
