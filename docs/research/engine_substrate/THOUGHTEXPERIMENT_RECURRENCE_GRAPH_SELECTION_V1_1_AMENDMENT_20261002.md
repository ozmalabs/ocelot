# Recurrence graph-selection v1.1 analysis amendment

The first analyzer treated fixed-point completion by every candidate as a single pass condition and therefore marked the full panel failed. This is retained as a real gate failure: the preregistered requirement that all candidate episodes reach a fixed point within 100 calls is not met. The corrected analysis separates that system-level closure condition from the candidate-selection subgate. The selected `dedup_identity_fix` candidate reaches fixed point and passes all train/held-out episodes; losing candidates that hit the per-call cap count as failed alternatives, not as proof that the selected repair failed. This is an analysis decomposition only; the source-locked runner, frozen orders, held-out scores, and literal full-gate outcome are unchanged.

Five of seven alternatives consume the 100-call `run_rules` cap in every episode. A cap hit establishes that the candidate did not reach the measured fixed point within the configured budget; it does not prove divergence or undecidability. The final analysis exposes both booleans: selection subgate passes, full protocol gate fails. No general closure complexity claim follows from this authored rule family.
