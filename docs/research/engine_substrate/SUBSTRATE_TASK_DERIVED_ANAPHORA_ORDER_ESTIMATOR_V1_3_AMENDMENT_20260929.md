# Anaphora order estimator v1.3 amendment (2026-09-29)

The v1.2 174-worker panel has stable source locks, complete cell coverage, exact target counters, and successful task oracles. Its graph digest nevertheless failed parity because it hashed the native graph serializer's edge-list order. A separate diagnostic compared sorted node/edge rows and `next_id` for D=0/2/4; all reordered states matched the source-order state exactly. Since v1.2 raw workers retained only the order-sensitive digest, its full-graph parity cannot be independently recovered from that capture and it is excluded from confirmatory parity claims.

The v1.2 analyzer also tested integer budget membership against JSON objects whose keys deserialize as strings. That creates false failures for the planning/install charge-presence gate. V1.3 keeps the same factorial, inputs, estimator, outcomes, and gates. It changes graph digest construction to sort node and edge rows by stable IDs/type/attributes before hashing, while retaining `next_id`, and checks budget keys in their serialized representation. A new lock and distinct raw/manifest/log namespace bind these corrections. No performance threshold or semantic criterion is relaxed.
