# Qwen3 open-vocabulary taxonomy traversal scaling v1 preregistration

## Question and claim boundary

What is the accuracy and operating cost of substrate-only transitive query on a task-derived, open-vocabulary knowledge graph at its recorded scale? Reuse the 5,772-edge, 6,445-node is-a seed harvested from 6,000 WordNet noun subjects and test every unique derived non-self closure pair whose shortest path is at least two, plus an equal-size sample of non-reachable pairs. This is a graph-operation/knowledge-use evaluation, not an inference-primal-graph or treewidth measurement. The heldout truth is closure of the stored graph, not external taxonomic truth; source fidelity is separately reported as 0.108 exact parent / 0.272 valid ancestor in the prior WordNet audit.

## Frozen inputs and query set

- Seed: `seeds/generated/qwen3_reaped_isa_full.json`, expected SHA-256 `30356bb366ea6ba9ee0f7006713cd19276405b14f763acfd2ed264294fca9891`.
- Query fixture: `evaluation/substrate_capability/fixtures/llm_taxonomy_traversal_scaling_v1_queries.json`, generated by the companion preparation script. It includes all unique shortest-path positives at distance ≥2 (expected 4,820) and the same number of unique non-reachable pairs sampled with `numpy.default_rng(20261003)`. The full fixture and generator are source-locked.
- Build the actual native `Microtheory` using `domains.llm_knowledge_seed.build_knowledge_mt`, relation `isa`, and `seeds/can_native_reimplementation.json`. Query through `query_transitive` with its default `max_hops=6`; do not change the implementation for this measurement.

## Measurements

Three fresh source/native-locked processes each build one graph and run the complete locked query set. Report graph construction separately from query time. Warm once on a fixed prefix, then time one complete positive/negative pass in deterministic fixture order. Record per-case answer, shortest-path distance, latency, traversal-neighbour calls, and returned-edge scans. Gather operation counts in a separate instrumented pass so instrumentation does not contaminate timing. Report outcomes and latency by positive shortest-path distance (2 through 8) and for negatives; report medians and p95 by worker and group.

Controls are the stored direct-edge query on every positive (expected zero recall) and a shuffled-target graph using `numpy.default_rng(0)` on the same query set. Report graph size, edge count, in/out-degree profile, weak-component sizes, directed cyclic components, closure size/depth profile, and source seed fidelity. Do not translate these state-graph statistics into a factor treewidth claim.

## Gates

Require seed/query hash equality, worker source/native lock parity, three unique fresh worker PIDs, exact query coverage without duplicates, independent host-adjacency oracle agreement for every expected label and shortest distance, full metric recomputation, positive/negative answer counts, direct/shuffle controls, graph node/edge parity, no graph mutation, and separate uninstrumented timing versus instrumented operation counts. A query beyond six hops is expected to be labeled positive by the unbounded oracle but missed by the existing default traversal; record this as a bounded-depth capability limit rather than weakening the oracle or discarding those cases.

## Interpretation boundary

A pass measures exact graph-closure use and its present depth limit/cost on one large graph harvested from model outputs. It does not show that the harvested edges are mostly true: the separate WordNet audit finds substantial source noise. It does not establish natural task prevalence, learned separators, exact probabilistic inference cost, or general language understanding.
