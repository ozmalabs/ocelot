# Thoughtexperiment effect-trace diagnosis v1 results

The source-locked capture passes corrected analysis on 80 held-out generated cases across 4, 8, 16, and 32 effects, replicated by three independent worker processes. Each case contains one rule firing with a separately randomized node order, match-clause order, effect order, and one known failing target node. Event-only and effect-trace arms reach identical closure outcomes. Event-only reports include the failing node among the firing's changed nodes but expose no effect-index mapping; effect snapshots identify exactly the effect that wrote the bad value in 80/80 cases, with no truncation. Source/native locks remain stable across capture.

The preregistered event-report-only baseline considers every effect in the firing a candidate and picks the lowest index. It identifies the oracle effect in 10/80 cases (12.5%). Effect traces reduce the candidate set from a mean of 15 effects to exactly one, an average 15× reduction. This demonstrates useful information in the trace for the specified query: identify the effect index that changed a supplied failing node, without rerunning matching or reconstructing the binding environment.

The baseline is intentionally limited to the current event report. A stronger system could rematch the graph, inspect the complete rule body, or reconstruct bindings; this capture does not compare against those methods. The cases are synthetic and deliberately hide the variable-to-node firing map from the query. Results therefore establish a concrete API observability capability, not realistic diagnosis accuracy, successful repair, tractability of induction, or natural-task prevalence.

The initial analyzer attempted to read endpoint values that the runner had intentionally omitted from its compact record and failed with a missing-field error. The locked analyzer was preserved; its separate [correction analyzer](../../../evaluation/substrate_capability/analyze_thoughtexperiment_effect_trace_diagnosis_v1_correction.py) uses the event's changed-node IDs and independently derives effect candidates from the raw snapshots. It passes every gate. Next test on a held-out workload where the diagnostic can rematch the graph and inspect rule definitions, and measure whether trace-guided counterfactual experiments reach the right repair with fewer branches. Keep effect traces opt-in until that stronger comparison shows benefit relative to their measured fan-out cost.
