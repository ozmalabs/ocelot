## P2.C1 — `SoftWeights` Term

**Spec, frozen by P2.C1.1.**

```
SoftWeights { source, var_name, value, temperature, default? }
```

- Iterate `source.snapshot()` in its snapshot order, binding each element to `var_name`, and evaluate `value` to a float. Elements whose value is non-numeric or non-finite are **skipped**, not zeroed.
- Let `T = evaluate(temperature)`. If `T > 0`, the weight is `w_i = exp((v_i - v_max)/T) / Σ_j exp((v_j - v_max)/T)`. Subtracting the max keeps the computation stable, and the sum is taken in snapshot order so results are deterministic.
- If `T <= 0` (the hard limit), the maximal elements share weight equally: each gets `1/k` for `k` tied maxima.
- Return `Value::List` of `Tuple(element, Float(w))` in snapshot order. An empty or all-skipped source returns `default` if given, else an empty `List`.
- Selection stays with the existing selectors. For example, `Argmax` over the result with `value = Index(pair, 1)`, or whatever the frozen spec settles on for reading the tuple.
- **Integer-cognition boundary.** Seeds that must stay integer can apply the existing `LogQuantum` or `Round` Terms to a weight. P2.C1.1 decides whether an `integer_scale` field (returning `Int(round(w·scale))`) is worth adding to the Term itself.

## P2.A5 — `thinking_budget` seed

**Mechanism.**

Seed `thinking_budget`: `depends_on: ["default_mode_core"]`, because it uses the `NetworkModeState` clock.

The budget node is `ThinkingBudget{enabled:0.0, capacity:16.0, remaining:16.0, refill_per_epoch:2.0, last_refill_epoch:-1.0}`, on `agent_root -has_thinking_budget->`.

Rules:
1. **`tb_refill_once_per_epoch`.** `remaining = Min(capacity, remaining + refill_per_epoch)` once per `mode.epoch`. This copies the debit idiom with the sign reversed.
2. **`tb_fund_from_horizon`.** This is the optional funding rule. When the agent has `governs_horizon -> ManifoldPolicy` with `future_manifold_projection_budget` (`arousal_horizon.json:213-352`), set `capacity = Min(capacity_ceiling, pol.future_manifold_projection_budget × funding_gain)`. Without that edge, `capacity` stays static.
3. **Request contract.** A requester adds `request -draws_on_thinking_budget-> budget` and a `cost` attribute. The P1 bridge mint rules (A1 `csb_open_request` excepted, since filing a concern costs nothing; A4 `isb_request_simulation`; B1 `csch_mint_offline_cycle`) gain the guard `Or(budget absent, budget.enabled != 1, budget.remaining >= pol.cost)` and the effect `budget.remaining -= cost`. Absent or disabled means unchanged behaviour.
4. **`tb_record_exhaustion`.** When a guard blocks a mint because `remaining < cost`, mint `ThinkingBudgetDenial{reason:"budget_exhausted", requester_kind, epoch}`, capped at one per kind per epoch, so that denials can be observed.
