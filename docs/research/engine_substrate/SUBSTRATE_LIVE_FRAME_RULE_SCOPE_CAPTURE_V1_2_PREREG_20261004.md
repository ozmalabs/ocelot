# Live frame rule-scope capture v1.2 preregistration

Date: 2026-10-04

## Objective

Refresh the live frame-interface and post-request native rule-definition
capture against the current worktree and native engine, replacing the stale
v1/v1.1 source baseline for evidence about currently available request behavior.

## Protocol

Run three fresh isolated workers over the existing two-prompt self-report
panel using the established access/work instrumentation and post-converse
native rule exports. Preserve the full request traces, graph summary, task
boundaries, rule definitions before and after each request, and semantic
controls. Require current engine provenance before every worker; lock the full
base input closure, current native extension/build record, v1 base protocol and
source, this protocol, this runner, and independent analyzer before execution.
Require identical final semantic graph digests, request access/work traces,
and exported definitions across workers; verify every observed runtime RuleUID
maps to a post-request definition, expected two-request lifecycle reproduces,
and all semantic controls pass. Analyze raw records independently. Historical
v1 outputs are provenance references only and are not expected-value oracles
for the changed worktree.

## Limits

This refresh measures only the existing two-prompt fixture. The authored task
set is narrow, exported rule syntax is not a complete dependency slice, and the
results do not establish learned frame discovery, multi-frame cheap-cut
prevalence, partitioned closure speedup, or natural-task scaling.
