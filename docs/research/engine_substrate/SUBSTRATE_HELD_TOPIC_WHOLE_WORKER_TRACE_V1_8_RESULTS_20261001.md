# Held-topic whole-worker operation-work trace v1.8 results

**Result:** the corrected capture gives repeatable operation-work totals across three fresh workers and accounts for the captured trace rows across pre-turn, in-conversation, and post-worker segments. It does not exercise deferred queue item flow.

The source-locked capture contains three workers and seven turns each. Capture integrity, worker-source stability, frame/access invariants, operation-row repeatability, and segment reconciliation pass. Per worker, it records 122,245 selected-rule units, 172,515 dirty-vector slots, 174,878 external-poll slots, 3,178 fixed-point probe slots, 112 scheduler passes, and 266 operation markers. It also records 51 deferred-queue drain batches, all for family code 3 (`fb_samples`).

There are no `deferred_queue_enqueue_items` or `deferred_queue_drained_items` rows in any worker. The drain batches therefore show empty drain attempts, not queue-item processing. The initial analyzer's queue-balance flag passed vacuously because it evaluated only families appearing in item-event rows; the independent [queue-item audit](../../../evaluation/reports/held_topic_runtime_interface_trace_v1_8_20261001/queue_item_audit_v1.json) corrects the interpretation to `not_evaluated_no_enqueue_or_drained_item_rows`. Queue accounting and deferred-effect coverage remain unmeasured on this route.

Task quality remains 18/21: the honest-capability copper prompt fails in each worker. This is separate from trace integrity. The v1.7 whole-worker pilot is retained; it omitted in-conversation operation work because the native access-trace toggle disabled all-scope work capture. V1.8 explicitly restores that capture mode around each access window.

This trace covers explicit scheduler/deferred instrumentation only. It does not represent all CPU work, all host callbacks, every queue producer, or general tractability.
