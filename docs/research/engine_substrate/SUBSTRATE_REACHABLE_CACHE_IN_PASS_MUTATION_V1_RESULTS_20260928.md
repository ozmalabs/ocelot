# ReachableFrom in-pass mutation probe v1 results

The source-locked five-worker falsifier loads three ordered rules: one primes `ReachableFrom(root, path)` without progress, one inserts a new path edge, and a later one derives a detection edge when the new target is reachable. The control with the experimental cache disabled reaches the expected fixed point in every worker. The cache-enabled build does not: it returns one progress step and omits the detection edge in all five workers. The only final graph difference is that missing edge.

All seven runner gates and six independent analyzer checks passed, including the declared `edge:path` read/write dependencies and stable source/native provenance. This is a reproducible correctness counterexample on a constructed monotone three-rule program. It shows the cache could leave `run_rules()` at an incomplete fixed point after same-pass add-only mutation; it does not estimate prevalence or performance impact.

The follow-up fix and post-fix replay are recorded in [v1.1](SUBSTRATE_REACHABLE_CACHE_IN_PASS_MUTATION_V1_1_RESULTS_20260928.md). The first exploratory one-off preceded the file named as a preregistration, and the v1 protocol text misstated the expected parity; see the [protocol amendment](SUBSTRATE_REACHABLE_CACHE_IN_PASS_MUTATION_V1_AMENDMENT_20260928.md).
