## Design and fixed allocation

Each paired stream is a fresh cognition-on graph with the same world model and
primitive access in all four arms. A 33-element permutation world provides 32
held swap processes. Two source SolveTasks require 32 native process steps and
produce the same solved trace. The full-sleep arm admits quiet offline replay,
consolidation, decay and library stages through native graph rules; the P13.03
learner must verify the repeated trace and account for its complete package
cost before retaining a chunk. The P13.04 subpanel separately learns strategies
from two solved small tasks and forces a funded recall attempt on a delayed
same-shape task. An unrelated observed episodic event is inserted between
offline/rehearsal work and the delayed task as the fixed interference event.

The four paired arms are:

- `full_sleep`: P1 replay scheduler plus enabled P13 sleep, verified library
  learning and observed-yield strategy recall.
- `replay_only`: P1 replay scheduler with all three P13 policies disabled.
- `awake_rehearsal`: no offline scheduler; real one-primitive process tasks are
  rehearsed until native rule-step work matches the full-sleep stage work
  within 5%.
- `no_offline`: offline scheduler and P13 policies disabled.

The delayed library task is generated by applying the public held primitive
sequence to a fixed held-out initial state. The agent receives only the task's
initial state and goal, never a solution, expected trace or strategy entry. The
strategy subpanel uses genuine solved training tasks; its task result is
reported separately from the primary delayed-library score. World actions are
zero: the panel measures native simulated task outcomes and exact process
traces, not physical sink parity. Every record reports that limitation.

Held-out stream seeds are the fixed block `13,100,000` through `13,100,199`.
Each seed is run in all four arms, for 800 paired records. One hundred
interrupt/restart controls use seeds `13,150,000` through `13,150,099`, for
900 total records. Each control enters a replay cycle, injects foreground task
demand before the next stage, checkpoints and reloads the graph, resumes at the
next quiet epoch, then ticks repeatedly at that epoch to verify no repeated
receipt or debit.

Limits are fixed at two 32-step source tasks, one delayed library task, 32
ThinkingBudget capacity, 100,000 native steps per settle, eight adapter ticks
per sleep epoch, and at most 64 native solver steps per task. Report actual
native rule steps, source/delayed trace lengths, library definition and package
cost, retrieval/decoder/exception/dispatch/validation overhead, stage and
strategy budget debits, net balance change, evidence exposures, external
actions, boot time, graph node growth and serialized graph bytes. Include
receipt provenance, world/access hashes, all input audits, control outcomes
and inherited regression exceptions.

## Frozen criteria

The primary sleep criterion is at least a 10 percentage-point delayed-task
accuracy gain over P1 replay-only, with new-task accuracy loss no greater than
2 points. Both thresholds remain fixed after the draw. A valid gain below 10
points is `FAIL`; any missing arm, unpaired world/primitive access, hidden
answer/strategy, missing adapter receipt or failed input audit is `INVALID`.

Library reuse must reduce exact held-out primitive or verifier work by at least
25% after amortizing the complete package cost over its two source traces and
including decoder, exception, dispatch, retrieval and validation costs.
Foreground interruption/restart must preserve the pending cursor and resume
the next stage; repeated same-epoch ticks must add neither a receipt nor a
budget debit. All sleep receipts must remain `not_observed` offline-stage
provenance, and foreground starvation, double debit and ungrounded
consolidation must each be zero. A failed accuracy advantage remains `FAIL`
even if library work reduction passes. Human comparison is
`UNAVAILABLE_PROTOCOL_NOT_MATCHED`.

Development used three paired streams and one restart control. It completed
all arms with 100% delayed accuracy, 0-point gain over replay-only and 0-point
new-task loss. Full sleep produced a verified cost-positive chunk, one-step
delayed reuse, and funded strategy recall. Its amortized exact-work reduction
was 35.9375%; the awake rehearsal matched measured sleep-stage native rule
steps within 5%. World/access pairing, answer and hidden-strategy audits,
receipt provenance and restart controls had zero integrity failures. This is
adapter validation only and is not pooled with held-out results.

## Commands

Run the adapter and analyzer checks, then the registered held-out draw:

```sh
OZMA_SEED_PERSIST_DISABLED=1 .venv/bin/python evaluation/process_mastery/linear_p13_v1.py --self-check --output /tmp/linear-p13-selfcheck.json
.venv/bin/python evaluation/process_mastery/analyze_linear_p13_v1.py --self-check
OZMA_SEED_PERSIST_DISABLED=1 .venv/bin/python evaluation/process_mastery/linear_p13_v1.py --split heldout --n 200 --output /tmp/linear-p13-heldout.json
.venv/bin/python evaluation/process_mastery/analyze_linear_p13_v1.py /tmp/linear-p13-heldout.json > /tmp/linear-p13-heldout-analysis.json
OZMA_SEED_PERSIST_DISABLED=1 .venv/bin/python -m pytest tests/test_sleep_regime_migrated.py tests/test_library_learning.py tests/test_strategy_library.py -q -p no:cacheprovider
```

Before the draw, verify scorecard provenance equals the frozen table and archive
the raw scorecard and analyzer output outside git. Do not retune or rerun the
same held-out allocation after seeing a failed result.
