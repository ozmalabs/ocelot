# Thoughtexperiment generated-residual adoption v1 — results

**Date:** 2026-10-01  
**Status:** source-locked rule-generated adoption probe; all 50 trials pass.

Five fresh workers execute ten seeded cases each. Every case installs a graph-resident rule that matches the injected hypothesis and a fixed target pattern, then actually runs through `imagine()` on a reusable native snapshot. The rule changes one node attribute, removes one edge, adds a derived node and edge, and deletes one stale node with its cascade edge.

All 50 trials pass the complete semantic-graph oracle. Rehearsal leaves the primary semantic node/edge projection equal to its pre-imagination baseline. A default-gate attempt refuses and leaves that projection unchanged. Explicit approval reports successful writeback, includes all five intended operation kinds, and produces exactly the oracle graph after the added-node ID is mapped from the write receipt. Source hashes and native build provenance are locked; all worker processes are distinct.

This closes the previous gap between manually authored mixed receipts and actual rule-generated residuals for one rule family and one locality shape. It does not show that the rule itself was learned, that proposals are useful on open tasks, or that broad rule/effect combinations match the same envelope. Graphs are small and focus nodes are arranged so the removed node's incident-edge aperture is fully represented. Next vary rule families and neighborhood shapes, add edge-attribute mutation to actual rule generation if supported by the DSL, measure scales, and assess held-out task utility.
