# Committed-result consumer gate v1.2 results

The corrected v1.2 panel passes all gates in three fresh workers across N=2/8/32/64 and unique/tied maxima. The consumer rule requires the max, count, decision, and resolved revision stamps to match. It produces no `consumed_label` when only the max stamp is current, and still produces none when all stage stamps are current but `resolved_revision` is old. After the commit rule updates `resolved_revision`, the consumer awakens within closure and copies the selected label. Unique cases consume the score-oracle winner; tied cases consume the empty no-selection sentinel. Integer operation counts replicate when elapsed and `_ns` timing values are excluded.

This demonstrates that graph-rule consumers can enforce the authored revision contract and react to the commit marker in this controlled fixture. It does not constrain direct host reads of uncommitted fields, prove that all production consumers use the guard, or establish transactional/atomic visibility across the whole graph. Persistence, concurrency, and process restart remain untested.

The first two captures are retained as exploratory only because their analyzers were defective: v1 failed while iterating mapping keys as checkpoint records; v1.1 included elapsed-time data in the integer-count replication gate. The v1.2 preregistration documents these corrections, and its raw capture's protocol and analyzer fingerprints match.
