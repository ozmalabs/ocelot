# Shared-substrate multi-sheet task pilot v1.2 amendment

V1 and v1.1 failed before a valid task-quality capture. V1.1's 3,000 development clock steps took 2.16 seconds. Source inspection, together with the established DualProcess latency-class behavior, identifies the missing benchmark tags as the likely cause: its `WaveWorld.step` calls default `tick`, but its cloned vision rules lacked `latency_class="hard_realtime"`. V1.2 tags every executable rule in benchmark clones of `vision_waves`, `vision_settle`, `vision_onoff`, `vision_lateral`, and `vision_compose`. It gates on the resulting rule classes and checks developed `g1/g2` gains plus nonzero ON and OFF bipolar activity on both roots before theta adaptation. Production manifests and native code remain unchanged.

The 200/2,000 adaptation heartbeat also showed that the existing scalar presenter is too expensive on the two-root graph. V1.2 uses `set_attr_many` for uniform `state` and on/off subsets of `bursting` and `last_burst`. Before the workload, it applies both scalar and batched forms of a registered paired frame to a scratch state, restores the base graph, and requires exact graph equality. This checks only the mechanical input-write equivalence; it does not count as task evidence.

To avoid repeating the 2,000-presentation preparation for B-blank and B-grating conditions, v1.2 prepares one graph per scope, captures `graph_to_dict()` immediately before readout, and restores that graph before each readout. Each scope runs blank, blank-replay, and grating contexts. The repeated blank must reproduce the first blank tuning matrix exactly; the analyzer also requires each restored graph digest to equal the prepared digest. This is an explicit control for hidden state not reset by graph restoration. The task contrast and K=16 instrument are otherwise unchanged. The new runner, lock, raw capture, and analysis are versioned separately.

## Serializer precision correction

The first tagged v1.2 execution passed retinal development (3,000 steps per retina; maximum gains 0.5273 and 0.5258) but stopped at the input-writer preflight. An isolated fixture reproduction found the first graph difference was an unrelated existing weight changing from `0.9998807713772867` to `0.9998807713772868` across `graph_from_dict()` restoration. This is floating-point round-trip drift, not a frame-write difference. V1.2 therefore defines graph equivalence and snapshot digests after rounding serialized floats to 12 decimal places; direct comparison of scalar and batched resulting graphs accepts numeric deviations no greater than 1e-12. The blank replay tuning matrix remains exact. The runner records this corrected comparison, and this amendment is included in the source lock before retry.
