# Core seed-root finite-key admission census v1 results

**Question.** Does any individual `CORE_SEEDS` root plus its declared dependency closure form a nonempty active rule profile entirely admitted by the existing finite-key insertion-only checker?

**Result.** No. The source-locked runner examined all 17 roots independently without executing rules. Thirteen profiles had active rules; none of those profiles passed the checker. Four roots loaded no active rules and are excluded as vacuous candidates. Across the 17 profiles, 209 active-rule instances were checked; the independent analyzer reproduced all 209 checker decisions. Per-root counts are in the [analysis capture](../../../evaluation/reports/substrate_core_seed_profile_admission_census_v1_analysis_20261005.json), with the [raw census](../../../evaluation/reports/substrate_core_seed_profile_admission_census_v1_20261005.json), [lock](../../../evaluation/substrate_capability/substrate_core_seed_profile_admission_census_v1_lock_20261005.json), [runner](../../../evaluation/substrate_capability/substrate_core_seed_profile_admission_census_v1.py), [independent analyzer](../../../evaluation/substrate_capability/analyze_substrate_core_seed_profile_admission_census_v1.py), and [preregistration](SUBSTRATE_CORE_SEED_PROFILE_ADMISSION_CENSUS_V1_PREREG_20261005.md).

**Interpretation.** The current conservative finite-key fragment is not already available as a nonempty profile selected from the core seed roots. This is a coverage/admission result, not evidence that any rejected rule fails to terminate. It does not justify silently disabling core rules. A termination guarantee covering useful production behavior therefore needs either a formally broader sufficient class that admits the needed constructs, or a separately designed restricted profile with explicit capability and coverage measurements. Admission must then be enforced at every rule mutation/import boundary before the guarantee applies.

**Integrity.** The runner's six capture checks and analyzer's ten independent checks passed, including exact 17-root coverage, unique rule identities per profile, stable locked inputs, all checker/analyzer decisions agreeing, and exclusion of empty profiles as candidates. The analyzer's unsupported-operation counts are diagnostic only: a rule can be rejected for multiple reasons, and those counts are not a disjoint classification.
