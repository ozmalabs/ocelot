# Thoughtexperiment direct/deferred event conflict v1.2.3 results

## Result

Three source-locked workers reproduce an authored conflict in which ordinary rule `identity_direct` sets one `CurPercept.identity` to 99 and queued `TrackIdentity` rule `identity_deferred` sets the same field to 0. The nine captured value transitions alternate direct and deferred writes (`<ABSENT>→99→0→99→0→99→0→99→0→99`). The event snapshots replay to the exact final graph, with plain/traced/exact closure parity and no event truncation. Settlement reaches the requested 10 progress steps and reports `progress_budget_reached`; the final event writes 99. This is evidence of a bounded non-settling writer conflict in the fixture, not a general termination claim. Across the three workers, median closure CPU is 0.082 ms plain, 0.367 ms traced, and 0.071 ms exact-snapshot mode; maximum worker RSS is 47,876 KiB. These very small, uncounterbalanced timings are descriptive only and do not estimate instrumentation overhead reliably.

The first locked analyzer run failed its last-writer assertion because it selected the first changed `identity` field in the graph (a PrevPercept field) instead of the CurPercept selected by both writers. The failed output is preserved in [the original analysis](../../../evaluation/reports/thoughtexperiment_event_value_attribution_v1_2_3_analysis_20261005.json). A separately named corrected analyzer filters the changed field by the conflict node, verifies the exact alternating chain and final value, and passes the remaining v1.2.3 checks; its result records the correction analyzer's hash and the failed analysis hash in [corrected analysis](../../../evaluation/reports/thoughtexperiment_event_value_attribution_v1_2_3_corrected_analysis_20261005.json). This correction does not alter the locked runner or original analyzer.
