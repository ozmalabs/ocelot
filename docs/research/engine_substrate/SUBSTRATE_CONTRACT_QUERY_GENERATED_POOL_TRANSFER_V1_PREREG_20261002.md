# Generated-pool lazy query-matrix transfer v1 — preregistration

## Question

Does the current lazy `TermPredictionMatrix` preserve query selection and reduce selector work when the hypotheses are actually generated by the substrate's bounded synthesis path, rather than authored as a finite binary code?

## Tasks and design

Recreate the locked v1.5 generated-pool tasks: triangular numbers, scalar squares, and Euler characteristic on the supplied descriptor families. Generate each version space once per fresh worker from the known examples with the recorded `Plus/Times/Minus/Div` grammar, constants, maximum size, full candidate probe environments, and 10,000-solution cap. Labels come from independent Python target functions: closed-form triangular/square arithmetic and a separate simplicial-closure Euler count. Share the exact generated pool, candidate descriptors, initial observations, and labels between uncached and lazy-matrix arms. Use three fresh workers per task (nine total).

The square task is retained as the pool-singleton control: it should require no query and should not construct/evaluate a prediction matrix. If pool generation is incomplete or empty, record that as an ordinary failure. For nontrivial pools, query both arms until singleton or candidate exhaustion, then check all surviving Terms on task-specific held-outs with the independent Python oracle. Convert numeric labels and predictions to finite Python floats for both arms so the query selector's exact equality policy matches the generated numeric task contract. Record pool completeness/size/hash, terms explored and generation cost, query histories, selector time/CPU, oracle time/calls, native evaluation calls, matrix cells/bytes, final survivor count, held-out exactness, and peak RSS.

## Gates

Require stable pre/post source/native hashes; complete/nonempty generated pools for triangular and Euler and the expected singleton square pool; exact paired query, entropy, prediction, label, terminal, and survivor parity; independent evaluation of all generated Terms on candidate/observation rows; no repeated query descriptors; exact Python oracle labels; and held-out exactness for all selected survivors. The singleton square case must use zero query and zero matrix evaluator calls. Preserve all incomplete-pool, unsupported-Term, and held-out failures.

This is a transfer/coverage panel on three previously authored bounded synthesis tasks, not fresh-domain evidence or a natural-task estimate. Pool generation and query selection costs are reported separately; no speed claim about the full learner follows from selector-only gains.
