# P2: concern supply v2, the agent's own bad replies (2026-10-10)

This is phase P2 of [the open-ended self-improvement plan](OPEN_ENDED_SELF_IMPROVEMENT_PLAN_20261010.md).

## What changed

Before P2, the loop got its concerns from four places:
- the agent's error floor (`unanswered_gap`);
- reader disagreements (`comprehension_health`);
- explicit reports;
- human flags.

A reply that was produced but did not fit filed nothing. That covers a goal-take given for a statement, a receipt given for a question, and a dictionary definition given for "what do you like to do for fun?".

**Production datum.** `WorldAdapter.record_turn_outcome` now writes the turn's ReplyQuality score onto the inbound Message, using the same measure and criteria as judge v2:
- `reply_quality_score`;
- `reply_quality_reason`, the class pair such as `statement->goal_take`;
- `reply_quality_reply_class`.

It passes the turn's `literal_form`. This is a mechanical write; graph rules decide what a low score means.

**Turn spine.** `receive_utterance` links each inbound turn to the previous interlocutor turn with a `follows_turn` edge. `responds_to` cannot be used for this: it points at either the agent's outbound reply or the previous turn, depending on which faculty replied.

**New seed.** `seeds/reply_feedback_gap.json` v1.0.0 (generated by `scripts/gen_reply_feedback_gap.py`) has three evidence rules, each feeding the conversation turn ring's shape tier:
- **act mismatch** (`tally_reply_act_mismatch`): a reply in production that scored 0 and is not the error floor or silence. Those two stay with `unanswered_gap`.
- **repair or rejection in the next turn** (`tally_reply_feedback_cue`): the next turn matches a held `ReplyFeedbackCue`. There are 17 cues, kept as agent-editable data:
  - repair: "what?", "huh?", "I don't understand", "what do you mean", …
  - rejection: "that's not what I asked", "no, I meant", "you didn't answer", …
- **repeated question** (`tally_repeated_question`): an attended earlier question is asked again.

Evidence about turn m1 is kept as `TurnShape{shape_kind:'reply_feedback', sig_signal, sig_reason}`. The signal is act_mismatch, repair, rejection or repeat; the reason is m1's ReplyQuality class pair.

`note_reply_quality_gap` files one `SelfConcern{kind:'reply_quality'}` per class once the class has recurred `min_recurrence` times (`ReplyFeedbackPolicy`, 2). The concern's `about_message` is the class's oldest turn, which is the turn whose reply the experiment must change. The feedback turn is linked by `drew_feedback`, never by `about_message`.

**Wiring:**
- `conversation_turn_ring` v1.1.0: a turn becomes evictable only after a bad produced reply has joined its shape.
- `reply_feedback_gap` is added to the conversation profile's self-improvement anchors and to the daemon's refreshable seeds.
- `reply_quality` is now a conversation-replay experiment kind (`_promote_relations_for_concern`) and a flagged probe kind (`read_corpus`).
- `self_promotion` v1.3.0 makes it self-promotable. The plan made this conditional on P1, which is now in place: judge v2 refuses fixes that lower reply quality.
- `ReplyFeedbackPolicy` and `ReplyFeedbackCue` are added to `improvement_integrity` `protected_node_types`, because they feed concern intake. This is a human-decision list, so the change is flagged here for review.

## Gate S2

**S2a: precision of filed concerns on the held-out labelled set.**
- Setup (`evaluation/substrate_capability/reply_feedback_s2_v1.py`): one fresh boot, self-promotion off, answering the 200 held-out turns that the Q0 sheet was built from, on the production path and offline.
- One class was filed: act_mismatch, `statement->goal_take`.
- All 31 of its turns matched the label sheet, and all 31 are labelled inappropriate. Precision is 1.0 against the 0.7 threshold. This uses the agent labels from Q0.
- This is one class only. The scripted persona dialogues contain no repair, rejection or repeat turns, so those three signals are not measured here. They are covered by unit tests.

**S2b: concerns filed for failures that were not errors, on a production run.**
- Setup: 120 persona turns with self-promotion on.
- Two `reply_quality` concerns were filed and self-promoted, both about produced replies:
  - `statement->goal_take` ("I like to play video games too! …" → "I took on the goal to play the video games …");
  - `question->receipt` ("So, what are we waiting for? Let's go pack our bags!" → "got it"). That question is rhetorical, which the measure cannot tell apart.
- The first concern's experiment picked the family-agnostic reply-ablation op (ablate `reply_to_adjacency_pair`). It was refuted (score sign, quality_delta −0.8, 2 quality drops) and not adopted.
- Everything else reproduced judge v2's run: the same 3 adoptions, the same reopen, the same post-run retest (error/none 25) and ReplyQuality 0.733.

So the new supply works and is safe. It does not yet improve anything. The only family that applies to a `reply_quality` concern is ablation, which cannot fix a misread. For `statement->goal_take`, the deep-reader correction is the fitting family, but `variation_pick` gates that by concern kind. Routing reply-quality classes to the families that can act on them belongs with P4/P5, where families become programs.

## Not done

**Post-adoption audit.** The plan's optional item is to re-measure these signals on turns handled by an adopted rule and trigger `revert_adoption` automatically. It is not built. The production datum and the `drew_feedback` evidence it would read now exist.

## Regression

The targeted scope (33 files) adds the new tests, phase 8 pins, the turn ring, long-session cost, self-promotion and production self-improvement. Nothing fails that did not fail before.

`tests/test_reply_feedback_gap_migrated.py` has 6 tests:
- the production datum is written;
- an act mismatch files once, about the class's first turn;
- the error floor is left to `unanswered_gap`;
- a next-turn repair is filed about the previous reply;
- a repeated question is filed, and a repeat without a "?" is not counted;
- `reply_quality` is a self-promotable experiment kind.
