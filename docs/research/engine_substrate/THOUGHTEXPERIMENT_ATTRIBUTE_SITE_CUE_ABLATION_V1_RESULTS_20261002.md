# Thoughtexperiment attribute-site cue ablation v1 — results

**Gate result: predicted cue-conditioned boundary reproduced.** Four workers each ran four cues against fresh substrate instances. The answer-bearing cue selected `bad_score -> good_score` in 4/4 workers. The direction-omitted, source-only, and destination-only cues each abstained in 4/4. Both opposing ordered swap candidates were present in every fixture, and the primary target rule remained unchanged in all 16 conditions. The corrected independent analysis passes 8/8 checks.

This confirms the composer does not discover the useful direction from these cues: its EditSite score ties and it abstains. The output is safe behavior, but no candidate comparison or oracle-guided resolution occurs. A capability-expanding follow-up must put multiple candidate edits into isolated branches, select discriminating probes, and let the substrate evaluate prediction/residual evidence before the oracle is exposed. Candidate enumeration and edit materialization are currently host-side, so those boundaries must be measured and reported.

The original analyzer incorrectly required exactly two swap candidates; the engine also offered valid swaps involving `positive` and `negative`. The corrected subset check, disclosure, and lock-hash limitation are documented in the [analysis amendment](THOUGHTEXPERIMENT_ATTRIBUTE_SITE_CUE_ABLATION_V1_AMENDMENT_20261002.md). The raw capture was not changed.
