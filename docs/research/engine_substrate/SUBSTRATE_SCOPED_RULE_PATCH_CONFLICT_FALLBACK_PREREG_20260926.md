# Preregistration: deferred RulePatch refusal and CAS conflict fallback

**Question.** Does the deferred pending flag plus global fallback preserve graph-native RulePatch refusal receipts and deterministic same-revision conflict behavior, including downstream outputs?

**Cases.** (A) `stale_at_submission`: one patch targets the current unique unprotected rule but declares `expected_revision=1` when actual revision is 0; it proposes `Lit(true)` and must be refused as `stale_revision` without changing the rule. (B) `same_revision_race`: two graph patches share the target's revision 0 and content hash; the first inserted patch proposes `Lit(true)`, the second proposes `Lit(false)`. The defined expected schedule is insertion order: first commits revision 1, second is refused with `stale_revision` because actual revision is now 1. The rule's initial where clause is `Lit(false)`, and its downstream effect writes each frame-owned output.

Each case runs at 1/2/4 frames, two fresh-process repeats, and three arms: ordinary `full`, one-step `scoped_only`, and `scoped_fallback` that invokes global closure only after pending work is reported. Patches are directly owned by the controller and the writer rule queues each while its graph status remains `pending`; the queue deduplicates any repeated enqueue until the durable receipt changes that status. Patch insertion/membership order and receipt states are captured directly.

**Gates.** Scoped arms report pending work and a one-step budget exit. Full/fallback settle; terminal closure does no work. Fallback state matches full exactly, including patch status/reason/result revision, target revision/hash, trigger, and frame outputs. In case A the refusal is `stale_revision`, target revision remains 0, and outputs remain false. In case B patch 1 commits, patch 2 refuses stale revision 1, target revision is 1, and every output is true. Scoped-only remains pending and does not produce downstream completion. Fresh PIDs and locked hashes are required.

**Claim boundary.** This tests one stale CAS and a two-patch conflict on one target in a synthetic rule/output graph. It does not establish concurrency across native threads, larger patch queues, arbitrary fields, mixed queue interactions, or cost. A failure to preserve deterministic insertion order is a result, not an invitation to adjust the expected order.
