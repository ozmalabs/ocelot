# Cognition build — Phase 1 detailed plan: wiring and quick wins

Parent plan: `COGNITION_BUILD_PLAN_20261010.md` (§4 Phase 1); task template in its §3. Prerequisite: the Phase 0 gate is green, and the baseline in `COGNITION_BUILD_BASELINE.md` is the reference for "no new failures".

Phase 1 is **seed-only**: no Rust, and no edits to frozen or CORE seed files. Every new behaviour lives in a **new seed** whose rules are guarded by an opt-in policy node that is seeded `enabled: 0`. Default boots are therefore byte-identical, and the profile in P1.H8 turns the behaviour on.

## P1.A1 — `capability_synthesis_bridge`: synthesis requests become graph objects and re-arm collapse

**Mechanism.**

Seed `capability_synthesis_bridge`: `depends_on: ["capability_collapse"]`, `self_load_only: true` (it bridges an SLO seed), integer-only.

The policy node is `CapabilitySynthesisBridgePolicy{enabled:0}`, reached by `agent_root -has_capability_synthesis_bridge_policy->`.

Rules:

1. **`csb_open_request`.**
   - Match: `[agent, has_capability_synthesis_bridge_policy, policy]`, `[state, has_active_capability_program, program]`.
   - Where:
     - `policy.enabled==1`
     - `state.synthesis_requested==1`
     - `state.stage=="unresolved"`
     - `Count(state -has_capability_synthesis_request-> r where r.status=="open")==0`
   - Effects:
     - add `CapabilitySynthesisRequest{status:"open", reason: state.unresolved_reason, request_epoch: state.request_epoch, order: program.order, residual_quanta: program.residual_quanta, boundary_quanta: program.capability_boundary_quanta}`;
     - edges `state -has_capability_synthesis_request-> r` and `r -requests_higher_program_for-> program`;
     - add `SelfConcern{status:"noted", source:"capability_collapse", kind:"capability_synthesis", content: reason}`, plus `agent -has_self_concern-> sc` and `sc -about_request-> r`. These are the same spine `af_forced_residual_is_a_concern` and `ps_gap_file` use.
2. **`csb_open_authority_conflict`.** This is the `cc_refuse_overlapping_override_leases` case. Here `override_status=="conflicting_leases"` sets the flag without `stage=="unresolved"`. The rule mints the request with `reason:"conflicting_leases"`, files the concern, and **never re-arms**.
3. **`csb_supplied_rearm_oneshot`.**
   - Where:
     - `r.status=="open"`
     - `r.reason != "conflicting_leases"`
     - `Count(program -continues_to_higher_order_capability_program->)==1`
     - `state.continuous_enabled != 1`
   - Effects:
     - `r.status="supplied"`;
     - `state.stage="ready"`, `state.collapse_armed=1`;
     - `state.request_epoch = state.request_epoch + 1`.
4. **`csb_supplied_rearm_continuous`.** The same, but for `continuous_enabled==1`. It sets `state.cycle_request_epoch = Max(cycle_request_epoch, completed_cycle_epoch) + 1` and leaves the stage alone, because `cc_continuous_arm_requested_cycle` re-arms.
5. **`csb_close_on_settlement`.** Where `r.status=="supplied"` and `state.stage=="settled"`. Effects: `r.status="resolved"` and `r.resolved_order = state.achieved_order`.
6. **`csb_close_on_ambiguity`.** Where the program now has more than one continuation. Effects: `r.status="ambiguous"`, no re-arm. Collapse's own `cc_request_synthesis_ambiguous_higher_program` handles the state.

**P1.A1.1 Frozen Spec Confirmation:**
- `cc_reset_published_outcome`, `cc_reset_active_program`, `cc_reset_effective_outcome`, and `cc_open` (all order 0, `hard_realtime`) restart from `has_root_capability_program` when `state.stage == "ready"` and `state.collapse_armed == 1` (one-shot) or after `cc_continuous_arm_requested_cycle` sees `cycle_request_epoch > completed_cycle_epoch` (continuous mode).
- All 6 bridge rules carry `latency_class: "hard_realtime"` and `area: "general_cognition_synthesis_bridge"` so they settle in the System-1 hard sheet alongside `capability_collapse` under both `StructRulesOnly` and `DualProcess`.
- `csb_open_request` guards against duplicate requests per epoch via `Count(Filter(N("state", "has_capability_synthesis_request"), "r", Or(Eq(A("r", "status"), L("open")), Eq(numeric("r", "request_epoch"), numeric("state", "request_epoch"))))) == 0` and excludes `override_status == "conflicting_leases"` (which is handled by `csb_open_authority_conflict`).
- `numeric("program", "residual_quanta")` (`Plus(Attr(program, "residual_quanta"), 0)`) safely coerces missing `residual_quanta` on channel-mode programs to integer `0`.

## P1.A2 — `decomposition_consumer`: `needs_decomposition` becomes distinct child axes

**Mechanism.**

Seed `decomposition_consumer`: `depends_on: []`. It matches only structure, so it can load beside `impasse_escalation` without depending on it, and the test stays light.

The policy node is `DecompositionConsumerPolicy{enabled:0.0, child_shortfall:0.6}`.

The partition source is the parent axis's `requires_key` CapKeys. These are backfilled from `capability_keys` by `WorldAdapter.wire_self_extension` (`substrate/world_adapter.py:17250`). Each child is distinguished by exactly one key, which satisfies the dedup constraint in `order3_reframe`.

1. **`dc_mint_child_per_key`.**
   - Match: `[agent, has_decomposition_consumer_policy, pol]`, `[mi, needs_decomposition, ax]`, `[ax, requires_key, k]`.
   - Where:
     - `pol.enabled==1`
     - `mi.dc_handled != 1`
     - `Not Exists(ax -decomposes_into-> c where c.decomposed_key == k.name)`
   - Effects:
     - add child `CapabilityAxis{is_axis:1.0, subskill:1.0, saturation:0.0, shortfall: pol.child_shortfall, mf_stall:0, decomposed_key: k.name, parent_axis_ref: ax}`. Its `capability_keys` are set by the T1 spec: either the parent keys plus the distinguishing key, or `[k.name]` alone. The constraint is that they must differ from the parent's.
     - edges `ax -decomposes_into-> child` and `child -requires_key-> k`.

     `subskill:1.0` keeps `escalate_open` and `escalate_open_on_stall` from opening nested ladders on children. Both rules exclude subskills.
2. **`dc_mark_handled`.** Where every `requires_key` of `ax` has a child with that `decomposed_key`, and `mi.dc_handled != 1`. Effects: `mi.dc_handled=1` and `mi.dc_outcome="partitioned"`.
3. **`dc_no_partition`.** Where `Count(ax -requires_key->)` ≤ 1. Effects: `mi.dc_handled=1` and `mi.dc_outcome="no_partition"`, which is an honest record that nothing finer exists. The ladder still climbs to order 4 as it does today.
4. **`dc_parent_progress_from_children`.**
   - Where `ax` has children and `ax.dc_child_epoch != <clock>`.
   - Effects: `ax.child_mean_saturation = Sum(children.saturation)/Count`.

   Whether this attribute should feed `ax.saturation` is a T1 decision. Writing `saturation` would interact with `escalation_resolve_high_confidence` (≥ 0.95) and `escalation_climb_low_confidence`. Default: write only `child_mean_saturation`, and decide in P1.H9.

**P1.A2.1 Frozen Spec Confirmation:**
- Child `capability_keys` are set to `Vec([k.name])` (a single-element list containing the child's distinguishing `CapKey.name`), and `dc_mint_child_per_key` fires only when `Count(ax -requires_key->) > 1`. Because the parent axis has ≥ 2 keys, `[k.name]` is always strictly distinct from the parent's `capability_keys` and from sibling children.
- `dc_inherit_operator` optionally binds `child -investigated_by-> op` when the parent axis has an `investigated_by` operator and `Count(child -investigated_by->) == 0`, while `dc_mint_child_per_key` does not require an operator on the parent.
- `dc_parent_progress_from_children` uses a value-change fixpoint guard (`Not(Eq(A("ax", "child_mean_saturation"), mean_term))`) rather than an external clock, so it works standalone and updates whenever any child's `saturation` changes, writing only `child_mean_saturation` (leaving `ax.saturation` untouched for P1.H9 evaluation).

## P1.A4 — `impasse_simulation_bridge`: a System-2 escalation asks the world model

**Mechanism.** This copies the default-mode lifecycle (`default_mode_core.json` rules at :716-838) onto dual-process escalations.

Seed `impasse_simulation_bridge`: `depends_on: ["dual_process_core", "generative_world_model", "default_mode_core"]`. `default_mode_core` supplies the `NetworkModeState` clock and the `default_mode_generative_world_model` task set (area `world_model_simulation`).

The policy node is `ImpasseSimulationPolicy{enabled:0.0, horizon:3.0, budget:6.0, maximum_branching:2.0, deadline_window:4.0}`.

**Why the bridge mints its own escalation.** A dual-process escalation is set to `serviced` after one admitted settle (`cognitive_cycle.rs:816-830`), so the GWM's soft rules would never be admitted on the next cycle. The bridge therefore mints its own `SystemTwoEscalation` that recruits the world-model task set, with `input_epoch` and `deadline_epoch` set so that the engine's staleness check applies (`request_is_stale`, `cognitive_cycle.rs:353`).

The trigger reasons are `instinct_conflict`, `near_conflict`, `low_confidence`, `no_grounded_default` and `controller_arbitration`, plus `prediction_error`, `novelty` and `uncertainty` when legacy recruitment is on (`dual_process_core.json:338-759`).

1. **`isb_request_simulation`** (hard_realtime, area `impasse_simulation`).
   - Match: `[agent, has_impasse_simulation_policy, pol]`, `[agent, has_dual_process_context, ctx]`, `[ctx, has_system_two_escalation, esc]`, `[agent, has_network_mode_state, mode]`, `[agent, has_belief_state, belief]`, `[agent, has_world_model_simulation_task_set, wts]`.
   - Where:
     - `pol.enabled==1`
     - `esc.reason` ∈ the trigger set
     - `Count(esc -has_impasse_simulation->)==0`
     - `belief` = Argmax-epoch over `status=="current"` and `provenance_kind=="perceived"` (copy `default_mode_bind_current_belief_to_goal_context`)
   - Effects:
     - add `SimulationRequest{status:"collecting_actions", request_kind:"impasse_counterfactual", provenance_kind:"imagined", observation_status:"not_observed", input_epoch: mode.epoch, deadline_epoch: mode.epoch + pol.deadline_window, horizon: pol.horizon, budget: pol.budget, maximum_branching: pol.maximum_branching, interruptible:1.0}`;
     - add `SystemTwoEscalation{status:"requested", reason:"impasse_simulation", request_kind:"impasse", input_epoch, deadline_epoch}`;
     - edges `agent -has_simulation_request-> sim`, `esc -has_impasse_simulation-> sim`, `sim -has_source_belief-> belief`, `sim -validated_by_clock-> mode`, `req -recruits_task_set-> wts`, `sim -driven_by_escalation-> req`.
2. **`isb_offer_actions`** and **`isb_seal`**. Copy `default_mode_offer_world_model_actions` and `default_mode_seal_world_model_action_snapshot`, re-keyed on `esc -has_impasse_simulation-> sim`.
3. **`isb_propose_imagined_candidate`** (hard_realtime).
   - Where:
     - `sim.status=="completed"`
     - `Count(esc -has_imagined_candidate->)==0`
     - trajectory `t` = Argmax over `sim -has_prediction_trajectory->` of `MaxOver(t -has_predicted_belief_state-> s, MaxOver(s -has_predicted_outcome-> o, o.outcome_value * o.confidence))`

     The GWM does not mark a best branch, so this rule must.
   - Effects:
     - add `ImaginedCandidate{status:"proposal", provenance_kind:"imagined", observation_status:"not_observed", root_action_kind: t.root_action_kind, expected_value: <the Argmax value>}`;

## P1.B1 — `consolidation_scheduler`: offline replay gets a producer (sleep v0)

**Facts.**
- `episodic_prioritize_one_replay_per_cycle` consumes `agent -has_memory_cycle-> MemoryCycle{status:"pending", mode:"offline"|"wake", epoch}`. Only tests mint these.
- Completed cycles are never deleted.
- `agent -has_memory_clock->` has no producer, yet two EWM rules (`working_memory_expire_unmaintained_slot`, `episodic_prune_expired_transient`) need it.
- `NetworkModeState` (DMN, CORE) carries `epoch`, `default_mode_weight`, `task_demand` and `exteroceptive_load`.

**Mechanism.**

Seed `consolidation_scheduler`: `depends_on: ["episodic_working_memory_core", "default_mode_core"]`.

The policy node is `ConsolidationSchedulerPolicy{enabled:0.0, entry_weight:0.6, maximum_task_demand:0.2, cooldown_epochs:4.0, retention_epochs:4.0, last_cycle_epoch:-1000000.0}`. The rule prefix is `csch_`, because `cs_` is already taken by `cognitive_supervision`.

1. **`csch_bind_memory_clock`.**
   - Where `Count(agent -has_memory_clock->)==0`.
   - Effects: `agent -has_memory_clock-> mode` (the NetworkModeState).
   - The production `Agent -has_memory_clock-> NetworkModeState` is declared in this seed. P1.B1.1 confirms that no existing production conflicts.
2. **`csch_mint_offline_cycle`.**
   - Where:
     - `pol.enabled==1`
     - `mode.default_mode_weight >= pol.entry_weight`
     - `mode.task_demand <= pol.maximum_task_demand`
     - `mode.epoch - pol.last_cycle_epoch >= pol.cooldown_epochs`
     - `Count(agent -recorded_episode->) > 0`
