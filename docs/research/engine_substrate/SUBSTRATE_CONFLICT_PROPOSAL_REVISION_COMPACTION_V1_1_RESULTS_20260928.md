# Bounded proposal revision-event retention v1.1 results

All gates pass in three fresh workers at N=2/8/32/64. Removing the previous revision event before creating the next one preserves exact max/count/ambiguity/selection state for the initial, higher-add, tie-add, tie-remove, and score-lowering states. Each completed revision retains exactly one revision node; cleanup removes one node and its five incident event/stage edges. Native integer counts replicate across workers. Cleanup elapsed time is measured separately as host-side work (about 0.0015–0.0054 ms in the observed cells); it is descriptive, not a stable latency claim.

The bounded protocol reduces later closure work at every tested size relative to retained-event v1. At N=64, stage Term evaluations for the five revisions are 789/801/479/801/801, compared with 789/1,602/1,437/3,204/4,005 when all revision nodes are retained. The last revision is therefore 80.0% lower in counted Term evaluations. Graph-resident revision history stays bounded at one active event. This isolates the source of the v1 growth: old stage bindings were revisited as revision nodes accumulated.

The tested cleanup is caller-managed `remove_node`; it is not an engine compaction facility. Historical audit data must be retained outside the live graph if required. The experiment does not cover crashes between the three closures, concurrent mutation, or replay/recovery. A partial pipeline may leave max/count/decision fields from different revisions; adding an atomic revision stamp and a recovery gate is the next correctness requirement. No asymptotic theorem follows from these four sizes.
