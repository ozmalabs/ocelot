# Deferred SetRuleClause competing-writer gate v1 (preregistration)

Question: does deferred source provenance remain correct with multiple queued clause edits, and can it distinguish final-state control from non-unique causes and refused ambiguous targets?

Three authored cases use one target rule with a true initial `where` clause and two one-shot producer rules. Producers enqueue edits in deterministic rule order and delete their trigger edges to prevent re-enqueue. In `competing`, the first writes true and the second false; omitting the second edit should restore the held-out probe marker, while omitting the first should not. In `duplicate`, both write false; both should commit but neither individual omission should restore the marker. In `ambiguous_target`, two active rules share the target name; both producer edits should be refused, with no rule revision changes or probe-marker suppression.

Compare event-order blind omission with successful receipt/origin attribution. For competing writes, the receipt policy tests candidates in queue order and must find the necessary second writer; this does not predict a branch reduction over blind order. For duplicate writes, it must report both successful origins and no individually necessary writer. For ambiguous names, it must abstain because no committed rule-change receipt exists. Each omission branch starts from the same shared-page snapshot and changes only the selected producer's SetRuleClause effect; its trigger-edge deletion remains, then a held-out probe is evaluated. Three workers and three isolated replicates per scenario are planned.

Gates: all source/native hashes match; expected event counts and origins; revisions advance once per successful queued item in queue order; duplicate writers yield no unique necessity; ambiguous target produces no commit and leaves all target revisions unchanged; held-out branch oracle matches the expected outcomes; primary graph/rule revisions remain unchanged. Timings are exploratory. This tests the legacy name-based deferred queue on synthetic one-shot producers, not natural repair, CAS-based patch behavior, or learned cause discovery.
