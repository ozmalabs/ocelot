# TermArena persistent-owner audit

## Scope

Read-only source audit prompted by the TermArena lifecycle measurements and the proposed future arena reclamation work. This classifies source-visible `TermIdx` owners in the Rust substrate and native JSON convenience paths. It is not an exhaustive dynamic reference census, nor proof that every parse entrypoint is covered.

## Persistent owners

| Owner | Stored TermIdx-bearing data | Lifetime / reclamation implication |
|---|---|---|
| `Substrate.terms` | Append-only `Vec<TermNode>`; TermIdx values address positions in this arena ([`term.rs`](../../../runners/dsl/src/term.rs)) | Index stability requires live handles to remain valid. Truncation can only release an unreferenced suffix. |
| Rewrite rules | `RewriteRule.where_`, `RewriteRule.effects` (`EffectArg::Computed`), `where_conjuncts`; derived JIT code can own executable bytes but not a TermIdx ([`rewrite.rs`](../../../runners/dsl/src/rewrite.rs), [`jit.rs`](../../../runners/dsl/src/jit.rs)) | Installed and staged rules are long-lived owners. Replacing/removing a rule must account for all of its Terms and any shared descendants. |
| Grammar productions | `Production.where_` and mandatory `Production.weight` ([`grammar.rs`](../../../runners/dsl/src/grammar.rs), owned in `Substrate.checker.grammar`) | Grammar terms persist independently of graph state and may be shared with other owners. |
| Concept resolver | `ConceptResolver = FxHashMap<Sym, TermIdx>` ([`term.rs`](../../../runners/dsl/src/term.rs)); populated by `Substrate::define_concept` ([`substrate.rs`](../../../runners/dsl/src/substrate.rs)) | Definitions remain reachable through `Holds` evaluation; cannot reclaim solely from graph-root deletion. |
| Shape cache | `ShapeCache.entries: FxHashMap<TermIdx, Shape>` ([`shape.rs`](../../../runners/dsl/src/shape.rs)); owned by `Substrate` ([`substrate.rs`](../../../runners/dsl/src/substrate.rs)) | A derived cache is also an index owner: removing/reusing TermIdx values requires invalidating corresponding keys. Current internal cache is keyed by stable arena index. |

## Temporary and graph-backed terms

Several PyO3 operations parse a Term into the main arena, use it synchronously, then truncate to a saved length. `evaluate`, `relax_to_fixpoint`, `search`, `add_term_subgraph`, `term_subgraph_json`, reflex stimulus conversion, and staged failed rule patches are visible examples in [`py.rs`](../../../runners/dsl/src/py.rs) and [`substrate.rs`](../../../runners/dsl/src/substrate.rs). The intended invariant is that the temporary suffix does not escape into a persistent rule, grammar, concept, or cache owner. The recent cleanup paths for evaluation and graph reflection explicitly truncate after use.

The follow-up call-site audit found failure-path gaps where parsing could append a prefix before returning an error. These were closed for `evaluate`, `relax_to_fixpoint`, `search` preparation, `term_subgraph_json`, failed `define_concept` parsing, failed `add_rule` parsing, and `parse_rule_json_pub`. The public shape APIs and `add_term_subgraph` also roll back failed partial parses. Successful `define_concept` is intentionally persistent because the resolver holds its TermIdx; successful `add_rule` / `import_rules` likewise install Terms through RewriteRule owners. `import_rules` now parses all entries before installing any, then commits in input order; failure rolls back the staged Term and interner suffixes. `codec::install_field_grammar_rules` now stages its full embedded manifest before adding rules and restores both suffixes if parsing fails. Three successful-path replicates install the expected 20 rules in stable order. Since runtime callers cannot inject a malformed embedded row, the codec installer's failure branch remains source-reviewed rather than dynamically tested. The public parser wrapper's failure rollback likewise remains to be directly exercised.

`add_shape_node_for_term` produces a graph-resident Shape node, so the Shape record survives independently of the parsed Term. `shape_of_term` returns only a structural Shape value. Before this audit, both parsed their JSON Terms into the persistent arena without releasing the suffix. Repeated identical JSON inputs received fresh TermIdx values, so the public `shape_of_term` path did not reuse its TermIdx-keyed cache. An exploratory current-extension probe ran batches totaling 1,111 calls on a one-node `Lit` and grew `term_arena_len()` from 0 to 1,111. This is logical arena growth; it is not an RSS measurement.

The implementation now assesses these JSON inputs directly and truncates the temporary suffix on success or parse failure. Stable-index internal callers still use `Substrate::shape_of_term` and `ShapeCache`. The rebuilt-extension confirmation passed. A separate failure-path audit covers seven scratch-operation errors at 100 attempts each over three replicates; all preserve arena length ([`SUBSTRATE_TERM_ARENA_FAILURE_ROLLBACK_RESULTS.md`](SUBSTRATE_TERM_ARENA_FAILURE_ROLLBACK_RESULTS.md)). The rule-import probe additionally checks that parse failure restores arena length, rule count, and subsequent Sym allocation ([`SUBSTRATE_RULE_IMPORT_ATOMICITY_RESULTS.md`](SUBSTRATE_RULE_IMPORT_ATOMICITY_RESULTS.md)).

## Reclamation constraints and next measurement

The arena is a shared index space, not a collection of independently owned trees. A correct reclamation design must account for rules, grammar productions, concepts, cache entries, live evaluation cursors, and shared child references. Suffix rollback is safe for operation-local parses only when no persistent owner has observed the new indices. General middle-of-arena reclamation would require stable indirection/generational handles or a complete remap of every owner; simply deleting graph reflection nodes does not reclaim `TermNode`s.

Direct `parse_rule_json_pub` rollback was then exercised through a locked Rust diagnostic: 25 late failures preserved both TermArena and interner lengths, and a valid parse succeeded afterward ([results](SUBSTRATE_PARSE_RULE_JSON_PUB_ROLLBACK_RESULTS.md), [raw](../../../evaluation/reports/substrate_parse_rule_json_pub_rollback_20260925.json), [lock](../../../evaluation/substrate_capability/parse_rule_json_pub_rollback_lock_20260925.json)). The next memory step is an isolated subprocess acquisition envelope with allocation-level capture and a newly frozen P4 task family; the existing 18-task diagnostic is same-process and discovery-only.
