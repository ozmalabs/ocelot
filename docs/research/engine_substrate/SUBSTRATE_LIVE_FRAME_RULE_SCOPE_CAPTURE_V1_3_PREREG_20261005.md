# Live frame rule-scope capture v1.3 preregistration

## Purpose

Refresh the two-request rule-definition and runtime-access capture after the current seed `composer_comprehension_graph.json` diverged from the v1.2 locked source closure. This is required before mapping current Term access declarations onto the captured live rule set.

## Protocol

Repeat the existing two-prompt `self_report` panel with three fresh workers and the same access/work instrumentation, post-converse rule exports, lifecycle controls, and semantic graph checks. Lock the complete current source closure, native build and extension, protocol, runner, and independent analyzer before running. Require identical final semantic graph digests, request access/work traces, and exported definitions across workers; every observed RuleUID must map to a same-request post-request definition; expected task lifecycle and controls must pass. Analyze raw worker records independently.

## Limits

This refresh updates source validity for one selected two-request route only. It does not supply factor variables/domains, a learned frame boundary, comprehensive matcher rejected-candidate traces, or natural-task prevalence.

## Reproduction

Run `python3 scripts/substrate_live_frame_rule_scope_capture_v1_3.py --lock`, then `python3 scripts/substrate_live_frame_rule_scope_capture_v1_3.py`, followed by `python3 scripts/analyze_live_frame_rule_scope_capture_v1_3.py` and `python3 evaluation/substrate_capability/analyze_live_frame_rule_scope_structural_v1_3.py`.
