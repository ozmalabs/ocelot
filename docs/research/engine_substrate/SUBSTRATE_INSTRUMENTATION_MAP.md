# Substrate instrumentation map — Phase A audit

**Status:** source audit started; no counters or runtime behavior changed here. This document maps existing instrumentation to the benchmark protocol and identifies observability gaps before a pilot is chosen.

**Protocol:** [`SUBSTRATE_BENCHMARK_PROTOCOL.md`](SUBSTRATE_BENCHMARK_PROTOCOL.md). **Capability map:** [`SUBSTRATE_CAPABILITY_MAP.md`](SUBSTRATE_CAPABILITY_MAP.md).

## Findings

The substrate already has more measurement infrastructure than a greenfield plan would suggest. `runners/dsl/src/ext.rs::Counters` exposes per-substrate monotonic totals for inserted nodes/edges, grammar admissibility, term evaluation/cache behavior, shape pruning, and numeric operand anomalies. `runners/dsl/src/scale_audit.rs` is a separate opt-in process-global audit with detailed candidate enumeration, repeat enumeration, where evaluation, pushdown, leaf visitation, rollback probes, rule enumeration, FFI crossings, graph writes, and term/variant work units. The scale audit documents its default-off behavior and provides sorted snapshots/reset.

This is significant capability and existing evidence. It is not yet one run-level measurement contract: the counters have different scopes and reset rules, some are per-substrate while others are process-global, and they do not by themselves capture outcomes, memory, termination status, or a unified mapping between run/instance and counter window.

## Rule-runner source facts relevant to measurement

1. `RewriteRule::derive_access` in `rewrite.rs` derives read/write sets, `batch_safe`, and pushdown/projection metadata from match edges, where terms, and effects. These are useful structural observables, but they are static access summaries, not a learned frame decomposition.
2. `rewrite::run_rules_opts` loops while progressing steps remain below `max_steps`. A progressing step is not necessarily a whole graph pass. At the `Substrate` API, `run_rules(max_steps)` returns the number of progressing steps. Therefore reaching the numeric cap cannot be reported as “fixpoint reached” solely from the return value; the pilot needs a separate terminal-status observation.
3. Optional cycle detection calls `TypedGraph::state_fingerprint` and tracks previously seen fingerprints. Its cost and semantics must be measured separately from the default committed runner.
4. `scale_audit` explicitly distinguishes first versus repeated candidate enumeration and scan/local/indexed candidates. It also documents that graph-level counts can miss work inside aggregate Terms; variant invocation and interior work-unit counters address part of that blind spot. This makes scale audit a strong starting point for closure/matching attribution, but not a replacement for wall/CPU/memory and task outcome measurement.
5. The scale audit is process-global and default-off. Parallel benchmark conditions sharing a process could contaminate counters; run each condition in a fresh process or establish an isolated epoch/reset protocol before using its snapshots.
6. A no-work terminal probe is not a semantic correctness check. The first closure pilot returned zero on its follow-up while the graph still lacked expected transitive edges. Trace attributed this to a cold-rematch cursor advanced past self-produced edge types; the fix and post-fix regression are recorded in `SUBSTRATE_CLOSURE_PILOT_RECHECK_RESULTS.md`. Benchmark records must preserve both terminal status and task-oracle correctness.

## Recommended first pilot instrumentation

Do not add new hot-path counters before using the existing ones. Build an external harness that:

1. starts one fresh process per condition/instance (or proves safe isolation for an alternative);
2. records graph dimensions before and after the run;
3. enables scale audit and snapshots/reset counters at a single-instance boundary;
4. snapshots `Counters` before and after the run and records deltas;
5. records `max_steps`, returned progress count, and an independent settled/capped determination;
6. captures wall time, CPU time, peak RSS, exit code, and stdout/stderr;
7. serializes the run manifest and instance record using schemas in `evaluation/substrate_capability/`;
8. compares instrumented and uninstrumented outputs and measures overhead on the same tiny and medium cases.

The pilot uses synthetic rules with hand-checkable closure counts and runs each topology/size instance in a fresh worker. Its first version exposed and helped fix a recursive cursor issue; post-fix cases pass the oracle. Candidate-counter partitions reconcile. The original graph_writes field is scoped to Python-boundary mutations; native edge, node, attribute, delete, and replacement effect families now have separate counters and a focused coverage test. Counter scopes intentionally distinguish attempts from committed deletes/inserts. A five-repeat enabled/disabled audit comparison is available, but compiled-out instrumentation cost remains unknown. Do not infer current `run_rules` cap status from `steps == max_steps` without checking implementation exit semantics on a controlled input.

## Open questions before implementation

- How is the native PyO3 extension built/loaded in the benchmark environment, and which supported package exposes the static scale-audit methods?
- Which stable rule names are available in scale-audit output, and can every per-rule counter be mapped without relying on unstable interner order?
- Which read-only graph stats API is cheapest for snapshots, and does it include live node/edge counts by type?
- Which exact workload is representative and safe to run in a clean process without optional network, simulator, or GPU dependencies?
- What minimal independent oracle will establish fixpoint completion for the pilot without doubling the same implementation logic?
- Which counters are default-on in production paths, and what is their measured overhead compared with scale-audit instrumentation?

## Runtime access-footprint observability audit (2026-09-25)

Before the smoke probe, the native runtime exposed no concrete per-firing read/write trace. `RewriteRule::derive_access` (`rewrite.rs`) provides per-rule resource classes (`Attr(Sym)`, `Type(Sym)`, `Edge(Sym)`) without bound node identity. The opt-in scale audit attributes counts to `RuleIdx`, not the graph objects touched. The graph mutation log records node/key for attribute writes in a narrow scheduler path; it is not a complete read/write event log. A new bounded, default-off first-slice trace now records successful pattern edges, interpreted `Attr`/`TypeOf` reads, and selected native effect accesses with stable rule UIDs ([smoke result](SUBSTRATE_RUNTIME_ACCESS_TRACE_SMOKE_RESULTS.md)). It has exact enabled/disabled parity on one controlled fixture. It remains incomplete and has not yet established dynamic frame boundaries on task workloads.

The source audit identifies the minimum trace surface and its semantic distinctions:

| Event family | Source site | Record | Caveat |
|---|---|---|---|
| Pattern enumeration | `rewrite.rs::extend_each` / `match_rule_each` | rule UID, match edge type, candidate edge ID/endpoints, accepted binding IDs | Candidate enumeration is not itself a semantic read footprint; record accepted pattern edges separately from rejected candidates. |
| Term graph reads | `term.rs::evaluate` arms such as `Attr`, `TypeOf`, `Edges`, `Neighbours`, `ReachableFrom`, and edge-attribute access | rule UID, variant, concrete node/edge IDs and resource key/type | Aggregate terms may traverse many objects; cache hits can suppress underlying graph calls. Report logical footprint separately from physical work. |
| Effect inputs | `rewrite.rs::apply_rule_full` effect argument resolution | rule UID, binding variables/nodes, source resources read while computing the value | This is where the known effect-only attribute reader lives; it must not be conflated with predicate reads. |
| Effect outputs | `rewrite.rs::apply_rule_full` mutation arms | rule UID, effect kind, concrete target node/edge IDs, resource key/type, attempted vs committed change | `SetAttr` and `SetAttrIfDifferent` differ; add/delete/mint and rollback require separate attempted/committed accounting. |
| External writes | `TypedGraph`/`Substrate` mutation APIs | caller/source label, concrete target, resource, epoch | Needed to relate external boundary perturbations to later rule firings. |

An implementable first slice should be default-off and opt-in for isolated workers. Add a bounded event collector keyed by stable rule UID (not only positional `RuleIdx`) at the matcher binding boundary, the Term graph-read sites, and effect application; emit overflow counts rather than silently truncating. Keep attempted candidate work, successful logical reads, attempted effects, and committed graph deltas in distinct channels. Compare traced and untraced twins for identical final graph, progress, and terminal status, then measure overhead. A shadow trace is diagnostic only: dynamic absence in a finite run is not proof that a static dependency is impossible.

This audit also clarifies the existing scheduler counterexample. `dirty_by_writeset` deliberately does not re-fire a where-less consumer for attribute-only changes: an effect-only `Attr` value can change while the binding remains stable, but replay can duplicate non-idempotent effects. The 18-case dynamic recall matrix finds exactly that stale case (17/18 reader outputs match a final-graph oracle); the predicate-read control succeeds. This is an execution-policy gap requiring an effect-semantics gate, not evidence that the static access extractor missed the attribute key. Preserve the existing full-rescan oracle while classifying idempotent attribute writes, edge writes/deletes, and fresh-node minting.
