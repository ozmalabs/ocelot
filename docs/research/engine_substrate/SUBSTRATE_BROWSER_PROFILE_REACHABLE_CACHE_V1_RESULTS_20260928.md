# Browser profile ReachableFrom cache panel v1 results

**All preregistered gates pass.** Twenty-four fresh workers crossed N={2,8,32,128} affordances and B={1,4} direct wrappers, with three replicates per cell and counterbalanced arms. Each arm booted the normal five-seed `WorldAdapter` browser profile; native rule readback matched exactly the eight rules declared by the transitive seed manifests.

Both arms ran `WorldAdapter.tick()` and produced exactly N session `has_affordance` edges. Tick progress, the complete native graph, terminal graph, matcher counters, runtime access-trace rows, and dropped-event counts matched exactly. A second normal adapter tick performed zero work. Independent analysis passes all 12 provenance, profile, semantic, parity, and counter checks.

At N=128, `ReachableFrom` adjacency visits fell from 2,097,280 to 257 with B=1 (8,161×) and from 587,776 to 260 with B=4 (2,261×). Median tick times were 197.6 ms off versus 74.0 ms on (2.67×), and 62.7 ms versus 22.5 ms (2.76×), respectively. At N=2, the work reduction was only 2× to 6.25× and elapsed times were sub-millisecond. Wall time includes the full seeded profile tick plus opt-in scale/access instrumentation; it is descriptive rather than a production latency claim.

This establishes that reuse survives the ordinary five-seed adapter scheduling path. The graph records were constructed to match DOM ingestion shape; no Chromium page ran. A separate Chromium preflight failed inside the sandbox with `sandbox_host_linux.cc` reporting “Operation not permitted,” so live browser latency and page-distribution prevalence remain unmeasured. `term_unit:ReachableFrom` gives inspected adjacency work, not explicit cache hit counts or retained bytes.
