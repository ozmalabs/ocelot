# Production-derived thoughtexperiment diagnosis v1 (preregistration)

Question: on a production-derived joined rule with a variable-bound effect value, does per-effect tracing improve diagnosis over blind omission and full graph/rule rematching?

Fixture: use the exact `discourse_goal_resolve` definition from `seeds/conversation_discourse_state.json`. Construct one `DiscourseState`, one origin `Event`, one executing `Goal`, and one later `action_result` `Event`; connect the four match edges and satisfy the seed's status, event-index, event-kind, and unique-owner guard. Only the `outcome` literal is changed to the known `fault_marker`. The existing `last_transition_event` variable binding, four-edge join, guards, remaining effects, and effect order remain as authored. This is a controlled fault-injection fixture, not a live dialogue task.

Four source-locked arms begin from the same graph/rule revision and use actual shared-graph-page snapshots for every omission branch: (A) endpoint event report followed by increasing-index omission search; (B) endpoint report, complete graph/rule rematch, then candidate omission search; (C) target-only per-effect report and candidate omission search; (D) value per-effect report and candidate omission search. Each branch removes one rule effect and reruns closure with a ten-pass safety budget and records the fixed point. Record all candidate lists, branches, exact outcomes, wall/CPU time, report sizes, and primary graph/rule revision. Three workers and three fresh-process replicates per arm are planned. Analyzer gates require source-lock integrity, exact rule/fixture fingerprint, expected unique match, all four arms to find an omission that removes the fault marker, final graph equality for healthy surviving fields, branch/primary isolation, and parity across workers/isolated runs.

Primary comparisons are total wall/CPU time and branch count from observer start through the first curing branch. No arm receives the oracle effect index. The full-rematch arm exports and checks the post-closure graph, including seed match edges and attribute guards. Value tracing's candidate selector reads event reports only. Target-only selector reads target IDs and edge keys only. This small authored fixture establishes diagnostic behavior on one production-derived rule shape; it does not establish prevalence, general diagnosis ability, deferred queue coverage, or general self-repair.
