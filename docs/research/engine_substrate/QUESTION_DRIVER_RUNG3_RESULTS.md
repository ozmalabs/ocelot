## 2. What was built

### 2.1 `seeds/problem_shape_growth.json` (generated by
    `tools/build_problem_shape_growth_seed.py`, never hand-edited — the
    same house convention `tools/build_meta_shape_growth_seed.py`
    established)

A new node type `ProblemShape{name, signature, support, minted, source}`
(field names mirror `MetaShape` exactly), mirroring the
`DirectionalCorrespondence` precedent per the prereg's Q2/§3 finding:
`ShapeDecode`'s live decode pool does not partition on `kind`
(`runners/dsl/src/shape_decode.rs::load_parts`, re-confirmed by direct
read, not re-litigated), so `ProblemShape` is a genuinely new node type,
not a `ShapeSignature{kind:"problem_shape"}`. Two entries are SEEDED
directly (`ps_has_statement=yes` / support 10, `ps_has_targets_mt=yes` /
support 5), grounded in the real §1 counts. Five rules:

- **`ps_decode`** (rung 1, DEQUANTIZE) — the UNCHANGED `ShapeDecode` Term,
  pointed at `codebook_type: "ProblemShape"`, `wild_objects: false`
  (literal — no `ProblemShape` signature carries WILD, unlike meta-shape's
  anti-unified lgg codebook, so the SIMPLER `Count(residual)==0` verdict
  from `shape_decode_loop.json::sd_recognize` is reused rather than
  `meta_shape_growth.json`'s `Covers`-based rung 1).
- **`ps_recognize`** (rung 1 HIT) — `residual` count `==0` →
  `status:"recognized"`, `covered_by` via the same
  `Argmax`/`FixedCount`/`AntiUnify` specificity metric `sd_recognize`
  already uses.
- **`ps_residual`** — a decoded observation the codebook did NOT fully
  explain becomes a mint CANDIDATE (mirrors `msg_residual`'s terminal-
  status role; reached directly after rung 1 here since rungs 2/3 are not
  wired at this grain — §3 below).
- **`ps_mint`** (rung 4) — built from **ONLY existing generic Terms**
  (`Eq`/`Exists`/`Argmin`/`Count`/`Plus`), no bespoke Rust Term (§4).
  Fires only when: the observation is a genuine residual; at least one
  OTHER decoded/residual/minted observation shares its `key` (recurrence,
  support≥2); this observation is the group's canonical minter (lowest
  node id — the SAME `Argmin` idiom `seeds/gap_awareness.json::
  retire_duplicate_gap` already uses for its own canonical-survivor pick);
  and no `ProblemShape` already carries this `key` as its `name`
  (mint-once guard).
- **`ps_redecode`** — any `recognized`/`residual`/`minted` observation
  decoded under an older `problem_codebook_epoch` re-arms to `pending`
  (mirrors `sd_redecode`/`msg_redecode` exactly, minus transform/dim flag
  resets since those rungs are not wired here).

Three new Γ productions declared (not omitted — per CLAUDE.md's
"SHAPES, NOT NUMBERS" finding that 454/634 manifests wrongly ship
`"productions": []`): `Agent -observed_problem-> ProblemShapeObservation`,
`ProblemShapeObservation -about_goal-> Goal` (traceability back to the real
Goal an observation was extracted from, mirroring
`gap_awareness.json`'s own `sc -about_goal-> g`), `ProblemShapeObservation
-minted_problem_shape-> ProblemShape`.

### 2.2 `domains/problem_shape.py`

`goal_signature(sub, native, goal_node)` — mechanical extraction of the
five real facts (§1) off a Goal's own attrs/edges into a fixed-arity
relation-set signature, mirroring `analogical_thinking._pair_witness`/
`_concept_shape_vector`'s idiom (fixed axis order, `_ABSENT` sentinel,
sorted by predicate). **`kind` is deliberately never read** — including it
would make recognition circular (the Goal already says what it is) and
would give the wrong answer once a future pre-mint dispatch caller needs
this signature BEFORE `kind` exists (§5).

`signature_key(signature)` — a deterministic identity string
(`predicate=value` pairs, sorted, joined), mirroring `sd_mint_quantum`'s
own `capability_keys` idiom exactly ("mechanical, stable... set... from the
observation's own predicate structure"). This stands in for
`MetaShapeMint`'s Rust-computed `name`/`field` outputs (§4).

`observe(agent, goal_node)` — mechanical ingest: writes a
`ProblemShapeObservation`, an `observed_problem` edge, an `about_goal` edge
back to the real Goal, and runs the rules. Mirrors `meta_shape.observe`
exactly.

## 3. Rungs 2/3 of the sd ladder — not wired, a deliberate no-op

`TransformDecode`/`DimInfer` are NOT wired at this grain, for the same
reason `META_SHAPE_FIRST_CLASS_RESULTS.md` §3 names its own rung 3 a
graceful no-op: every axis here is a categorical presence/value string
(`"yes"`/a direction literal/`_ABSENT`), never an integer coordinate — the
generators (rotation90/reflections/scale2/modular) have nothing to act on,
and "transform" is not a meaningful concept between two DIFFERENT facts
("has a statement" vs "has a targets_mt edge" are not the same fact shifted
by a delta). Named as an explicit, deliberate scope cut; a genuine future
numeric-valued axis would light these rungs up for free.

## 4. Mint via existing Terms only — no `ProblemShapeMint` Rust Term

`META_SHAPE_FIRST_CLASS_RESULTS.md` built a bespoke `MetaShapeMint` Rust
Term because its recurrence-grouping needed predicate-SET equality over
signatures that could differ in WHICH predicates were present. This rung's
minted candidate did not need that: every real `solve_decompose`
observation in the corpus produces the IDENTICAL literal signature
(confirmed directly from `domains/solver_dispatch.py`:
`mint_solve_decompose_goal` never writes `statement`/`targets_mt`/
`targets_correspondence`/`direction`), so recurrence is exact `key`
equality, and anti-unifying two identical relation sets is a no-op —
minting directly from the observation's own signature is correct.
**Zero new Rust Term variants; zero cargo rebuild needed for this rung.**
