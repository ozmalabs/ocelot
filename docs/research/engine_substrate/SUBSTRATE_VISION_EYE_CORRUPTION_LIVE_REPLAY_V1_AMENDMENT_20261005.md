# Live corruption replay v1 analysis amendment

The capture completed from the source lock with 12 distinct workers. Its runner checks passed: source stability, six paired seeds, the exact 36,000-step schedule, 75 clean plus 240 corrupted probes per worker, clean winner uniqueness, and unchanged weights after freezing. The native replay therefore ran successfully.

The first independent analysis found that the native winner check was stricter than the numeric representation supports. Captured binary weights are serialized as `f64`; the native rule path and the analyzer sum those values in different orders. Seven of 3,456 corrupted probes select a unit whose reconstructed score is exactly one ULP below the reconstructed maximum. Maximum activation error across all units and probes is `1.11e-16`. The preregistered exact-max gate is retained as failed; this amendment does not silently widen it. A future protocol should specify a ULP-based winner-equivalence rule and validate that tolerance against the native accumulator.

The initial analysis also compared native single-winner region outcomes with the offline report's set-valued treatment of all tied maxima. These are different outcome definitions. The amended report separates the live winner's result from the offline tie-set result: they disagree on 32/2,880 cases. This count is descriptive, not a parity gate. Live accuracy by morphology and corruption dose is reported from the actual graph winner. Region assignment uses each field's receptive center recomputed from its weights, matching the offline analyzer's definition.

The amended analyzer was changed after capture, so its hash differs from the analyzer hash in the capture's original lock. The raw capture and original lock are preserved; the amended report states both analyzer hashes and marks this deviation. Its analysis is exploratory and does not inherit the original preregistered independent-analyzer status. No retraining or recapture was performed for this amendment.
