**Date:** 2026-09-26. **Purpose:** consolidate current Phase C evidence and decide what it supports. This is a source-linked audit of existing captures, not a new workload sample or a new runtime experiment. ## Quantitative evidence by representation

### Graph-level cuts

The synthetic graph census shows why edge count alone is insufficient. At n=64, an ID-contiguous hierarchy has max cut boundaries 2 for paths, 4 for banded DAGs, and 3 for modular chains; five shuffled orders have medians 53, 62, and 61. A star has exact treewidth 1 but balanced-cut boundary 33. A sparse random graph with 99 edges has min-fill width upper bound 9 and max boundary 51. These are generated families with deliberately informative ID order, not discovered cuts in task state ([synthetic census results](SUBSTRATE_STRUCTURAL_CENSUS_PILOT_RESULTS.md), [raw census](../../../evaluation/reports/substrate_structural_census_pilot_20260924.json)).

On the authored CAN structural envelope, the causal graph family is explicitly varied rather than inferred from the loaded rule graph: for N=32 and frame size four, the path has 62 directed edges and 14 cross-frame edges, banded-2 has 122 and 42, and complete coupling has 992 and 896. Exact family widths are 1, 2, and 31 respectively. Execution remains monolithic in that envelope ([CAN structure results](SUBSTRATE_CAN_STRUCTURE_ENVELOPE_RESULTS.md), [raw envelope](../../../evaluation/reports/substrate_can_structure_envelope_20260924.json)).

The Vision `st_settle` rule adds a semantic counterexample to a spatial-grid-only model: besides local neighbours, it reads every SUnit activation. The resulting primal dependency graph is K_N, with width N−1; at N=64 and four-unit frames, 93.75% of global input incidences cross the hypothetical cut. This is a source-derived dependency statement, not a runtime cost or a claim that all vision operations are global ([Vision census](SUBSTRATE_VISION_SETTLE_CHEAP_CUT_CENSUS_RESULTS.md), [seed](../../../seeds/vision_settle.json)).

### Rule-resource and runtime-access graphs

The static rule census agrees exactly with native access keys and wildcard flags on the selected six CAN and ten conversation rules. Yet conversation width changes from 9 under globally aliased attribute keys to 4 under a variable-role projection. The native scheduler uses the global resource-key model, so width 4 is only a sensitivity analysis; width 9 is the conservative warning on this representation ([rule dependency census](SUBSTRATE_RULE_DEPENDENCY_CENSUS_RESULTS.md), [raw](../../../evaluation/reports/substrate_rule_dependency_census_20260924.json)).

Runtime traces identify concrete writer-reader overlaps among observed firings: CAN reports 4 concrete pairs against 24 global-key possibilities in the summarized rule set; conversation reports 14 against 46. This is evidence that resource-only projections overstate some observed interaction on these runs. It does not license removal of the other pairs, because dynamic traces cover only executed paths and remain partial ([CAN trace](SUBSTRATE_CAN_RUNTIME_ACCESS_TRACE_RESULTS.md), [conversation trace](SUBSTRATE_CONVERSATION_RUNTIME_ACCESS_TRACE_RESULTS.md)).

### Factorisation outcomes

For native CAN rule execution, independent four-concept frames exactly match the monolithic result and full-graph fixed-point check on all 12 disconnected `blocks4` controls. Across the 36 connected path, banded, and complete runs, only 3 match and remain full-graph stable. Independent frame-local stability therefore fails as a general substitute for boundary-aware execution. The study intentionally has no boundary exchange, native wakeup, or parallelism, so it is a negative control for naive factorisation, not a failed test of a complete message-passing algorithm ([factorisation results](SUBSTRATE_CAN_FRAME_FACTORIZATION_RESULTS.md), [raw](../../../evaluation/reports/substrate_can_frame_factorization_20260924.json)).

Conversation deliberation's full and round-robin scoped implementations preserve expected decisions and normalized state through eight independent tasks. At eight tasks the scoped API performs 5,380 versus 312 candidate pairs and 40,264 versus 2,584 Term evaluations, with median time 1.619 versus 0.356 ms. This is exact parity under a generic repeated-scope implementation, not a speed result or a connected-boundary factorisation result ([conversation scoped scale](SUBSTRATE_CONVERSATION_FRAME_SCOPED_SCALE_RESULTS.md), [raw](../../../evaluation/reports/substrate_conversation_frame_scoped_scale_v1_1_20260925.json)).

Caller-driven Bigville event queues do demonstrate substantial counter reductions with exact full-closure parity under fixed task-derived disconnected components and injected cross-frame links. Scope derivation/notification remains Python-side; the runtime queue is not native writer-to-frame notification, and the connected links in the stress test are controlled perturbations rather than authored cast dependencies ([Bigville dynamic links](SUBSTRATE_BIGVILLE_RUNTIME_PARTITION_DYNAMIC_LINKS_RESULTS.md), [Bigville task-derived replay](SUBSTRATE_BIGVILLE_CAN_RUNTIME_PARTITION_REPLAY_V3_1_RESULTS.md)).

A fresh task-path access diagnostic on the existing 100-resident Bigville cast builds 100 five-Concept frames and observes zero cross-frame causal edges in the live authored graph; exact component treewidth is 2. For one resident update, the caller-notified one-frame arm matches full closure and an independent zero-residual oracle, while reducing candidate pairs by 97.1% and Term evaluations by 96.0%. One-run settlement time is 0.199 ms versus 3.81 ms, but per-worker graph/partition construction takes 52.7–55.0 ms; observed setup-plus-settlement differs by 1.65 ms, less than the 1.96 ms setup-time difference between arms. This single-update evidence does not resolve an end-to-end cost advantage. The partial runtime trace observes 596 reads and five writes in the mutated frame, but the native static rule still declares `reads_any=true`. Resident 40 was selected after resident 0 produced a no-op, so this remains a diagnostic on a previously used workload, not a confirmatory sample or evidence that absent trace events imply absent dependencies ([results](SUBSTRATE_BIGVILLE_TASK_ACCESS_CENSUS_RESULTS_20260926.md), [preregistration](SUBSTRATE_BIGVILLE_TASK_ACCESS_CENSUS_PREREG_20260926.md), [raw capture](../../../evaluation/reports/substrate_bigville_task_access_census_v1_20260926.json), [analysis](../../../evaluation/reports/substrate_bigville_task_access_census_v1_analysis_20260926.json)).

A second, connected task-derived census materializes a ten-event mixed dialogue incrementally and assigns three event frames from the fixture's origin/unsolicited markers. The final graph has 261 nodes/235 edges; the 12 owned event/goal nodes have two direct cross-frame `follows_event` edges and 40 incidences to five shared boundary nodes. The exact frame interaction projection is a three-node clique of treewidth 2 because the DiscourseState is shared across all frames. Native closure after each event makes six progress steps over 135 candidate pairs and 558 Term evaluations; the two goal lifecycles and common-ground outputs match their task oracle. The runtime trace records 193 events but no direct cross-frame endpoint pair; this cannot be read as independence because the shared state boundary is explicit. This is a new task path but still one authored fixture, and it does not compare a partitioned schedule or estimate natural-task frequency ([results](SUBSTRATE_DISCOURSE_CONNECTED_TASK_CENSUS_RESULTS_20260926.md), [protocol](SUBSTRATE_DISCOURSE_CONNECTED_TASK_CENSUS_PREREG_20260926.md), [raw](../../../evaluation/reports/substrate_discourse_connected_task_census_v1_20260926.json), [analysis](../../../evaluation/reports/substrate_discourse_connected_task_census_v1_analysis_20260926.json)).

The direct native owner-report contract is now better tested than the earlier audit stated. Across 60 locked workers, five effect shapes (shared edge insert/delete, shared-node attribute write, owned-node birth/delete), and 2/4/8 consumer frames, changed-node/edge reports map to exactly the owners found by an independent full before/after snapshot; no unrelated owner is reported. This establishes direct mutation-to-owner attribution for these tested graph effects. It does not establish transitive reader notification, complete dependencies, deferred-effect routing, or automatic queue delivery ([native owner effect matrix](SUBSTRATE_NATIVE_SCOPED_OWNER_EFFECT_MATRIX_RESULTS_20260926.md), [analysis](../../../evaluation/reports/substrate_native_scoped_owner_effect_matrix_v1_analysis_20260926.json)).

Generated notification probes separate that correctness result from efficiency. In the 2–64 frame star sweep, event/full semantic parity, exact owner coverage, and omission controls pass, but event-queue median time rises from 0.152 ms to 9.445 ms while full closure rises from 0.083 ms to 0.724 ms; the event path is slower throughout and reaches 13.05× at 64 frames. This is a high-fanout generated control, not a natural-task estimate. Requeue attribution identifies repeated owner-turn work and additional star cost, while the local chain benefits in a separate candidate-seeding probe. Queue correctness alone therefore does not support an efficiency claim; structural partition discovery and matched-topology end-to-end cost are required ([fanout results](SUBSTRATE_SCOPED_NOTIFICATION_FANOUT_SCALE_RESULTS_20260926.md), [requeue attribution](SUBSTRATE_SCOPED_NOTIFICATION_REQUEUE_ATTRIBUTION_RESULTS_20260926.md), [local candidate results](SUBSTRATE_SCOPED_LOCAL_CANDIDATES_RESULTS_20260926.md)).

A current-source 9-worker Bigville cut capture extends the existing ring, star, and random-connected mutation seam over 63 full-graph checkpoints. All-owner sweeps and independently recomputed CAN residuals pass. On fully linked graphs, authored and balanced-ID partitions have 198–200 directed causal crossings, while grouping contiguous five-node chunks from min-fill elimination has 592–680 crossings and retains 40.0–60.4% of authored within-frame pairs, despite induced width 2. The result warns that elimination width/order is not itself a frame constructor; stable IDs perform well here because this builder makes IDs contiguous by resident. Candidate scopes still refuse on `reads_any`, so no partitioned execution claim follows ([results](SUBSTRATE_BIGVILLE_DYNAMIC_LINK_CUT_CAPTURE_V1_RESULTS_20260926.md), [independent analysis](../../../evaluation/reports/substrate_bigville_dynamic_link_cut_capture_v1_analysis_20260926.json)).

## Claim decision

The current evidence does **not** support a general cheap-cut hypothesis for the substrate. It supports three narrower statements:

1. Some generated and authored workloads have useful sparse separators when their topology or owner-based partition is already known.
2. The substrate can preserve exact outcomes under disconnected partitioning and under selected caller-notified queues with explicitly measured boundary changes.
3. Other active paths have global coupling or fail when cross-frame terms are omitted; generic scoped execution can add substantial overhead.

These findings bound the cheap-cut idea as a workload- and path-specific empirical hypothesis. They do not change the conclusion that rung 1–2 operation may be cheap when held structure is appropriate, nor do they establish that natural task distributions supply such structure frequently.

## Next structural gate

The next confirmatory structural programme should preselect workload families and task-generation rules before inspecting new outcomes, using at least one locally sparse path, one connected multi-frame path, and one known global-coupling control. For each actual runtime graph, retain node/edge identity, owner/frame membership, native static resource sets, concrete observed reads/writes, and per-checkpoint graph changes. Report exact treewidth where feasible and a named upper bound otherwise; separately report frame aperture/boundary, hierarchy, dynamic cross-boundary dependencies, and the cost to build/update the partition. Compare monolithic closure with a boundary-aware partitioned schedule and an omitted-notification negative control under independently recomputed state/fixpoint or task oracles. The one stale effect-only reader and Vision global fold must remain counterexamples in the evaluation set. Cost must include seed/rule setup, partition maintenance, queue/message updates, synchronization, CPU, and memory.

The current primary blockers are evidence coverage and dependency semantics. The native scope is still a Microtheory `has_concept` owner, not a general stable frame-ID interface; its write-owner report is useful but declares `frame_notifications_complete=false`. There is no production queue that derives all transitive readers from changed state, maintains arbitrary task-derived cuts, and safely falls back on unsupported dependency classes. Do not infer a general frame-locality speedup from caller queues or the synthetic cut census. Keep Phase C open until the representative-set and boundary-aware gates pass or establish a measured failure rate.

The diagnostic panel now contains named sparse/disconnected Bigville and connected mixed-dialogue paths, alongside the Vision global-fold counterexample. This improves structural coverage but does not yet meet C2's representative-set requirement: Bigville is a fixed cast/task replay, dialogue is one authored ten-event fixture, and Vision is one source-derived rule path. Frame definitions differ by workload and were not learned by a common constructor. A retrospective ranking of authored, balanced-ID, and dependency-min-fill cuts on the existing Bigville and dialogue captures finds identical cut metrics across all three arms; it also measures dialogue's 40 task/global boundary incidences. This analysis is explicitly not the preregistered mutation and execution gate ([results](SUBSTRATE_AUTHORED_CAPTURE_CUT_RANKING_RESULTS_20260926.md)). The next step remains a fresh confirmatory run with the preregistered mutation branches, trace controls, boundary-contract refusal/parity, and rebuild costs; repeated analysis of these same snapshots cannot close the distribution gap.

A six-worker Bigville follow-up now performs independent fresh insertion, retraction, and reweight branches with tracing on/off and recomputes all three cuts from complete graph snapshots. Full closure and independent residual checks pass; the active wildcard-reading CAN rule correctly causes every candidate partition to refuse before scoped execution. However, this particular single inserted edge is semantically inactive: all closure calls make zero progress, residual remains zero, and tracing observes no accesses. The capture therefore does not meet the omitted-boundary sensitivity gate and is classified inconclusive for factorisation. The complete typed graph capture does improve boundary accounting, and reconstruction costs about 174–191 ms median per checkpoint for the 500-node diagnostic implementation. The dialogue mutation cell remains unsupported. See [Bigville mutation results](SUBSTRATE_AUTHORED_BIGVILLE_CUT_MUTATION_V1_RESULTS_20260926.md) and [independent analysis](../../../evaluation/reports/substrate_authored_bigville_cut_mutation_v1_analysis_20260926.json).

## Implementation sequence for the next gate

Source inspection narrows the execution-interface gap. [`Substrate::run_rules_scoped`](../../../runners/dsl/src/substrate.rs) accepts `Option<NodeID>` and scopes to a single Microtheory's owned nodes. [`run_rules_scoped_delta_report`](../../../runners/dsl/src/substrate.rs) returns changed node IDs, changed edge keys, affected Microtheory IDs, budget status, and a deferred-effects flag. The owner mapping is based on `has_concept` membership; it does not describe rule reads, arbitrary frame membership, cross-boundary messages, or whether all consumers were notified. The Python binding explicitly returns `frame_notifications_complete: false` ([`PySubstrate::run_rules_scoped_delta_report`](../../../runners/dsl/src/py.rs)). Therefore the current owner report is useful mutation evidence, but is not itself a boundary scheduler.

Implement the next C3 attempt as three separately gated steps:

1. **Task-derived dependency panel (no engine change).** Freeze one sparse task path, one genuinely connected multi-frame task path, and the Vision global-fold control before collection. At every task checkpoint, serialize stable node/edge identities, frame membership, static read/write declarations, observed runtime reads/writes, frame boundary keys, and partition build/update time. Treat unobserved accesses as unknown; do not prune static dependencies from a partial trace. This produces a workload and interface specification, not a speed claim.
2. **Boundary-aware schedule prototype (opt-in).** Add arbitrary stable frame-ID membership and an explicit boundary dependency relation to an opt-in executor. A frame settles against the current shared graph; changed boundary values enqueue only declared/observed dependent frames. Recompute dependencies after node/edge birth, deletion, ownership change, or rule mutation. If a dependency is wildcarded, uncovered by instrumentation, has a deferred effect, or hits budget, stop the scoped schedule and run global closure. Preserve ordinary full closure as the oracle and keep the current Microtheory API unchanged.
3. **Confirmatory parity and cost gate.** Pair full closure, boundary-aware settlement, and deliberately omitted-notification controls on fresh workers and the frozen task panel. Require exact graph/task-oracle parity and independent full-graph residual zero at each terminal checkpoint; omission controls must expose a detectable stale result. Charge partition construction and maintenance, trace/index work, queue/message updates, global fallbacks, synchronization, CPU, and peak memory. Report per-task and aggregate tails as well as means. A semantic mismatch, missing mutation coverage, or loss of oracle independence fails the gate regardless of speed.

Do not begin step 3 by tuning on the confirmatory panel. If step 1 shows that an authored task family has no useful separators, retain it as negative evidence and report the failure frequency; do not replace it with a more favorable family. A successful result remains bounded to the selected task families. It does not establish natural-distribution prevalence without an independently sampled task corpus.
