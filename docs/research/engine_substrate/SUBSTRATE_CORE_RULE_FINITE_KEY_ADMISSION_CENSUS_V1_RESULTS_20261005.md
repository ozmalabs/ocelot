# Default core finite-key rule admission census v1 results

The source-locked read-only census loaded the default `boot_core()` profile: 17 seed manifests, 135 exported/active rules, and a 740-node/739-edge initial graph. None of the 135 active rules is accepted by the existing `monotone_finite_key_insertions_v0` checker, either individually or as the complete profile. An independent second acceptance predicate agrees on every rule and on the aggregate result; all source, native, seed, graph-inventory, and capture gates pass.

The common exclusions explain why the current finite-key proof cannot be applied to this default profile: 132 rules have `where` clauses; captured effects include 71 `add_node`, 229 `set_attr`, 21 `del_node`, eight `del_edge`, and one `net_collapse` operation, alongside 195 `add_edge` operations. The checker also reports edges whose endpoints are not bound by its positive-match-and-earlier-mint discipline. This is a language/profile mismatch, not evidence that any rejected rule set diverges. The checker describes a narrow sufficient fragment and is not a general termination analyzer.

The result rules out turning on this exact finite-key fragment as a universal default-core admission rule without changing or replacing many current rules. A path to a termination guarantee must either define a broader proven class compatible with required core behavior, or expose an explicitly restricted profile whose complete active rule set passes one common admission invariant. Dynamic self-mint, patch, seed load, and checkpoint import still require enforcement at their respective mutation boundaries.
