# Thoughtexperiment effect-target trace cost panel v1

The new opt-in `run_rules_effect_target_delta_report` attributes each effect to bounded node IDs and edge keys, without retaining node/edge before-after values. Rust checks compile; the Python smoke and source-locked panel verify effect index partitioning, empty value payloads, zero value-snapshot bytes, event/report target caps, visible truncation, and identical final graph digests across endpoint-only, value, and target-only observers.

The source-locked capture has three workers and 27 isolated runs (three fixture families × three observer modes × three replicates). At report-object saturation, target-only median time is 326.1 ms and post-run RSS/PSS delta is 163,672 KiB, compared with 230.7 ms / 118,048 KiB for endpoint-only and 600.2 ms / 276,292 KiB for full effect values. Thus target-only cuts the measured value trace's added RSS/PSS by about 71% and its observer time by about 46%, while still costing about 1.42× endpoint-only time and adding about 44.6 MiB RSS/PSS. On the small direct fixture, medians are 0.248 ms target-only and 0.247 ms endpoint-only; same-event multiwrite medians are 0.217 and 0.274 ms respectively. Those sub-millisecond differences are too small for a speed claim.

The implementation enforces a 512-object per-effect/event cap and 16,384-object report cap at write-target admission. The cap-stress panel retains exactly 16,384 targets and reports 512 effect truncations; JSON event size is 3.31 MiB. These post-run RSS/PSS values do not bound transient allocation or prove a hard process-memory ceiling. The fixture is synthetic and event-heavy. Production-derived joins, deferred/dynamic effects, realistic diagnosis value, and natural-task prevalence remain open.
