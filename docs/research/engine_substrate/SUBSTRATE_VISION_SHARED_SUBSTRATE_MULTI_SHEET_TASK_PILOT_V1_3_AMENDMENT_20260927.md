# Shared-substrate multi-sheet task pilot v1.3 amendment

V1.2's fail-fast capture identified one high-work event in the global two-sheet preparation: presentation 213 reached the per-call 200,000 progress budget at exactly 200,000 steps after 199,992 passes. The engine's outcome contract treats this as incomplete settlement and preserves the dirty graph state so a later `run_rules_report` call can continue. The single-sheet comparator has no such budget hits across six arms. V1.3 therefore measures bounded continuation instead of rejecting at the first per-call budget boundary.

For each paired presentation, v1.3 applies the input frame once, runs with a 200,000 progress budget, and only if the result is `progress_budget_reached` resumes the same graph state without reapplying the frame. Subsequent budgets double, bounded by a maximum cumulative progress of 1,600,000 per presentation. Every invocation's requested budget, status, progress, and passes are retained; each presentation records its cumulative work, number of intermediate budget hits, and final status. `fixed_point` and `repeated_graph_state` remain distinct recorded outcomes; the latter is not described as a fixed point. If cumulative work reaches 1,600,000 without a terminal status, the runner stops and preserves a cap diagnostic with prior completed contexts. The bound is an experimental work guard, not a claim of a complexity threshold.

All task inputs, graph topology, adaptation count, probes, and the global-versus-root-scoped contrast remain as in v1.2. This amendment changes only how a conservatively budgeted closure call resumes and how its cost is reported. The current execution is source-locked separately; no tuning or quality result from v1.2's capped run enters the v1.3 analysis.
