## Workloads and findings

The audit measured 100 authored Bigville resident models after shared scenario evidence and 80 models generated by the native CAN fixture after authored asynchronous rule closure. Every extracted model was passed through the same forest detector and selected-order policy; exact MAP was run only when the selected order was within the width-4 gate.

| Workload | Cases | Graph shape | Forests | Width | Gate result | Exact MAP / oracle |
|---|---:|---|---:|---:|---|---:|
| Bigville authored cast | 100 | 5 nodes, 5 undirected pairs | 0 | 2 | 100 admitted | 100/100 |
| Native-rule-generated CAN | 80 | 8 nodes, 28 undirected pairs (complete) | 0 | 7 | 80 refused | Not run |

All 80 native-rule closures settled and their terminal probes returned zero work. The Bigville exact solver matched an independent exhaustive 3^5-state oracle on all 100 cases. Median Bigville costs were 3.04 µs for forest classification, 20.82 µs for min-fill ordering, and 0.105 ms for exact MAP. The detector therefore adds measurable but small work on these tiny authored graphs and never selects the forest path.

The four edge-policy controls behaved as predeclared: a duplicate undirected edge and a self-loop returned nonforest/fallback; negative and out-of-range endpoints were rejected before the detector or ordering routine. These were benchmark wrapper checks, not production API validation.

## Interpretation and limits

This audit supplies source-linked authored workloads against which the forest optimization was not useful: the tested Bigville and native CAN families contain no forests. It also confirms exact inference and width refusal on those named families. It does not estimate forest prevalence in natural tasks, across other substrate domains, or in user-generated workloads. The two workload sources are project-authored, and the native fixture intentionally generates complete graphs.

No production dispatcher was added. Invalid-endpoint checks exist only in the measurement harness. A production ordering interface would need to validate endpoints against the extracted node set before any algorithm runs, and preserve the generic fallback and width refusal. The forest specialization should remain conditional until a broader representative topology census shows where it applies.
