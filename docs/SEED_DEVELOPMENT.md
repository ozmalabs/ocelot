# Developing New Seeds on the OCELOT Substrate

In OCELOT, **the agent is a graph, running in Rust (`substrate_rs`)**. An agent does not boot with a monolithic hardcoded mind, nor does it execute reasoning inside Python classes or decision trees. Instead, every capability—perception, conversation, spatial navigation, program synthesis, affect, self-monitoring, and domain physics—is shipped as **seeds**: modular, versioned, dependency-resolved units of graph data (`seeds/<id>.json`).

This guide covers the architectural invariants, manifest schema, Term DSL, rule-authoring idioms, tooling, and testing workflow for creating and maintaining seeds.

> **Terminology note ("Seed" has two meanings in this repo):**
> 1. **Graph-data seed (`seeds/<id>.json`)** — a modular unit of agent prior knowledge and executable rewrite rules loaded into the substrate at boot. *(The subject of this guide.)*
> 2. **Experimental RNG seed (`default_rng(s)`)** — an integer random seed tracked in the burned-seed ledger (`VISION_PROTOCOL.md`, `scripts/seed_claim.py`, `domains/seed_record.py`) for statistical pre-registration and reproducibility. *(See [`docs/SCIENCE_RESEARCH.md`](SCIENCE_RESEARCH.md).)*

## 1. Core Architectural Invariants for Seed Authors

Before authoring a seed, internalize the four invariants from [`CLAUDE.md`](../CLAUDE.md) that govern all graph data in this repository:

### 1.1 The Agent is Rust; Python is Only the World Adapter
- **All reasoning is graph data.** Every conditional over graph state, state transition, recognition step, or policy choice must be expressed as a **Rule**, **Reflex**, **Production**, or **Term** inside a seed manifest.
- **Python only translates I/O.** World adapters (`substrate/world_adapter.py`, `worlds/*.py`, `domains/*_world.py`) do two mechanical things: **ingest** external events into nodes/edges (`add_node`, `add_edge`), call `substrate.tick()` / `run_rules()`, and **emit** external effects by reading graph state back out.
- **When the DSL lacks a primitive, extend Rust.** Add a new Term variant in `runners/dsl/src/term.rs` (and its evaluator), expose a one-line handoff in `runners/dsl/src/py.rs`, and compose it in seed JSON. Never implement agent reasoning in Python.

### 1.2 Shapes, Not Numbers (`sd` Loop + Admissibility Grammar `Γ`)
Every defect audited in [`docs/research/engine_substrate/SHAPE_AUDIT.md`](research/engine_substrate/SHAPE_AUDIT.md) came from putting a scalar knob (an ad-hoc learning rate, a magic threshold, a fixed weight) or an unchecked edge write where a **shape** belonged. Before writing a new subsystem, compose with the substrate's two core generative primitives:

1. **Dynamic Quantization (`seeds/shape_decode_loop.json`, `runners/dsl/src/shape_decode.rs`) — for quantities and representations that change:**
   - Observations are decoded against a held codebook via `ShapeDecode`.
   - Growth follows the four-rung **Occam ladder** in a single `run_rules` fixpoint:
     1. **Rung 1 — Exact recognize** (`sd_decode` / `sd_recognize`, or `CoversOpen` for pattern codebooks): full coverage by held codebook entries; no growth.
     2. **Rung 2 — Transform in existing basis** (`TransformDecode` → `sd_transform_decode` / `sd_recognize_transformed`): residual is explained by one consistent per-dimension quantum delta (`Transform{dim, delta}`); no codebook growth.
     3. **Rung 3 — Infer a missing dimension** (`DimInfer` → `sd_infer_dimension` / `sd_recognize_dim`): coupled cross-dimension residual is explained by a held `DimensionGenerator` (`rotation90`, `reflection_r`, `reflection_c`, `scale2`, `cycle4`, or length-≤2 compositions), minting a `LatentDimension`.
     4. **Rung 4 — Mint novelty** (`sd_mint_quantum` / `MetaShapeMint`): only after rungs 1–3 fail (and recurrence is established) does the seed mint a new codebook entry and increment the codebook epoch (`codebook_epoch`, `meta_codebook_epoch`) to re-arm `sd_redecode`.
   - `shape_decode.rs::load_parts` is **grain-agnostic**: passing `"codebook_type": "<YourNodeType>"` to `ShapeDecode`, `TransformDecode`, and `DimInfer` gives any node type carrying `name` + `signature` the entire Occam ladder with zero new Rust (see [`tools/build_meta_shape_growth_seed.py`](../tools/build_meta_shape_growth_seed.py)).
2. **The Admissibility Grammar (`Γ`, `runners/dsl/src/grammar.rs`) — for what a system may do:**
   - Every edge type your seed's rules match on or mint should be declared in the manifest's `"productions"` array (`Production{src, edge_type, tgt, where, weight}`).
   - Do not ship rule-heavy seeds with `"productions": []`. In `(G, Γ, C)`, allowed conduct/transitions are generated by `Γ`.

### 1.3 Base-as-Dimension & the Frame/Continuum Invariant
- **In-frame coordinates are strictly INTEGER.** Grounded/observed frame coordinates live on an integer lattice (`shape_decode.rs::coord_ints` returns `None` on float slots intentionally).
- **Non-integer math is CROSS-FRAME.** Real-valued quantities—angles, scale ratios, log bases, Fourier transforms, and continuous verdict comparators (`SC+TPS`, `DtwTo`, `PointSetDist`)—live in the **map between frames** (`Hom(frame, frame)`: a `DimensionGenerator`, `Transform`, rendering, or comparator), never as in-frame coordinates.
- *"Bins propose, continuous decides"*: quantized integer bins handle codebook learning and proposal; continuous cross-frame comparators adjudicate rendered candidates.

### 1.4 Shape is Acquisition; Rule is Execution
- **Rules** (`match` / `where` / `effects`) execute what the substrate already knows.
- **Shapes** (anti-unification via `AntiUnifyWitness`, `Substitute`, `CoversOpen`, `ShapeDecode`) are how the substrate generalizes and expands what it knows.

## 2. Anatomy of a Seed Manifest (`seeds/<id>.json`)

A seed manifest is a JSON object parsed directly by the Rust runtime in [`runners/dsl/src/seed_manifest.rs`](../runners/dsl/src/seed_manifest.rs) (`Substrate::load_seed_manifest_value`) and orchestrated at boot by [`substrate/seed_loader.py`](../substrate/seed_loader.py), [`substrate/boot_core.py`](../substrate/boot_core.py), and [`substrate/boot_all.py`](../substrate/boot_all.py).

```json
{
  "id": "my_capability",
  "version": "1.0.0",
  "depends_on": ["decision_core", "shape_decode_loop"],
  "description": "Concise architectural summary of what this seed does and why.",
  "microtheory": {
    "name": "my_capability",
    "description": "Short description of this microtheory grain."
  },
  "capability_keys": ["my_skill"],
  "nodes": [ ... ],
  "edges": [ ... ],
  "productions": [ ... ],
  "rules": [ ... ],
  "reflexes": [ ... ]
}
```

### 2.1 Top-Level Metadata & Scheduling Keys

| Key | Type | Purpose |
|---|---|---|
| `id` | `str` | Unique seed identifier (matches filename `seeds/<id>.json`). |
| `version` | `str` | Semantic version (e.g., `"1.2.0"`). |
| `depends_on` | `list[str]` | Seed IDs that must be installed before this seed. Walked topologically; cycles raise `ValueError`. (`"core"` is treated as the built-in substrate root.) |
| `description` | `str` | Human- and agent-readable explanation + version changelog. |
| `microtheory` | `dict` | Optional `{"name": str, "description": str}` grouping the seed's knowledge into a `Microtheory` node during full boot. |
| `capability_keys` | `list[str]` | Optional tags indexing the seed's capabilities for selective boot (`substrate/boot_all.py`). |
| `self_load_only` | `bool` | If `true`, `boot_all.py` skips this manifest during a global sweep so it is only loaded on demand via `manifest_for(seed_id)`. |
| `self_modification_patchable_rules` | `list[str]` | Names of rules in this seed that the agent's self-modification pipeline is permitted to patch (`rule.mutation_protected` defaults to `true` for all unlisted rules). |
| `area`, `order`, `latency_class` | `str`, `int`, `str` | Optional default scheduling metadata inherited by every rule in `"rules"` that does not set its own. |

### 2.2 `"nodes"` and `"edges"` (with Cross-Reference Resolution)

Nodes are allocated first and mapped from their manifest-local integer `local_id` to a runtime `NodeID`:

```json
"nodes": [
  {
    "local_id": 1,
    "type": "Concept",
    "attrs": {
      "name": "cannot",
      "description": "deficiency cue: inability to do something"
    }
  },
  {
    "local_id": 2,
    "type": "DimInferPolicy",
    "attrs": {
      "name": "default_dim_infer_policy",
      "dim_grains": [0]
    }
  }
]
```

Edges connect nodes using one of **three endpoint reference formats** resolved by `resolve_seed_ref` (`runners/dsl/src/seed_manifest.rs`):

1. **Seed-local reference (`{"local": <int>}`):** Points to a node defined in the same manifest's `"nodes"` list.
2. **Agent root reference (`{"role": "agent_root"}`):** Points to the agent's root `Agent` node passed into `load_seed_manifest`.
3. **Cross-seed typed attribute reference (`{"type": "<NodeType>", "<attr>": "<str_value>"}`):** Queries the live graph for an existing node of `<NodeType>` whose string attributes match all remaining keys (typically `name` or `id` from a dependency seed). Fails loudly if the dependency node is absent.

```json
"edges": [
  {
    "src": { "role": "agent_root" },
    "type": "has_dim_infer_policy",
    "tgt": { "local": 2 },
    "attrs": {}
  },
  {
    "src": { "local": 2 },
    "type": "applies_to_concept",
    "tgt": { "type": "Concept", "name": "cannot" },
    "attrs": {}
  }
]
```

### 2.3 `"productions"` (The Admissibility Grammar `Γ`)

Every edge type your seed introduces or mutates should be declared as a `Production`:

```json
"productions": [
  {
    "provenance": "seed:my_capability:observed_shape",
    "src": { "type": "Agent", "var": "ag" },
    "edge_type": "observed_shape",
    "tgt": { "type": "ShapeObservation", "var": "obs" }
  }
]
```
Productions may also carry optional `"where"` (a Term JSON guard) and `"weight"` (a Term JSON weight) fields parsed by `grammar_from_json`.

### 2.4 `"rules"` (Executable Rewrite Rules vs. Declarative Principles)

In `seeds/*.json`, `"rules"` always means **executable engine rewrite rules** (parsed by `runners/dsl/src/rule_json.rs::parse_rule_json`).

> **Note on legacy declarative principles:** Some encyclopedic knowledge seeds carry `"concepts"` or rules written with `"if"` / `"then"` / `"why"` or `"head"` / `"body"` keys and no `"match"` array. `substrate/seed_loader.py::normalize_declarative` automatically folds those into `Concept` and `Principle` graph nodes before handing the manifest to Rust. New execution seeds should always author explicit `match` / `where` / `effects` rules.

### 2.5 `"reflexes"` (Stimulus → Response Bindings)

A seed can ship graph-resident `Reflex` nodes under the `"reflexes"` key (`load_reflex_json` in `runners/dsl/src/seed_manifest.rs`). The loader converts the `"stimulus"` Term AST into a reified G-subgraph (`term_to_subgraph`), creates a `Reflex` node attached to `agent_root` via `has_reflex`, and links the stimulus subgraph via `stimulus_term`:

```json
"reflexes": [
  {
    "name": "question_pursue",
    "response": "question_pursue_advance",
    "refractory_ticks": 0,
    "autonomous": 1,
    "stimulus": {
      "type": "Gt",
      "a": { "type": "Count", "source": { "type": "NodesOfType", "node_type": "Goal" } },
      "b": { "type": "Lit", "value": 0 }
    }
  }
]
```

## 3. Authoring Rules, Terms, and Effects

An executable rule in `"rules"` has the following structure (`runners/dsl/src/rule_json.rs`):

```json
{
  "name": "note_unresolved_topic_gap",
  "comment": "Why this rule exists, what guard guarantees fixpoint termination, and what it writes.",
  "match_type": "Goal",
  "match": [
    ["agent", "has_goal", "g"]
  ],
  "where": {
    "type": "And",
    "items": [
      { "type": "Eq", "a": { "type": "Attr", "node": { "type": "Var", "name": "g" }, "key": "kind" }, "b": { "type": "Lit", "value": "answer_topic" } },
      { "type": "Eq", "a": { "type": "Attr", "node": { "type": "Var", "name": "g" }, "key": "outcome" }, "b": { "type": "Lit", "value": "unresolved" } },
      { "type": "Not", "arg": { "type": "Eq", "a": { "type": "Attr", "node": { "type": "Var", "name": "g" }, "key": "gap_noted" }, "b": { "type": "Lit", "value": 1.0 } } }
    ]
  },
  "effects": [
    ["set_attr", "g", "gap_noted", 1.0],
    ["add_node", "sc", "SelfConcern", {
      "status": "noted",
      "source": "implicit",
      "kind": "knowledge",
      "content": {
        "__term__": { "type": "Attr", "node": { "type": "Var", "name": "g" }, "key": "concept" }
      }
    }],
    ["add_edge", "agent", "has_self_concern", "sc"]
  ]
}
```

### 3.1 `match` Triples and Topology Gotchas
- Each element of `"match"` is a 3-element array `["src_var", "edge_type", "tgt_var"]`.
- **Always anchor on a specific relational edge** (e.g., `["ag", "observed", "obs"]` or `["agent", "has_goal", "g"]`). Avoid matching bare `["agent", "is_a", "Agent"]` alone, which over-fires across unrelated turns.
- **Known engine gotcha (two same-type incoming edges):** Having two incoming edges of the *exact same edge type* converging on one node can break `run_rules` matching for that edge type. Use distinct, semantically descriptive edge types for distinct roles (e.g., `wrote_transform` vs. `has_transform`).
- Optional performance hints: `"match_type"` (restricts target node type), `"batch"` (`bool`), `"scope_anchor_*"` (all 5 fields required if used), and `"index_hints"` (join-index probes).

### 3.2 Common Term Variants in `where` and Computed Effects
Every Term is a JSON object with a `"type"` key (defined in `runners/dsl/src/term.rs` and `runners/dsl/src/jsonio.rs`):

- **Variables & Literals:**
  - `{"type": "Var", "name": "obs"}`
  - `{"type": "Lit", "value": 42}` (supports `int`, `float`, `str`, `bool`, `null`, lists, and exact rationals via `{"__rational__": [num, den]}`)
- **Node Inspection:**
  - `{"type": "Attr", "node": <Term>, "key": "status"}`
  - `{"type": "AttrByName", "node": <Term>, "name": <Term>}` (dynamic attribute key)
  - `{"type": "TypeOf", "node": <Term>}`
- **Logic & Comparisons:**
  - `{"type": "Eq", "a": <Term>, "b": <Term>}` (note: comparing two `Var` nodes checks NodeID identity!)
  - `{"type": "Lt" | "Lte" | "Gt" | "Gte", "a": <Term>, "b": <Term>}`
  - `{"type": "And" | "Or", "items": [<Term>, ...]}`
  - `{"type": "Not", "arg": <Term>}`
  - `{"type": "IfThenElse", "cond": <Term>, "then": <Term>, "other": <Term>}`
  - `{"type": "In", "member": <Term>, "container": <Term>}`
- **Graph Traversal & Quantifiers:**
  - `{"type": "Neighbours", "node": <Term>, "edge_type": "has_mention"}` (outgoing)
  - `{"type": "InNeighbours", "node": <Term>, "edge_type": "next_detail"}` (incoming)
  - `{"type": "NodesOfType", "node_type": "SelfConcern"}`
  - `{"type": "Exists", "source": <Term>, "var_name": "x", "predicate": <Term>}`
  - `{"type": "Filter" | "FilterList", "source": <Term>, "var_name": "x", "predicate": <Term>}`
  - `{"type": "Count", "source": <Term>}`
  - `{"type": "Pick", "source": <Term>}` (use **only** on traversal-scoped sources like `Neighbours`)
  - `{"type": "PickUnique", "source": <Term>}` (**mandatory** for singleton config reads like `PickUnique(NodesOfType("EyeParams"))` — panics if `>1` node exists instead of silently ignoring config!)
  - `{"type": "Argmin" | "Argmax" | "MinOver" | "MaxOver", "source": <Term>, "var_name": "x", "value": <Term>, "default": <Term>}`
- **Shape & Dynamic Quantization Primitives:**
  - `ShapeDecode`, `TransformDecode`, `DimInfer`, `GenInfer`, `MetaShapeMint`, `RecogniseShape`
  - `AntiUnify`, `AntiUnifyWitness`, `Substitute`, `Unify`, `Covers`, `CoversOpen`, `FixedCount`, `StructSim`

### 3.3 Supported Rule Effects (`runners/dsl/src/rule_json.rs`)
Any value slot or attribute dictionary value in an effect can be either a JSON literal or a computed Term wrapped in `{"__term__": <Term>}`:

| Effect Syntax | Description |
|---|---|
| `["set_attr", "var", "key", <val_or_term>]` | Set attribute `key` on node `var`. |
| `["set_attr_if_different", "var", "key", <val_or_term>]` | Set attribute only if the new value differs from current. |
| `["add_node", "new_var", "NodeType", {"k": <val_or_term>, ...}]` | Allocate a new node bound to `new_var` for subsequent effects in the same firing. |
| `["add_node_if_absent", "new_var", "NodeType", {"k": ...}]` | Find-or-create a node of `NodeType` with matching attributes. |
| `["del_node", "var"]` | Delete node bound to `var`. |
| `["add_edge", "src_var", "edge_type", "tgt_var", {"k": ...}]` | Insert a typed edge (attrs dict is optional). |
| `["del_edge", "src_var", "edge_type", "tgt_var"]` | Remove a typed edge. |
| `["define_concept", <name_or_term>, <term>]` | Register a concept Term in the substrate's `Holds` registry. |
| `["set_rule_clause", <rule_name>, <field>, <term>]` | Reflective self-modification of a patchable rule's clause. |
| `["apply_rule_patch", "patch_var"]` | Apply a structured `RulePatch` node. |

### 3.4 Three Critical Rule-Authoring Safeguards

1. **Fixpoint Idempotence (Mint-Once Guards):**
   `run_rules` executes rules repeatedly until no rule mutates the graph. If a rule matches `["ag", "observed", "obs"]` and runs `["add_node", ...]` without changing the state that enabled the match, it will mint nodes on every pass until the iteration cap is hit! Always close the guard in the same firing:
   - Transition a status attribute (`"status": "pending"` → `"decoded"`), or
   - Stamp a completion marker (`"gap_noted": 1.0`, `"transform_checked": 1`), or
   - Check for absence of the output edge/node (`Count(Neighbours(obs, "minted_shape")) == 0` and `Not(Exists(NodesOfType(CODEBOOK), ...))`).
   - Note: there is no `unset_attr` effect; to re-arm a boolean/flag guard (as in `sd_redecode`), reset the attribute to `0` and write guards as `Not(Eq(Attr(obs, "flag"), Lit(1)))`.
2. **Positive Evidence vs. Lookup Absence:**
   `Count(None)` evaluates to `0`. If a Term like `ShapeDecode` cannot run (e.g., an empty codebook returns `{authored: false}` with no `residual` key), a naive guard `Count(Attr(obs, "residual")) == 0` evaluates to `True` and falsely claims 100% recognition! Always require positive evidence alongside an empty residual (e.g., `covered_count > 0` or `FixedCount(pattern) > 0` + `CoversOpen`).
3. **Absence-Tolerant Optional Lesions/Policies:**
   When adding an optional ablation or policy node (such as `AgnosiaParams` in `shape_decode_loop.json`), do not guard core rules with `PickUnique(NodesOfType("AgnosiaParams"))` if most agents don't load the lesion seed. Instead, use an absence-tolerant count guard:
   ```json
   {
     "type": "Lt",
     "a": {
       "type": "Count",
       "source": {
         "type": "Filter",
         "source": { "type": "NodesOfType", "node_type": "AgnosiaParams" },
         "var_name": "ap",
         "predicate": { "type": "Gt", "a": { "type": "Attr", "node": { "type": "Var", "name": "ap" }, "key": "associative" }, "b": { "type": "Lit", "value": 0.5 } }
       }
     },
     "b": { "type": "Lit", "value": 1 }
   }
   ```
   When the lesion seed is not loaded, `Count(...)` is `0 < 1` (`True`), preserving byte-identical behavior.

## 4. Workflow: Building, Registering, and Teaching Seeds

### 4.1 Writing a Seed Emitter (`tools/build_*_seed.py`)
Hand-editing thousands of lines of nested Term JSON is error-prone. The standard convention is to write a small, deterministic Python emitter script in `tools/` (see [`tools/build_meta_shape_growth_seed.py`](../tools/build_meta_shape_growth_seed.py) as the canonical model):

```python
#!/usr/bin/env python3
"""Emit `seeds/my_capability.json`."""
import json, os

ROOT = os.path.dirname(os.path.dirname(os.path.abspath(__file__)))
OUT = os.path.join(ROOT, "seeds", "my_capability.json")

# Term shorthands — pure JSON assembly, zero runtime decisions
def var(n): return {"type": "Var", "name": n}
def attr(n, k): return {"type": "Attr", "node": var(n), "key": k}
def lit(v): return {"type": "Lit", "value": v}
def eq(a, b): return {"type": "Eq", "a": a, "b": b}
def ne(a, b): return {"type": "Not", "arg": eq(a, b)}
def and_(*items): return {"type": "And", "items": list(items)}
def T(term): return {"__term__": term}

MANIFEST = {
    "id": "my_capability",
    "version": "1.0.0",
    "depends_on": ["decision_core"],
    "description": "...",
    "nodes": [],
    "edges": [],
    "productions": [
        {
            "provenance": "my_capability:has_item",
            "src": {"type": "Agent", "var": "ag"},
            "edge_type": "has_item",
            "tgt": {"type": "Item", "var": "it"},
        }
    ],
    "rules": [
        {
            "name": "process_pending_item",
            "match_type": "Item",
            "match": [["ag", "has_item", "it"]],
            "where": eq(attr("it", "status"), lit("pending")),
            "effects": [
                ["set_attr", "it", "status", "done"],
            ],
        }
    ],
}

if __name__ == "__main__":
    with open(OUT, "w") as f:
        json.dump(MANIFEST, f, indent=1)
        f.write("\n")
```

> **Graceful skip when developing a new Rust Term in parallel:**
> `load_seed_manifest` skips an entire rule if *any* effect or clause references a Term variant not yet compiled into `substrate_rs`. If a downstream rule depends on a marker attribute (`dim_checked = 1`), split the marker into a separate, Term-free resilience rule (like `sd_dim_check_mark` in `seeds/shape_decode_loop.json`) so existing gates stay green before and after the new Term lands.

### 4.2 Registering and Booting Seeds
There are three ways a seed enters a running substrate:

1. **Core Boot (`substrate/boot_core.py`):**
   - `boot_core(seeds=CORE_SEEDS)` creates a bare `substrate_rs.Substrate()`, creates the `Agent` root node, resolves `depends_on` closures directly from `seeds/<id>.json`, and calls `inner.load_seed_manifest(manifest, agent)`.
2. **Named Seed Loading (`substrate/boot_core.py::load_seeds_into` + `domains/seed_registry.py`):**
   - Register your seed in [`domains/seed_registry.py`](../domains/seed_registry.py):
     ```python
     REGISTRY.register(Seed(
         id="my_capability", version="1.0.0",
         depends_on=("decision_core",),
         installer=_installer_from_manifest("my_capability"),
         description="...",
     ))
     ```
   - Call `load_seeds_into(s, agent, ["my_capability"])` to install the seed and its dependency closure idempotently, recording `Seed{id, version}` nodes and `depends_on` edges in the graph.
3. **Full / Selective Agent Boot (`substrate/boot_all.py`):**
   - `load_all_seeds` indexes `seeds/*.json` and `seeds/generated/*.json`, resolves typed content providers and `depends_on` edges directly from the JSON manifests, and loads the closure.

### 4.3 Live Daemon Reconciliation (`scripts/jabberwock_daemon.py`)
When working with a checkpointed long-running daemon (`scripts/jabberwock_daemon.py`):
- Editing an existing rule in a seed listed in `_REFRESHABLE_SEEDS` automatically tombstones the stale rule (`remove_rule`) and reinstalls the updated rule body on daemon resume (`_reconcile_seed_rules`) whenever its canonical JSON body changes.
- Top-level `Concept` nodes (`_reconcile_seed_concepts`) and typed nodes like `SelfProcess` (`_reconcile_seed_typed_nodes`) are also reconciled idempotently on resume.

### 4.4 Runtime Teaching (`domains/teach.py`)
When an agent learns a new fact, hint, or concept at runtime that should survive across boots, **do not hand-write a new seed JSON per item**. Use the `teach()` facility:

```python
from domains.teach import teach

teach(agent, "TaughtHint", {
    "topic": "rule_fixpoint_idempotence",
    "answer": "Always close the match guard in the rule's own effects."
})
```
`teach()` performs three steps:
1. Adds the node to the live graph immediately (idempotent on `(type, attrs)`).
2. Ingests a `ShapeObservation` (`domains.meta_shape.observe`) and runs the agent's own `RecogniseShape` meta-shape classifier (`categorise_by_shape`) so the agent files the knowledge under its own structural category (and grows a new `MetaShape` when a residual recurs!).
3. Appends the node to `seeds/<category>.json`. *(In tests, pass `seeds_dir=tmp_path` or set `OZMA_SEED_PERSIST_DISABLED=1` so tests never mutate tracked `seeds/*.json` files.)*

## 5. Auditing and Testing New Seeds

1. **Structural AST Audit (`tools/term_ast_audit.py`):**
   Before claiming a seed has no scalar bounds or hidden comparators, run `tools/term_ast_audit.py` (`audit_seed_file("seeds/<id>.json")`). Unlike naive string greps, it walks the full Term AST across `match`, `where`, and `effects` under arbitrary `Not`/`Exists`/`Filter` nesting and reports `T0_any_comparator`, `T1_bound_like`, `T2_bound_like` (codebook-crossing `Attr`-vs-`Attr` comparisons), and `undecidable_residual`.
2. **Write a Migrated Gate (`tests/test_<feature>_migrated.py`):**
   Every new seed should be accompanied by a `tests/test_<feature>_migrated.py` test module that boots the seed on `substrate_rs`, exercises its rules via `tick()` / `run_rules()`, and tests:
   - **Positive case:** The target phenomenon works end-to-end.
   - **Fixpoint termination / idempotence:** Running `run_rules()` a second time performs zero additional applications (`0` churn).
   - **Negative / scrambled control:** Unstructured or incoherent input does not falsely trigger recognition or corrupt the codebook.
   - **No-Python-decision audit:** The adapter layer only ingests and reads back.
3. **Run Scoped Tests:**
   ```bash
   pytest tests/test_<feature>_migrated.py
   ```
   *(Never invoke `pytest -n auto` on the full `-k migrated` suite; see [`CLAUDE.md`](../CLAUDE.md) for memory bounds.)*
